检查、暂存并打包 IPv6 Prefix Updater for pfSense，然后将软件包发布到 GitHub 发布版本。

## 前提条件 \{#requirements}

- **Node.js 22、24 或 26** — 根目录和工作区的清单文件都接受 `^22 || ^24 || ^26`。
- **PHP 或 Docker** — PHP 测试套件在本地有 `php` 时直接使用它，否则通过 Docker 使用 `php:8.3-cli-alpine` 镜像。`PHP_TEST_IMAGE` 可覆盖所用的镜像。
- **用于打包的 FreeBSD** — `npm run deploy` 只能在 FreeBSD 上运行，并且需要将 `PFSENSE_PORTS_DIR` 指向 pfSense FreeBSD-ports 仓库的本地检出副本。

## 检查、暂存与打包 \{#check-stage-and-package}

在仓库根目录中运行以下命令：

```bash
# Lint and type-check the scripts, run the PHP and Vitest suites, and validate the port.
npm run check --workspace pfsense-pkg-ipv6-prefix-updater

# Copy the port into packages/ipv6-prefix-updater/build/port with the workspace version.
npm run build --workspace pfsense-pkg-ipv6-prefix-updater

# Build the package on FreeBSD into packages/ipv6-prefix-updater/build/release.
PFSENSE_PORTS_DIR=/path/to/FreeBSD-ports npm run deploy --workspace pfsense-pkg-ipv6-prefix-updater
```

- 暂存步骤会将 `port/Makefile.template` 转换为 `build/port/Makefile`，并写入 `packages/ipv6-prefix-updater/package.json` 中的 `version`。
- 打包步骤会将暂存好的 port 复制到 ports 检出副本中的 `sysutils/pfSense-pkg-Ipv6PrefixUpdater`，运行 `make package`，然后再删除该副本。如果目标位置已存在，它会停止。
- 之后，`build/release` 中会包含带版本号的 `.pkg`、一个名为 `pfSense-pkg-Ipv6PrefixUpdater.pkg` 的副本，以及分别对应二者、只包含哈希值的 `.sha256` 文件。

## 发布工作流 \{#release-workflow}

Nova 生成的 `.github/workflows/nova-publish-project.yml` 中的 `publish-pfsense-packages-ipv6-prefix-updater` 作业会在发布工作流中运行：

1. 在 Ubuntu 运行器上验证并暂存 port。
2. 设置了 `PFSENSE_RELEASE_SIGNING_KEY` 机密时，从 `PFSENSE_RELEASE_SIGNING_KEY` 派生公钥，并将其追加到已暂存 port 的 `usr/local/share/pfSense-pkg-Ipv6PrefixUpdater/release-signing.pub`。
3. 使用已配置的 pfSense FreeBSD-ports 检出副本在 FreeBSD 上构建软件包。
4. 设置了该机密时，使用 `ssh-keygen -Y sign -n pfSense-pkg-Ipv6PrefixUpdater` 将每个 `.pkg` 签名为 `<file>.pkg.sig`。
5. 将软件包、校验和与签名作为保留 7 天的工作流制品上传，并将相同文件附加到发布版本。

由于软件包不含编译代码，构建会将它标记为适用于任何 FreeBSD 版本，因此一个软件包即可安装在所有受支持的 pfSense 版本上。`PFSENSE_FREEBSD_VERSION` 仅选择构建虚拟机使用的 FreeBSD 版本。安装指南中的 `pkg add` 命令会从 GitHub 标记为最新（latest）的发布版本获取 `pfSense-pkg-Ipv6PrefixUpdater.pkg`。

## 发布签名 \{#release-signing}

签名唯一需要的配置是仓库机密 `PFSENSE_RELEASE_SIGNING_KEY`，其中包含未加密的 OpenSSH Ed25519 私钥。

1. 在 1Password 中选择 **New Item → SSH Key → Generate a New Key → Ed25519**。
2. 在私钥字段中选择 **Export**，选择 OpenSSH 格式，不要设置密码。
3. 保存机密前检查剪贴板：

   ```bash
   pbpaste | head -1
   ```

   命令应输出 `-----BEGIN OPENSSH PRIVATE KEY-----`。

4. 将剪贴板直接发送到 GitHub，或读取已导出的文件：

   ```bash
   pbpaste | gh secret set PFSENSE_RELEASE_SIGNING_KEY
   gh secret set PFSENSE_RELEASE_SIGNING_KEY < <file>
   ```

5. 保存机密后，删除已导出的私钥文件。

如果没有该机密，软件包不会携带公钥，发布版本也不会签名。更换密钥时，将新的 `ssh-ed25519 ...` 公钥添加到 `release-signing.pub`，在旧密钥仍是机密时发布一个版本，然后用新密钥替换该机密。

如果签名密钥丢失，已安装副本无法验证使用替代密钥签名的发布版本。每个受影响的安装都需手动执行一次 `pkg add -f`，以安装携带新公钥的软件包。

## 在虚拟机中测试更新端点 \{#test-update-endpoints-in-a-vm}

CLI 接受两个环境变量，仅用于受控的虚拟机测试：

- `IPV6_PREFIX_UPDATER_RELEASES_API` 替换最新发布版本的 API URL。
- `IPV6_PREFIX_UPDATER_DOWNLOAD_PREFIX` 替换允许的资源 URL 前缀。

它们只由 `/usr/local/sbin/ipv6-prefix-updater` 读取，绝不会保存到软件包配置中，也不会由 WebGUI 直接读取。请在同一次 CLI 调用中设置所有需要的覆盖值：

```shell
IPV6_PREFIX_UPDATER_RELEASES_API=http://192.0.2.10/latest.json \
IPV6_PREFIX_UPDATER_DOWNLOAD_PREFIX=http://192.0.2.10/releases/ \
/usr/local/sbin/ipv6-prefix-updater --check-updates
```

使用 `--self-update` 代替 `--check-updates`，可针对测试发布版本走完完整的下载、SHA-256 校验和、发布签名、软件包元数据和 `pkg add -f` 流程。

## 文档站点 \{#documentation-site}

在 `apps/docs` 中，`npm run check` 会运行 ESLint、翻译树检查、三项类型检查，以及针对 `.env` 文件、frontmatter、链接、表格、术语链接和类型声明的 Vitest 测试套件。`npm run build` 会构建所有语言版本。

各语言的已翻译文档页面位于 `apps/docs/i18n/<locale>/docusaurus-plugin-content-docs/current/`，与英文页面一一对应，因此英文页面有更改时，也需要同步更新这些页面。界面文本（首页、导航栏、页脚、博客和侧边栏标签）来自 `scripts/generate-locales.mjs`，它读取 `scripts/locale-copies.json` 和软件包翻译。`npm run i18n` 会先运行该生成器，并且会保留已翻译的文档页面。

`.github/workflows/nova-publish-project.yml` 会在发布版本发布时构建站点，并将其部署到 GitHub Pages。
