确认你的防火墙、接口和 ISP 委派都满足软件包的要求，然后再依靠<Terminology title="按计划自动检查，启用前一直关闭" to="/docs/reference/terminology#running-checks">计划更新</Terminology>自动运行。

## 支持的版本 \{#supported-releases}

- 软件包已在 pfSense CE 2.9.1、2.9.0 和 2.8.1 以及 pfSense Plus 26.07.1、26.07 和 26.03.1 上测试过。**关于** 选项卡会列出每个版本经过测试的 pfSense 版本，并将与当前防火墙匹配的版本标记为 **此防火墙**。
- 软件包不检查 pfSense 版本。每次运行都会确认自己运行在 pfSense 上且所需的文件和函数齐全，缺少时会在读取设置之前停止。
- 软件包代码需要 PHP 8.1 或更高版本。
- 发布的软件包标记为适用于任意 FreeBSD 版本（`FreeBSD:*`）并标记为 vital，因此同一个软件包可以安装在所有受支持的 pfSense 版本上，pfSense 升级时也会保留它。

## 地址要求 \{#address-requirements}

- 每个<Terminology title="通过其地址揭示当前前缀的接口" to="/docs/reference/terminology#interfaces-and-detection">监控接口</Terminology>都必须有活动的<Terminology title="位于 2000::/3 内的公网 IPv6 地址，唯一会用到的类型" to="/docs/reference/terminology#addresses-and-prefixes">全局单播地址</Terminology>。软件包绝不会回退使用<Terminology title="以 fe80 开头的地址，永远不会用作源地址" to="/docs/reference/terminology#addresses-and-prefixes">链路本地地址</Terminology>。
- 唯一本地地址（`fc00::/7`）、组播地址、环回地址、未指定地址、IPv4 映射地址以及带区域标识符的地址都不能作为<Terminology title="每次运行读取前缀所用的实时地址" to="/docs/reference/terminology#interfaces-and-detection">源地址</Terminology>。
- <Terminology title="ISP 前缀的大小，例如 /56，由你设置" to="/docs/reference/terminology#addresses-and-prefixes">委派前缀长度</Terminology>必须介于 `/48` 到 `/64` 之间。边界落在某个十六进制位内部的长度（如 `/57`）同样适用。

某个地址不符合条件时，该接口会以<Terminology title="运行在某个检查或安全阶段停止" to="/docs/reference/terminology#run-outcomes">失败</Terminology>结束并给出原因，例如 `接口“lan”没有活动的全局 IPv6 地址。` [故障排除](/docs/operate/troubleshooting#run-failed)列出了这些消息。

## WAN 没有全局地址时 \{#when-wan-has-no-global-address}

有些 ISP 只委派前缀，而不为 WAN 本身分配<Terminology title="位于 2000::/3 内的公网 IPv6 地址，唯一会用到的类型" to="/docs/reference/terminology#addresses-and-prefixes">全局地址</Terminology>。这时，LAN 等<Terminology title="用另一个接口的前缀生成 IPv6 的接口" to="/docs/reference/terminology#interfaces-and-detection">跟踪接口</Terminology>会持有来自<Terminology title="ISP 分配给你的 IPv6 网络，可能会变化" to="/docs/reference/terminology#addresses-and-prefixes">委派前缀</Terminology>的地址，应当监控的就是它。

**Status → Interfaces**（状态 → 接口）会显示哪些接口具有<Terminology title="位于 2000::/3 内的公网 IPv6 地址，唯一会用到的类型" to="/docs/reference/terminology#addresses-and-prefixes">全局地址</Terminology>。

## 软件包能识别的内容 \{#what-the-package-recognizes}

软件包会更新<Terminology title="允许软件包改写的设置" to="/docs/reference/terminology#fields-and-change-plans">已批准字段</Terminology>中以字面形式写出的 IPv6 地址和网络。主机名、URL、IPv4 值和其他文本保持不变。

由 pfSense 生成的地址（例如<Terminology title="用另一个接口的前缀生成 IPv6 的接口" to="/docs/reference/terminology#interfaces-and-detection">跟踪接口</Terminology>上的地址）绝不会被更改。描述其他设备的地址（例如远程 VPN 网络和 WireGuard 对等端）只有在你于[其他设置](/docs/configure/configuration-scopes#other-settings)中勾选后才会更改。

## 可选依赖项 \{#optional-dependencies}

- **WireGuard 软件包**：仅在需要更改 <Terminology title="WireGuard 隧道接口上的地址" to="/docs/reference/terminology#pfsense-features">WireGuard 隧道地址</Terminology>时才需要。若未安装，包含 WireGuard 更改的实际运行会在备份之前停止。

## 已知限制 \{#known-limits}

- 添加<Terminology title="通过其地址揭示当前前缀的接口" to="/docs/reference/terminology#interfaces-and-detection">监控接口</Terminology>或将某一行切换为其他接口时，会为它记录新的<Terminology title="记录下来的起始前缀，变化以它为准" to="/docs/reference/terminology#baselines-and-transitions">基线</Terminology>；更改某一行的<Terminology title="ISP 前缀的大小，例如 /56，由你设置" to="/docs/reference/terminology#addresses-and-prefixes">委派前缀长度</Terminology>则算作一次<Terminology title="前缀变了，软件包开始工作" to="/docs/reference/terminology#baselines-and-transitions">前缀变化</Terminology>。
- <Terminology title="预览改动，但不写入任何内容" to="/docs/reference/terminology#running-checks">试运行</Terminology>无法模拟前缀变化，因此只有在真正发生变化后才会出现计划的更改。
- 高可用（CARP）对不会得到特殊处理。
- 作为<Terminology title="从 GitHub 安装，而非来自 Netgate 软件包仓库" to="/docs/reference/terminology#package-origins">非官方软件包</Terminology>，新版本需要用 `pkg` 安装，详见[更新或移除](/docs/reference/package-lifecycle)。

如何选择地址来源请参阅[接口与前缀](/docs/configure/interface-and-prefix)，软件包可更改的字段请参阅[字段](/docs/configure/configuration-scopes)。
