检查防火墙上的接口、前缀、恢复途径和通知，然后再让软件包按计划运行。

## 1. 确认地址来源 \{#1-confirm-the-source}

在 **<Terminology title="按计划自动检查，启用前一直关闭" to="/docs/reference/terminology#running-checks">启用计划更新</Terminology>** 未勾选的情况下保存设置，并选择一次 **立即运行**。然后检查“状态”选项卡：

- **<Terminology title="通过其地址揭示当前前缀的接口" to="/docs/reference/terminology#interfaces-and-detection">监控接口</Terminology>** 是预期的 WAN 或<Terminology title="用另一个接口的前缀生成 IPv6 的接口" to="/docs/reference/terminology#interfaces-and-detection">跟踪接口</Terminology>。
- **<Terminology title="每次运行读取前缀所用的实时地址" to="/docs/reference/terminology#interfaces-and-detection">上次成功源地址</Terminology>** 与 **Status → Interfaces**（状态 → 接口）中的地址一致。
- **<Terminology title="每次检查用来比较的已存前缀" to="/docs/reference/terminology#baselines-and-transitions">上次成功前缀</Terminology>** 与 ISP 委派的前缀一致。
- **上次运行** 下的 **结果** 为<Terminology title="初次检查：记录基线，不做任何改动" to="/docs/reference/terminology#run-outcomes">已初始化</Terminology>，**已更改字段** 为 `0`。

如果任何值不符合预期，建议先更正再继续。[接口与前缀](/docs/configure/interface-and-prefix#changing-the-interfaces)说明了<Terminology title="记录下来的起始前缀，变化以它为准" to="/docs/reference/terminology#baselines-and-transitions">基线</Terminology>建立后更改接口或长度会产生什么影响。

## 2. 运行预览 \{#2-run-a-preview}

选择 **<Terminology title="预览改动，但不写入任何内容" to="/docs/reference/terminology#running-checks">试运行</Terminology>**。前缀未变化时，它会报告<Terminology title="前缀与上次相同，无需任何操作" to="/docs/reference/terminology#run-outcomes">无变化</Terminology>，**<Terminology title="每次写入前一刻保存的配置副本" to="/docs/reference/terminology#backups-and-service-reloads">已创建配置备份</Terminology>** 显示“否”。

<Terminology title="预览改动，但不写入任何内容" to="/docs/reference/terminology#running-checks">试运行</Terminology>无法模拟前缀变化，因此只有在真正发生<Terminology title="前缀变了，软件包开始工作" to="/docs/reference/terminology#baselines-and-transitions">前缀变化</Terminology>后，它才会列出计划更改的字段。

## 3. 检查恢复途径 \{#3-check-recovery}

打开 **Diagnostics → Backup & Restore → Config History**（诊断 → 备份与恢复 → 配置历史），确认 pfSense 会保留配置历史。需要写入的运行会在第一次更改之前将<Terminology title="每次写入前一刻保存的配置副本" to="/docs/reference/terminology#backups-and-service-reloads">配置备份</Terminology>保存在那里。

建议现在就阅读[找到正确的修订版本](/docs/operate/backups-and-recovery#find-the-right-revision)，因为以软件包命名的修订版本保存的是更新后的配置。另外也值得下载一份设备外备份，因为<Terminology title="pfSense 保存的可供恢复的配置修订" to="/docs/reference/terminology#backups-and-service-reloads">配置历史</Terminology>存放在防火墙本机上。

## 4. 测试通知 \{#4-test-notifications}

如果勾选了 **<Terminology title="地址更新后发送的通知" to="/docs/reference/terminology#notifications-and-logs">发送变化通知</Terminology>**，建议使用 pfSense 在 **System → Advanced → Notifications**（系统 → 高级 → 通知）中自带的按钮发送一条测试通知。软件包使用的就是在那里配置好的<Terminology title="pfSense 的邮件等远程通知服务" to="/docs/reference/terminology#notifications-and-logs">通知渠道</Terminology>。

<Terminology title="前缀变了，但没有已批准字段使用旧前缀" to="/docs/reference/terminology#run-outcomes">警告</Terminology>和<Terminology title="运行在某个检查或安全阶段停止" to="/docs/reference/terminology#run-outcomes">失败</Terminology>通知只显示在 WebGUI 中，不使用这些渠道。

## 5. 开启计划更新 \{#5-turn-on-the-schedule}

上述步骤显示的地址和前缀都符合预期后，勾选 **<Terminology title="按计划自动检查，启用前一直关闭" to="/docs/reference/terminology#running-checks">启用计划更新</Terminology>**。**计划** 的默认值为 **每小时**。

到达第一个计划时间后，建议查看 **上次运行** 下的 **时间戳 (UTC)** 和 **结果**。

## 需要真实前缀变化才能验证的内容 \{#what-needs-a-real-prefix-change}

<Terminology title="在任何改动之前就列好的全部改写" to="/docs/reference/terminology#fields-and-change-plans">变更计划</Terminology>、<Terminology title="每次写入前一刻保存的配置副本" to="/docs/reference/terminology#backups-and-service-reloads">配置备份</Terminology>、<Terminology title="将更改后的设置应用到正在运行的服务" to="/docs/reference/terminology#backups-and-service-reloads">服务重新加载</Terminology>和<Terminology title="地址更新后发送的通知" to="/docs/reference/terminology#notifications-and-logs">变化通知</Terminology>只会在真正发生<Terminology title="前缀变了，软件包开始工作" to="/docs/reference/terminology#baselines-and-transitions">前缀变化</Terminology>后才出现。要观察一次完整运行，最安全的地方是前缀可以变化的实验室防火墙。

在你自己的防火墙上，建议在“状态”选项卡中检查第一次真实的变化，先从 **已更改字段**、**<Terminology title="将更改后的设置应用到正在运行的服务" to="/docs/reference/terminology#backups-and-service-reloads">已重新加载的服务</Terminology>** 和 **摘要** 看起。

运行后显示的每个字段请参阅[状态与操作](/docs/operate/status-and-actions)。
