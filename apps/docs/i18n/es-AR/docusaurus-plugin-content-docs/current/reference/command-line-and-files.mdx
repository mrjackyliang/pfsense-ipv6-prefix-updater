Ejecutá el comando del paquete desde una shell y encontrá los archivos, registros y avisos que usa.

## Uso \{#usage}

```shell
/usr/local/sbin/ipv6-prefix-updater [--manual] [--dry-run] [--accept-current-prefix [--interface=NAME]] [--migrate-legacy] [--help]
```

La entrada de cron administrada por pfSense ejecuta el comando como `root` sin opciones. Antes de cada comprobación, también traslada al paquete cualquier resto del <Terminology title="script update.php original que ejecutaba el paquete Cron" to="/docs/reference/terminology#legacy-updater">actualizador heredado</Terminology>. La pestaña Estado usa `--manual` para **Ejecutar ahora**, `--dry-run` para **<Terminology title="vista previa que nunca hace copias ni escribe" to="/docs/reference/terminology#dry-run">Simulación</Terminology>** y `--accept-current-prefix` para la recuperación de la referencia, y la pestaña Limpieza usa `--migrate-legacy`.

Sin opciones, el comando se comporta como una comprobación programada y devuelve <Terminology title="resultado: comprobación programada omitida con las actualizaciones desactivadas" to="/docs/reference/terminology#disabled">Desactivado</Terminology> cuando **<Terminology title="comprobaciones automáticas desde una entrada de cron administrada por pfSense" to="/docs/reference/terminology#scheduled-updates">Activar actualizaciones programadas</Terminology>** está desactivada.

## Opciones \{#options}

| Opción                    | Descripción                                                                                                                                                                                                                                                                                                                  |
|---------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `--manual`                | Se ejecuta aunque las <Terminology title="comprobaciones automáticas desde una entrada de cron administrada por pfSense" to="/docs/reference/terminology#scheduled-updates">actualizaciones programadas</Terminology> estén desactivadas.                                                                                    |
| `--dry-run`               | Muestra una vista previa sin copia de seguridad ni escritura, e implica `--manual`.                                                                                                                                                                                                                                          |
| `--accept-current-prefix` | Registra la dirección de origen, el prefijo y la longitud activos como referencia sin analizar los campos aprobados, crear una copia de seguridad, escribir la configuración ni recargar servicios. Implica `--manual` y no se puede combinar con `--dry-run`.                                                               |
| `--interface=NAME`        | Limita `--accept-current-prefix` a una sola interfaz supervisada, indicada por su nombre interno, como `lan`. Sin esta opción, se aceptan todas las interfaces supervisadas que tengan dirección.                                                                                                                            |
| `--migrate-legacy`        | Traslada enseguida el <Terminology title="script update.php original que ejecutaba el paquete Cron" to="/docs/reference/terminology#legacy-updater">actualizador heredado</Terminology> al paquete y muestra cada paso, sin ejecutar una comprobación del prefijo. Sale con `2` cuando la migración informó una advertencia. |
| `--help`                  | Muestra la línea de uso y sale con `0`. La línea de uso no incluye el propio `--help`.                                                                                                                                                                                                                                       |

Cualquier otra opción muestra `Opción desconocida: <opción>` en la salida de error estándar y sale con `64`. Combinar `--accept-current-prefix` con `--dry-run` también sale con `64`.

## Salida \{#output}

Una ejecución terminada que supervisa una sola interfaz muestra nueve líneas en la salida estándar, seguidas de los cambios de campos después de una <Terminology title="vista previa que nunca hace copias ni escribe" to="/docs/reference/terminology#dry-run">simulación</Terminology> o de un resultado <Terminology title="resultado: campos actualizados, guardados, recargados y verificados" to="/docs/reference/terminology#success">Correcto</Terminology>:

```text
Estado: Correcto
Interfaz: lan
Dirección de origen observada: 2001:db8:abcd:88aa::1
Prefijo anterior: 2001:db8:abcd:7800::
Prefijo actual: 2001:db8:abcd:8800::/56
Campos planificados o modificados: 1
Copia de seguridad de la configuración: Creada
Servicios recargados: Filtro del firewall
Resumen: Se actualizaron 1 campo(s) aprobado(s) de 2001:db8:abcd:7800::/56 a 2001:db8:abcd:8800::/56 en la interfaz lan.
Cambios de campos:
- aliases/alias/0/address: 2001:db8:abcd:78aa::10 → 2001:db8:abcd:88aa::10
```

- `Prefijo anterior` no tiene longitud, y muestra `No disponible` después de <Terminology title="resultado: referencia registrada, configuración sin cambios" to="/docs/reference/terminology#initialized">Inicializado</Terminology> o <Terminology title="resultado: simulación antes de que exista una referencia" to="/docs/reference/terminology#initialization-preview">Vista previa de la inicialización</Terminology>.
- `Servicios recargados` enumera las etiquetas de la pestaña Estado o `Ninguno`. Después de una <Terminology title="vista previa que nunca hace copias ni escribe" to="/docs/reference/terminology#dry-run">simulación</Terminology>, enumera los servicios que se recargarían.
- `Cambios de campos` tiene una línea por cada dirección reemplazada, escrita como `- <ruta>: <anterior> → <nueva>`, para un máximo de 200 campos.
- Cuando la ejecución volvió a aplicar la configuración de otro paquete u omitió un campo tildado que ya no existe, sigue una línea por cada caso, con el mismo texto que en la pestaña Estado.
- Cuando otra comprobación tiene el <Terminology title="protección que evita dos comprobaciones al mismo tiempo" to="/docs/reference/terminology#run-lock">bloqueo de ejecución</Terminology>, la única salida es `Otra ejecución posee el bloqueo del paquete; esta invocación salió sin leer la configuración.`
- Con varias interfaces supervisadas, la salida empieza con las líneas generales de `Estado`, `Resumen`, paquetes y campos omitidos, seguidas de las líneas de cada interfaz, separadas por líneas en blanco.
- Cuando hubo una migración del <Terminology title="script update.php original que ejecutaba el paquete Cron" to="/docs/reference/terminology#legacy-updater">actualizador heredado</Terminology> antes de la comprobación, sus pasos se muestran primero.
- Las etiquetas y los mensajes siguen la opción de idioma de pfSense.

## Formato del estado del paquete \{#package-state-format}

| Clave                 | Descripción                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
|-----------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `schema_version`      | Siempre `1`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `targets.<interface>` | Una <Terminology title="prefijo inicial registrado sin cambiar la configuración" to="/docs/reference/terminology#baseline">referencia</Terminology> por cada interfaz supervisada, con su nombre interno como clave y con `interface`, `source_address`, `prefix`, `prefix_length` y `updated_at`. Una referencia tomada del <Terminology title="script update.php original que ejecutaba el paquete Cron" to="/docs/reference/terminology#legacy-updater">actualizador heredado</Terminology> también tiene `source` con el valor `legacy_cache`. |
| `last_run`            | La última ejecución registrada, con `status`, `timestamp`, `interface`, `observed_address`, `previous_prefix`, `current_prefix`, `current_prefix_length`, `change_count`, `backup_created`, `services`, `message`, `message_key` y `message_arguments`.                                                                                                                                                                                                                                                                                            |
| `legacy_migration`    | Aparece después de una migración del <Terminology title="script update.php original que ejecutaba el paquete Cron" to="/docs/reference/terminology#legacy-updater">actualizador heredado</Terminology>, con `status`, `steps`, `warnings` y `recorded_at`. La pestaña Limpieza lo muestra.                                                                                                                                                                                                                                                         |

- `status` es uno de estos valores: `initialized`, `initialization_preview`, `no_change`, `dry_run`, `warning`, `accepted`, `success` o `failure`.
- Después de un resultado <Terminology title="resultado: campos actualizados, guardados, recargados y verificados" to="/docs/reference/terminology#success">Correcto</Terminology>, `last_run.notification` es `disabled` cuando las notificaciones están desactivadas, o `sent` o `failed` después de un intento de envío.
- Después de una <Terminology title="vista previa que nunca hace copias ni escribe" to="/docs/reference/terminology#dry-run">simulación</Terminology> o de un resultado <Terminology title="resultado: campos actualizados, guardados, recargados y verificados" to="/docs/reference/terminology#success">Correcto</Terminology>, cada resultado también tiene `changes`, que enumera la `path` y los `replacements` de un máximo de 200 campos, donde cada reemplazo es una dirección anterior y una nueva.
- `package_reapply` enumera la `section`, el `package`, el `status` y el `error` de cada paquete cuya configuración volvió a aplicar la ejecución, y `skipped_fields` enumera los campos tildados que ya no existen. Cada uno aparece solo cuando no está vacío.
- Con varias interfaces supervisadas, `last_run` contiene los totales y una lista `targets` con un resultado por interfaz.
- Las marcas de tiempo usan ISO 8601 en UTC. Un archivo que no se puede analizar, o que tiene otra versión de esquema, detiene cada ejecución con `El estado del Actualizador de prefijo IPv6 no es válido o no es compatible.`

## Almacenamiento de las opciones \{#settings-storage}

Las opciones se guardan en la configuración de pfSense, en `installedpackages/ipv6prefixupdater/config/0`.

| Clave              | Descripción                                                                                                                                                                                                                            |
|--------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `enabled`          | **<Terminology title="comprobaciones automáticas desde una entrada de cron administrada por pfSense" to="/docs/reference/terminology#scheduled-updates">Activar actualizaciones programadas</Terminology>**, `on` cuando está tildada. |
| `row`              | **Interfaces supervisadas**, una lista con un `interface` (una clave de interfaz, como `lan`) y un `prefix_length` (de `48` a `64`) por fila.                                                                                          |
| `update_frequency` | **Programación**, uno de `every_fifteen_minutes`, `hourly`, `every_six_hours` o `daily`.                                                                                                                                               |
| `notifications`    | **<Terminology title="alerta enviada después de una actualización correcta verificada" to="/docs/reference/terminology#change-notification">Enviar notificaciones de cambios</Terminology>**, `on` cuando está tildada.                |

### Selección de campos \{#field-selection}

Las elecciones de la pestaña Campos se guardan junto al registro de opciones, en `installedpackages/ipv6prefixupdater/fields`, así que guardar la pestaña Configuración, que reemplaza `config/0`, nunca las borra.

| Clave                  | Descripción                                                                                                                                              |
|------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------|
| `schema`               | Siempre `1`. Indica una selección guardada desde la pestaña Campos, aunque esté vacía.                                                                   |
| `enabled_groups/item`  | Grupos activados, como `firewall_rules`, `dhcpv6` o `package:<section>` para la configuración de otro paquete.                                           |
| `disabled_groups/item` | Grupos de pfSense desactivados. Un grupo de pfSense que no está en ninguna de las dos listas está activado, y el grupo de otro paquete está desactivado. |
| `include/item`         | Identidades de los campos tildados en un grupo desactivado.                                                                                              |
| `exclude/item`         | Identidades de los campos destildados en un grupo activado.                                                                                              |

- Las claves de los grupos de pfSense son `interfaces`, `virtual_ips`, `aliases`, `firewall_rules`, `nat`, `dhcpv6`, `router_advertisements`, `dns_host_overrides`, `ipsec`, `openvpn` y `wireguard`.
- `include` y `exclude` guardan como máximo 1000 identidades cada una, y cada identidad sigue [Identidades de campos](/docs/reference/approved-fields#field-identities).

## Entrada de cron \{#cron-entry}

Al guardar las opciones se borra cualquier entrada existente del comando y, cuando `enabled` es `on`, se instala una nueva para `root` con `install_cron_job()` de pfSense.

| Valor de programación   | Campos de cron |
|-------------------------|----------------|
| `every_fifteen_minutes` | `*/15 * * * *` |
| `hourly`                | `0 * * * *`    |
| `every_six_hours`       | `0 */6 * * *`  |
| `daily`                 | `0 0 * * *`    |

Si el valor es desconocido, se usan los campos de cada hora. Mientras una migración del <Terminology title="script update.php original que ejecutaba el paquete Cron" to="/docs/reference/terminology#legacy-updater">actualizador heredado</Terminology> espera a que termine el script heredado, el paquete mantiene una entrada `*/15 * * * *` para que la migración se vuelva a intentar aunque las actualizaciones programadas estén desactivadas.

## Registros y avisos \{#logs-and-notices}

Cada línea del <Terminology title="registro general de pfSense donde escribe el paquete" to="/docs/reference/terminology#system-log">registro del sistema</Terminology> se escribe con `log_error()` de pfSense y empieza con `IPv6 Prefix Updater:`. Los avisos se crean con `file_notice()` y enlazan con `/ipv6-prefix-updater-status.php`, salvo el aviso de migración, que enlaza con `/ipv6-prefix-updater-cleanup.php`.

| ID del aviso                            | Se crea cuando                                                                                                                                                                                                                                                  | Entrega                                                                                                                                                                         |
|-----------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `ipv6-prefix-updater-success`           | <Terminology title="resultado: campos actualizados, guardados, recargados y verificados" to="/docs/reference/terminology#success">Correcto</Terminology> con `notifications` en `on`                                                                            | WebGUI y <Terminology title="servicios de alertas remotas configurados en pfSense" to="/docs/reference/terminology#notification-channels">canales de notificación</Terminology> |
| `ipv6-prefix-updater-no-matches`        | <Terminology title="resultado: el prefijo cambió, pero ningún campo aprobado coincidió" to="/docs/reference/terminology#warning">Advertencia</Terminology>                                                                                                      | Solo WebGUI                                                                                                                                                                     |
| `ipv6-prefix-updater-failure`           | <Terminology title="resultado: una verificación o etapa de seguridad detuvo la ejecución" to="/docs/reference/terminology#failure">Fallo</Terminology>                                                                                                          | Solo WebGUI                                                                                                                                                                     |
| `ipv6-prefix-updater-package-<section>` | Una ejecución cambió la configuración de otro paquete, y ningún paquete instalado es dueño de la sección o falló la nueva aplicación de su configuración                                                                                                        | Solo WebGUI                                                                                                                                                                     |
| `ipv6-prefix-updater-legacy-migration`  | Una migración del <Terminology title="script update.php original que ejecutaba el paquete Cron" to="/docs/reference/terminology#legacy-updater">actualizador heredado</Terminology> que hizo al menos un paso, o una migración que falló durante la instalación | Solo WebGUI                                                                                                                                                                     |

Si falla la verificación del entorno del propio comando, o no se puede abrir su archivo de bloqueo, el motivo solo va a la salida de error estándar. Cada ejecución que escribe también guarda una revisión de la configuración descrita como `El Actualizador de prefijo IPv6 cambió <cantidad> campo(s) aprobado(s) para la interfaz <interfaz>`.

## Privilegios de las páginas \{#page-privileges}

Cada página del paquete declara su propio privilegio de pfSense, así que el acceso se puede otorgar página por página:

- **Estado**: `page-services-ipv6-prefix-updater-status`, llamado `Services: IPv6 Prefix Updater: Status`.
- **Campos**: `page-services-ipv6-prefix-updater-fields`, llamado `Services: IPv6 Prefix Updater: Fields`. Puede cambiar qué campos reescribe una ejecución, así que se recomienda otorgarlo solo a administradores.
- **Copias de seguridad**: `page-services-ipv6-prefix-updater-backups`, llamado `Services: IPv6 Prefix Updater: Backups`. Permite descargar copias completas de la configuración, así que se recomienda otorgarlo solo a administradores.
- **Limpieza**: `page-services-ipv6-prefix-updater-cleanup`, llamado `Services: IPv6 Prefix Updater: Cleanup`.
