Verificá la versión instalada, instalá una versión más nueva o desinstalá el paquete desde una shell de pfSense.

## Verificar la versión instalada \{#check-the-installed-version}

```shell
pkg info pfSense-pkg-Ipv6PrefixUpdater
```

Compará la versión que aparece con la [última versión de GitHub](https://github.com/mrjackyliang/pfsense-ipv6-prefix-updater/releases/latest).

## Actualizar el paquete \{#update-the-package}

Se recomienda descargar primero una copia de la configuración desde **Diagnostics → Backup & Restore**. Después, instalá la última versión sobre el paquete existente:

```shell
pkg add -f https://github.com/mrjackyliang/pfsense-ipv6-prefix-updater/releases/latest/download/pfSense-pkg-Ipv6PrefixUpdater.pkg
```

El paso de instalación vuelve a sincronizar las dos entradas de cron, la comprobación del prefijo y la comprobación de versiones, con las opciones guardadas y conserva todas las <Terminology title="El prefijo inicial registrado con el que se miden los cambios" to="/docs/reference/terminology#baselines-and-transitions">referencias</Terminology>. Los pasos de la suma de verificación de [Instalar el paquete](/docs/installation#verify-the-download-first) también sirven para las actualizaciones.

Después de la actualización:

1. Abrí la pestaña **Configuración** de **Services → IPv6 Prefix Updater** y confirmá los valores guardados.
2. En la pestaña Estado, revisá **Estado actual**. Cada interfaz conserva su <Terminology title="El prefijo inicial registrado con el que se miden los cambios" to="/docs/reference/terminology#baselines-and-transitions">referencia</Terminology>.

Si una fila muestra `No inicializado`, **Ejecutar ahora** registra una <Terminology title="El prefijo inicial registrado con el que se miden los cambios" to="/docs/reference/terminology#baselines-and-transitions">referencia</Terminology> nueva para ella. En ese caso, las direcciones que todavía usan un prefijo anterior a esa referencia no cambian.

## Desinstalar el paquete \{#remove-the-package}

Si primero destildás **<Terminology title="Comprobaciones automáticas programadas, apagadas por defecto" to="/docs/reference/terminology#running-checks">Activar actualizaciones programadas</Terminology>**, evitás que una reinstalación posterior active la programación enseguida en caso de que pfSense conserve las opciones guardadas. Después, ejecutá:

```shell
pkg delete -f pfSense-pkg-Ipv6PrefixUpdater
```

El paquete está marcado como `vital`, por lo que las actualizaciones propias de pfSense lo mantienen instalado y `pkg delete` sin `-f` rechaza los paquetes vitales.

La desinstalación borra las dos entradas de cron (comprobación del prefijo y comprobación de versiones), cierra el aviso de actualización disponible y borra el archivo de <Terminology title="Impide que dos comprobaciones se ejecuten a la vez" to="/docs/reference/terminology#running-checks">bloqueo de ejecución</Terminology> cuando ninguna ejecución lo tiene. Conserva el <Terminology title="El archivo con cada referencia, que sobrevive a una reinstalación" to="/docs/reference/terminology#running-checks">estado del paquete</Terminology>, `updates.json`, `update-status.json` y las copias de la pestaña **Copias de seguridad** en `/cf/conf/ipv6-prefix-updater`.

Las actualizaciones propias de pfSense mantienen el paquete instalado (es `vital`), y el estado conservado hace que una desinstalación y reinstalación nunca pierda una <Terminology title="El prefijo inicial registrado con el que se miden los cambios" to="/docs/reference/terminology#baselines-and-transitions">referencia</Terminology>.

La desinstalación no deshace las direcciones ya guardadas en la configuración, y las revisiones del paquete quedan en el <Terminology title="Las revisiones de configuración guardadas en pfSense que podés restaurar" to="/docs/reference/terminology#backups-and-service-reloads">historial de configuración</Terminology>. Para borrar también los archivos conservados, ejecutá `rm -rf /cf/conf/ipv6-prefix-updater` después de desinstalar el paquete.

## Reinstalar más adelante \{#reinstall-later}

Una reinstalación encuentra el <Terminology title="El archivo con cada referencia, que sobrevive a una reinstalación" to="/docs/reference/terminology#running-checks">estado del paquete</Terminology> conservado, así que la primera ejecución compara contra cada <Terminology title="El prefijo inicial registrado con el que se miden los cambios" to="/docs/reference/terminology#baselines-and-transitions">referencia</Terminology> guardada y actualiza los campos que quedaron en un prefijo más viejo. Si las opciones anteriores siguen presentes con **<Terminology title="Comprobaciones automáticas programadas, apagadas por defecto" to="/docs/reference/terminology#running-checks">Activar actualizaciones programadas</Terminology>** tildada, el paso de instalación activa la programación enseguida.

Para empezar de cero, borrá `/cf/conf/ipv6-prefix-updater` antes de reinstalar. Así, la primera ejecución registra una <Terminology title="El prefijo inicial registrado con el que se miden los cambios" to="/docs/reference/terminology#baselines-and-transitions">referencia</Terminology> nueva y devuelve <Terminology title="Primer vistazo: se registra la referencia y nada cambia" to="/docs/reference/terminology#run-outcomes">Inicializado</Terminology> sin cambiar la configuración.

Revisá [Copias de seguridad y recuperación](/docs/operate/backups-and-recovery) antes del mantenimiento y [Establecer la referencia](/docs/first-run) después de una reinstalación.
