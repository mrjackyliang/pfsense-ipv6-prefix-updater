Verificá, prepará y empaquetá IPv6 Prefix Updater for pfSense y después publicá el paquete en una versión de GitHub.

## Requisitos \{#requirements}

- **Node.js 22, 24 o 26** — Los manifiestos de la raíz y del workspace aceptan `^22 || ^24 || ^26`.
- **PHP o Docker** — Las suites de PHP usan un `php` local si existe o, si no, la imagen `php:8.3-cli-alpine` mediante Docker. `PHP_TEST_IMAGE` reemplaza la imagen.
- **FreeBSD para empaquetar** — `npm run deploy` solo corre en FreeBSD, con `PFSENSE_PORTS_DIR` apuntando a un checkout de FreeBSD-ports de pfSense.

## Verificar, preparar y empaquetar \{#check-stage-and-package}

Ejecutá estos comandos desde la raíz del repositorio:

```bash
# Lint and type-check the scripts, run the PHP and Vitest suites, and validate the port.
npm run check --workspace pfsense-pkg-ipv6-prefix-updater

# Copy the port into packages/ipv6-prefix-updater/build/port with the workspace version.
npm run build --workspace pfsense-pkg-ipv6-prefix-updater

# Build the package on FreeBSD into packages/ipv6-prefix-updater/build/release.
PFSENSE_PORTS_DIR=/path/to/FreeBSD-ports npm run deploy --workspace pfsense-pkg-ipv6-prefix-updater
```

- La preparación convierte `port/Makefile.template` en `build/port/Makefile` y le agrega la `version` de `packages/ipv6-prefix-updater/package.json`.
- El empaquetado copia el port preparado en `sysutils/pfSense-pkg-Ipv6PrefixUpdater` dentro del checkout de ports, ejecuta `make package` y después borra esa copia. Se detiene si el destino ya existe.
- Después, `build/release` contiene el `.pkg` con versión, una copia llamada `pfSense-pkg-Ipv6PrefixUpdater.pkg` y un archivo `.sha256` para cada uno que solo contiene el hash.

## Flujo de publicación \{#release-workflow}

El trabajo `publish-pfsense-packages-ipv6-prefix-updater` de `.github/workflows/nova-publish-project.yml`, generado por Nova, se ejecuta en el flujo de publicación:

1. Valida y prepara el port en un runner de Ubuntu.
2. Cuando el secret `PFSENSE_RELEASE_SIGNING_KEY` está configurado, deriva la clave pública de `PFSENSE_RELEASE_SIGNING_KEY` y la agrega a `usr/local/share/pfSense-pkg-Ipv6PrefixUpdater/release-signing.pub` en el port preparado.
3. Compila el paquete en FreeBSD con el checkout configurado de FreeBSD-ports de pfSense.
4. Cuando el secret está configurado, firma cada `.pkg` como `<file>.pkg.sig` con `ssh-keygen -Y sign -n pfSense-pkg-Ipv6PrefixUpdater`.
5. Sube los paquetes, las sumas y las firmas como artefacto del flujo durante 7 días y adjunta los mismos archivos a la versión.

La compilación marca el paquete para cualquier versión de FreeBSD porque no contiene código compilado, por lo que un solo paquete se instala en todas las versiones compatibles de pfSense. `PFSENSE_FREEBSD_VERSION` solo selecciona la versión de FreeBSD que usa la VM de compilación. El comando `pkg add` de la guía de instalación descarga `pfSense-pkg-Ipv6PrefixUpdater.pkg` de la versión que GitHub marque como la más reciente.

## Firma de versiones \{#release-signing}

La única configuración de firma es el secret de repositorio `PFSENSE_RELEASE_SIGNING_KEY`, que contiene una clave privada OpenSSH Ed25519 sin cifrar.

1. En 1Password, elegí **New Item → SSH Key → Generate a New Key → Ed25519**.
2. En el campo de la clave privada, elegí **Export**, seleccioná el formato OpenSSH y no pongas contraseña.
3. Verificá el portapapeles antes de guardar el secret:

   ```bash
   pbpaste | head -1
   ```

   El comando debe mostrar `-----BEGIN OPENSSH PRIVATE KEY-----`.

4. Enviá el portapapeles directamente a GitHub o leé un archivo exportado:

   ```bash
   pbpaste | gh secret set PFSENSE_RELEASE_SIGNING_KEY
   gh secret set PFSENSE_RELEASE_SIGNING_KEY < <file>
   ```

5. Borrá el archivo de la clave privada exportada después de guardar el secret.

Sin el secret, los paquetes no incluyen una clave pública y las versiones no se firman. Para cambiar la clave, agregá la nueva clave pública `ssh-ed25519 ...` a `release-signing.pub`, publicá una versión mientras la clave anterior todavía sea el secret y después reemplazá el secret por la clave nueva.

Si se pierde la clave de firma, las copias instaladas no pueden autenticar una versión firmada por la clave de reemplazo. Cada instalación afectada necesita ejecutar una vez el comando manual `pkg add -f` para instalar un paquete que contenga la nueva clave pública.

## Probar endpoints de actualización en una VM \{#test-update-endpoints-in-a-vm}

La CLI acepta dos variables de entorno únicamente para pruebas controladas en una VM:

- `IPV6_PREFIX_UPDATER_RELEASES_API` reemplaza la URL de la API de la última versión.
- `IPV6_PREFIX_UPDATER_DOWNLOAD_PREFIX` reemplaza el prefijo de URL permitido para los archivos de la versión.

Solo las lee `/usr/local/sbin/ipv6-prefix-updater`; nunca se guardan en la configuración del paquete ni las lee directamente la WebGUI. Definí todos los reemplazos necesarios en la misma invocación de la CLI:

```shell
IPV6_PREFIX_UPDATER_RELEASES_API=http://192.0.2.10/latest.json \
IPV6_PREFIX_UPDATER_DOWNLOAD_PREFIX=http://192.0.2.10/releases/ \
/usr/local/sbin/ipv6-prefix-updater --check-updates
```

Usá `--self-update` en lugar de `--check-updates` para probar todo el proceso de descarga, suma SHA-256, firma de versión, metadatos del paquete y `pkg add -f`.

## Suites de pruebas de PHP \{#php-test-suites}

- **`tests/domain.php`**: la <Terminology title="La forma corta y en minúsculas, como 2001:db8::1" to="/docs/reference/terminology#addresses-and-prefixes">forma canónica</Terminology>, los límites `/48` y `/64`, el enmascaramiento, los <Terminology title="Los bits después del prefijo, que siempre se copian sin cambios" to="/docs/reference/terminology#addresses-and-prefixes">bits de host</Terminology> en `/53`, las direcciones rechazadas, la planificación sin cambios, el filtrado por prefijo anterior y un cambio de longitud tratado como <Terminology title="Tu prefijo cambió, así que el paquete se pone a trabajar" to="/docs/reference/terminology#baselines-and-transitions">cambio de prefijo</Terminology>.
- **`tests/runtime.php`**: el análisis de cada <Terminology title="Un solo interruptor para todo un tipo de ajuste" to="/docs/reference/terminology#fields-and-change-plans">grupo de campos</Terminology>, las excepciones de campos individuales, la nueva aplicación de la configuración de otros paquetes, el <Terminology title="El archivo con cada referencia, que sobrevive a una reinstalación" to="/docs/reference/terminology#running-checks">estado del paquete</Terminology> atómico, el <Terminology title="Impide que dos comprobaciones se ejecuten a la vez" to="/docs/reference/terminology#running-checks">bloqueo de ejecución</Terminology>, las plataformas no compatibles y las comprobaciones programadas desactivadas. También cubre el orden de la transacción y los fallos en la escritura, la copia de seguridad, la verificación previa de recargas, las recargas y la notificación, además de la <Terminology title="El prefijo cambió, pero ningún campo aprobado usaba el anterior" to="/docs/reference/terminology#run-outcomes">Advertencia</Terminology> sin coincidencias.
- **`tests/pfsense-adapter.php`**: una actualización forzada de la dirección sin alternativa de <Terminology title="Una dirección fe80 que nunca se usa como origen" to="/docs/reference/terminology#addresses-and-prefixes">enlace local</Terminology>, la copia de seguridad antes del guardado de solo escritura y una copia de seguridad fallida que se detiene antes de la escritura.
- **`tests/updates.php`**: comparación de versiones, procesamiento de versiones y validación de URL, cronogramas aleatorios estables, deduplicación de avisos, digests de la API de GitHub, alternativas `.sha256`, procesamiento de claves de firma, salida de allowed-signers, argumentos exactos y entrada estándar de `ssh-keygen`, firmas válidas, claves y namespaces incorrectos, y paquetes alterados.
- **`tests/translations.php`** y **`tests/webgui-localization.php`**: catálogos completos para cada identificador de idioma de pfSense, y el formulario de Configuración y los mensajes de validación localizados.

## Sitio de documentación \{#documentation-site}

Desde `apps/docs`, `npm run check` ejecuta ESLint, la verificación del árbol de traducciones, tres verificaciones de tipos y las suites de Vitest para los archivos `.env`, el frontmatter, los enlaces, las tablas, los enlaces del glosario y las declaraciones de tipos. `npm run build` compila todos los idiomas.

Las páginas de documentación traducidas de cada idioma están en `apps/docs/i18n/<locale>/docusaurus-plugin-content-docs/current/` y replican las páginas en inglés, así que actualizalas cuando cambie una página en inglés. Los textos de la interfaz (página de inicio, barra de navegación, pie de página, blog y etiquetas de la barra lateral) salen de `scripts/generate-locales.mjs`, que lee `scripts/locale-copies.json` y las traducciones del paquete. `npm run i18n` ejecuta primero ese generador, que deja intactas las páginas de documentación traducidas.

`.github/workflows/nova-publish-project.yml` compila el sitio y lo despliega en GitHub Pages cuando se publica una versión.
