Provjerite, pripremite i zapakujte IPv6 Prefix Updater for pfSense, a zatim objavite paket u izdanju na GitHubu.

## Zahtjevi \{#requirements}

- **Node.js 22, 24 ili 26** — glavni manifest i manifesti radnog prostora prihvataju `^22 || ^24 || ^26`.
- **PHP ili Docker** — PHP skupovi testova koriste lokalni `php` kada postoji, ili sliku `php:8.3-cli-alpine` putem Dockera. `PHP_TEST_IMAGE` zamjenjuje tu sliku.
- **FreeBSD za pakovanje** — `npm run deploy` radi samo na FreeBSD-u, uz `PFSENSE_PORTS_DIR` koji pokazuje na radnu kopiju pfSense FreeBSD-ports repozitorija.

## Provjera, priprema i pakovanje \{#check-stage-and-package}

Pokrenite ove naredbe iz korijena repozitorija:

```bash
# Lint and type-check the scripts, run the PHP and Vitest suites, and validate the port.
npm run check --workspace pfsense-pkg-ipv6-prefix-updater

# Copy the port into packages/ipv6-prefix-updater/build/port with the workspace version.
npm run build --workspace pfsense-pkg-ipv6-prefix-updater

# Build the package on FreeBSD into packages/ipv6-prefix-updater/build/release.
PFSENSE_PORTS_DIR=/path/to/FreeBSD-ports npm run deploy --workspace pfsense-pkg-ipv6-prefix-updater
```

- Priprema pretvara `port/Makefile.template` u `build/port/Makefile` i označava ga vrijednošću `version` iz `packages/ipv6-prefix-updater/package.json`.
- Pakovanje kopira pripremljeni port u `sysutils/pfSense-pkg-Ipv6PrefixUpdater` u radnoj kopiji portova, pokreće `make package` i ponovo uklanja tu kopiju. Zaustavlja se ako odredište već postoji.
- `build/release` tada sadrži `.pkg` s verzijom, kopiju nazvanu `pfSense-pkg-Ipv6PrefixUpdater.pkg` i za svaku od njih `.sha256` datoteku koja sadrži samo hash vrijednost.

## Radni tok izdanja \{#release-workflow}

Posao `publish-pfsense-packages-ipv6-prefix-updater` u datoteci `.github/workflows/nova-publish-project.yml`, koju generiše Nova, pokreće se u radnom toku za objavljivanje:

1. Provjerava i priprema port na Ubuntu runneru.
2. Kada je postavljena tajna `PFSENSE_RELEASE_SIGNING_KEY`, izvodi javni ključ iz `PFSENSE_RELEASE_SIGNING_KEY` i dodaje ga u `usr/local/share/pfSense-pkg-Ipv6PrefixUpdater/release-signing.pub` pripremljenog porta.
3. Gradi paket na FreeBSD-u pomoću konfigurisanog checkouta pfSense FreeBSD-ports.
4. Kada je tajna postavljena, potpisuje svaki `.pkg` kao `<file>.pkg.sig` naredbom `ssh-keygen -Y sign -n pfSense-pkg-Ipv6PrefixUpdater`.
5. Otprema pakete, kontrolne zbirove i potpise kao artefakt radnog toka koji se čuva 7 dana te iste datoteke prilaže izdanju.

Izgradnja označava paket za bilo koju verziju FreeBSD-a jer ne sadrži kompajlirani kôd, pa se jedan paket instalira na svako podržano izdanje pfSense-a. `PFSENSE_FREEBSD_VERSION` bira samo izdanje FreeBSD-a koje koristi VM za izgradnju. Naredba `pkg add` iz uputstva za instalaciju preuzima `pfSense-pkg-Ipv6PrefixUpdater.pkg` iz izdanja koje GitHub označi kao najnovije.

## Potpisivanje izdanja \{#release-signing}

Jedino podešavanje za potpisivanje je tajna repozitorija `PFSENSE_RELEASE_SIGNING_KEY`, koja sadrži nešifrirani privatni OpenSSH Ed25519 ključ.

1. U aplikaciji 1Password odaberite **New Item → SSH Key → Generate a New Key → Ed25519**.
2. U polju privatnog ključa odaberite **Export**, zatim OpenSSH format i ne postavljajte lozinku.
3. Prije spremanja tajne provjerite međuspremnik:

   ```bash
   pbpaste | head -1
   ```

   Naredba treba ispisati `-----BEGIN OPENSSH PRIVATE KEY-----`.

4. Pošaljite sadržaj međuspremnika direktno na GitHub ili učitajte izvezenu datoteku:

   ```bash
   pbpaste | gh secret set PFSENSE_RELEASE_SIGNING_KEY
   gh secret set PFSENSE_RELEASE_SIGNING_KEY < <file>
   ```

5. Izbrišite izvezenu datoteku privatnog ključa nakon spremanja tajne.

Bez te tajne paketi ne sadrže javni ključ, a izdanja nisu potpisana. Za promjenu ključa dodajte novi javni ključ `ssh-ed25519 ...` u `release-signing.pub`, objavite jedno izdanje dok je stari ključ još uvijek tajna, pa zamijenite tajnu novim ključem.

Ako se ključ za potpisivanje izgubi, instalirane kopije ne mogu provjeriti izdanje potpisano zamjenskim ključem. Svaka takva instalacija mora jednom upotrijebiti ručnu naredbu `pkg add -f` kako bi instalirala paket sa zamjenskim javnim ključem.

## Testiranje odredišta ažuriranja u VM-u \{#test-update-endpoints-in-a-vm}

CLI prihvata dvije varijable okruženja isključivo za kontrolisane VM testove:

- `IPV6_PREFIX_UPDATER_RELEASES_API` zamjenjuje URL API-ja za najnovije izdanje.
- `IPV6_PREFIX_UPDATER_DOWNLOAD_PREFIX` zamjenjuje dozvoljeni prefiks URL-a za datoteke izdanja.

Čita ih samo `/usr/local/sbin/ipv6-prefix-updater`; nikada se ne čuvaju u konfiguraciji paketa niti ih WebGUI čita direktno. Postavite sve potrebne zamjene u istom pozivu CLI-ja:

```shell
IPV6_PREFIX_UPDATER_RELEASES_API=http://192.0.2.10/latest.json \
IPV6_PREFIX_UPDATER_DOWNLOAD_PREFIX=http://192.0.2.10/releases/ \
/usr/local/sbin/ipv6-prefix-updater --check-updates
```

Koristite `--self-update` umjesto `--check-updates` za testiranje potpunog puta preuzimanja, SHA-256 kontrolnog zbira, potpisa izdanja, metapodataka paketa i naredbe `pkg add -f`.

## PHP skupovi testova \{#php-test-suites}

- **`tests/domain.php`**: <Terminology title="Kratki zapis malim slovima, npr. 2001:db8::1" to="/docs/reference/terminology#addresses-and-prefixes">kanonski oblik</Terminology>, granice `/48` i `/64`, maskiranje, <Terminology title="Bitovi nakon prefiksa, uvijek kopirani bez promjene" to="/docs/reference/terminology#addresses-and-prefixes">bitovi hosta</Terminology> na `/53`, odbačene adrese, planiranje bez promjena, filtriranje prema prethodnom prefiksu i promjena dužine koja se tretira kao <Terminology title="Vaš prefiks se promijenio, pa paket kreće na posao" to="/docs/reference/terminology#baselines-and-transitions">promjena prefiksa</Terminology>.
- **`tests/runtime.php`**: skeniranje svake <Terminology title="Jedan prekidač za cijelu vrstu postavki" to="/docs/reference/terminology#fields-and-change-plans">grupe polja</Terminology>, izuzeci za pojedinačna polja, ponovna primjena postavki drugih paketa, atomsko <Terminology title="Datoteka sa svakim početnim stanjem, sačuvana i nakon reinstalacije" to="/docs/reference/terminology#running-checks">stanje paketa</Terminology>, <Terminology title="Sprečava da se dvije provjere pokrenu istovremeno" to="/docs/reference/terminology#running-checks">zaključavanje pokretanja</Terminology>, nepodržane platforme i onemogućene zakazane provjere. Pokriva i redoslijed transakcije te greške pri upisu, sigurnosnoj kopiji, prethodnoj provjeri ponovnog učitavanja, ponovnom učitavanju i obavještenju, kao i <Terminology title="Prefiks se promijenio, ali nijedno odobreno polje nije koristilo stari" to="/docs/reference/terminology#run-outcomes">Upozorenje</Terminology> bez podudaranja.
- **`tests/pfsense-adapter.php`**: prisilno osvježavanje adrese bez zamjene <Terminology title="fe80 adresa koja se nikad ne koristi kao izvor" to="/docs/reference/terminology#addresses-and-prefixes">link-local</Terminology> adresom, sigurnosna kopija prije čuvanja koje samo upisuje i neuspjela sigurnosna kopija koja zaustavlja pokretanje prije upisa.
- **`tests/updates.php`**: poređenje verzija, obrada izdanja i provjera URL-ova, stabilni nasumični rasporedi, uklanjanje duplih obavještenja, GitHub API sažeci, rezervne `.sha256` datoteke, obrada ključeva za potpisivanje, sadržaj allowed-signers, tačni argumenti i standardni ulaz za `ssh-keygen`, valjani potpisi, pogrešni ključevi i namespaceovi te izmijenjeni paketi.
- **`tests/translations.php`** i **`tests/webgui-localization.php`**: potpuni katalozi za svaki identifikator jezika pfSense-a te lokalizirani obrazac Postavke i poruke validacije.

## Stranica dokumentacije \{#documentation-site}

U `apps/docs`, `npm run check` pokreće ESLint, provjeru stabla prijevoda, tri provjere tipova i Vitest skupove testova za `.env` datoteke, frontmatter, linkove, tabele, linkove na pojmovnik i deklaracije tipova. `npm run build` gradi svaku jezičku verziju.

Prevedene stranice dokumentacije za svaku jezičku verziju nalaze se u `apps/docs/i18n/<locale>/docusaurus-plugin-content-docs/current/` i prate engleske stranice, pa se preporučuje da ih ažurirate kada se engleska stranica promijeni. Tekst korisničkog interfejsa (početna stranica, navigaciona traka, podnožje, blog i oznake bočne trake) dolazi iz `scripts/generate-locales.mjs`, koji čita `scripts/locale-copies.json` i prijevode paketa. `npm run i18n` prvo pokreće taj generator, koji prevedene stranice dokumentacije ostavlja netaknute.

`.github/workflows/nova-publish-project.yml` gradi stranicu i postavlja je na GitHub Pages kada se objavi izdanje.
