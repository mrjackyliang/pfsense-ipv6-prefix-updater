Wählen Sie die Schnittstellen, die Ihre aktuellen Präfixe verraten, und geben Sie für jede die <Terminology title="Das /56 oder /64, das sagt, wie viele Bits das Netz benennen" to="/docs/reference/terminology#addresses-and-prefixes">Präfixlänge</Terminology> ein, die Ihr Internetanbieter delegiert.

## Überwachte Schnittstellen wählen \{#choose-the-monitored-interfaces}

Fügen Sie unter **Überwachte Schnittstellen** eine Zeile für jede Schnittstelle hinzu, deren <Terminology title="Eine öffentliche IPv6-Adresse in 2000::/3, die einzige genutzte Art" to="/docs/reference/terminology#addresses-and-prefixes">globale Adresse</Terminology> aus dem <Terminology title="Das IPv6-Netz, das Ihr Anbieter vergibt und das sich ändern kann" to="/docs/reference/terminology#addresses-and-prefixes">delegierten Präfix</Terminology> stammt. Das Paket liest jede Adresse bei jedem Lauf neu und greift nie auf eine <Terminology title="Eine fe80-Adresse, die nie als Quelle dient" to="/docs/reference/terminology#addresses-and-prefixes">Link-Local-Adresse</Terminology> zurück.

Wenn WAN nur ein <Terminology title="Das IPv6-Netz, das Ihr Anbieter vergibt und das sich ändern kann" to="/docs/reference/terminology#addresses-and-prefixes">delegiertes Präfix</Terminology> erhält, trägt meist eine <Terminology title="Eine Schnittstelle, die ihr IPv6 aus einem fremden Präfix bildet" to="/docs/reference/terminology#interfaces-and-detection">Track-Schnittstelle</Terminology> wie LAN eine <Terminology title="Eine öffentliche IPv6-Adresse in 2000::/3, die einzige genutzte Art" to="/docs/reference/terminology#addresses-and-prefixes">globale Adresse</Terminology> daraus und ist die richtige Wahl.

<img src={monitoredInterfaces} alt="Registerkarte Einstellungen von IPv6 Prefix Updater mit zwei Zeilen unter Überwachte Schnittstellen, LAN und LAB, jeweils mit einer Länge des delegierten Präfixes von /56, und einem Hinweis auf die Registerkarte Felder" width={1024} height={768} style={{maxWidth: '100%', height: 'auto'}} />

- **Hinzufügen**: fügt eine Zeile hinzu. Jede Schnittstelle darf nur in einer Zeile stehen, und das Speichern ohne Zeilen wird abgelehnt.
- **Löschen**: entfernt eine Zeile. pfSense blendet die Schaltfläche aus, solange nur eine Zeile übrig ist.
- **Ein Lauf für alle Zeilen**: jede geplante Prüfung liest alle überwachten Schnittstellen und speichert ihre Änderungen in einem einzigen gesicherten Schreibvorgang.

Die meisten Firewalls brauchen eine Zeile. Fügen Sie weitere hinzu, wenn mehrere Schnittstellen ihr eigenes delegiertes Präfix erhalten, etwa bei zwei WAN-Verbindungen, oder wenn Sie die Adresse jedes LAN-Segments prüfen lassen möchten.

So bestätigen Sie die Wahl:

1. Speichern Sie die Einstellungen mit deaktiviertem **<Terminology title="Automatische Prüfungen nach Zeitplan, aus bis Sie sie aktivieren" to="/docs/reference/terminology#running-checks">Geplante Aktualisierungen aktivieren</Terminology>**.
2. Wählen Sie auf der Registerkarte Status **Jetzt ausführen**.
3. Vergleichen Sie **<Terminology title="Die aktuelle Adresse, aus der jeder Lauf das Präfix liest" to="/docs/reference/terminology#interfaces-and-detection">Beobachtete Quelladresse</Terminology>** mit der Adresse unter **Status → Interfaces**.
4. Wenn die Adresse zum falschen Netz gehört, wählen Sie eine andere Schnittstelle und wiederholen Sie die Schritte.

Die Registerkarte Status zeigt die Beschreibung jeder Schnittstelle, gefolgt vom internen pfSense-Namen, etwa `LAN (lan)`.

## Länge des delegierten Präfixes eingeben \{#enter-the-delegated-prefix-length}

Wählen Sie die Länge aus den Vertragsdetails Ihres Internetanbieters oder aus der Größe der DHCPv6-Präfixdelegierung auf der WAN-Schnittstelle. **<Terminology title="Wie groß das Präfix Ihres Anbieters ist, etwa /56; Sie legen es fest" to="/docs/reference/terminology#addresses-and-prefixes">Länge des delegierten Präfixes</Terminology>** akzeptiert `/48` bis `/64`, steht anfangs auf `/56` und wird nie automatisch erkannt.

:::tip

Es empfiehlt sich, die Länge vor dem ersten **Jetzt ausführen** zu bestätigen, weil die <Terminology title="Das erfasste Startpräfix, an dem Änderungen gemessen werden" to="/docs/reference/terminology#baselines-and-transitions">Basislinie</Terminology> die Länge zusammen mit dem Präfix speichert.

:::

## Berechnetes Netz prüfen \{#check-the-calculated-network}

Nach einem Lauf zeigt **<Terminology title="Das jetzt gesehene Präfix, verglichen mit dem letzten" to="/docs/reference/terminology#interfaces-and-detection">Beobachtetes Präfix</Terminology>** das berechnete Netz. Längen, die innerhalb einer Hexadezimalziffer enden, etwa `/57` oder `/63`, funktionieren genauso, weil das Paket Adressen bitweise maskiert.

Für eine `/56`-Delegierung, die von `2001:db8:abcd:7800::/56` zu `2001:db8:abcd:8800::/56` wechselt:

```text
Source address:    2001:db8:abcd:88aa::1
Current prefix:    2001:db8:abcd:8800::/56
Previous address:  2001:db8:abcd:78aa::42
Updated address:   2001:db8:abcd:88aa::42
```

Nur die ersten 56 Bits ändern sich, und der <Terminology title="Die Bits nach dem Präfix, immer unverändert übernommen" to="/docs/reference/terminology#addresses-and-prefixes">Hostanteil</Terminology> `aa::42` bleibt gleich. Adressen unter `2001:db8::/32` sind in diesen Anleitungen Dokumentationsbeispiele.

## Schnittstellen ändern \{#changing-the-interfaces}

:::warning

Wenn Sie eine <Terminology title="Die Schnittstelle, deren Adresse Ihr aktuelles Präfix verrät" to="/docs/reference/terminology#interfaces-and-detection">überwachte Schnittstelle</Terminology> hinzufügen oder eine Zeile auf eine andere umstellen, zeichnet der nächste Lauf für sie eine neue <Terminology title="Das erfasste Startpräfix, an dem Änderungen gemessen werden" to="/docs/reference/terminology#baselines-and-transitions">Basislinie</Terminology> auf, ohne die Konfiguration zu ändern. Hatte sich ihr Präfix geändert, ohne dass das Paket die Änderung schon angewendet hat, wird diese Änderung übersprungen.

:::

Wenn Sie eine Zeile löschen, bleibt die <Terminology title="Das erfasste Startpräfix, an dem Änderungen gemessen werden" to="/docs/reference/terminology#baselines-and-transitions">Basislinie</Terminology> dieser Schnittstelle im <Terminology title="Die Datei mit jeder Basislinie, bleibt bei Neuinstallation erhalten" to="/docs/reference/terminology#running-checks">Paketzustand</Terminology> erhalten. Fügen Sie die Schnittstelle später wieder hinzu, vergleicht der Lauf mit dieser gespeicherten Basislinie, statt eine neue aufzuzeichnen.

## Präfixlänge ändern \{#changing-the-prefix-length}

Eine Änderung von **<Terminology title="Wie groß das Präfix Ihres Anbieters ist, etwa /56; Sie legen es fest" to="/docs/reference/terminology#addresses-and-prefixes">Länge des delegierten Präfixes</Terminology>**, nachdem die <Terminology title="Das erfasste Startpräfix, an dem Änderungen gemessen werden" to="/docs/reference/terminology#baselines-and-transitions">Basislinie</Terminology> existiert, zählt als <Terminology title="Ihr Präfix hat sich geändert, also legt das Paket los" to="/docs/reference/terminology#baselines-and-transitions">Präfixwechsel</Terminology>, auch wenn das Netz selbst gleich bleibt. Das Paket gleicht Adressen mit der in der <Terminology title="Das erfasste Startpräfix, an dem Änderungen gemessen werden" to="/docs/reference/terminology#baselines-and-transitions">Basislinie</Terminology> gespeicherten Länge ab und ersetzt Bits mit der neuen Länge.

:::danger

Wenn Sie die Länge verengen, werden die Subnetzbits jeder passenden Adresse überschrieben. Mit der <Terminology title="Die aktuelle Adresse, aus der jeder Lauf das Präfix liest" to="/docs/reference/terminology#interfaces-and-detection">Quelladresse</Terminology> `2001:db8:1234:ab00::1` und einer `/56`-<Terminology title="Das erfasste Startpräfix, an dem Änderungen gemessen werden" to="/docs/reference/terminology#baselines-and-transitions">Basislinie</Terminology> macht ein Wechsel auf `/64` aus `2001:db8:1234:abcc::42` die Adresse `2001:db8:1234:ab00::42`.

:::

Wenn Sie die Länge erweitern, etwa von `/64` auf `/56`, hat der Lauf möglicherweise nichts zu ändern. Jeder Lauf meldet dann <Terminology title="Präfix geändert, aber kein genehmigtes Feld nutzte das alte" to="/docs/reference/terminology#run-outcomes">Warnung</Terminology>, bis sich das Präfix selbst ändert oder bis Sie die gespeicherten Adressen prüfen und [das aktuelle Präfix als neue Basislinie übernehmen](/docs/operate/backups-and-recovery#after-a-failed-run).

Bevor Sie die Länge ändern, empfiehlt es sich, im selben Speichervorgang **<Terminology title="Automatische Prüfungen nach Zeitplan, aus bis Sie sie aktivieren" to="/docs/reference/terminology#running-checks">Geplante Aktualisierungen aktivieren</Terminology>** zu deaktivieren. Ein **<Terminology title="Eine Vorschau der Änderungen, die nichts schreibt" to="/docs/reference/terminology#running-checks">Testlauf</Terminology>** zeigt dann die Anzahl der geplanten Felder, jede geplante Änderung unter `Feldänderungen` und die **Zusammenfassung**, bevor Sie **Jetzt ausführen** wählen.

Als Nächstes folgt [Basislinie festlegen](/docs/first-run), danach wählen Sie die Felder auf der Registerkarte [Felder](/docs/configure/configuration-scopes).
