pfSense의 `pkg` 도구로 GitHub 릴리스에서 패키지를 설치한 다음, WebGUI에 패키지 페이지가 나타나는지 확인합니다.

## 요구 사항 \{#requirements}

- **관리자 셸** — pfSense 셸에 SSH 또는 콘솔로 접근할 수 있어야 합니다. WebGUI의 **Diagnostics → Command Prompt**에서도 명령을 하나씩 실행할 수 있습니다.
- **GitHub에 대한 HTTPS 접근** — 방화벽이 GitHub Releases에서 패키지를 다운로드합니다.
- **일치하는 패키지 빌드** — 패키지는 사용 중인 pfSense 릴리스가 기반으로 하는 FreeBSD 버전용으로 빌드되어야 합니다.
- **최신 백업** — 설치하기 전에 **Diagnostics → Backup & Restore**에서 구성 사본을 다운로드합니다.
- **<Terminology title="Cron 패키지로 실행하던 원래 update.php 스크립트" to="/docs/reference/terminology#legacy-updater">레거시 업데이터</Terminology>는 남겨 두어도 됨** — 버전 1.x 스크립트가 아직 Cron 패키지로 실행되고 있다면 그대로 둡니다. [스크립트에서 마이그레이션](/docs/migrate-from-legacy)에서 설명하듯이 설치 단계가 스크립트를 패키지로 옮깁니다.

:::warning

pfSense IPv6 Prefix Updater는 <Terminology title="Netgate 저장소가 아닌 GitHub에서 설치하는 패키지" to="/docs/reference/terminology#unofficial-package">비공식 패키지</Terminology>입니다. GitHub의 `.pkg` 파일을 설치하면 Netgate의 패키지 검토와 지원을 거치지 않으므로, 먼저 백업해 둔 방화벽이나 테스트용 방화벽에서 사용해 보는 것을 권장합니다.

:::

## 릴리스 확인 \{#check-the-release}

패키지 릴리스는 [GitHub Releases 페이지](https://github.com/mrjackyliang/pfsense-ipv6-prefix-updater/releases)에 나와 있습니다. 각 패키지 릴리스에는 다음 파일이 들어 있습니다.

| 파일                                            | 설명                               |
|-----------------------------------------------|----------------------------------|
| `pfSense-pkg-Ipv6PrefixUpdater.pkg`           | 이 페이지의 명령이 사용하는, 이름이 고정된 패키지입니다. |
| `pfSense-pkg-Ipv6PrefixUpdater-<version>.pkg` | 파일 이름에 버전이 들어간 같은 패키지입니다.        |
| `.sha256` 파일                                  | 패키지 파일마다 하나씩 있는 SHA-256 체크섬입니다.  |

:::info

버전 1.x 릴리스에는 <Terminology title="Cron 패키지로 실행하던 원래 update.php 스크립트" to="/docs/reference/terminology#legacy-updater">레거시 업데이터</Terminology>만 들어 있습니다. 최신 릴리스에 `.pkg` 파일이 없으면 이 페이지의 명령은 찾을 수 없음(404) 오류로 실패합니다.

:::

## 패키지 설치 \{#install-the-package}

pfSense 셸에서 다음 명령을 실행합니다.

```shell
pkg add https://github.com/mrjackyliang/pfsense-ipv6-prefix-updater/releases/latest/download/pfSense-pkg-Ipv6PrefixUpdater.pkg
```

`pkg`는 최신 릴리스에서 패키지를 다운로드하고 설치 단계를 실행하며, 이 단계에서 **Services → IPv6 Prefix Updater**가 pfSense에 등록됩니다.

## 먼저 다운로드 검증하기 \{#verify-the-download-first}

설치하기 전에 파일을 체크섬과 대조하려면 두 파일을 `/tmp`에 다운로드하고 두 값을 출력합니다.

```shell
cd /tmp
fetch https://github.com/mrjackyliang/pfsense-ipv6-prefix-updater/releases/latest/download/pfSense-pkg-Ipv6PrefixUpdater.pkg
fetch https://github.com/mrjackyliang/pfsense-ipv6-prefix-updater/releases/latest/download/pfSense-pkg-Ipv6PrefixUpdater.pkg.sha256
sha256 -q pfSense-pkg-Ipv6PrefixUpdater.pkg
cat pfSense-pkg-Ipv6PrefixUpdater.pkg.sha256
```

다운로드가 손상되지 않았다면 마지막 두 명령은 같은 값을 출력합니다. 그런 다음 검증한 파일을 `pkg add /tmp/pfSense-pkg-Ipv6PrefixUpdater.pkg`로 설치할 수 있습니다.

## WebGUI에서 확인 \{#confirm-in-the-webgui}

1. pfSense WebGUI에 로그인합니다.
2. **Services → IPv6 Prefix Updater**를 열고 **설정**, **상태**, **필드**, **백업**, **정리** 탭이 나타나는지 확인합니다.
3. 상태 탭의 **현재 상태**에 `저장된 모니터링할 인터페이스가 아직 없습니다. 설정 탭에서 추가하십시오.`가 표시되는지 확인합니다. 레거시 업데이터 전환 후에는 그 대신 옮겨진 인터페이스가 나열됩니다.
4. [기준선을 설정](/docs/first-run)할 때까지 **<Terminology title="pfSense가 관리하는 cron 항목으로 실행하는 자동 확인" to="/docs/reference/terminology#scheduled-updates">예약 업데이트 사용</Terminology>**은 기본값대로 해제해 둡니다. 레거시 업데이터 전환 후에는 이전 Cron 일정에 맞춰 이미 켜져 있습니다.

## 설치에 실패하는 경우 \{#if-installation-fails}

- **찾을 수 없음(404)**: 최신 릴리스에 패키지 파일이 없습니다. 어떤 릴리스에 패키지 파일이 있는지는 [릴리스 확인](/docs/installation#check-the-release)에서 설명합니다.
- **ABI 또는 OS 버전 불일치**: 패키지가 사용 중인 pfSense 릴리스와 다른 FreeBSD 버전용으로 빌드되었습니다. 설치를 강제하기보다 일치하는 빌드를 사용하는 것을 권장합니다.
- **DNS, TLS 또는 인증서 오류**: pfSense가 `github.com`의 이름을 확인하고 HTTPS로 접속할 수 있어야 하며, 인증서 검사를 위해 정확한 시간을 유지해야 합니다.

WebGUI에 패키지가 나타나면 [기준선 설정](/docs/first-run)으로 계속합니다.
