## 현재 상태와 마지막 실행의 차이 \{#current-state-versus-last-run}

**현재 상태**는 <Terminology title="결과: 기준선 기록, 구성 변경 없음" to="/docs/reference/terminology#initialized">초기화됨</Terminology>, **수락됨**, <Terminology title="결과: 필드 업데이트, 저장, 다시 로드, 검증 완료" to="/docs/reference/terminology#success">성공</Terminology>에서만 바뀝니다. 실패한 시도는 운영자가 나중에 저장된 값을 검증하고 활성 접두사를 명시적으로 수락하지 않는 한 다음 비교 기준이 되지 않으며, **마지막 실행**은 표에 있는 모든 결과의 최근 실행을 기록합니다.

다른 확인이 <Terminology title="두 확인이 동시에 실행되지 않게 막는 잠금" to="/docs/reference/terminology#run-lock">실행 잠금</Terminology>을 잡고 있거나, 모니터링하는 어떤 인터페이스에도 <Terminology title="2000::/3 범위의 공인 IPv6 주소" to="/docs/reference/terminology#global-unicast-address">글로벌 주소</Terminology>가 없을 때처럼 실행이 <Terminology title="기준선과 마지막 실행을 담은 패키지 파일" to="/docs/reference/terminology#package-state">패키지 상태</Terminology>를 읽기 전에 멈추면 **마지막 실행**은 그대로 유지됩니다. 이런 실행은 이유를 <Terminology title="지금 실행이나 시험 실행 후 표시되는 읽기 전용 결과" to="/docs/reference/terminology#command-output">명령 출력</Terminology>과 <Terminology title="패키지가 기록하는 pfSense 일반 로그" to="/docs/reference/terminology#system-log">시스템 로그</Terminology>에 남깁니다.

## 경고: 일치하는 필드 없음 \{#warning-no-matching-fields}

<Terminology title="결과: 접두사가 바뀌었지만 일치하는 승인된 필드 없음" to="/docs/reference/terminology#warning">경고</Terminology>는 접두사가 바뀌었지만 이전 접두사에 속한 <Terminology title="패키지가 다시 쓸 수 있는 정확한 구성 필드" to="/docs/reference/terminology#approved-field">승인된 필드</Terminology>가 하나도 없다는 뜻입니다. 아무것도 쓰지 않고 <Terminology title="구성을 바꾸지 않고 기록한 시작 접두사" to="/docs/reference/terminology#baseline">기준선</Terminology>은 이전 접두사에 머물므로, 다음 실행은 같은 <Terminology title="마지막 성공 접두사나 길이와 달라진 상태" to="/docs/reference/terminology#prefix-transition">접두사 전환</Terminology>을 다시 검사합니다.

<Terminology title="결과: 접두사가 바뀌었지만 일치하는 승인된 필드 없음" to="/docs/reference/terminology#warning">경고</Terminology>가 발생할 때마다 <Terminology title="pfSense 알림 목록에 표시되는 항목" to="/docs/reference/terminology#webgui-notice">WebGUI 알림</Terminology>이 추가되며, <Terminology title="백업도 쓰기도 하지 않는 미리 보기" to="/docs/reference/terminology#dry-run">시험 실행</Terminology>에서 발생한 경고도 마찬가지입니다. 원인을 해결하지 않으면 예약 실행 때마다 새 알림이 추가됩니다.

흔한 원인:

- 주소가 있는 <Terminology title="필드 탭에서 스위치 하나로 켜고 끄는 필드 묶음" to="/docs/reference/terminology#field-group">필드 그룹</Terminology>이 꺼져 있거나 해당 필드가 선택 해제되어 있습니다.
- 주소가 이미 패키지 밖에서 변경되었습니다.
- 주소가 [기타 설정](/docs/configure/configuration-scopes#other-settings) 그룹에 있으며, 이 그룹은 주소를 선택할 때까지 꺼져 있습니다.
- 이전 <Terminology title="결과: 검사나 안전 단계가 실행을 중단함" to="/docs/reference/terminology#failure">실패</Terminology>가 새 값을 저장했지만 이전 <Terminology title="구성을 바꾸지 않고 기록한 시작 접두사" to="/docs/reference/terminology#baseline">기준선</Terminology>을 유지했습니다.
- 접두사 변경 없이 <Terminology title="ISP 접두사 크기 설정, /48~/64" to="/docs/reference/terminology#delegated-prefix-length">위임된 접두사 길이</Terminology>를 줄여 범위를 [넓혔습니다](/docs/configure/interface-and-prefix#changing-the-prefix-length).

각 원인은 [문제 해결](/docs/operate/troubleshooting#warning-on-every-run)에서 다룹니다.

주소가 이미 올바르게 변경되었다면 저장된 주소와 영향을 받는 서비스를 검증한 뒤 **상태 → 작업 → 기준선 복구 → 현재 접두사 수락**을 사용합니다. 이 작업은 승인된 필드를 검색하거나 방화벽 구성을 변경하지 않고 **수락됨** 결과를 기록하므로, 승인된 필드에 아직 이전 접두사가 들어 있다면 사용하지 마십시오.

## 저장 후 실패 \{#failures-after-the-save}

저장 뒤에 이어지는 값 검사나 <Terminology title="변경된 설정을 적용하는 pfSense 동작" to="/docs/reference/terminology#service-reload">서비스 다시 로드</Terminology> 중에 발생한 <Terminology title="결과: 검사나 안전 단계가 실행을 중단함" to="/docs/reference/terminology#failure">실패</Terminology>는 새 값을 저장된 채로 남깁니다. 자동으로 롤백되는 것은 없으며 <Terminology title="구성을 바꾸지 않고 기록한 시작 접두사" to="/docs/reference/terminology#baseline">기준선</Terminology>은 이전 접두사에 머뭅니다.

이런 실행에서는 **<Terminology title="쓰기 전에 저장한 구성 사본" to="/docs/reference/terminology#configuration-backup">구성 백업 생성됨</Terminology>**에 예가 표시됩니다. 복원 후 다시 시도하는 방법과 **현재 접두사 수락**으로 검증된 저장 값을 유지하는 방법은 [백업 및 복구](/docs/operate/backups-and-recovery#after-a-failed-run)에서 설명합니다.

## 알림 실패 \{#notification-failures}

<Terminology title="검증된 업데이트가 성공한 뒤 보내는 알림" to="/docs/reference/terminology#change-notification">변경 알림</Terminology>을 보낼 수 없어도 결과는 여전히 <Terminology title="결과: 필드 업데이트, 저장, 다시 로드, 검증 완료" to="/docs/reference/terminology#success">성공</Terminology>이며 <Terminology title="구성을 바꾸지 않고 기록한 시작 접두사" to="/docs/reference/terminology#baseline">기준선</Terminology>도 새 접두사로 이동합니다. 상태 탭은 전달 상태를 표시하지 않으며, <Terminology title="패키지가 기록하는 pfSense 일반 로그" to="/docs/reference/terminology#system-log">시스템 로그</Terminology>에는 `구성은 성공했지만 변경 알림에 실패했습니다.`가 기록됩니다.

각 결과에 해당하는 필드는 [상태 및 작업](/docs/operate/status-and-actions)에서, 단계 순서는 [업데이트 작동 방식](/docs/safety/how-updates-work)에서 검토합니다.
