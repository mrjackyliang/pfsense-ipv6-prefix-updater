<Terminology title="pfSense가 관리하는 cron 항목으로 실행하는 자동 확인" to="/docs/reference/terminology#scheduled-updates">예약 업데이트</Terminology>를 켜기 전에 현재 접두사를 <Terminology title="구성을 바꾸지 않고 기록한 시작 접두사" to="/docs/reference/terminology#baseline">기준선</Terminology>으로 기록하고 확인합니다.

## 초기 설정 저장 \{#save-the-initial-settings}

1. **Services → IPv6 Prefix Updater**를 연 다음 **설정** 탭을 엽니다.
2. **<Terminology title="pfSense가 관리하는 cron 항목으로 실행하는 자동 확인" to="/docs/reference/terminology#scheduled-updates">예약 업데이트 사용</Terminology>**은 해제한 상태로 둡니다.
3. [인터페이스와 접두사](/docs/configure/interface-and-prefix)에 설명된 대로, <Terminology title="2000::/3 범위의 공인 IPv6 주소" to="/docs/reference/terminology#global-unicast-address">글로벌 주소</Terminology>가 <Terminology title="ISP가 방화벽으로 라우팅하는 IPv6 네트워크" to="/docs/reference/terminology#delegated-prefix">위임된 접두사</Terminology>에서 오는 인터페이스마다 **<Terminology title="주소로 현재 접두사를 알려 주는 인터페이스" to="/docs/reference/terminology#monitored-interface">모니터링할 인터페이스</Terminology>** 행을 하나씩 추가합니다.
4. 각 행에서 ISP가 위임하는 길이를 **<Terminology title="ISP 접두사 크기 설정, /48~/64" to="/docs/reference/terminology#delegated-prefix-length">위임된 접두사 길이</Terminology>**에서 선택합니다.
5. 저장하고 `설정이 저장되었습니다.` 메시지를 확인합니다.

## 첫 확인 실행 \{#run-the-first-check}

**상태** 탭에서 **지금 실행**을 선택합니다. 아직 <Terminology title="구성을 바꾸지 않고 기록한 시작 접두사" to="/docs/reference/terminology#baseline">기준선</Terminology>이 없으므로 실행은 인터페이스마다 <Terminology title="pfSense가 모니터링할 인터페이스에 보고하는 글로벌 주소" to="/docs/reference/terminology#source-address">원본 주소</Terminology>와 접두사를 기록하고 <Terminology title="결과: 기준선 기록, 구성 변경 없음" to="/docs/reference/terminology#initialized">초기화됨</Terminology>을 보고합니다.

<Terminology title="구성을 바꾸지 않고 기록한 시작 접두사" to="/docs/reference/terminology#baseline">기준선</Terminology>을 기록해도 구성을 변경하거나, 백업을 만들거나, 알림을 보내지 않습니다.

## 결과 검증 \{#verify-the-result}

**현재 상태**의 각 행에서 다음 값을 확인합니다.

- **<Terminology title="주소로 현재 접두사를 알려 주는 인터페이스" to="/docs/reference/terminology#monitored-interface">모니터링할 인터페이스</Terminology>**에 의도한 인터페이스가 `LAN (lan)`처럼 설명과 내부 이름으로 표시됩니다.
- **<Terminology title="pfSense가 모니터링할 인터페이스에 보고하는 글로벌 주소" to="/docs/reference/terminology#source-address">마지막 성공 원본 주소</Terminology>**가 **Status → Interfaces**에 표시된 해당 인터페이스의 주소와 일치합니다.
- **<Terminology title="다음 확인이 비교 기준으로 삼는 접두사" to="/docs/reference/terminology#last-successful-prefix">마지막 성공 접두사</Terminology>**가 ISP가 위임하는 접두사와 일치합니다.
- **마지막 성공 업데이트**에 이번 실행 시각이 UTC로 표시됩니다.

<Terminology title="지금 실행이나 시험 실행 후 표시되는 읽기 전용 결과" to="/docs/reference/terminology#command-output">명령 출력</Terminology>에는 `상태: 초기화됨`, `계획되었거나 변경된 필드: 0`, `구성 백업: 생성되지 않음`이 표시되어야 합니다. 예를 들어 문서용 주소 `2001:db8:abcd:78aa::1`에 `/56` 길이를 적용하면 `2001:db8:abcd:7800::/56`에 속합니다.

:::warning

인터페이스나 길이가 잘못되었다면 일정을 켜기 전에 설정을 바로잡는 것을 권장합니다. [인터페이스와 접두사](/docs/configure/interface-and-prefix#changing-the-prefix-length)에서 설명하듯이 인터페이스를 바꾸면 새 <Terminology title="구성을 바꾸지 않고 기록한 시작 접두사" to="/docs/reference/terminology#baseline">기준선</Terminology>이 기록되고, 길이를 바꾸면 <Terminology title="마지막 성공 접두사나 길이와 달라진 상태" to="/docs/reference/terminology#prefix-transition">접두사 전환</Terminology>으로 간주됩니다.

:::

## 필드 검토 \{#review-the-fields}

**필드** 탭을 엽니다. <Terminology title="구성을 바꾸지 않고 기록한 시작 접두사" to="/docs/reference/terminology#baseline">기준선</Terminology>이 기록되었으므로 탭에는 접두사 안의 모든 주소와, 그중 다음 변경에서 업데이트될 주소가 표시됩니다.

1. 방화벽에서 쓰지 않는 <Terminology title="필드 탭에서 스위치 하나로 켜고 끄는 필드 묶음" to="/docs/reference/terminology#field-group">필드 그룹</Terminology>을 끕니다. pfSense 그룹 열한 개는 모두 켜진 상태로 시작합니다.
2. 값을 그대로 유지해야 하는 개별 필드는 선택을 해제하고, 접두사를 따라야 하는 다른 패키지의 필드는 선택합니다.
3. **기타 설정**에서 게이트웨이나 정적 경로처럼 접두사를 따라야 하는 필드를 선택합니다.
4. **저장**을 선택하고 `필드 선택을 저장했습니다.` 메시지를 확인합니다.

각 그룹과 컨트롤은 [필드](/docs/configure/configuration-scopes)에서 설명합니다.

## 지금 시험 실행이 보여 주는 것 \{#what-a-dry-run-shows-now}

계획은 실제 <Terminology title="마지막 성공 접두사나 길이와 달라진 상태" to="/docs/reference/terminology#prefix-transition">접두사 전환</Terminology>이 일어난 뒤에야 시작되므로, 접두사가 바뀌지 않았다면 **<Terminology title="백업도 쓰기도 하지 않는 미리 보기" to="/docs/reference/terminology#dry-run">시험 실행</Terminology>**은 구성을 검색하지 않고 <Terminology title="결과: 접두사 그대로, 검색이나 쓰기 없음" to="/docs/reference/terminology#no-change">변경 없음</Terminology>을 보고합니다. 앞으로의 변경이 어떤 필드에 영향을 줄지는 필드 탭에서 확인할 수 있습니다.

<Terminology title="구성을 바꾸지 않고 기록한 시작 접두사" to="/docs/reference/terminology#baseline">기준선</Terminology>이 생기기 전에 수행한 <Terminology title="백업도 쓰기도 하지 않는 미리 보기" to="/docs/reference/terminology#dry-run">시험 실행</Terminology>은 <Terminology title="결과: 기준선이 생기기 전의 시험 실행" to="/docs/reference/terminology#initialization-preview">초기화 미리 보기</Terminology>를 보고하며 아무것도 기록하지 않습니다.

## 일정 켜기 \{#turn-on-the-schedule}

값이 일치하면 **<Terminology title="pfSense가 관리하는 cron 항목으로 실행하는 자동 확인" to="/docs/reference/terminology#scheduled-updates">예약 업데이트 사용</Terminology>**을 선택하고 **일정**을 고른 뒤 저장합니다. 각 옵션은 [일정 및 알림](/docs/configure/schedule-and-notifications)에서 설명합니다.

처음 예약된 시각이 지나면 **마지막 실행**의 **타임스탬프(UTC)**에 해당 확인이 실행된 시각이 표시됩니다.

전체 점검 목록은 [자동화 전 점검](/docs/safety/testing-and-verification)에서 이어서 확인합니다.
