각 인터페이스 주소를 읽는 것부터 결과를 기록하는 것까지, 실행이 멈출 수 있는 모든 지점을 포함해 실행 하나를 따라갑니다.

## 1. 읽기 및 검증 \{#1-read-and-validate}

- 예약 확인은 **<Terminology title="pfSense가 관리하는 cron 항목으로 실행하는 자동 확인" to="/docs/reference/terminology#scheduled-updates">예약 업데이트 사용</Terminology>**이 꺼져 있으면 즉시 <Terminology title="결과: 업데이트가 꺼져 있어 예약 확인을 건너뜀" to="/docs/reference/terminology#disabled">사용 안 함</Terminology>으로 멈춥니다. <Terminology title="상태 탭에서 시작한 확인" to="/docs/reference/terminology#manual-run">수동 실행</Terminology>은 계속 진행됩니다.
- 양식을 저장한 뒤 설정이 바뀌었을 수 있으므로 실행은 저장된 설정을 다시 검사합니다.
- 각 <Terminology title="주소로 현재 접두사를 알려 주는 인터페이스" to="/docs/reference/terminology#monitored-interface">모니터링할 인터페이스</Terminology>의 <Terminology title="2000::/3 범위의 공인 IPv6 주소" to="/docs/reference/terminology#global-unicast-address">글로벌 주소</Terminology>를 <Terminology title="하나의 링크에서만 동작하는 fe80:: 주소" to="/docs/reference/terminology#link-local-address">링크 로컬 주소</Terminology>로 대체하지 않고 새로 읽어 <Terminology title="소문자로 쓴 가장 짧은 표준 주소 표기" to="/docs/reference/terminology#canonical-form">정규 형식</Terminology>으로 변환합니다.
- 각 주소를 해당 행의 <Terminology title="ISP 접두사 크기 설정, /48~/64" to="/docs/reference/terminology#delegated-prefix-length">위임된 접두사 길이</Terminology>로 마스킹해 <Terminology title="접두사 길이로 마스킹한 원본 주소" to="/docs/reference/terminology#observed-prefix">관찰된 접두사</Terminology>를 얻습니다.

## 2. 비교 \{#2-compare}

- 인터페이스에 대한 <Terminology title="구성을 바꾸지 않고 기록한 시작 접두사" to="/docs/reference/terminology#baseline">기준선</Terminology>이 없으면 실행은 기준선을 기록하고 <Terminology title="결과: 기준선 기록, 구성 변경 없음" to="/docs/reference/terminology#initialized">초기화됨</Terminology>으로 끝납니다.
- 접두사와 길이가 <Terminology title="다음 확인이 비교 기준으로 삼는 접두사" to="/docs/reference/terminology#last-successful-prefix">마지막 성공 접두사</Terminology>와 일치하면 실행은 구성을 검색하지 않고 <Terminology title="결과: 접두사 그대로, 검색이나 쓰기 없음" to="/docs/reference/terminology#no-change">변경 없음</Terminology>으로 끝납니다.
- 접두사나 길이가 다르면 <Terminology title="마지막 성공 접두사나 길이와 달라진 상태" to="/docs/reference/terminology#prefix-transition">접두사 전환</Terminology>이며 실행이 계속됩니다.

## 3. 계획 \{#3-plan}

- 실행은 pfSense 구성 함수로 구성을 읽고 필드 탭에서 선택된 필드만 남깁니다. 더 이상 존재하지 않는 선택된 필드는 건너뛰고 **건너뛴 필드** 아래에 나열합니다.
- <Terminology title="패키지가 다시 쓸 수 있는 정확한 구성 필드" to="/docs/reference/terminology#approved-field">승인된 필드</Terminology>의 주소 중 저장된 길이 기준으로 이전 접두사에 속하는 주소는 현재 길이 기준의 새 접두사 비트를 받고 <Terminology title="위임된 접두사 뒤의 주소 비트" to="/docs/reference/terminology#host-portion">호스트 부분</Terminology>은 유지합니다. 이 변경을 모두 모은 것이 완전한 <Terminology title="쓰기 전에 만드는 전체 필드 변경 목록" to="/docs/reference/terminology#change-plan">변경 계획</Terminology>입니다.
- 변경할 것이 없으면 실행은 <Terminology title="결과: 접두사가 바뀌었지만 일치하는 승인된 필드 없음" to="/docs/reference/terminology#warning">경고</Terminology>로 끝납니다. 변경이 있는 <Terminology title="백업도 쓰기도 하지 않는 미리 보기" to="/docs/reference/terminology#dry-run">시험 실행</Terminology>은 여기서 <Terminology title="백업도 쓰기도 하지 않는 미리 보기" to="/docs/reference/terminology#dry-run">시험 실행</Terminology> 결과로 끝납니다.

## 4. 사전 점검 \{#4-preflight}

- 실행은 pfSense가 계획에 있는 모든 서비스를 다시 로드할 수 있는지 확인합니다. <Terminology title="pfSense WireGuard 터널에 할당된 주소" to="/docs/reference/terminology#wireguard-tunnel-address">WireGuard 터널 주소</Terminology>에는 이를 위해 WireGuard 패키지가 필요합니다.
- 계획된 각 필드가 계획을 만들 때의 값을 아직 가지고 있는지 확인합니다.

## 5. 백업 후 한 번 쓰기 \{#5-back-up-and-write-once}

- pfSense가 <Terminology title="쓰기 전에 저장한 구성 사본" to="/docs/reference/terminology#configuration-backup">구성 백업</Terminology>을 만들며, pfSense가 백업을 확인하지 않으면 실행이 멈춥니다.
- 실행은 모든 변경을 적용하고 `IPv6 접두사 업데이터가 인터페이스 <interface>의 승인된 필드 <count>개를 변경했습니다`라는 설명으로 한 번 저장합니다.
- pfSense가 저장 실패를 보고하면 실행은 메모리에 있는 원래 값을 복원하고 멈춥니다.

## 6. 검증, 다시 로드, 검증 \{#6-verify-reload-verify}

- 실행은 저장된 값이 계획과 일치하는지 검사하고, 영향을 받는 서비스를 다시 로드한 뒤 값을 다시 검사합니다.
- 서비스는 [다시 로드 작업](/docs/reference/approved-fields#reload-actions)에 나열된 고정된 순서에 따라 인터페이스부터 WireGuard까지 다시 로드됩니다. 인터페이스를 다시 로드하면 이어서 방화벽 필터가 다시 로드되며, 그 뒤에는 반복하지 않습니다.
- 방화벽 필터, DNS 해석기, DNS 전달자 다시 로드는 실패를 반환하면 실행을 실패시킵니다. 다른 다시 로드는 오류를 발생시킬 때만 실행을 실패시킵니다.
- 다른 패키지의 설정은 다시 로드와 그 검증이 끝난 뒤 마지막으로 다시 적용됩니다. 적용할 수 없는 패키지는 보고되며, 저장된 값은 그대로 남습니다.
- 이 단계에서 실패하면 새 값은 저장된 채로 남습니다.

## 7. 기록 및 알림 \{#7-record-and-notify}

- <Terminology title="구성을 바꾸지 않고 기록한 시작 접두사" to="/docs/reference/terminology#baseline">기준선</Terminology>이 새 접두사로 이동하고, **마지막 실행**에 변경된 필드 수와 <Terminology title="변경된 설정을 적용하는 pfSense 동작" to="/docs/reference/terminology#service-reload">다시 로드된 서비스</Terminology>와 함께 <Terminology title="결과: 필드 업데이트, 저장, 다시 로드, 검증 완료" to="/docs/reference/terminology#success">성공</Terminology>이 기록됩니다.
- 실행은 <Terminology title="패키지가 기록하는 pfSense 일반 로그" to="/docs/reference/terminology#system-log">시스템 로그</Terminology>에 한 줄을 쓰고, 켜져 있으면 <Terminology title="검증된 업데이트가 성공한 뒤 보내는 알림" to="/docs/reference/terminology#change-notification">변경 알림</Terminology>을 보냅니다. 알림이 실패해도 결과는 바뀌지 않습니다.
