패키지를 일정에 따라 실행하기 전에 방화벽에서 인터페이스, 접두사, 복구 경로, 알림을 점검합니다.

## 1. 원본 확인 \{#1-confirm-the-source}

**<Terminology title="일정에 따른 자동 확인으로, 켜기 전까지는 꺼져 있음" to="/docs/reference/terminology#running-checks">예약 업데이트 사용</Terminology>**을 해제한 상태로 설정을 저장하고 **지금 실행**을 한 번 선택합니다. 그런 다음 상태 탭에서 다음을 확인합니다.

- **<Terminology title="주소로 현재 접두사를 알려 주는 인터페이스" to="/docs/reference/terminology#interfaces-and-detection">모니터링할 인터페이스</Terminology>**가 의도한 WAN 또는 <Terminology title="다른 인터페이스의 접두사로 IPv6를 만드는 인터페이스" to="/docs/reference/terminology#interfaces-and-detection">추적 인터페이스</Terminology>입니다.
- **<Terminology title="실행할 때마다 접두사를 읽어 오는 현재 주소" to="/docs/reference/terminology#interfaces-and-detection">마지막 성공 원본 주소</Terminology>**가 **Status → Interfaces**의 주소와 일치합니다.
- **<Terminology title="확인할 때마다 비교 대상이 되는 저장된 접두사" to="/docs/reference/terminology#baselines-and-transitions">마지막 성공 접두사</Terminology>**가 ISP가 위임하는 접두사와 일치합니다.
- **마지막 실행**의 **결과**가 <Terminology title="첫 확인: 기준선만 기록하고 아무것도 바꾸지 않음" to="/docs/reference/terminology#run-outcomes">초기화됨</Terminology>이고 **변경된 필드**가 `0`입니다.

예상과 다른 값이 있으면 계속하기 전에 바로잡는 것을 권장합니다. <Terminology title="변경을 판단하는 기준이 되는 기록된 시작 접두사" to="/docs/reference/terminology#baselines-and-transitions">기준선</Terminology>이 생긴 뒤 인터페이스나 길이를 바꾸면 어떻게 되는지는 [인터페이스와 접두사](/docs/configure/interface-and-prefix#changing-the-interfaces)에서 설명합니다.

## 2. 미리 보기 실행 \{#2-run-a-preview}

**<Terminology title="아무것도 쓰지 않는 변경 미리 보기" to="/docs/reference/terminology#running-checks">시험 실행</Terminology>**을 선택합니다. 접두사가 바뀌지 않았다면 <Terminology title="지난번과 같은 접두사라 할 일이 없음" to="/docs/reference/terminology#run-outcomes">변경 없음</Terminology>을 보고하고, **<Terminology title="쓰기 직전에 만든 구성 사본" to="/docs/reference/terminology#backups-and-service-reloads">구성 백업 생성됨</Terminology>**에는 아니요가 표시됩니다.

<Terminology title="아무것도 쓰지 않는 변경 미리 보기" to="/docs/reference/terminology#running-checks">시험 실행</Terminology>은 접두사 변경을 시뮬레이션할 수 없으므로, 실제 <Terminology title="접두사가 바뀌어 패키지가 작업을 시작함" to="/docs/reference/terminology#baselines-and-transitions">접두사 전환</Terminology>이 일어난 뒤에만 계획된 필드를 보여 줍니다.

## 3. 복구 확인 \{#3-check-recovery}

**Diagnostics → Backup & Restore → Config History**를 열고 pfSense가 구성 기록을 보관하는지 확인합니다. 쓰기를 하는 실행은 첫 변경 전에 그곳에 <Terminology title="쓰기 직전에 만든 구성 사본" to="/docs/reference/terminology#backups-and-service-reloads">구성 백업</Terminology>을 저장합니다.

패키지 이름이 붙은 리비전에는 업데이트된 구성이 들어 있으므로, 지금 [올바른 리비전 찾기](/docs/operate/backups-and-recovery#find-the-right-revision)를 읽어 두는 것을 권장합니다. <Terminology title="복원할 수 있는 pfSense의 저장된 구성 버전" to="/docs/reference/terminology#backups-and-service-reloads">Config History</Terminology>는 방화벽에 저장되므로 장치 외부 백업도 다운로드해 둘 만합니다.

## 4. 알림 테스트 \{#4-test-notifications}

**<Terminology title="주소가 업데이트된 뒤 보내는 알림" to="/docs/reference/terminology#notifications-and-logs">변경 알림 보내기</Terminology>**가 선택되어 있다면 **System → Advanced → Notifications**에 있는 pfSense 자체 버튼으로 테스트를 보내는 것을 권장합니다. 패키지는 그곳에 이미 설정된 <Terminology title="pfSense의 이메일 등 원격 알림 서비스" to="/docs/reference/terminology#notifications-and-logs">알림 채널</Terminology>을 사용합니다.

<Terminology title="접두사가 바뀌었지만 이전 접두사를 쓰는 승인된 필드가 없음" to="/docs/reference/terminology#run-outcomes">경고</Terminology> 및 <Terminology title="확인 또는 안전 단계에서 실행이 멈춤" to="/docs/reference/terminology#run-outcomes">실패</Terminology> 알림은 WebGUI에만 남으며 이 채널을 사용하지 않습니다.

## 5. 일정 켜기 \{#5-turn-on-the-schedule}

위 단계에서 예상한 주소와 접두사가 확인되면 **<Terminology title="일정에 따른 자동 확인으로, 켜기 전까지는 꺼져 있음" to="/docs/reference/terminology#running-checks">예약 업데이트 사용</Terminology>**을 선택합니다. 기본 **일정**은 **매시간**입니다.

처음 예약된 시각이 지나면 **마지막 실행**의 **타임스탬프(UTC)**와 **결과**를 확인하는 것을 권장합니다.

## 실제 접두사 변경이 필요한 항목 \{#what-needs-a-real-prefix-change}

<Terminology title="무엇이든 바꾸기 전에 만든 모든 다시 쓰기 계획" to="/docs/reference/terminology#fields-and-change-plans">변경 계획</Terminology>, <Terminology title="쓰기 직전에 만든 구성 사본" to="/docs/reference/terminology#backups-and-service-reloads">구성 백업</Terminology>, <Terminology title="바뀐 설정을 실행 중인 서비스에 적용함" to="/docs/reference/terminology#backups-and-service-reloads">서비스 다시 로드</Terminology>, <Terminology title="주소가 업데이트된 뒤 보내는 알림" to="/docs/reference/terminology#notifications-and-logs">변경 알림</Terminology>은 실제 <Terminology title="접두사가 바뀌어 패키지가 작업을 시작함" to="/docs/reference/terminology#baselines-and-transitions">접두사 전환</Terminology>이 일어난 뒤에만 발생합니다. 접두사가 바뀔 수 있는 실험용 방화벽이 전체 실행을 관찰하기에 가장 안전한 곳입니다.

자신의 방화벽에서는 첫 실제 변경을 상태 탭에서 **변경된 필드**, **<Terminology title="바뀐 설정을 실행 중인 서비스에 적용함" to="/docs/reference/terminology#backups-and-service-reloads">다시 로드된 서비스</Terminology>**, **요약**부터 검토하는 것을 권장합니다.

실행 후 표시되는 모든 필드는 [상태 및 작업](/docs/operate/status-and-actions)에서 검토합니다.
