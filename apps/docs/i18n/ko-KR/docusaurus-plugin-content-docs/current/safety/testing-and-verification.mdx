패키지를 일정에 따라 실행하기 전에 방화벽에서 인터페이스, 접두사, 복구 경로, 알림을 점검합니다.

## 1. 원본 확인 \{#1-confirm-the-source}

**<Terminology title="pfSense가 관리하는 cron 항목으로 실행하는 자동 확인" to="/docs/reference/terminology#scheduled-updates">예약 업데이트 사용</Terminology>**을 해제한 상태로 설정을 저장하고 **지금 실행**을 한 번 선택합니다. 그런 다음 상태 탭에서 다음을 확인합니다.

- **<Terminology title="주소로 현재 접두사를 알려 주는 인터페이스" to="/docs/reference/terminology#monitored-interface">모니터링할 인터페이스</Terminology>**가 의도한 WAN 또는 <Terminology title="다른 인터페이스의 위임된 접두사로 주소를 받는 인터페이스" to="/docs/reference/terminology#tracked-interface">추적 인터페이스</Terminology>입니다.
- **<Terminology title="pfSense가 모니터링할 인터페이스에 보고하는 글로벌 주소" to="/docs/reference/terminology#source-address">마지막 성공 원본 주소</Terminology>**가 **Status → Interfaces**의 주소와 일치합니다.
- **<Terminology title="다음 확인이 비교 기준으로 삼는 접두사" to="/docs/reference/terminology#last-successful-prefix">마지막 성공 접두사</Terminology>**가 ISP가 위임하는 접두사와 일치합니다.
- **마지막 실행**의 **결과**가 <Terminology title="결과: 기준선 기록, 구성 변경 없음" to="/docs/reference/terminology#initialized">초기화됨</Terminology>이고 **변경된 필드**가 `0`입니다.

예상과 다른 값이 있으면 계속하기 전에 바로잡는 것을 권장합니다. <Terminology title="구성을 바꾸지 않고 기록한 시작 접두사" to="/docs/reference/terminology#baseline">기준선</Terminology>이 생긴 뒤 인터페이스나 길이를 바꾸면 어떻게 되는지는 [인터페이스와 접두사](/docs/configure/interface-and-prefix#changing-the-interfaces)에서 설명합니다.

## 2. 미리 보기 실행 \{#2-run-a-preview}

**<Terminology title="백업도 쓰기도 하지 않는 미리 보기" to="/docs/reference/terminology#dry-run">시험 실행</Terminology>**을 선택합니다. 접두사가 바뀌지 않았다면 <Terminology title="결과: 접두사 그대로, 검색이나 쓰기 없음" to="/docs/reference/terminology#no-change">변경 없음</Terminology>을 보고하고, **<Terminology title="쓰기 전에 저장한 구성 사본" to="/docs/reference/terminology#configuration-backup">구성 백업 생성됨</Terminology>**에는 아니요가 표시됩니다.

<Terminology title="백업도 쓰기도 하지 않는 미리 보기" to="/docs/reference/terminology#dry-run">시험 실행</Terminology>은 접두사 변경을 시뮬레이션할 수 없으므로, 실제 <Terminology title="마지막 성공 접두사나 길이와 달라진 상태" to="/docs/reference/terminology#prefix-transition">접두사 전환</Terminology>이 일어난 뒤에만 계획된 필드를 보여 줍니다.

## 3. 복구 확인 \{#3-check-recovery}

**Diagnostics → Backup & Restore → Config History**를 열고 pfSense가 구성 기록을 보관하는지 확인합니다. 쓰기를 하는 실행은 첫 변경 전에 그곳에 <Terminology title="쓰기 전에 저장한 구성 사본" to="/docs/reference/terminology#configuration-backup">구성 백업</Terminology>을 저장합니다.

패키지 이름이 붙은 리비전에는 업데이트된 구성이 들어 있으므로, 지금 [올바른 리비전 찾기](/docs/operate/backups-and-recovery#find-the-right-revision)를 읽어 두는 것을 권장합니다. <Terminology title="저장된 구성 리비전을 보여 주는 pfSense 목록" to="/docs/reference/terminology#config-history">Config History</Terminology>는 방화벽에 저장되므로 장치 외부 백업도 다운로드해 둘 만합니다.

## 4. 알림 테스트 \{#4-test-notifications}

**<Terminology title="검증된 업데이트가 성공한 뒤 보내는 알림" to="/docs/reference/terminology#change-notification">변경 알림 보내기</Terminology>**가 선택되어 있다면 **System → Advanced → Notifications**에 있는 pfSense 자체 버튼으로 테스트를 보내는 것을 권장합니다. 패키지는 그곳에 이미 설정된 <Terminology title="pfSense에 구성된 원격 알림 서비스" to="/docs/reference/terminology#notification-channels">알림 채널</Terminology>을 사용합니다.

<Terminology title="결과: 접두사가 바뀌었지만 일치하는 승인된 필드 없음" to="/docs/reference/terminology#warning">경고</Terminology> 및 <Terminology title="결과: 검사나 안전 단계가 실행을 중단함" to="/docs/reference/terminology#failure">실패</Terminology> 알림은 WebGUI에만 남으며 이 채널을 사용하지 않습니다.

## 5. 일정 켜기 \{#5-turn-on-the-schedule}

위 단계에서 예상한 주소와 접두사가 확인되면 **<Terminology title="pfSense가 관리하는 cron 항목으로 실행하는 자동 확인" to="/docs/reference/terminology#scheduled-updates">예약 업데이트 사용</Terminology>**을 선택합니다. 기본 **일정**은 **매시간**입니다.

처음 예약된 시각이 지나면 **마지막 실행**의 **타임스탬프(UTC)**와 **결과**를 확인하는 것을 권장합니다.

## 실제 접두사 변경이 필요한 항목 \{#what-needs-a-real-prefix-change}

<Terminology title="쓰기 전에 만드는 전체 필드 변경 목록" to="/docs/reference/terminology#change-plan">변경 계획</Terminology>, <Terminology title="쓰기 전에 저장한 구성 사본" to="/docs/reference/terminology#configuration-backup">구성 백업</Terminology>, <Terminology title="변경된 설정을 적용하는 pfSense 동작" to="/docs/reference/terminology#service-reload">서비스 다시 로드</Terminology>, <Terminology title="검증된 업데이트가 성공한 뒤 보내는 알림" to="/docs/reference/terminology#change-notification">변경 알림</Terminology>은 실제 <Terminology title="마지막 성공 접두사나 길이와 달라진 상태" to="/docs/reference/terminology#prefix-transition">접두사 전환</Terminology>이 일어난 뒤에만 발생합니다. 접두사가 바뀔 수 있는 실험용 방화벽이 전체 실행을 관찰하기에 가장 안전한 곳입니다.

자신의 방화벽에서는 첫 실제 변경을 상태 탭에서 **변경된 필드**, **<Terminology title="변경된 설정을 적용하는 pfSense 동작" to="/docs/reference/terminology#service-reload">다시 로드된 서비스</Terminology>**, **요약**부터 검토하는 것을 권장합니다.

실행 후 표시되는 모든 필드는 [상태 및 작업](/docs/operate/status-and-actions)에서 검토합니다.
