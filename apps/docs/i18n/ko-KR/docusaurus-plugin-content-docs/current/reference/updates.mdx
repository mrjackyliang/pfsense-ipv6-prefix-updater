pfSense Package Manager에는 GitHub에서 직접 설치한 패키지가 표시되지 않으므로 IPv6 Prefix Updater는 GitHub 릴리스를 직접 확인합니다.

## 확인하는 내용 \{#what-is-checked}

확인은 GitHub에서 최신 릴리스 메타데이터를 요청하고 그 버전을 설치된 패키지 버전과 비교합니다. 확인 시각, 최신 버전, 릴리스 링크, 게시 시각, 알림 상태, 마지막 오류를 `/cf/conf/ipv6-prefix-updater/updates.json`에 저장합니다. 방화벽 구성은 GitHub로 전송하지 않습니다.

**Services → IPv6 Prefix Updater → 설정 → 패키지 업데이트**에서 빈도를 선택합니다.

- **매일**은 설치 중에 무작위로 정한 시각에 하루 한 번 실행됩니다.
- **매주**는 기본값이며, 고정된 요일과 시각도 하나씩 정합니다.
- **매월**은 1일부터 28일 중 고정된 날짜 하나와 고정된 시각 하나를 정합니다.
- **사용 안 함**은 예약된 릴리스 확인을 제거합니다.

무작위 일정은 pfSense 구성에 저장되므로 설정을 저장하거나 패키지를 다시 설치해도 바뀌지 않습니다. **정보** 탭의 **지금 확인**은 빈도가 **사용 안 함**일 때를 포함해 항상 수동 확인을 수행합니다.

## 네트워크 대상 \{#network-destinations}

업데이트 확인 또는 업데이트는 GitHub가 운영하는 다음 호스트에 연결할 수 있습니다.

- 최신 릴리스 메타데이터와 게시된 SHA-256 다이제스트를 위한 `api.github.com`
- 릴리스 파일 URL을 위한 `github.com`
- 파일 요청이 리디렉션된 후 사용하는 GitHub의 릴리스 다운로드 호스트 `release-assets.githubusercontent.com`

요청은 TLS 인증서 검증, 짧은 제한 시간, 패키지 User-Agent, pfSense에 구성된 프록시를 사용합니다. `403` 또는 `429` 응답은 요청 제한으로 처리되며, 마지막으로 유효했던 릴리스 정보를 지우지 않습니다.

## 알림 \{#notices}

더 새로운 버전이 처음 나타나면 패키지는 그 버전에 대한 pfSense 벨 알림을 하나 추가합니다. 이 알림은 **정보** 탭으로 연결되며 기본적으로 로컬에만 표시됩니다.

**원격 알림**을 선택하면 pfSense에 구성된 이메일, Telegram, Pushover 또는 기타 원격 채널로도 보냅니다. 이 경우에도 패키지는 새 버전마다 알림을 하나만 만듭니다. 해당 버전이 설치되거나 이후 확인에서 설치된 패키지가 최신으로 확인되면 알림을 닫습니다.

## 업데이트 설치 \{#install-an-update}

**Services → IPv6 Prefix Updater → 정보**를 엽니다. 더 새로운 버전이 있으면 **_버전_(으)로 업데이트**가 백그라운드 작업을 시작하고, 페이지에 진행 상황이 표시됩니다.

작업은 릴리스를 다시 가져오고 버전이 포함된 `.pkg`를 다운로드합니다. 그리고 GitHub API 자산의 `sha256:<hex>` 다이제스트로 패키지를 검사하며, 다이제스트가 없으면 대신 같은 릴리스에서 일치하는 `.pkg.sha256` 파일을 다운로드합니다.

릴리스 패키지에는 `/usr/local/share/pfSense-pkg-Ipv6PrefixUpdater/release-signing.pub`에 릴리스 워크플로의 서명 공개 키가 들어 있습니다. 이 파일에 키가 하나 이상 있으면 설치된 복사본은 그중 하나로 서명된 업데이트만 허용합니다. 파일이 없거나 주석만 있으면 서명 검사가 꺼진 상태로 유지되며, 업데이트는 SHA-256 검사에만 의존합니다.

SHA-256 검사 후 설치된 키 파일에 키가 있으면 작업은 같은 릴리스의 일치하는 `.pkg.sig`를 다운로드하고 아카이브를 읽기 전에 `ssh-keygen -Y verify`로 검증합니다. 서명이 없거나 다른 키로 서명된 릴리스는 거부되며 설치된 버전은 유지됩니다.

그런 다음 작업은 `pkg add -f`를 실행하기 전에 아카이브의 패키지 이름과 버전을 확인합니다. 두 체크섬 소스가 모두 없으면 업데이트를 거부하고 설치된 버전을 유지합니다. 패키지 잠금은 접두사 실행과 업데이트가 겹치지 않게 합니다.

## 수동 설치 \{#install-manually}

관리자는 여전히 pfSense 셸에서 릴리스 파일을 설치할 수 있습니다.

```shell
pkg add -f https://github.com/mrjackyliang/pfsense-ipv6-prefix-updater/releases/latest/download/pfSense-pkg-Ipv6PrefixUpdater.pkg
```

이 수동 명령은 정보 탭의 SHA-256 검사와 릴리스 서명 검사를 모두 우회합니다. 사용 전에 릴리스, 체크섬 및 서명을 확인하십시오.

## 확인 끄기 \{#turn-checks-off}

**업데이트 확인**을 **사용 안 함**으로 설정하고 설정 탭을 저장합니다. 패키지는 업데이트 확인 cron 항목을 제거하며, 예약된 외부 업데이트 요청을 보내지 않습니다. 접두사 모니터링은 자체적인 독립 일정을 유지하며, 관리자가 직접 요청할 수 있도록 **지금 확인**은 계속 사용할 수 있습니다.
