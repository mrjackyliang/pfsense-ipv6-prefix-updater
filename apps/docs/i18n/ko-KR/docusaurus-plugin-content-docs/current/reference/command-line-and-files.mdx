셸에서 패키지 명령을 실행하고, 명령이 사용하는 파일, 로그, 알림을 찾습니다.

## 사용법 \{#usage}

```text
Usage: ipv6-prefix-updater [--manual] [--dry-run] [--accept-current-prefix [--interface=NAME]] [--migrate-legacy]
업데이트 옵션: --check-updates [--no-notice], --self-update.
```

pfSense가 관리하는 접두사 확인 cron 항목은 이 명령을 옵션 없이 `root`로 실행하고, 별도의 릴리스 확인 항목은 `--check-updates`와 함께 실행합니다. 명령은 각 확인 전에 <Terminology title="버전 1.x: Cron 패키지가 실행하던 update.php 스크립트" to="/docs/reference/terminology#package-origins">레거시 업데이터</Terminology>의 남은 항목도 패키지로 옮깁니다. 상태 탭은 **지금 실행**에 `--manual`을, **<Terminology title="아무것도 쓰지 않는 변경 미리 보기" to="/docs/reference/terminology#running-checks">시험 실행</Terminology>**에 `--dry-run`을, 기준선 복구에 `--accept-current-prefix`를 사용하고, 정리 탭은 `--migrate-legacy`를 사용합니다.

옵션 없이 실행하면 명령은 예약 확인처럼 동작하며, **<Terminology title="일정에 따른 자동 확인으로, 켜기 전까지는 꺼져 있음" to="/docs/reference/terminology#running-checks">예약 업데이트 사용</Terminology>**이 꺼져 있으면 <Terminology title="예약 업데이트가 꺼져 있어 건너뛴 예약 확인" to="/docs/reference/terminology#run-outcomes">사용 안 함</Terminology>을 보고합니다.

## 옵션 \{#options}

| 플래그                       | 설명                                                                                                                                                                                                      |
|---------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `--manual`                | <Terminology title="일정에 따른 자동 확인으로, 켜기 전까지는 꺼져 있음" to="/docs/reference/terminology#running-checks">예약 업데이트</Terminology>가 꺼져 있어도 실행합니다.                                                                 |
| `--dry-run`               | 백업이나 쓰기 없이 미리 보며, `--manual`을 포함합니다.                                                                                                                                                                    |
| `--accept-current-prefix` | 승인된 필드 검색, 백업 생성, 구성 쓰기, 서비스 다시 로드 없이 활성 원본 주소, 접두사, 길이를 기준선으로 기록합니다. `--manual`을 포함하며 `--dry-run`과 함께 사용할 수 없습니다.                                                                                      |
| `--interface=NAME`        | `--accept-current-prefix`를 모니터링하는 인터페이스 하나로 제한하며, 인터페이스는 `lan` 같은 내부 이름으로 지정합니다. 이 옵션이 없으면 모니터링하는 인터페이스 중 주소가 있는 인터페이스를 모두 수락합니다.                                                                       |
| `--migrate-legacy`        | 접두사 확인을 실행하지 않고 <Terminology title="버전 1.x: Cron 패키지가 실행하던 update.php 스크립트" to="/docs/reference/terminology#package-origins">레거시 업데이터</Terminology>를 즉시 패키지로 옮기며 각 단계를 출력합니다. 전환에서 경고가 보고되면 `2`로 종료합니다. |
| `--check-updates`         | GitHub에서 최신 패키지 릴리스를 확인하고 결과를 `/cf/conf/ipv6-prefix-updater/updates.json`에 저장합니다. 확인 방식은 [업데이트](/docs/reference/updates)에서 설명합니다.                                                                       |
| `--no-notice`             | `--check-updates`의 업데이트 알림을 만들지 않고 최신 버전을 이미 알린 것으로 기록합니다. `--check-updates`와 함께 사용할 때만 유효합니다.                                                                                                          |
| `--self-update`           | 최신 릴리스를 다운로드, 검증, 설치하고 진행 상황을 `/cf/conf/ipv6-prefix-updater/update-status.json`에 기록합니다.                                                                                                                 |
| `--help`                  | 사용법 줄과 업데이트 옵션 줄을 출력하고 `0`으로 종료합니다. 두 줄 모두 `--help` 자체는 나열하지 않습니다.                                                                                                                                      |

그 밖의 옵션은 표준 오류에 `알 수 없는 옵션: <option>`을 출력하고 `64`로 종료합니다. `--accept-current-prefix`를 `--dry-run`과 함께 사용해도 `64`로 종료하며, `--check-updates`와 `--self-update`를 서로 함께 사용하거나 접두사 옵션과 함께 사용해도 마찬가지입니다. `--check-updates` 없이 `--no-notice`를 사용해도 `64`로 종료합니다.

## 출력 \{#output}

인터페이스 하나를 모니터링하는 완료된 실행은 표준 출력에 아홉 줄을 출력하며, <Terminology title="아무것도 쓰지 않는 변경 미리 보기" to="/docs/reference/terminology#running-checks">시험 실행</Terminology>이나 <Terminology title="접두사가 바뀌었고 승인된 필드가 모두 업데이트됨" to="/docs/reference/terminology#run-outcomes">성공</Terminology> 후에는 그 뒤에 필드 변경이 이어집니다.

```text
상태: 성공
인터페이스: lan
관찰된 원본 주소: 2001:db8:abcd:88aa::1
이전 접두사: 2001:db8:abcd:7800::
현재 접두사: 2001:db8:abcd:8800::/56
계획되었거나 변경된 필드: 1
구성 백업: 생성됨
다시 로드된 서비스: 방화벽 필터
요약: 인터페이스 lan에서 승인된 필드 1개를 2001:db8:abcd:7800::/56에서 2001:db8:abcd:8800::/56(으)로 업데이트했습니다.
필드 변경:
- aliases/alias/0/address: 2001:db8:abcd:78aa::10 → 2001:db8:abcd:88aa::10
```

- `이전 접두사`에는 길이가 없으며, <Terminology title="첫 확인: 기준선만 기록하고 아무것도 바꾸지 않음" to="/docs/reference/terminology#run-outcomes">초기화됨</Terminology> 또는 <Terminology title="기록할 기준선을 보여 주는 시험 실행" to="/docs/reference/terminology#run-outcomes">초기화 미리 보기</Terminology> 후에는 `사용할 수 없음`이 표시됩니다.
- `다시 로드된 서비스`에는 상태 레이블이나 `없음`이 표시됩니다. <Terminology title="아무것도 쓰지 않는 변경 미리 보기" to="/docs/reference/terminology#running-checks">시험 실행</Terminology> 후에는 다시 로드될 서비스가 나열됩니다.
- `필드 변경`에는 바뀐 주소마다 `- <path>: <old> → <new>` 형식으로 한 줄씩 표시되며, 최대 200개 필드까지 나옵니다.
- 실행이 다른 패키지의 설정을 다시 적용했거나 더 이상 존재하지 않는 선택된 필드를 건너뛰었다면, 각각에 대해 상태 탭과 같은 문구의 줄이 하나씩 이어집니다.
- 다른 확인이 <Terminology title="두 확인이 동시에 실행되지 않게 막음" to="/docs/reference/terminology#running-checks">실행 잠금</Terminology>을 잡고 있으면 `다른 실행이 패키지 잠금을 소유하고 있어 구성을 읽지 않고 이 호출을 종료했습니다.`만 출력됩니다.
- 모니터링하는 인터페이스가 여러 개이면 출력은 전체 `상태`, `요약`, 패키지 줄, 건너뛴 필드 줄로 시작하고, 그 뒤에 인터페이스마다 그 인터페이스의 줄이 빈 줄로 구분되어 이어집니다.
- 확인 전에 <Terminology title="버전 1.x: Cron 패키지가 실행하던 update.php 스크립트" to="/docs/reference/terminology#package-origins">레거시 업데이터</Terminology> 전환이 이루어졌다면 그 단계가 먼저 출력됩니다.
- 레이블과 메시지는 pfSense 언어 설정을 따릅니다.

## 패키지 상태 형식 \{#package-state-format}

| 키                     | 설명                                                                                                                                                                                                                                                                                                                                                                                                                                      |
|-----------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `schema_version`      | 항상 `1`입니다.                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `targets.<interface>` | 모니터링하는 인터페이스마다 하나씩 있는 <Terminology title="변경을 판단하는 기준이 되는 기록된 시작 접두사" to="/docs/reference/terminology#baselines-and-transitions">기준선</Terminology>으로, 내부 이름을 키로 사용하며 `interface`, `source_address`, `prefix`, `prefix_length`, `updated_at`을 포함합니다. <Terminology title="버전 1.x: Cron 패키지가 실행하던 update.php 스크립트" to="/docs/reference/terminology#package-origins">레거시 업데이터</Terminology>에서 가져온 기준선에는 `legacy_cache`로 설정된 `source`도 있습니다. |
| `last_run`            | `status`, `timestamp`, `interface`, `observed_address`, `previous_prefix`, `current_prefix`, `current_prefix_length`, `change_count`, `backup_created`, `services`, `message`, `message_key`, `message_arguments`를 포함하는 최근 기록된 실행입니다.                                                                                                                                                                                                   |
| `legacy_migration`    | <Terminology title="버전 1.x: Cron 패키지가 실행하던 update.php 스크립트" to="/docs/reference/terminology#package-origins">레거시 업데이터</Terminology> 전환 후에 생기며 `status`, `steps`, `warnings`, `recorded_at`을 포함합니다. 정리 탭에 표시됩니다.                                                                                                                                                                                                                         |

- `status`는 `initialized`, `initialization_preview`, `no_change`, `dry_run`, `warning`, `accepted`, `success`, `failure` 중 하나입니다.
- <Terminology title="접두사가 바뀌었고 승인된 필드가 모두 업데이트됨" to="/docs/reference/terminology#run-outcomes">성공</Terminology> 후 `last_run.notification`은 알림이 꺼져 있으면 `disabled`이고, 전달을 시도한 뒤에는 `sent` 또는 `failed`입니다.
- <Terminology title="아무것도 쓰지 않는 변경 미리 보기" to="/docs/reference/terminology#running-checks">시험 실행</Terminology>이나 <Terminology title="접두사가 바뀌었고 승인된 필드가 모두 업데이트됨" to="/docs/reference/terminology#run-outcomes">성공</Terminology> 후에는 각 결과에 `changes`도 있으며, 최대 200개 필드의 `path`와 `replacements`를 나열합니다. 각 교체 항목은 이전 주소와 새 주소로 이루어집니다.
- `package_reapply`는 실행이 설정을 다시 적용한 각 패키지의 `section`, `package`, `status`, `error`를 나열하고, `skipped_fields`는 더 이상 존재하지 않는 선택된 필드를 나열합니다. 둘 다 비어 있지 않을 때만 나타납니다.
- 모니터링하는 인터페이스가 여러 개이면 `last_run`에는 합계와, 인터페이스마다 결과가 하나씩 담긴 `targets` 목록이 들어 있습니다.
- 타임스탬프는 UTC 기준 ISO 8601 형식입니다. 구문 분석할 수 없거나 스키마 버전이 다른 파일이 있으면 각 실행이 `IPv6 접두사 업데이터 상태가 잘못되었거나 지원되지 않습니다.` 메시지와 함께 멈춥니다.

## 설정 저장소 \{#settings-storage}

설정은 pfSense 구성의 `installedpackages/ipv6prefixupdater/config/0`에 저장됩니다.

| 키                             | 설명                                                                                                                                               |
|-------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------|
| `enabled`                     | **<Terminology title="일정에 따른 자동 확인으로, 켜기 전까지는 꺼져 있음" to="/docs/reference/terminology#running-checks">예약 업데이트 사용</Terminology>**이며, 선택하면 `on`입니다. |
| `row`                         | **모니터링할 인터페이스**이며, 행마다 `interface`(`lan` 같은 인터페이스 키) 하나와 `prefix_length`(`48`부터 `64`까지) 하나가 있는 목록입니다.                                            |
| `update_frequency`            | **일정**이며, `every_fifteen_minutes`, `hourly`, `every_six_hours`, `daily` 중 하나입니다.                                                                 |
| `notifications`               | **<Terminology title="주소가 업데이트된 뒤 보내는 알림" to="/docs/reference/terminology#notifications-and-logs">변경 알림 보내기</Terminology>**이며, 선택하면 `on`입니다.     |
| `update_check_frequency`      | **업데이트 확인**이며, `daily`, `weekly`, `monthly`, `never` 중 하나입니다.                                                                                    |
| `update_remote_notifications` | **원격 알림**이며, 선택하면 `on`입니다.                                                                                                                       |

고정된 릴리스 확인 일정은 설정 레코드 옆의 `installedpackages/ipv6prefixupdater/update_schedule`에 저장되며, `minute`은 0부터 59까지, `hour`는 0부터 23까지, `weekday`는 0부터 6까지, `monthday`는 1부터 28까지입니다. 값이 없거나, 형식이 잘못되었거나, 범위를 벗어나면 다시 생성되어 저장됩니다.

### 필드 선택 \{#field-selection}

필드 탭의 선택은 설정 레코드 옆의 `installedpackages/ipv6prefixupdater/fields`에 저장되므로, `config/0`을 교체하는 설정 탭 저장이 이 선택을 지우는 일은 없습니다.

| 키                      | 설명                                                                                     |
|------------------------|----------------------------------------------------------------------------------------|
| `schema`               | 항상 `1`입니다. 비어 있더라도 필드 탭에서 저장한 선택임을 나타냅니다.                                              |
| `enabled_groups/item`  | 켜진 그룹입니다. `firewall_rules`, `dhcpv6`, 또는 다른 패키지의 설정을 나타내는 `package:<section>` 같은 값입니다. |
| `disabled_groups/item` | 꺼진 pfSense 그룹입니다. 두 목록 어디에도 없는 pfSense 그룹은 켜져 있고, 다른 패키지의 그룹은 꺼져 있습니다.                 |
| `include/item`         | 꺼진 그룹에서 선택한 필드의 식별자입니다.                                                                |
| `exclude/item`         | 켜진 그룹에서 선택을 해제한 필드의 식별자입니다.                                                            |

- pfSense 그룹 키는 `interfaces`, `virtual_ips`, `aliases`, `firewall_rules`, `nat`, `dhcpv6`, `router_advertisements`, `dns_host_overrides`, `ipsec`, `openvpn`, `wireguard`입니다.
- `include`와 `exclude`는 각각 최대 1,000개의 식별자를 보관하며, 모든 식별자는 [필드 식별자](/docs/reference/approved-fields#field-identities) 형식을 따릅니다.

## Cron 항목 \{#cron-entry}

설정을 저장하면 이 명령의 기존 항목을 모두 제거하고, `enabled`가 `on`이면 pfSense의 `install_cron_job()`으로 `root`용 새 항목을 설치합니다.

| 일정 값                    | Cron 필드        |
|-------------------------|----------------|
| `every_fifteen_minutes` | `*/15 * * * *` |
| `hourly`                | `0 * * * *`    |
| `every_six_hours`       | `0 */6 * * *`  |
| `daily`                 | `0 0 * * *`    |

알 수 없는 값은 매시간 필드로 대체됩니다. <Terminology title="버전 1.x: Cron 패키지가 실행하던 update.php 스크립트" to="/docs/reference/terminology#package-origins">레거시 업데이터</Terminology> 전환이 레거시 스크립트가 끝나기를 기다리는 동안에는, 예약 업데이트가 꺼져 있어도 전환을 다시 시도하도록 패키지가 `*/15 * * * *` 항목을 유지합니다.

두 번째 항목은 **업데이트 확인** 빈도에 따라, 무작위로 정해졌지만 고정된 분, 시, 요일, 날짜에 `/usr/local/sbin/ipv6-prefix-updater --check-updates`를 `root`로 실행합니다. 설정을 저장하면 이 항목이 교체되고, `never`이면 제거됩니다.

## 페이지 권한 \{#page-privileges}

각 패키지 페이지는 자체 pfSense 권한을 선언하므로 페이지별로 접근 권한을 부여할 수 있습니다.

- **상태**: `page-services-ipv6-prefix-updater-status`이며, 이름은 `Services: IPv6 Prefix Updater: Status`입니다.
- **필드**: `page-services-ipv6-prefix-updater-fields`이며, 이름은 `Services: IPv6 Prefix Updater: Fields`입니다. 실행이 다시 쓰는 필드를 바꿀 수 있으므로 관리자에게만 부여하는 것을 권장합니다.
- **백업**: `page-services-ipv6-prefix-updater-backups`이며, 이름은 `Services: IPv6 Prefix Updater: Backups`입니다. 전체 구성 사본을 다운로드할 수 있으므로 관리자에게만 부여하는 것을 권장합니다.
- **정리**: `page-services-ipv6-prefix-updater-cleanup`이며, 이름은 `Services: IPv6 Prefix Updater: Cleanup`입니다.
- **정보**: `page-services-ipv6-prefix-updater-about`이며, 이름은 `Services: IPv6 Prefix Updater: About`입니다.
