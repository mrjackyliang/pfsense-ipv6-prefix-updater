접두사가 바뀔 때 변경할 구성 필드를 고릅니다.

## 필드 탭 \{#the-fields-tab}

**Services → IPv6 Prefix Updater** 아래의 **필드** 탭은 각 <Terminology title="구성을 바꾸지 않고 기록한 시작 접두사" to="/docs/reference/terminology#baseline">기준선</Terminology> 접두사 안에 있는 모든 주소를 종류별로 묶어 나열합니다. **기준선** 줄에는 탭이 비교 기준으로 삼는 접두사가 표시됩니다. 첫 확인이 기준선을 기록하기 전에는 탭에 그룹 스위치만 표시됩니다.

<img src={fieldsTab} alt="자동 선택 및 모두 지우기 버튼, 검색 상자, 필터, 그리고 접두사 부분이 강조 표시된 LAN과 LAB 주소를 나열하는 정적 인터페이스 그룹이 있는 IPv6 Prefix Updater 필드 탭" width={1024} height={768} style={{maxWidth: '100%', height: 'auto'}} />

각 행에는 다음 항목이 표시됩니다.

- **확인란**: 다음 <Terminology title="마지막 성공 접두사나 길이와 달라진 상태" to="/docs/reference/terminology#prefix-transition">접두사 전환</Terminology>에서 업데이트될 필드라면 선택되어 있습니다.
- **필드**: 규칙 설명이나 별칭 이름 같은 항목, 이어서 필드 레이블과 그 구성 경로.
- **현재 값**: 각 주소의 접두사 부분이 강조 표시된 값. 강조 표시된 부분만 바뀌고 <Terminology title="위임된 접두사 뒤의 주소 비트" to="/docs/reference/terminology#host-portion">호스트 부분</Terminology>은 그대로 유지됩니다.

## 그룹 스위치와 예외 \{#group-switches-and-exceptions}

각 <Terminology title="필드 탭에서 스위치 하나로 켜고 끄는 필드 묶음" to="/docs/reference/terminology#field-group">필드 그룹</Terminology>의 머리글에는 스위치가 있습니다.

- **켜짐**: 나중에 추가되는 필드를 포함해 그 종류의 모든 필드가 접두사와 함께 바뀌며, 선택을 해제한 필드만 제외됩니다.
- **꺼짐**: 선택한 필드만 바뀝니다.

그룹 스위치와 다른 선택은 <Terminology title="그룹 스위치와 반대로 선택하거나 선택 해제한 개별 필드" to="/docs/reference/terminology#field-exception">필드 예외</Terminology>입니다. 그룹에 예외가 있는 동안에는 머리글에 대시가 표시되고, **M개 중 N개 선택됨**에 선택된 필드 수가 표시됩니다. 머리글을 클릭하면 그룹이 켜지거나 꺼지고, 그 안의 모든 선택이 스위치에 맞게 다시 설정됩니다. 변경 내용을 유지하려면 **저장**을 선택합니다.

<img src={fieldException} alt="방화벽 규칙 그룹이 켜져 있고, 규칙 하나가 선택 해제되어 머리글에 대시와 3개 중 2개 선택됨이 표시되며, 트래커 ID가 없어 그룹 스위치를 따르는 규칙이 있는 필드 탭" width={1024} height={768} style={{maxWidth: '100%', height: 'auto'}} />

선택은 목록 안의 위치가 아니라 항목을 따라가므로, 다른 항목을 옮기거나 삭제해도 선택이 다른 항목으로 넘어가지 않습니다. 패키지는 다음 값으로 각 항목을 식별합니다.

- **방화벽 규칙**: 규칙의 트래커 ID.
- **별칭**: 별칭 이름.
- **DHCPv6 정적 매핑**: DUID. pfSense는 DHCPv6 매핑을 MAC 주소가 아니라 DUID로 식별하기 때문입니다.
- **포트 포워드와 아웃바운드 NAT**: 규칙이 생성된 시각.
- **1:1 NAT 및 NPt 항목과 DHCPv6 풀**: 설명.
- **DNS 호스트 재정의**: 호스트, 도메인, 그리고 항목에 IPv4 주소, IPv6 주소, 또는 둘 다가 들어 있는지 여부.
- **다른 패키지의 설정**: 이름이나 설명처럼 각 목록 항목을 고유하게 가리키는 필드.
- **기타 설정**: 게이트웨이 이름처럼 각 목록 항목을 고유하게 가리키며 주소를 담지 않는 필드. **System → General Setup** 아래의 DNS 서버 같은 단순 목록은 모든 항목을 선택 하나로 함께 다룹니다.
- **그 밖의 항목**: 인터페이스, 이름 또는 pfSense ID. 한 인터페이스의 모든 DNS 서버, NTP 서버 또는 RA 서브넷은 선택 하나로 함께 다룹니다.

항목에 이런 식별자가 없거나 다른 항목과 식별자를 공유하는 행에는 확인란이 없고 `안정적인 식별자가 없으므로 이 필드는 그룹 스위치를 따릅니다.`가 표시됩니다. 선택은 설정과 별도로 보관되므로 설정 탭을 저장해도 지워지지 않습니다.

## 버튼, 검색, 필터 \{#buttons-search-and-filters}

- **자동 선택**: 모든 pfSense 그룹을 켜고 그 안의 모든 필드를 선택합니다. 기타 설정 그룹과 다른 패키지의 설정은 그대로 유지됩니다.
- **모두 지우기**: 모든 그룹을 끄고 모든 필드의 선택을 해제합니다.
- **필드 검색**: 그룹, 항목, 레이블, 값 또는 경로에 입력한 텍스트가 들어 있는 행만 표시합니다.
- **필터**: 모든 행, 선택된 행만, 또는 다른 패키지의 행만 표시합니다.

**자동 선택**과 **모두 지우기**는 **저장**을 선택하기 전까지 페이지만 바꿉니다. 아무 필드도 선택하지 않은 상태가 저장되면 탭에 경고가 표시되고, 필드를 다시 선택할 때까지 실행은 `선택된 구성 필드가 없습니다. 필드 탭에서 필드를 선택하십시오.` 메시지와 함께 멈춥니다.

탭에 나열되는 필드가 40개를 넘으면 그룹이 접힌 상태로 시작합니다. 그룹을 펼치려면 그룹 이름을 선택합니다.

## 다른 패키지의 설정 \{#other-packages-settings}

다른 패키지가 `installedpackages` 아래에 보관하는 설정은 별도의 그룹을 받습니다. 이 그룹에는 설정을 소유한 설치된 패키지의 이름이, 소유한 패키지가 없으면 섹션 이름이 붙습니다. 패키지는 이 필드의 의미를 알 수 없으므로 선택 해제된 상태로 시작하며, **자동 선택**도 이 필드를 절대 선택하지 않습니다. 필드는 그 패키지에서 어떤 역할을 하는지 확인한 뒤에만 선택합니다.

실행이 이 필드 중 하나를 변경하면 그 패키지 자체의 **Save** 버튼처럼 패키지의 설정을 다시 적용합니다. 상태 탭의 **마지막 실행**은 각 결과를 **패키지** 아래에 나열합니다.

- `<package> 패키지 설정을 다시 적용했습니다.`
- `<section> 설정을 소유한 설치된 패키지가 없습니다. 이 설정을 사용하는 서비스를 직접 다시 시작하십시오.` 그래도 값은 저장됩니다. 패키지가 설정 일부를 이름이 다른 섹션 아래에 보관할 때도 이렇게 됩니다.
- `<package> 패키지 설정을 다시 적용할 수 없습니다: <reason>` 새 값은 저장된 채로 남고 아무것도 롤백되지 않습니다.

두 문제 모두 <Terminology title="pfSense 알림 목록에 표시되는 항목" to="/docs/reference/terminology#webgui-notice">WebGUI 알림</Terminology>도 추가합니다.

## 더 이상 존재하지 않는 필드 \{#fields-that-no-longer-exist}

선택한 필드가 속한 항목이 삭제되면 그 필드는 탭 맨 위의 **누락된 필드** 아래에 나타납니다. 실행은 이 필드를 건너뛰고 상태 탭의 **건너뛴 필드** 아래에 나열합니다. **누락된 필드 잊기**는 이 선택을 제거합니다.

## 기타 설정 \{#other-settings}

**기타 설정** 그룹에는 기준선 접두사 안에 있는 그 밖의 모든 주소가 나열됩니다. 이 그룹은 꺼진 상태로 시작하므로 그 안의 값은 직접 선택하거나 그룹을 켤 때만 바뀌며, 그룹을 켜면 나중에 추가되는 값도 포함됩니다. 각 행에는 해당 종류가 표시됩니다.

- 모든 VPN의 원격 쪽: IPsec 원격 네트워크와 원격 게이트웨이, OpenVPN 원격 네트워크와 서버 주소.
- 허용 IP와 엔드포인트를 포함한 WireGuard 피어.
- 게이트웨이와 정적 경로.
- 인증서, 개인 키, 암호, 사전 공유 키. 이 값은 `값 숨김`으로 표시됩니다.
- DNS Resolver의 사용자 지정 옵션처럼 Base64로 저장된 값. 이 값은 디코딩하고 다시 쓴 뒤 다시 인코딩합니다.
- 설명.
- DNS Resolver 도메인 재정의와 **System → General Setup** 아래의 DNS 서버처럼 종류 대신 설정 이름이 표시되는 그 밖의 모든 설정.

<img src={otherSettings} alt="정적 경로, 별칭 설명, Base64로 인코딩된 DNS Resolver 사용자 지정 옵션, 도메인 재정의, 게이트웨이를 각각의 종류와 함께 나열하는 필드 탭의 기타 설정 그룹" width={1024} height={768} style={{maxWidth: '100%', height: 'auto'}} />

실행이 이 값 중 하나를 변경하면, 그 설정을 저장할 때 pfSense가 다시 로드하는 대상을 똑같이 다시 로드합니다.

- **게이트웨이와 정적 경로**: 라우팅, 그다음 방화벽 필터.
- **System → General Setup 아래의 DNS 서버**: 시스템의 DNS 설정, 그다음 DNS Resolver 또는 DNS Forwarder.
- **DNS Resolver, DNS Forwarder, IPsec, OpenVPN, WireGuard 값**: 해당 서비스.
- **다른 패키지의 값**: [다른 패키지의 설정](#other-packages-settings)에서 설명한 대로 그 패키지의 설정.
- **설명, 인증서, 알려진 서비스가 없는 값**: 없음. 새 값은 저장만 됩니다.

변경이 일어난 뒤에는 탭이 새 접두사를 기준으로 비교하므로, 기준선이 아직 이전 접두사일 때 이 필드를 선택해 두는 것을 권장합니다. 원격 VPN 피어는 자체 구성을 유지하므로, 변경된 주소를 가리키는 피어는 그쪽에서 업데이트해야 합니다.

## 값을 일치시키는 방식 \{#how-values-are-matched}

- 주소는 <Terminology title="구성을 바꾸지 않고 기록한 시작 접두사" to="/docs/reference/terminology#baseline">기준선</Terminology>에 저장된 길이를 기준으로 <Terminology title="다음 확인이 비교 기준으로 삼는 접두사" to="/docs/reference/terminology#last-successful-prefix">마지막 성공 접두사</Terminology>에 속할 때만 변경됩니다. 다른 네트워크의 주소, IPv4 주소, 호스트 이름, 별칭 이름은 그대로 두며 탭에도 나열하지 않습니다.
- 별칭 항목, OpenVPN 로컬 네트워크, DNS Resolver 호스트 재정의 같은 목록에서는 각 항목을 따로 검사하고 구분 기호는 쓰인 그대로 유지합니다.
- 다른 패키지의 설정과 기타 설정 그룹에서는 텍스트 안의 모든 주소를 따로 검사하고 나머지 텍스트는 쓰인 그대로 유지합니다.
- `/64` 같은 CIDR 접미사는 쓰인 그대로 유지되고, 각 주소의 <Terminology title="위임된 접두사 뒤의 주소 비트" to="/docs/reference/terminology#host-portion">호스트 부분</Terminology>도 보존됩니다.
- <Terminology title="다른 인터페이스의 위임된 접두사로 주소를 받는 인터페이스" to="/docs/reference/terminology#tracked-interface">Track Interface</Terminology>로 주소를 받는 인터페이스에서는 DHCPv6 범위와 정적 매핑에 `::1000` 같은 호스트 접미사가 들어 있으며, 이 접미사는 그대로 유지됩니다.
- 다시 쓴 주소는 <Terminology title="소문자로 쓴 가장 짧은 표준 주소 표기" to="/docs/reference/terminology#canonical-form">정규 형식</Terminology>으로 저장되므로 입력한 것과 표기가 다를 수 있습니다.

## 변경 미리 보기 \{#previewing-changes}

<Terminology title="백업도 쓰기도 하지 않는 미리 보기" to="/docs/reference/terminology#dry-run">시험 실행</Terminology>은 <Terminology title="마지막 성공 접두사나 길이와 달라진 상태" to="/docs/reference/terminology#prefix-transition">접두사 전환</Terminology>이 일어난 뒤에만 선택된 필드를 읽습니다. 접두사가 그대로인 동안에는 <Terminology title="결과: 접두사 그대로, 검색이나 쓰기 없음" to="/docs/reference/terminology#no-change">변경 없음</Terminology>을 보고하므로, 새 선택은 필드 탭에서 미리 봅니다. 전환이 일어난 뒤에는 시험 실행의 <Terminology title="지금 실행이나 시험 실행 후 표시되는 읽기 전용 결과" to="/docs/reference/terminology#command-output">명령 출력</Terminology>이 바꿀 각 주소를 `필드 변경` 아래에 나열합니다.

<Terminology title="백업도 쓰기도 하지 않는 미리 보기" to="/docs/reference/terminology#dry-run">시험 실행</Terminology>은 pfSense가 영향을 받는 서비스를 다시 로드할 수 있는지 확인하는 검사도 건너뜁니다. 따라서 WireGuard 패키지가 없다는 사실은 실제 실행에서만 드러납니다.

## WireGuard 패키지 \{#wireguard-package}

<Terminology title="pfSense WireGuard 터널에 할당된 주소" to="/docs/reference/terminology#wireguard-tunnel-address">WireGuard 터널 주소</Terminology>를 업데이트하려면 WireGuard 패키지가 필요합니다. 이 주소를 변경해야 하는데 패키지가 설치되어 있지 않으면 실제 실행은 백업 전에 `필수 pfSense 종속성 “/usr/local/pkg/wireguard/includes/wg.inc”을(를) 사용할 수 없습니다.` 메시지와 함께 멈춥니다.

각 그룹이 사용하는 정확한 구성 경로와 각 선택이 저장되는 식별자는 [승인된 필드](/docs/reference/approved-fields)에 나와 있습니다.
