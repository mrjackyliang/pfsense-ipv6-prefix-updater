현재 접두사를 드러내는 인터페이스를 고르고, 각 인터페이스에 대해 ISP가 위임하는 <Terminology title="/56처럼 네트워크를 나타내는 앞쪽 비트 수" to="/docs/reference/terminology#prefix-length">접두사 길이</Terminology>를 입력합니다.

## 모니터링할 인터페이스 선택 \{#choose-the-monitored-interfaces}

<Terminology title="2000::/3 범위의 공인 IPv6 주소" to="/docs/reference/terminology#global-unicast-address">글로벌 주소</Terminology>가 <Terminology title="ISP가 방화벽으로 라우팅하는 IPv6 네트워크" to="/docs/reference/terminology#delegated-prefix">위임된 접두사</Terminology>에서 오는 인터페이스마다 **모니터링할 인터페이스** 행을 하나씩 추가합니다. 패키지는 실행할 때마다 각 주소를 새로 읽으며 <Terminology title="하나의 링크에서만 동작하는 fe80:: 주소" to="/docs/reference/terminology#link-local-address">링크 로컬 주소</Terminology>로 대체하지 않습니다.

WAN이 <Terminology title="ISP가 방화벽으로 라우팅하는 IPv6 네트워크" to="/docs/reference/terminology#delegated-prefix">위임된 접두사</Terminology>만 받는다면 보통 LAN 같은 <Terminology title="다른 인터페이스의 위임된 접두사로 주소를 받는 인터페이스" to="/docs/reference/terminology#tracked-interface">추적 인터페이스</Terminology>가 그 접두사의 <Terminology title="2000::/3 범위의 공인 IPv6 주소" to="/docs/reference/terminology#global-unicast-address">글로벌 주소</Terminology>를 가지므로 이 인터페이스가 알맞은 선택입니다.

<img src={monitoredInterfaces} alt="LAN과 LAB 두 개의 모니터링할 인터페이스 행이 각각 /56 위임된 접두사 길이로 설정되어 있고 필드 탭 안내 문구가 표시된 IPv6 Prefix Updater 설정 탭" width={1024} height={768} style={{maxWidth: '100%', height: 'auto'}} />

- **추가**: 행을 추가합니다. 각 인터페이스는 한 행에만 나타날 수 있으며, 행 없이 저장하면 거부됩니다.
- **삭제**: 행을 제거합니다. 행이 하나만 남아 있는 동안에는 pfSense가 이 버튼을 숨깁니다.
- **모든 행을 한 번의 실행으로**: 각 예약 확인은 모니터링하는 모든 인터페이스를 읽고, 그 변경을 백업 후 한 번의 쓰기로 저장합니다.

대부분의 방화벽은 행 하나면 충분합니다. 두 개의 WAN 연결처럼 여러 인터페이스가 각자 위임된 접두사를 받을 때나, 각 LAN 세그먼트의 주소를 확인하려고 할 때 행을 더 추가합니다.

선택이 맞는지 확인하려면 다음을 수행합니다.

1. **<Terminology title="pfSense가 관리하는 cron 항목으로 실행하는 자동 확인" to="/docs/reference/terminology#scheduled-updates">예약 업데이트 사용</Terminology>**을 해제한 상태로 설정을 저장합니다.
2. 상태 탭에서 **지금 실행**을 선택합니다.
3. **<Terminology title="pfSense가 모니터링할 인터페이스에 보고하는 글로벌 주소" to="/docs/reference/terminology#source-address">관찰된 원본 주소</Terminology>**를 **Status → Interfaces**에 표시된 주소와 비교합니다.
4. 주소가 잘못된 네트워크에 속하면 다른 인터페이스를 선택하고 다시 시도합니다.

상태 탭에는 `LAN (lan)`처럼 각 인터페이스의 설명 뒤에 pfSense 내부 이름이 표시됩니다.

## 위임된 접두사 길이 입력 \{#enter-the-delegated-prefix-length}

ISP의 서비스 정보나 WAN 인터페이스의 DHCPv6 접두사 위임 크기를 보고 길이를 선택합니다. **<Terminology title="ISP 접두사 크기 설정, /48~/64" to="/docs/reference/terminology#delegated-prefix-length">위임된 접두사 길이</Terminology>**는 `/48`부터 `/64`까지 허용하고, 처음 값은 `/56`이며, 자동으로 감지되지 않습니다.

:::tip

<Terminology title="구성을 바꾸지 않고 기록한 시작 접두사" to="/docs/reference/terminology#baseline">기준선</Terminology>은 접두사와 함께 길이도 저장하므로, 첫 **지금 실행** 전에 길이를 확인하는 것을 권장합니다.

:::

## 계산된 네트워크 확인 \{#check-the-calculated-network}

실행이 끝나면 **<Terminology title="접두사 길이로 마스킹한 원본 주소" to="/docs/reference/terminology#observed-prefix">관찰된 접두사</Terminology>**에 계산된 네트워크가 표시됩니다. 패키지는 주소를 비트 단위로 마스킹하므로 `/57`이나 `/63`처럼 16진수 숫자 중간에서 끝나는 길이도 같은 방식으로 동작합니다.

`2001:db8:abcd:7800::/56`에서 `2001:db8:abcd:8800::/56`으로 바뀌는 `/56` 위임의 예는 다음과 같습니다.

```text
Source address:    2001:db8:abcd:88aa::1
Current prefix:    2001:db8:abcd:8800::/56
Previous address:  2001:db8:abcd:78aa::42
Updated address:   2001:db8:abcd:88aa::42
```

처음 56비트만 바뀌고 <Terminology title="위임된 접두사 뒤의 주소 비트" to="/docs/reference/terminology#host-portion">호스트 부분</Terminology>인 `aa::42`는 그대로입니다. 이 가이드에 나오는 `2001:db8::/32` 범위의 주소는 문서용 예시입니다.

## 인터페이스 변경 \{#changing-the-interfaces}

:::warning

<Terminology title="주소로 현재 접두사를 알려 주는 인터페이스" to="/docs/reference/terminology#monitored-interface">모니터링할 인터페이스</Terminology>를 추가하거나 행을 다른 인터페이스로 바꾸면 다음 실행은 구성을 변경하지 않고 그 인터페이스에 대한 새 <Terminology title="구성을 바꾸지 않고 기록한 시작 접두사" to="/docs/reference/terminology#baseline">기준선</Terminology>을 기록합니다. 그 인터페이스의 접두사가 바뀌었는데 패키지가 아직 적용하지 않은 상태였다면 그 변경은 건너뜁니다.

:::

행을 삭제해도 그 인터페이스의 <Terminology title="구성을 바꾸지 않고 기록한 시작 접두사" to="/docs/reference/terminology#baseline">기준선</Terminology>은 <Terminology title="기준선과 마지막 실행을 담은 패키지 파일" to="/docs/reference/terminology#package-state">패키지 상태</Terminology>에 남습니다. 나중에 그 인터페이스를 다시 추가하면 새 기준선을 기록하지 않고 저장된 기준선과 비교합니다.

## 접두사 길이 변경 \{#changing-the-prefix-length}

<Terminology title="구성을 바꾸지 않고 기록한 시작 접두사" to="/docs/reference/terminology#baseline">기준선</Terminology>이 생긴 뒤 **<Terminology title="ISP 접두사 크기 설정, /48~/64" to="/docs/reference/terminology#delegated-prefix-length">위임된 접두사 길이</Terminology>**를 변경하면, 네트워크 자체는 같더라도 <Terminology title="마지막 성공 접두사나 길이와 달라진 상태" to="/docs/reference/terminology#prefix-transition">접두사 전환</Terminology>으로 간주됩니다. 패키지는 <Terminology title="구성을 바꾸지 않고 기록한 시작 접두사" to="/docs/reference/terminology#baseline">기준선</Terminology>에 저장된 길이로 주소를 일치시키고 새 길이로 비트를 바꿉니다.

:::danger

길이를 늘려 범위를 좁히면 일치하는 모든 주소의 서브넷 비트를 덮어씁니다. <Terminology title="pfSense가 모니터링할 인터페이스에 보고하는 글로벌 주소" to="/docs/reference/terminology#source-address">원본 주소</Terminology>가 `2001:db8:1234:ab00::1`이고 <Terminology title="구성을 바꾸지 않고 기록한 시작 접두사" to="/docs/reference/terminology#baseline">기준선</Terminology>이 `/56`일 때 `/64`로 바꾸면 `2001:db8:1234:abcc::42`가 `2001:db8:1234:ab00::42`로 바뀝니다.

:::

길이를 줄여 범위를 넓히면(예: `/64`에서 `/56`으로) 실행에서 변경할 것이 없을 수 있습니다. 그러면 접두사 자체가 바뀌거나, 저장된 주소를 확인하고 [현재 접두사를 새 기준선으로 수락](/docs/operate/backups-and-recovery#after-a-failed-run)할 때까지 매 실행마다 <Terminology title="결과: 접두사가 바뀌었지만 일치하는 승인된 필드 없음" to="/docs/reference/terminology#warning">경고</Terminology>를 보고합니다.

길이를 변경하기 전에 같은 저장에서 **<Terminology title="pfSense가 관리하는 cron 항목으로 실행하는 자동 확인" to="/docs/reference/terminology#scheduled-updates">예약 업데이트 사용</Terminology>**을 해제하는 것을 권장합니다. 그러면 **지금 실행**을 선택하기 전에 **<Terminology title="백업도 쓰기도 하지 않는 미리 보기" to="/docs/reference/terminology#dry-run">시험 실행</Terminology>**으로 계획된 필드 수, `필드 변경` 아래의 계획된 각 변경, **요약**을 볼 수 있습니다.

다음으로 [기준선을 설정](/docs/first-run)한 뒤 [필드](/docs/configure/configuration-scopes) 탭에서 필드를 고릅니다.
