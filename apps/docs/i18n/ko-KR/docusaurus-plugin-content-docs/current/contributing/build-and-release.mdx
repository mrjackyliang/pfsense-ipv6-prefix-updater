IPv6 Prefix Updater for pfSense를 검사, 스테이징, 패키징한 다음 패키지를 GitHub 릴리스에 게시합니다.

## 요구 사항 \{#requirements}

- **Node.js 22, 24 또는 26** — 루트 및 워크스페이스 매니페스트는 `^22 || ^24 || ^26`을 허용합니다.
- **PHP 또는 Docker** — PHP 테스트 모음은 로컬 `php`가 있으면 그것을 사용하고, 없으면 Docker로 `php:8.3-cli-alpine` 이미지를 사용합니다. `PHP_TEST_IMAGE`로 이미지를 재정의할 수 있습니다.
- **패키징용 FreeBSD** — `npm run deploy`는 FreeBSD에서만 실행되며, `PFSENSE_PORTS_DIR` 변수가 pfSense FreeBSD-ports 체크아웃을 가리켜야 합니다.

## 검사, 스테이징, 패키징 \{#check-stage-and-package}

저장소 루트에서 다음 명령을 실행합니다.

```bash
# Lint and type-check the scripts, run the PHP and Vitest suites, and validate the port.
npm run check --workspace pfsense-pkg-ipv6-prefix-updater

# Copy the port into packages/ipv6-prefix-updater/build/port with the workspace version.
npm run build --workspace pfsense-pkg-ipv6-prefix-updater

# Build the package on FreeBSD into packages/ipv6-prefix-updater/build/release.
PFSENSE_PORTS_DIR=/path/to/FreeBSD-ports npm run deploy --workspace pfsense-pkg-ipv6-prefix-updater
```

- 스테이징은 `port/Makefile.template`을 `build/port/Makefile`로 바꾸고 `packages/ipv6-prefix-updater/package.json`의 `version`을 기록합니다.
- 패키징은 스테이징된 포트를 ports 체크아웃의 `sysutils/pfSense-pkg-Ipv6PrefixUpdater`로 복사하고, `make package`를 실행한 뒤, 그 사본을 다시 제거합니다. 대상이 이미 있으면 멈춥니다.
- 그러면 `build/release`에 버전이 붙은 `.pkg`, `pfSense-pkg-Ipv6PrefixUpdater.pkg`라는 이름의 사본, 그리고 각각에 대해 해시만 담은 `.sha256` 파일이 생깁니다.

## 릴리스 워크플로 \{#release-workflow}

Nova가 생성한 `.github/workflows/nova-publish-project.yml`의 `publish-pfsense-packages-ipv6-prefix-updater` 작업은 게시 워크플로에서 실행됩니다.

1. Ubuntu 러너에서 포트를 검증하고 스테이징합니다.
2. `PFSENSE_RELEASE_SIGNING_KEY` 비밀이 설정되어 있으면 `PFSENSE_RELEASE_SIGNING_KEY`에서 공개 키를 추출하여 스테이징된 포트의 `usr/local/share/pfSense-pkg-Ipv6PrefixUpdater/release-signing.pub` 파일에 추가합니다.
3. 구성된 pfSense FreeBSD-ports 체크아웃을 사용해 FreeBSD에서 패키지를 빌드합니다.
4. 비밀이 설정되어 있으면 `ssh-keygen -Y sign -n pfSense-pkg-Ipv6PrefixUpdater`와 함께 각 `.pkg`를 `<file>.pkg.sig`로 서명합니다.
5. 패키지, 체크섬, 서명을 7일 동안 보관되는 워크플로 아티팩트로 업로드하고 같은 파일을 릴리스에 첨부합니다.

빌드 결과에는 컴파일된 코드가 없으므로 패키지가 모든 FreeBSD 버전용으로 표시되며, 하나의 패키지를 지원되는 모든 pfSense 릴리스에 설치할 수 있습니다. `PFSENSE_FREEBSD_VERSION`은 빌드 VM에서 사용할 FreeBSD 릴리스만 선택합니다. 설치 가이드의 `pkg add` 명령은 GitHub가 최신으로 표시한 릴리스에서 `pfSense-pkg-Ipv6PrefixUpdater.pkg`를 가져옵니다.

## 릴리스 서명 \{#release-signing}

서명에 필요한 유일한 설정은 암호화되지 않은 OpenSSH Ed25519 개인 키를 담은 `PFSENSE_RELEASE_SIGNING_KEY` 저장소 비밀입니다.

1. 1Password에서 **New Item → SSH Key → Generate a New Key → Ed25519**를 선택합니다.
2. 개인 키 필드에서 **Export**를 선택하고 OpenSSH 형식을 선택한 다음 암호는 비워 둡니다.
3. 비밀을 저장하기 전에 클립보드를 확인합니다.

   ```bash
   pbpaste | head -1
   ```

   명령은 `-----BEGIN OPENSSH PRIVATE KEY-----`를 출력해야 합니다.

4. 클립보드를 GitHub에 바로 보내거나 내보낸 파일을 읽습니다.

   ```bash
   pbpaste | gh secret set PFSENSE_RELEASE_SIGNING_KEY
   gh secret set PFSENSE_RELEASE_SIGNING_KEY < <file>
   ```

5. 비밀을 저장한 후 내보낸 개인 키 파일을 삭제합니다.

비밀이 없으면 패키지에 공개 키가 포함되지 않고 릴리스도 서명되지 않습니다. 키를 변경하려면 새 `ssh-ed25519 ...` 공개 키를 `release-signing.pub`에 추가하고, 기존 키가 아직 비밀인 상태에서 릴리스를 한 번 게시한 뒤 비밀을 새 키로 교체합니다.

서명 키를 잃으면 설치된 복사는 대체 키로 서명된 릴리스를 인증할 수 없습니다. 영향을 받은 각 설치에서 대체 공개 키가 담긴 패키지를 설치하려면 수동 `pkg add -f` 명령을 한 번 사용해야 합니다.

## VM에서 업데이트 엔드포인트 테스트 \{#test-update-endpoints-in-a-vm}

CLI는 제어된 VM 테스트 용도로만 두 가지 환경 변수를 받습니다.

- `IPV6_PREFIX_UPDATER_RELEASES_API`는 최신 릴리스 API URL을 대체합니다.
- `IPV6_PREFIX_UPDATER_DOWNLOAD_PREFIX`는 허용되는 릴리스 파일 URL 접두사를 대체합니다.

이 변수는 `/usr/local/sbin/ipv6-prefix-updater`만 읽으며, 패키지 구성에 저장되거나 WebGUI가 직접 읽는 일은 없습니다. 필요한 재정의는 모두 같은 CLI 호출에서 설정하십시오.

```shell
IPV6_PREFIX_UPDATER_RELEASES_API=http://192.0.2.10/latest.json \
IPV6_PREFIX_UPDATER_DOWNLOAD_PREFIX=http://192.0.2.10/releases/ \
/usr/local/sbin/ipv6-prefix-updater --check-updates
```

다운로드, SHA-256 체크섬, 릴리스 서명, 패키지 메타데이터 및 `pkg add -f` 전체 경로를 테스트하려면 `--check-updates` 대신 `--self-update`를 사용하십시오.

## 문서 사이트 \{#documentation-site}

`apps/docs`에서 `npm run check`를 실행하면 ESLint, 번역 트리 검사, 세 가지 타입 검사, 그리고 `.env` 파일, 프런트매터, 링크, 표, 용어집 링크, 타입 선언에 대한 Vitest 테스트 모음이 실행됩니다. `npm run build`는 모든 로캘을 빌드합니다.

각 로캘의 번역된 문서 페이지는 `apps/docs/i18n/<locale>/docusaurus-plugin-content-docs/current/`에 있으며 영어 페이지와 같은 구성을 따르므로, 영어 페이지가 바뀌면 함께 업데이트합니다. 인터페이스 텍스트(홈페이지, 내비게이션 바, 바닥글, 블로그, 사이드바 레이블)는 `scripts/locale-copies.json`과 패키지 번역을 읽는 `scripts/generate-locales.mjs`에서 생성됩니다. `npm run i18n`은 이 생성기를 먼저 실행하며, 생성기는 번역된 문서 페이지를 그대로 둡니다.

`.github/workflows/nova-publish-project.yml`은 릴리스가 게시되면 사이트를 빌드해 GitHub Pages에 배포합니다.
