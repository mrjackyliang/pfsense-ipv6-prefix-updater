pfSense IPv6 Prefix Updater를 검사, 스테이징, 패키징한 다음 패키지를 GitHub 릴리스에 게시합니다.

## 요구 사항 \{#requirements}

- **Node.js 22 또는 24** — 루트 및 워크스페이스 매니페스트는 `^22 || ^24`를 허용합니다.
- **PHP 또는 Docker** — PHP 테스트 모음은 로컬 `php`가 있으면 그것을 사용하고, 없으면 Docker로 `php:8.3-cli-alpine` 이미지를 사용합니다. `PHP_TEST_IMAGE`로 이미지를 재정의할 수 있습니다.
- **패키징용 FreeBSD** — `npm run deploy`는 FreeBSD에서만 실행되며, `PFSENSE_PORTS_DIR` 변수가 pfSense FreeBSD-ports 체크아웃을 가리켜야 합니다.

## 검사, 스테이징, 패키징 \{#check-stage-and-package}

저장소 루트에서 다음 명령을 실행합니다.

```bash
# Lint and type-check the scripts, run the PHP and Vitest suites, and validate the port.
npm run check --workspace pfsense-pkg-ipv6-prefix-updater

# Copy the port into packages/ipv6-prefix-updater/build/port with the workspace version.
npm run build --workspace pfsense-pkg-ipv6-prefix-updater

# Build the package on FreeBSD into packages/ipv6-prefix-updater/build/release.
PFSENSE_PORTS_DIR=/path/to/FreeBSD-ports npm run deploy --workspace pfsense-pkg-ipv6-prefix-updater
```

- 스테이징은 `port/Makefile.template`을 `build/port/Makefile`로 바꾸고 `packages/ipv6-prefix-updater/package.json`의 `version`을 기록합니다.
- 패키징은 스테이징된 포트를 ports 체크아웃의 `sysutils/pfSense-pkg-Ipv6PrefixUpdater`로 복사하고, `make package`를 실행한 뒤, 그 사본을 다시 제거합니다. 대상이 이미 있으면 멈춥니다.
- 그러면 `build/release`에 버전이 붙은 `.pkg`, `pfSense-pkg-Ipv6PrefixUpdater.pkg`라는 이름의 사본, 그리고 각각에 대해 해시만 담은 `.sha256` 파일이 생깁니다.

## 릴리스 워크플로 \{#release-workflow}

`.github/workflows/pfsense-ipv6-prefix-updater.yml`은 GitHub 릴리스가 게시될 때, 또는 기존 릴리스의 태그로 수동 실행할 때 실행됩니다.

1. Ubuntu 러너에서 포트를 검증하고 스테이징합니다.
2. `PFSENSE_FREEBSD_VERSION` 저장소 변수에 지정된 릴리스(설정되지 않았다면 `15`)의 FreeBSD VM을 시작합니다.
3. pfSense FreeBSD-ports 저장소의 `devel` 브랜치를 체크아웃하고 패키지 빌드를 실행합니다.
4. `build/release`를 7일간 보관되는 워크플로 아티팩트로 업로드하고, 같은 파일을 릴리스에 첨부해 기존 자산을 교체합니다.

`PFSENSE_FREEBSD_VERSION`은 대상 pfSense 릴리스의 FreeBSD 주 버전으로 설정하고, 다른 주 버전으로 빌드한 패키지는 게시하지 않는 것을 권장합니다. 설치 가이드의 `pkg add` 명령은 GitHub가 최신으로 표시한 릴리스에서 `pfSense-pkg-Ipv6PrefixUpdater.pkg`를 가져옵니다.

## 문서 사이트 \{#documentation-site}

`apps/docs`에서 `npm run check`를 실행하면 ESLint, 번역 트리 검사, 세 가지 타입 검사, 그리고 `.env` 파일, 프런트매터, 링크, 표, 용어집 링크, 타입 선언에 대한 Vitest 테스트 모음이 실행됩니다. `npm run build`는 모든 로캘을 빌드합니다.

각 로캘의 번역된 문서 페이지는 `apps/docs/i18n/<locale>/docusaurus-plugin-content-docs/current/`에 있으며 영어 페이지와 같은 구성을 따르므로, 영어 페이지가 바뀌면 함께 업데이트합니다. 인터페이스 텍스트(홈페이지, 내비게이션 바, 바닥글, 블로그, 사이드바 레이블)는 `scripts/locale-copies.json`과 패키지 번역을 읽는 `scripts/generate-locales.mjs`에서 생성됩니다. `npm run i18n`은 이 생성기를 먼저 실행하며, 생성기는 번역된 문서 페이지를 그대로 둡니다.

`.github/workflows/nova-publish-project.yml`은 릴리스가 게시되면 사이트를 빌드해 GitHub Pages에 배포합니다.
