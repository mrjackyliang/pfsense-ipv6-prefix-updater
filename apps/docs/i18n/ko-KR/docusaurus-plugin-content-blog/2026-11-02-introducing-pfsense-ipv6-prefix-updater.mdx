많은 ISP가 예고 없이 바뀔 수 있는 IPv6 접두사를 위임합니다. 접두사가 바뀌면 pfSense 별칭, 인터페이스, VPN 설정에서 이전 접두사에 속한 주소가 한꺼번에 낡은 값이 되고, 서비스에 원인을 찾기 어려운 장애가 생길 수 있습니다.

pfSense IPv6 Prefix Updater가 바로 제 해답입니다. 새 접두사를 따라가고 승인한 설정 영역의 주소를 업데이트하는 네이티브 pfSense 패키지입니다.

## 제가 이 패키지를 만든 이유 \{#why-i-built-it}

이 프로젝트는 `/root`에 설치되고 Cron 패키지 항목으로 실행되는 스크립트인 `update.php`로 시작했습니다. 이 스크립트는 pfSense가 새 접두사를 감지하고, 구성을 백업하고, 이전 주소를 다시 쓸 수 있다는 것을 입증했습니다.

하지만 설치와 업그레이드가 불안정했고, 스크립트는 구성 어디에서든 이전 접두사 텍스트를 바꿔 넣었습니다. 저는 수동 설치나 직접 만든 Cron 항목 없이도, 자신이 이해하는 필드만 변경하고 무엇을 했는지 보여 주는 후속 버전을 원했습니다.

## 패키지가 하는 일 \{#what-it-does}

패키지는 사용자가 고른 인터페이스를 감시합니다. 접두사가 바뀌면 다음과 같이 동작합니다.

- **호스트 부분 유지** — 접두사 비트만 바뀌므로 각 장치의 주소 접미사는 그대로입니다.
- **승인된 필드만 변경** — 별칭, 방화벽 규칙, DHCPv6 서버, WireGuard 같은 pfSense 그룹 열한 개가 켜진 상태로 시작하며, 필드 탭에서 그룹을 끄거나 개별 필드의 선택을 해제할 수 있습니다.
- **쓰기 전 백업** — 먼저 구성 백업을 Config History에 남긴 다음, 모든 변경을 한 번의 쓰기로 저장합니다.
- **결과 검증** — 저장된 값을 검사하고, 영향을 받는 서비스만 다시 로드한 뒤 값을 다시 검사합니다.

원격 VPN 네트워크와 피어는 [기타 설정](/docs/configure/configuration-scopes#other-settings)에서 직접 선택할 때만 바뀌며, 업데이트가 성공할 때마다 변경 알림이 선택적으로 전송됩니다.

## 설정 방법 \{#how-you-set-it-up}

**Services → IPv6 Prefix Updater** 아래의 설정 탭에서 감시할 인터페이스마다 ISP에 맞는 위임된 접두사 길이로 모니터링할 인터페이스 행을 추가한 뒤 저장합니다.

그런 다음 상태 탭에서 **지금 실행**을 선택합니다. 첫 실행은 기준선만 기록하므로 예약 업데이트를 켜기 전에 주소와 접두사를 확인하고 필드 탭을 검토할 수 있으며, 예약 업데이트는 기본적으로 pfSense가 관리하는 cron 항목에서 매시간 실행됩니다.

확인 결과 접두사가 같으면 아무것도 쓰지 않으며, **시험 실행**은 백업이나 쓰기 없이 확인을 실행합니다.

:::info

이 비공식 패키지는 GitHub 릴리스에서 `pkg`로 설치되며, Netgate가 검토하거나 지원하지 않습니다. 버전 1.x 릴리스에는 스크립트만 들어 있으므로, 최신 릴리스에 `.pkg` 파일이 없으면 `pkg add`가 찾을 수 없음(404) 오류로 실패합니다.

:::

## 스크립트에서 옮겨 오기 \{#moving-from-the-script}

`update.php`가 아직 Cron 패키지로 실행되고 있다면 그대로 둔 채 패키지를 설치합니다. 패키지는 [스크립트에서 마이그레이션](/docs/migrate-from-legacy)에서 설명하듯이 스크립트의 Cron 항목, 저장된 접두사, 백업을 패키지로 옮기고 이전 파일을 삭제합니다.

이 프로젝트를 처음 접한다면 [패키지 설치](/docs/installation)부터 시작하면 됩니다.
