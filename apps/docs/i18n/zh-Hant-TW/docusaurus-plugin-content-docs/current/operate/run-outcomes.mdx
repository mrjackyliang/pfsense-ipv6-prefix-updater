## 「目前狀態」與「上次執行」的差異 \{#current-state-versus-last-run}

**目前狀態** 只會在<Terminology title="初次檢查：記錄基準，不做任何改動" to="/docs/reference/terminology#run-outcomes">已初始化</Terminology>、**已接受** 與<Terminology title="前綴變了，所有已核准欄位都已更新" to="/docs/reference/terminology#run-outcomes">成功</Terminology>時改變。失敗的嘗試永遠不會成為下一次比較的依據，除非管理人員事後核對已儲存的值並明確接受目前作用中的前綴；**上次執行** 則會記錄表中任何結果的最近一次執行。

當另一個檢查持有<Terminology title="確保兩次檢查不會同時執行" to="/docs/reference/terminology#running-checks">執行鎖定</Terminology>，或執行在讀取<Terminology title="保存每個基準的檔案，重新安裝後依然保留" to="/docs/reference/terminology#running-checks">套件狀態</Terminology>之前就已停止（例如沒有任何監控介面具有<Terminology title="位於 2000::/3 內的公用 IPv6 位址，唯一會用到的類型" to="/docs/reference/terminology#addresses-and-prefixes">全域位址</Terminology>）時，**上次執行** 維持不變。這些執行會將原因留在<Terminology title="最近一次執行的輸出行，啟動後立即顯示" to="/docs/reference/terminology#running-checks">命令輸出</Terminology>與<Terminology title="pfSense 的一般記錄，每次執行都會留下內容" to="/docs/reference/terminology#notifications-and-logs">系統記錄</Terminology>中。

## 警告：沒有相符的欄位 \{#warning-no-matching-fields}

<Terminology title="前綴變了，但沒有已核准欄位使用舊前綴" to="/docs/reference/terminology#run-outcomes">警告</Terminology>表示前綴已變更，但沒有任何<Terminology title="允許套件改寫的設定" to="/docs/reference/terminology#fields-and-change-plans">已核准欄位</Terminology>屬於舊前綴。不會寫入任何內容，<Terminology title="記錄下來的起始前綴，變更以它為準" to="/docs/reference/terminology#baselines-and-transitions">基準</Terminology>也停留在舊前綴，因此下一次執行會再次檢查同一個<Terminology title="前綴變了，套件開始工作" to="/docs/reference/terminology#baselines-and-transitions">前綴變更</Terminology>。

每次<Terminology title="前綴變了，但沒有已核准欄位使用舊前綴" to="/docs/reference/terminology#run-outcomes">警告</Terminology>都會新增一則 <Terminology title="pfSense 自身通知清單中的提醒" to="/docs/reference/terminology#notifications-and-logs">WebGUI 通知</Terminology>，<Terminology title="預覽改動，但不寫入任何內容" to="/docs/reference/terminology#running-checks">試執行</Terminology>產生的警告也不例外。如果原因沒有排除，每次排程執行都會再新增一則通知。

常見原因：

- 包含這些位址的<Terminology title="一個開關管住一整類設定" to="/docs/reference/terminology#fields-and-change-plans">欄位群組</Terminology>已關閉，或這些欄位未勾選。
- 這些位址已在套件之外被變更。
- 這些位址位於[其他設定](/docs/configure/configuration-scopes#other-settings)群組中，此群組在您勾選這些位址之前會保持關閉。
- 先前的一次<Terminology title="執行在某個檢查或安全階段停止" to="/docs/reference/terminology#run-outcomes">失敗</Terminology>已儲存新值，但保留了舊的<Terminology title="記錄下來的起始前綴，變更以它為準" to="/docs/reference/terminology#baselines-and-transitions">基準</Terminology>。
- <Terminology title="ISP 前綴的大小，例如 /56，由你設定" to="/docs/reference/terminology#addresses-and-prefixes">委派前綴長度</Terminology>被[改得較短](/docs/configure/interface-and-prefix#changing-the-prefix-length)（網路範圍變寬），但前綴本身並未變更。

[疑難排解](/docs/operate/troubleshooting#warning-on-every-run)逐一說明了這些原因。

如果這些位址已經正確變更，請在核對已儲存的位址與受影響的服務後，使用 **狀態 → 動作 → 基準復原 → 接受目前前綴**。這會記錄一個 **已接受** 結果，既不掃描已核准欄位，也不變更防火牆設定；如果已核准欄位中仍包含舊前綴，請不要使用它。

## 儲存後的失敗 \{#failures-after-the-save}

如果在儲存之後的值檢查或<Terminology title="將變更後的設定套用到執行中的服務" to="/docs/reference/terminology#backups-and-service-reloads">服務重新載入</Terminology>中發生<Terminology title="執行在某個檢查或安全階段停止" to="/docs/reference/terminology#run-outcomes">失敗</Terminology>，新值仍會保持已儲存狀態。系統不會自動回復任何變更，<Terminology title="記錄下來的起始前綴，變更以它為準" to="/docs/reference/terminology#baselines-and-transitions">基準</Terminology>也停留在舊前綴。

這類執行的 **<Terminology title="每次寫入前一刻保存的設定副本" to="/docs/reference/terminology#backups-and-service-reloads">已建立設定備份</Terminology>** 顯示「是」。[備份與復原](/docs/operate/backups-and-recovery#after-a-failed-run)說明了如何還原後重試，或透過 **接受目前前綴** 保留已核對的已儲存值。

## 通知失敗 \{#notification-failures}

如果<Terminology title="位址更新後傳送的通知" to="/docs/reference/terminology#notifications-and-logs">變更通知</Terminology>無法傳送，結果仍為<Terminology title="前綴變了，所有已核准欄位都已更新" to="/docs/reference/terminology#run-outcomes">成功</Terminology>，<Terminology title="記錄下來的起始前綴，變更以它為準" to="/docs/reference/terminology#baselines-and-transitions">基準</Terminology>也照樣移到新前綴。「狀態」分頁不會顯示傳送狀態，<Terminology title="pfSense 的一般記錄，每次執行都會留下內容" to="/docs/reference/terminology#notifications-and-logs">系統記錄</Terminology>則會記錄 `設定已成功更新，但變更通知失敗。`

每種結果對應的欄位請參閱[狀態與動作](/docs/operate/status-and-actions)，各階段的順序請參閱[更新運作方式](/docs/safety/how-updates-work)。
