了解套件在變更設定之前採取的保護措施，以及哪些情況仍可能影響流量。

## 前綴變更時會發生什麼 \{#what-happens-on-a-prefix-change}

套件發現<Terminology title="前綴變了，套件開始工作" to="/docs/reference/terminology#baselines-and-transitions">前綴變更</Terminology>後，會依下列順序運作：

1. 讀取每個<Terminology title="透過其位址揭示目前前綴的介面" to="/docs/reference/terminology#interfaces-and-detection">監控介面</Terminology>的<Terminology title="位於 2000::/3 內的公用 IPv6 位址，唯一會用到的類型" to="/docs/reference/terminology#addresses-and-prefixes">全域位址</Terminology>並計算其前綴。
2. 將該前綴與<Terminology title="每次檢查用來比較的已存前綴" to="/docs/reference/terminology#baselines-and-transitions">上次成功前綴</Terminology>比較。
3. 找出仍在使用舊前綴的<Terminology title="允許套件改寫的設定" to="/docs/reference/terminology#fields-and-change-plans">已核准欄位</Terminology>，並建立完整的<Terminology title="在任何改動之前就列好的全部改寫" to="/docs/reference/terminology#fields-and-change-plans">變更計畫</Terminology>。
4. 確認 pfSense 能重新載入每個受影響的服務，且規劃中的欄位自讀取後都沒有被更動。
5. 儲存<Terminology title="每次寫入前一刻保存的設定副本" to="/docs/reference/terminology#backups-and-service-reloads">設定備份</Terminology>。
6. 套用所有變更，並只儲存一次設定。
7. 檢查已儲存的值，只重新載入受影響的服務，然後再次檢查這些值。
8. 將<Terminology title="記錄下來的起始前綴，變更以它為準" to="/docs/reference/terminology#baselines-and-transitions">基準</Terminology>移到新前綴，記錄結果，並在已開啟時傳送<Terminology title="位址更新後傳送的通知" to="/docs/reference/terminology#notifications-and-logs">變更通知</Terminology>。

如果備份之前的任何一個步驟失敗，設定都會維持原狀。

## 哪些情況絕不會寫入 \{#what-never-causes-a-write}

出現以下結果時，套件不會變更設定：

- <Terminology title="初次檢查：記錄基準，不做任何改動" to="/docs/reference/terminology#run-outcomes">已初始化</Terminology>與<Terminology title="顯示將會記錄之基準的試執行" to="/docs/reference/terminology#run-outcomes">初始化預覽</Terminology>。
- <Terminology title="前綴與上次相同，無需任何動作" to="/docs/reference/terminology#run-outcomes">無變更</Terminology>。
- <Terminology title="預覽改動，但不寫入任何內容" to="/docs/reference/terminology#running-checks">試執行</Terminology>。
- <Terminology title="前綴變了，但沒有已核准欄位使用舊前綴" to="/docs/reference/terminology#run-outcomes">警告</Terminology>。
- 在備份之前就停止的<Terminology title="執行在某個檢查或安全階段停止" to="/docs/reference/terminology#run-outcomes">失敗</Terminology>。

## 仍可能影響流量的情況 \{#what-can-still-affect-traffic}

- **<Terminology title="將變更後的設定套用到執行中的服務" to="/docs/reference/terminology#backups-and-service-reloads">服務重新載入</Terminology>**：變更靜態介面或<Terminology title="介面上的額外位址，例如 CARP VIP" to="/docs/reference/terminology#pfsense-features">虛擬 IP</Terminology> 會重新載入所有介面，接著重新載入防火牆篩選器。變更閘道與靜態路由會重新載入路由與篩選器，變更 OpenVPN 會重新載入所有 OpenVPN 執行個體；DHCPv6、路由器通告與 DNS 的變更則會重新啟動這些服務。
- **儲存後的失敗**：如果儲存後的檢查或<Terminology title="將變更後的設定套用到執行中的服務" to="/docs/reference/terminology#backups-and-service-reloads">服務重新載入</Terminology>失敗，新值仍會保持已儲存狀態，且不會回復任何變更。如[執行結果](/docs/operate/run-outcomes#failures-after-the-save)所述，<Terminology title="記錄下來的起始前綴，變更以它為準" to="/docs/reference/terminology#baselines-and-transitions">基準</Terminology>仍停留在舊前綴。
- **等待您勾選的值**：閘道、靜態路由、DNS 網域覆寫，以及[其他設定](/docs/configure/configuration-scopes#other-settings)中的其他值，在您勾選之前都會保留舊前綴；位於關閉群組中的欄位也是如此。

## 復原途徑 \{#recovery-path}

每次寫入之前的設定都在<Terminology title="pfSense 保存、可供還原的設定修訂" to="/docs/reference/terminology#backups-and-service-reloads">設定歷程</Terminology>中留有一份<Terminology title="每次寫入前一刻保存的設定副本" to="/docs/reference/terminology#backups-and-service-reloads">設定備份</Terminology>。以套件命名的修訂版本保存的是更新後的設定，因此要還原哪個修訂版本，請參閱[備份與復原](/docs/operate/backups-and-recovery)。

建議同時保留您平常存放在裝置以外的 pfSense 備份。

## 您可以核對的內容 \{#what-you-can-verify}

「狀態」分頁會顯示最近一次執行的<Terminology title="每次執行讀取前綴所用的即時位址" to="/docs/reference/terminology#interfaces-and-detection">來源位址</Terminology>、<Terminology title="目前看到的前綴，會與上一次比較" to="/docs/reference/terminology#interfaces-and-detection">觀察到的前綴</Terminology>、結果、已變更欄位數、備份結果、<Terminology title="將變更後的設定套用到執行中的服務" to="/docs/reference/terminology#backups-and-service-reloads">已重新載入的服務</Terminology>、時間與摘要。<Terminology title="自己發起的檢查，即使排程已關閉也能執行" to="/docs/reference/terminology#running-checks">手動執行</Terminology>結束後，<Terminology title="最近一次執行的輸出行，啟動後立即顯示" to="/docs/reference/terminology#running-checks">命令輸出</Terminology>會立即顯示相同的詳細資訊。
