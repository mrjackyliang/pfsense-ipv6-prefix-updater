檢查、暫存並封裝 IPv6 Prefix Updater for pfSense，然後將套件發布到 GitHub 發行版本。

## 需求 \{#requirements}

- **Node.js 22、24 或 26** — 根目錄與工作區的資訊清單檔都接受 `^22 || ^24 || ^26`。
- **PHP 或 Docker** — PHP 測試套件在本機有 `php` 時會直接使用，否則透過 Docker 使用 `php:8.3-cli-alpine` 映像檔。`PHP_TEST_IMAGE` 可覆寫所用的映像檔。
- **用於封裝的 FreeBSD** — `npm run deploy` 只能在 FreeBSD 上執行，且需要將 `PFSENSE_PORTS_DIR` 指向 pfSense FreeBSD-ports 儲存庫的本機簽出副本。

## 檢查、暫存與封裝 \{#check-stage-and-package}

在儲存庫根目錄中執行下列命令：

```bash
# Lint and type-check the scripts, run the PHP and Vitest suites, and validate the port.
npm run check --workspace pfsense-pkg-ipv6-prefix-updater

# Copy the port into packages/ipv6-prefix-updater/build/port with the workspace version.
npm run build --workspace pfsense-pkg-ipv6-prefix-updater

# Build the package on FreeBSD into packages/ipv6-prefix-updater/build/release.
PFSENSE_PORTS_DIR=/path/to/FreeBSD-ports npm run deploy --workspace pfsense-pkg-ipv6-prefix-updater
```

- 暫存步驟會將 `port/Makefile.template` 轉換為 `build/port/Makefile`，並寫入 `packages/ipv6-prefix-updater/package.json` 中的 `version`。
- 封裝步驟會將暫存好的 port 複製到 ports 簽出副本中的 `sysutils/pfSense-pkg-Ipv6PrefixUpdater`，執行 `make package`，然後再移除該副本。如果目的地已經存在，它會停止。
- 之後，`build/release` 中會包含含版本號碼的 `.pkg`、一個名為 `pfSense-pkg-Ipv6PrefixUpdater.pkg` 的副本，以及分別對應兩者、只含雜湊值的 `.sha256` 檔案。

## 發行工作流程 \{#release-workflow}

Nova 產生的 `.github/workflows/nova-publish-project.yml` 中的 `publish-pfsense-packages-ipv6-prefix-updater` 作業會在發布工作流程中執行：

1. 在 Ubuntu 執行器上驗證並暫存 port。
2. 設定了 `PFSENSE_RELEASE_SIGNING_KEY` 機密時，從 `PFSENSE_RELEASE_SIGNING_KEY` 衍生公開金鑰，並將其附加到已暫存 port 的 `usr/local/share/pfSense-pkg-Ipv6PrefixUpdater/release-signing.pub`。
3. 使用已設定的 pfSense FreeBSD-ports 簽出副本在 FreeBSD 上建置套件。
4. 設定了該機密時，使用 `ssh-keygen -Y sign -n pfSense-pkg-Ipv6PrefixUpdater` 將每個 `.pkg` 簽署為 `<file>.pkg.sig`。
5. 將套件、總和檢查碼與簽署上傳為保留 7 天的工作流程成品，並將相同檔案附加至發行版本。

由於套件不含編譯程式碼，建置會將它標示為適用於任何 FreeBSD 版本，因此一個套件即可安裝在所有受支援的 pfSense 版本上。`PFSENSE_FREEBSD_VERSION` 僅選擇建置虛擬機器使用的 FreeBSD 版本。安裝指南中的 `pkg add` 命令會從 GitHub 標示為最新（latest）的發行版本取得 `pfSense-pkg-Ipv6PrefixUpdater.pkg`。

## 發行簽署 \{#release-signing}

簽署唯一需要的設定是儲存庫機密 `PFSENSE_RELEASE_SIGNING_KEY`，其中包含未加密的 OpenSSH Ed25519 私密金鑰。

1. 在 1Password 中選擇 **New Item → SSH Key → Generate a New Key → Ed25519**。
2. 在私密金鑰欄位選擇 **Export**，選取 OpenSSH 格式，並且不要設定密碼。
3. 儲存機密前檢查剪貼簿：

   ```bash
   pbpaste | head -1
   ```

   命令應顯示 `-----BEGIN OPENSSH PRIVATE KEY-----`。

4. 將剪貼簿直接傳送到 GitHub，或讀取已匯出的檔案：

   ```bash
   pbpaste | gh secret set PFSENSE_RELEASE_SIGNING_KEY
   gh secret set PFSENSE_RELEASE_SIGNING_KEY < <file>
   ```

5. 儲存機密後，刪除已匯出的私密金鑰檔案。

如果沒有該機密，套件不會帶有公開金鑰，發行版本也不會簽署。更換金鑰時，將新的 `ssh-ed25519 ...` 公開金鑰加入 `release-signing.pub`，在舊金鑰仍是機密時發布一個發行版本，然後用新金鑰取代該機密。

如果簽署金鑰遺失，已安裝的副本無法驗證使用替代金鑰簽署的發行版本。每個受影響的安裝都必須手動執行一次 `pkg add -f`，以安裝帶有新公開金鑰的套件。

## 在虛擬機器中測試更新端點 \{#test-update-endpoints-in-a-vm}

CLI 接受兩個環境變數，僅用於受控的虛擬機器測試：

- `IPV6_PREFIX_UPDATER_RELEASES_API` 取代最新發行版本的 API URL。
- `IPV6_PREFIX_UPDATER_DOWNLOAD_PREFIX` 取代允許的資源 URL 前綴。

它們只由 `/usr/local/sbin/ipv6-prefix-updater` 讀取，絕不會儲存在套件設定中，也不會由 WebGUI 直接讀取。請在同一次 CLI 呼叫中設定所有需要的覆寫值：

```shell
IPV6_PREFIX_UPDATER_RELEASES_API=http://192.0.2.10/latest.json \
IPV6_PREFIX_UPDATER_DOWNLOAD_PREFIX=http://192.0.2.10/releases/ \
/usr/local/sbin/ipv6-prefix-updater --check-updates
```

使用 `--self-update` 取代 `--check-updates`，即可針對測試發行版本走完完整的下載、SHA-256 總和檢查碼、發行簽署、套件中繼資料與 `pkg add -f` 流程。

## 文件網站 \{#documentation-site}

在 `apps/docs` 中，`npm run check` 會執行 ESLint、翻譯樹檢查、三項型別檢查，以及針對 `.env` 檔案、frontmatter、連結、表格、術語連結與型別宣告的 Vitest 測試套件。`npm run build` 會建置所有語系。

各語系已翻譯的文件頁面位於 `apps/docs/i18n/<locale>/docusaurus-plugin-content-docs/current/`，並與英文頁面一一對應，因此英文頁面有變更時，也需要同步更新這些頁面。介面文字（首頁、導覽列、頁尾、網誌與側邊欄標籤）來自 `scripts/generate-locales.mjs`，它會讀取 `scripts/locale-copies.json` 與套件翻譯。`npm run i18n` 會先執行該產生器，並且會保留已翻譯的文件頁面。

`.github/workflows/nova-publish-project.yml` 會在發行版本發布時建置網站，並將其部署到 GitHub Pages。
