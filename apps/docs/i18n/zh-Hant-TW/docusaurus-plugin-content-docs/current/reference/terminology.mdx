說明「設定」「狀態」與「欄位」分頁以及本指南中有關位址、前綴、執行與 pfSense 功能的術語。

## 委派前綴 \{#delegated-prefix}

ISP 路由到防火牆的 IPv6 網路，通常透過 DHCPv6 前綴委派（Prefix Delegation）取得。套件會跟隨這個前綴，但從不要求、續約或變更它。

## 前綴長度 \{#prefix-length}

識別網路的開頭位元數，以斜線加數字表示，例如 `/56`。設定值上的 CIDR 尾碼（例如 `/64`）在套件改寫位址時會維持原樣。

## 委派前綴長度 \{#delegated-prefix-length}

**委派前綴長度** 設定，保存 ISP 委派的前綴大小，範圍為 `/48` 到 `/64`。初始值為 `/56`，套件從不自動偵測；在基準已存在後變更它，會視為一次前綴變更。

## 全域單播位址 \{#global-unicast-address}

位於 `2000::/3` 內的 IPv6 位址，也是套件唯一會讀取為來源或進行改寫的位址類型。鏈路本機、唯一本機（`fc00::/7`）、多播、迴路、未指定與 IPv4 對映位址都不會被接受為來源，在設定中也維持不變。

## 鏈路本機位址 \{#link-local-address}

僅在單一網路鏈路上有效、以 `fe80` 開頭的位址。套件從不改用這種位址，因此介面沒有全域位址時，執行會失敗。

## 主機部分 \{#host-portion}

位址中位於委派前綴長度之後的所有位元，也稱為主機位元。套件會將這些位元原封不動地複製到新位址中，即使邊界落在某個十六進位數字內部也一樣。

## 標準形式 \{#canonical-form}

IPv6 位址標準的小寫、最短寫法，例如 `2001:0DB8:0:0::1` 的標準形式為 `2001:db8::1`。套件以這種形式比較位址，也以這種形式寫入改寫後的值，因此某個值看起來可能不同，但代表的是同一個位址。

## 追蹤介面 \{#tracked-interface}

透過 **Track Interface**（追蹤介面）設定類型，從另一個介面的委派前綴取得 IPv6 位址的 pfSense 介面。當 WAN 沒有全域位址時，它通常就是適當的監控介面；由於其位址由 pfSense 產生，套件從不改寫它。

## 監控介面 \{#monitored-interface}

**監控介面** 設定中的一列，指定一個全域位址能反映目前前綴的介面。「狀態」分頁會顯示該介面的描述，後接 pfSense 對該介面的內部名稱，例如 `LAN (lan)`。

新增介面後，下一次執行會為它記錄新的基準，而不是比較前綴。

## 來源位址 \{#source-address}

pfSense 為監控介面回報的主要全域位址，每次執行都會重新讀取。「狀態」分頁會以標準形式將其顯示為 **觀察到的來源位址** 與 **上次成功來源位址**。

## 觀察到的前綴 \{#observed-prefix}

依來源位址與委派前綴長度計算出的網路，在「狀態」分頁中連同其長度一起顯示。每次執行都會將它與上次成功前綴進行比較。

## 基準 \{#baseline}

套件記錄為起點的前綴與來源位址，記錄時不會變更設定。每個監控介面第一次執行時、套件狀態遺失時、管理人員明確接受目前作用中的前綴時，以及遷移期間依據舊版更新器已儲存的前綴，都會記錄基準。

## 上次成功前綴 \{#last-successful-prefix}

已儲存的前綴與長度，下一次檢查會與之比較。只有「已初始化」「已接受」與「成功」這三種結果會變更它，其他結果都會讓它維持原樣。

## 前綴變更 \{#prefix-transition}

上次成功前綴與觀察到的前綴之間的差異，包括網路相同但前綴長度不同的情況。只有發生前綴變更時，套件才會掃描設定、規劃變更並寫入。

## 欄位群組 \{#field-group}

「欄位」分頁上共用一個開關的一組欄位。十一個 pfSense 群組為靜態介面、虛擬 IP 位址、別名、防火牆規則、NAT 與 NPt、DHCPv6 伺服器、路由器通告、DNS 主機覆寫、IPsec、OpenVPN 與 WireGuard，預設為開啟。其他每個套件的設定各有一個預設關閉的專屬群組，其餘所有值則屬於同樣預設關閉的「其他設定」群組。開啟的群組涵蓋該類型的所有欄位，包括日後新增的欄位。

## 已核准欄位 \{#approved-field}

允許套件改寫的確切設定欄位：開啟的群組中未被取消勾選的欄位，或關閉的群組中已勾選的欄位。已核准欄位以外的值絕不會被變更。

## 欄位例外 \{#field-exception}

在「欄位」分頁上勾選狀態與所屬群組開關不一致的單一欄位：開啟的群組中被取消勾選的欄位，或關閉的群組中被勾選的欄位。每個例外都以其項目命名（例如防火牆規則的追蹤 ID），而不是以清單位置命名。

## 變更計畫 \{#change-plan}

將要變更的已核准欄位完整清單，包含每個欄位的舊值、新值以及需要重新載入的服務。套件會在變更任何內容之前建立完整的計畫。

## 排程更新 \{#scheduled-updates}

由 **啟用排程更新**（預設關閉）與 **排程**（預設為每小時）控制的自動檢查。儲存設定時會新增或移除一個由 pfSense 管理的 cron 項目，因此不需要 Cron 套件。

## 手動執行 \{#manual-run}

在「狀態」分頁中透過 **立即執行** 或 **試執行** 啟動的檢查。即使排程更新已關閉，它也會執行。

## 試執行 \{#dry-run}

透過 **試執行** 啟動的預覽，從不建立備份，也從不寫入設定。如果它發現了前綴變更且有欄位需要變更，結果為 **試執行**，並列出規劃變更的欄位數。

前綴未變更時，試執行會回報「無變更」，且不會掃描設定。

## 命令輸出 \{#command-output}

執行「立即執行」「試執行」或「接受目前前綴」後，出現在 **命令輸出** 下的唯讀 **最新執行** 文字方塊。它會顯示這次執行從 `狀態` 到 `摘要` 的各行內容，在試執行或成功之後還會接著顯示 `欄位變更`；動作失敗或另一個執行持有鎖定時，則只顯示一行。

## 執行鎖定 \{#run-lock}

確保同一時間只有一個檢查執行的鎖定。第二個檢查會直接結束而不讀取設定；正在執行的檢查一結束，鎖定就會釋放。

## 套件狀態 \{#package-state}

檔案 `/cf/conf/ipv6-prefix-updater/state.json`，套件在 pfSense 設定之外用它保存每個基準與最近一次執行。只有 root 可以讀取它；它在重新開機、啟用 RAM 磁碟與移除套件後都會保留，因此重新安裝後每個基準依然存在。

## 已初始化 \{#initialized}

記錄新基準的執行所得到的結果。它不會建立備份、變更設定或傳送通知。

## 初始化預覽 \{#initialization-preview}

在尚無基準時進行試執行所得到的結果。它會顯示正常執行將記錄的基準，但不會實際記錄。

## 無變更 \{#no-change}

觀察到的前綴及其長度與上次成功前綴相同時的結果，也稱為無作業執行。此類執行不會掃描設定、建立備份、重新載入服務或傳送通知。

## 警告 \{#warning}

發現了前綴變更，但沒有已核准欄位屬於舊前綴時的結果。不會寫入任何內容，基準維持原處，每次警告都會新增一則 WebGUI 通知。

## 已接受 \{#accepted}

管理人員選取 **接受目前前綴** 並確認已儲存的位址已在使用目前作用中的前綴後的結果。套件會移動基準，但不會掃描已核准欄位、建立備份、寫入設定，也不會重新載入服務。

## 成功 \{#success}

備份、單次設定寫入、服務重新載入與值檢查全部完成後的結果。基準移到新前綴；如果已開啟變更通知，還會傳送通知。

## 失敗 \{#failure}

檢查或安全階段中止執行時的結果。如果在設定儲存之後才停止，新值會保持已儲存狀態，基準則停留在舊前綴。

## 已停用 \{#disabled}

在 **啟用排程更新** 關閉時執行的排程檢查所得到的結果。它會在讀取任何介面或套件狀態之前停止，而且只會出現在命令本身的輸出中。

## 變更通知 \{#change-notification}

勾選 **傳送變更通知**（預設已勾選）時，在「成功」之後傳送的訊息。它會傳送到 pfSense 中設定的通知管道，同時也會以 WebGUI 通知的形式出現。

## 通知管道 \{#notification-channels}

在 **System → Advanced → Notifications**（系統 → 進階 → 通知）中設定的遠端警示服務，例如電子郵件。變更通知使用這些管道，而警告與失敗通知只會保留在本機。

## WebGUI 通知 \{#webgui-notice}

pfSense WebGUI 通知清單中的一則警示，連結到套件的「狀態」分頁；從舊版更新器遷移後則連結到「清理」分頁。即使未勾選 **傳送變更通知**，警告與失敗結果也一定會新增一則。

## 系統記錄 \{#system-log}

位於 **Status → System Logs → System → General**（狀態 → 系統記錄 → 系統 → 一般）下的 pfSense 一般記錄。套件寫入的每一行都以 `IPv6 Prefix Updater:` 開頭。

## 設定備份 \{#configuration-backup}

使用 pfSense 備份功能製作的、寫入之前的設定副本，同時也會保存在 **備份** 分頁中。套件在每次需要寫入的執行中、變更任何欄位之前都會建立一份，不寫入的執行則不會建立。

## 設定歷程 \{#config-history}

**Diagnostics → Backup & Restore → Config History**（診斷 → 備份與還原 → 設定歷程）下已儲存設定修訂版本的清單。描述為 `IPv6 前綴更新器為介面 ... 變更了 ...` 的修訂版本保存的是更新後的設定，因此應該還原的是在它之前儲存的修訂版本。

## 服務重新載入 \{#service-reload}

將變更後的設定套用到執行中服務的 pfSense 動作。套件只會重新載入欄位有變更的服務，並在 **已重新載入的服務** 下列出它們。

## 虛擬 IP \{#virtual-ip}

在 **Firewall → Virtual IPs**（防火牆 → 虛擬 IP）中指派給介面的額外位址。「虛擬 IP 位址」群組只會更新 CARP 與 IP Alias 類型的項目。

## IPsec 階段 2 \{#ipsec-phase-2}

定義通道本機網路與遠端網路的 IPsec 項目（Phase 2）。IPsec 群組涵蓋 Tunnel IPv6 與 Routed (VTI) 模式項目的本機端，遠端則屬於「其他設定」群組。

## 用戶端特定覆寫 \{#client-specific-override}

位於 **VPN → OpenVPN → Client Specific Overrides**（VPN → OpenVPN → 用戶端特定覆寫）下、為單一用戶端設定選項的 OpenVPN 項目。套件可以更新其 IPv6 通道網路與 IPv6 本機網路。

## WireGuard 通道位址 \{#wireguard-tunnel-address}

在 pfSense 上指派給 WireGuard 通道的介面位址。更新它需要 WireGuard 套件，對等端的允許 IP 與端點屬於「其他設定」群組。

## 舊版更新器 \{#legacy-updater}

本專案的 1.x 版，也就是安裝在 `/root` 中、由 Cron 套件項目執行的 `update.php` 指令碼。它會取代設定中任何位置出現的舊前綴文字。

## 非官方套件 \{#unofficial-package}

透過 `pkg add` 從 GitHub 而非 Netgate 套件庫安裝的套件。Netgate 不會審查或支援它，其更新也需要您自行安裝。
