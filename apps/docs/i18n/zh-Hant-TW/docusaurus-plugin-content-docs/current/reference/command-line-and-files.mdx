在 shell 中執行套件命令，並找出它使用的檔案、記錄與通知。

## 用法 \{#usage}

```text
用法：ipv6-prefix-updater [--manual] [--dry-run] [--accept-current-prefix [--interface=NAME]] [--migrate-legacy]
更新選項：--check-updates [--no-notice]、--self-update。
```

由 pfSense 管理的前綴檢查 cron 項目會以 `root` 身分不帶選項執行該命令，另一個獨立的發行版本檢查項目則以 `--check-updates` 執行它。每次檢查之前，它也會將<Terminology title="1.x 版：由 Cron 套件執行的 update.php 指令碼" to="/docs/reference/terminology#package-origins">舊版更新器</Terminology>的所有遺留內容遷移到套件中。「狀態」分頁在 **立即執行** 時使用 `--manual`，在 **<Terminology title="預覽改動，但不寫入任何內容" to="/docs/reference/terminology#running-checks">試執行</Terminology>** 時使用 `--dry-run`，在基準復原時使用 `--accept-current-prefix`；「清理」分頁則使用 `--migrate-legacy`。

不帶選項時，該命令的行為與排程檢查相同；**<Terminology title="依排程自動檢查，啟用前一直關閉" to="/docs/reference/terminology#running-checks">啟用排程更新</Terminology>** 關閉時會回報<Terminology title="因排程更新已關閉而略過的排程檢查" to="/docs/reference/terminology#run-outcomes">已停用</Terminology>。

## 選項 \{#options}

| 參數                        | 說明                                                                                                                                                                     |
|---------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `--manual`                | 即使<Terminology title="依排程自動檢查，啟用前一直關閉" to="/docs/reference/terminology#running-checks">排程更新</Terminology>已關閉也會執行。                                                      |
| `--dry-run`               | 只預覽，不備份也不寫入，並隱含 `--manual`。                                                                                                                                            |
| `--accept-current-prefix` | 將目前作用中的來源位址、前綴與長度記錄為基準，不會掃描已核准欄位、建立備份、寫入設定或重新載入服務。它隱含 `--manual`，且不能與 `--dry-run` 同時使用。                                                                                |
| `--interface=NAME`        | 將 `--accept-current-prefix` 限定於一個監控介面，以其內部名稱（例如 `lan`）指定。不使用此選項時，所有具有位址的監控介面都會被接受。                                                                                     |
| `--migrate-legacy`        | 立即將<Terminology title="1.x 版：由 Cron 套件執行的 update.php 指令碼" to="/docs/reference/terminology#package-origins">舊版更新器</Terminology>遷移到套件中並列印每個步驟，不會執行前綴檢查。遷移回報警告時會以 `2` 結束。 |
| `--check-updates`         | 在 GitHub 上檢查最新的套件發行版本，並將結果儲存到 `/cf/conf/ipv6-prefix-updater/updates.json`。[更新](/docs/reference/updates)說明了此檢查。                                                         |
| `--no-notice`             | 讓 `--check-updates` 不建立更新通知，並將最新版本記錄為已通知。僅可與 `--check-updates` 一起使用。                                                                                                   |
| `--self-update`           | 下載、驗證並安裝最新的發行版本，並將進度記錄到 `/cf/conf/ipv6-prefix-updater/update-status.json`。                                                                                             |
| `--help`                  | 列印用法說明行與更新選項行，並以 `0` 結束。這兩行都不會列出 `--help` 本身。                                                                                                                          |

任何其他選項都會向標準錯誤輸出 `未知選項：<option>`，並以 `64` 結束。將 `--accept-current-prefix` 與 `--dry-run` 一起使用同樣會以 `64` 結束；將 `--check-updates` 與 `--self-update` 一起使用，或將兩者之一與任何前綴選項一起使用，也是如此。未與 `--check-updates` 一起使用 `--no-notice` 時同樣會以 `64` 結束。

## 輸出 \{#output}

監控一個介面的執行完成後，會在標準輸出列印九行；在<Terminology title="預覽改動，但不寫入任何內容" to="/docs/reference/terminology#running-checks">試執行</Terminology>或<Terminology title="前綴變了，所有已核准欄位都已更新" to="/docs/reference/terminology#run-outcomes">成功</Terminology>之後，還會接著列出欄位變更：

```text
狀態: 成功
介面: lan
觀察到的來源位址: 2001:db8:abcd:88aa::1
先前前綴: 2001:db8:abcd:7800::
目前前綴: 2001:db8:abcd:8800::/56
計畫或已變更欄位: 1
設定備份: 已建立
已重新載入的服務: 防火牆篩選器
摘要: 已在介面 lan 將 1 個已核准欄位從 2001:db8:abcd:7800::/56 更新為 2001:db8:abcd:8800::/56。
欄位變更:
- aliases/alias/0/address: 2001:db8:abcd:78aa::10 → 2001:db8:abcd:88aa::10
```

- `先前前綴`不含長度；在<Terminology title="初次檢查：記錄基準，不做任何改動" to="/docs/reference/terminology#run-outcomes">已初始化</Terminology>或<Terminology title="顯示將會記錄之基準的試執行" to="/docs/reference/terminology#run-outcomes">初始化預覽</Terminology>之後，它會顯示為 `無法使用`。
- `已重新載入的服務`會列出各服務的狀態標籤，沒有時則顯示 `無`。<Terminology title="預覽改動，但不寫入任何內容" to="/docs/reference/terminology#running-checks">試執行</Terminology>之後，它列出的是將會重新載入的服務。
- `欄位變更`中每個被取代的位址各占一行，格式為 `- <path>: <old> → <new>`，最多列出 200 個欄位。
- 如果執行重新套用了其他套件的設定，或略過了已不存在的已勾選欄位，每一項都會接著輸出一行，措辭與「狀態」分頁上相同。
- 當另一個檢查持有<Terminology title="確保兩次檢查不會同時執行" to="/docs/reference/terminology#running-checks">執行鎖定</Terminology>時，唯一的輸出是 `另一個執行程序持有套件鎖定；此次呼叫未讀取設定便已結束。`
- 監控多個介面時，輸出會以整體的 `狀態`、`摘要`、套件與略過欄位的各行開頭，接著是每個介面各自的各行內容，各組之間以空白行分隔。
- 如果檢查之前進行了<Terminology title="1.x 版：由 Cron 套件執行的 update.php 指令碼" to="/docs/reference/terminology#package-origins">舊版更新器</Terminology>遷移，會先列印遷移的各個步驟。
- 標籤與訊息會依照 pfSense 的語言設定顯示。

## 套件狀態格式 \{#package-state-format}

| 鍵                     | 說明                                                                                                                                                                                                                                                                                                                                                                            |
|-----------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `schema_version`      | 一律為 `1`。                                                                                                                                                                                                                                                                                                                                                                      |
| `targets.<interface>` | 每個監控介面一個<Terminology title="記錄下來的起始前綴，變更以它為準" to="/docs/reference/terminology#baselines-and-transitions">基準</Terminology>，以介面的內部名稱為鍵，包含 `interface`、`source_address`、`prefix`、`prefix_length` 與 `updated_at`。從<Terminology title="1.x 版：由 Cron 套件執行的 update.php 指令碼" to="/docs/reference/terminology#package-origins">舊版更新器</Terminology>接手的基準還會將 `source` 設為 `legacy_cache`。 |
| `last_run`            | 最近記錄的一次執行，包含 `status`、`timestamp`、`interface`、`observed_address`、`previous_prefix`、`current_prefix`、`current_prefix_length`、`change_count`、`backup_created`、`services`、`message`、`message_key` 與 `message_arguments`。                                                                                                                                                         |
| `legacy_migration`    | 在<Terminology title="1.x 版：由 Cron 套件執行的 update.php 指令碼" to="/docs/reference/terminology#package-origins">舊版更新器</Terminology>遷移之後出現，包含 `status`、`steps`、`warnings` 與 `recorded_at`。「清理」分頁會顯示它。                                                                                                                                                                                 |

- `status` 的值為 `initialized`、`initialization_preview`、`no_change`、`dry_run`、`warning`、`accepted`、`success` 或 `failure` 之一。
- <Terminology title="前綴變了，所有已核准欄位都已更新" to="/docs/reference/terminology#run-outcomes">成功</Terminology>之後，如果通知已關閉，`last_run.notification` 為 `disabled`；嘗試傳送後則為 `sent` 或 `failed`。
- <Terminology title="預覽改動，但不寫入任何內容" to="/docs/reference/terminology#running-checks">試執行</Terminology>或<Terminology title="前綴變了，所有已核准欄位都已更新" to="/docs/reference/terminology#run-outcomes">成功</Terminology>之後，每筆結果還會包含 `changes`，列出最多 200 個欄位的 `path` 與 `replacements`，其中每個取代項目都是一組舊位址與新位址。
- `package_reapply` 會列出這次執行重新套用了其設定的每個套件的 `section`、`package`、`status` 與 `error`，`skipped_fields` 則列出已不存在的已勾選欄位。兩者都只會在不為空時出現。
- 監控多個介面時，`last_run` 會保存總計以及一個 `targets` 清單，其中每個介面各有一筆結果。
- 時間戳記採用 UTC 的 ISO 8601 格式。如果檔案無法解析，或其結構版本不同，每次執行都會停止，並顯示 `IPv6 前綴更新器狀態無效或不受支援。`

## 設定的儲存位置 \{#settings-storage}

設定儲存在 pfSense 設定中的 `installedpackages/ipv6prefixupdater/config/0`。

| 鍵                             | 說明                                                                                                                          |
|-------------------------------|-----------------------------------------------------------------------------------------------------------------------------|
| `enabled`                     | **<Terminology title="依排程自動檢查，啟用前一直關閉" to="/docs/reference/terminology#running-checks">啟用排程更新</Terminology>**，勾選時為 `on`。    |
| `row`                         | **監控介面**，一份清單，每一列包含一個 `interface`（介面鍵，例如 `lan`）與一個 `prefix_length`（`48` 到 `64`）。                                            |
| `update_frequency`            | **排程**，值為 `every_fifteen_minutes`、`hourly`、`every_six_hours` 或 `daily` 之一。                                                  |
| `notifications`               | **<Terminology title="位址更新後傳送的通知" to="/docs/reference/terminology#notifications-and-logs">傳送變更通知</Terminology>**，勾選時為 `on`。 |
| `update_check_frequency`      | **更新檢查**，值為 `daily`、`weekly`、`monthly` 或 `never` 之一。                                                                        |
| `update_remote_notifications` | **遠端通知**，勾選時為 `on`。                                                                                                         |

固定的發行版本檢查排程儲存在設定記錄旁的 `installedpackages/ipv6prefixupdater/update_schedule`，其中 `minute` 為 0 到 59，`hour` 為 0 到 23，`weekday` 為 0 到 6，`monthday` 為 1 到 28。缺少、格式錯誤或超出範圍的值會重新產生並儲存。

### 欄位選取 \{#field-selection}

「欄位」分頁上的選擇儲存在設定記錄旁的 `installedpackages/ipv6prefixupdater/fields`，因此儲存「設定」分頁（會取代 `config/0`）絕不會清除它們。

| 鍵                      | 說明                                                                 |
|------------------------|--------------------------------------------------------------------|
| `schema`               | 一律為 `1`。它表示這是從「欄位」分頁儲存的選取，即使是空的選取也一樣。                              |
| `enabled_groups/item`  | 開啟的群組，例如 `firewall_rules`、`dhcpv6`，或代表其他套件設定的 `package:<section>`。 |
| `disabled_groups/item` | 關閉的 pfSense 群組。不在任何一份清單中的 pfSense 群組為開啟，其他套件的群組則為關閉。               |
| `include/item`         | 在關閉的群組中已勾選欄位的識別碼。                                                  |
| `exclude/item`         | 在開啟的群組中已取消勾選欄位的識別碼。                                                |

- pfSense 群組的鍵為 `interfaces`、`virtual_ips`、`aliases`、`firewall_rules`、`nat`、`dhcpv6`、`router_advertisements`、`dns_host_overrides`、`ipsec`、`openvpn` 與 `wireguard`。
- `include` 與 `exclude` 各最多保存 1,000 個識別碼，每個識別碼都遵循[欄位識別碼](/docs/reference/approved-fields#field-identities)中的格式。

## Cron 項目 \{#cron-entry}

儲存設定時會移除該命令既有的項目；當 `enabled` 為 `on` 時，會透過 pfSense 的 `install_cron_job()` 為 `root` 安裝新的項目。

| 排程值                     | Cron 欄位        |
|-------------------------|----------------|
| `every_fifteen_minutes` | `*/15 * * * *` |
| `hourly`                | `0 * * * *`    |
| `every_six_hours`       | `0 */6 * * *`  |
| `daily`                 | `0 0 * * *`    |

未知的值會改用每小時一次的欄位。在<Terminology title="1.x 版：由 Cron 套件執行的 update.php 指令碼" to="/docs/reference/terminology#package-origins">舊版更新器</Terminology>遷移等待舊版指令碼執行結束期間，套件會保留一個 `*/15 * * * *` 項目，讓遷移即使在排程更新關閉時也會重試。

另一個項目會依 **更新檢查** 的頻率，在固定的隨機分鐘、小時、星期與月中日期，以 `root` 身分執行 `/usr/local/sbin/ipv6-prefix-updater --check-updates`。儲存設定會取代此項目，選擇 `never` 則會移除它。

## 記錄與通知 \{#logs-and-notices}

每一行<Terminology title="pfSense 的一般記錄，每次執行都會留下內容" to="/docs/reference/terminology#notifications-and-logs">系統記錄</Terminology>都會透過 pfSense 的 `log_error()` 寫入，並以 `IPv6 Prefix Updater:` 開頭。通知則透過 `file_notice()` 建立。執行通知會連結到 `/ipv6-prefix-updater-status.php`，遷移通知會連結到 `/ipv6-prefix-updater-cleanup.php`，有可用更新的通知則連結到 `/ipv6-prefix-updater-about.php`。

## 頁面權限 \{#page-privileges}

套件的每個頁面都宣告了各自的 pfSense 權限，因此可以逐頁授予存取權：

- **狀態**：`page-services-ipv6-prefix-updater-status`，其名稱為 `Services: IPv6 Prefix Updater: Status`。
- **欄位**：`page-services-ipv6-prefix-updater-fields`，其名稱為 `Services: IPv6 Prefix Updater: Fields`。它可以變更執行會改寫哪些欄位，因此建議只授予管理員。
- **備份**：`page-services-ipv6-prefix-updater-backups`，其名稱為 `Services: IPv6 Prefix Updater: Backups`。它允許下載完整的設定副本，因此建議只授予管理員。
- **清理**：`page-services-ipv6-prefix-updater-cleanup`，其名稱為 `Services: IPv6 Prefix Updater: Cleanup`。
- **關於**：`page-services-ipv6-prefix-updater-about`，其名稱為 `Services: IPv6 Prefix Updater: About`。
