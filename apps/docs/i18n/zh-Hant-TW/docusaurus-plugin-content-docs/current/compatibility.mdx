確認您的防火牆、介面與 ISP 委派都符合套件的需求，然後再倚賴<Terminology title="依排程自動檢查，啟用前一直關閉" to="/docs/reference/terminology#running-checks">排程更新</Terminology>自動執行。

## 支援的版本 \{#supported-releases}

- 套件已在 pfSense CE 2.9.1、2.9.0 與 2.8.1 以及 pfSense Plus 26.07.1、26.07 與 26.03.1 上測試過。**關於** 分頁會列出每個版本曾測試過的 pfSense 版本，並將與目前防火牆相符的版本標示為 **此防火牆**。
- 套件不會檢查 pfSense 版本。每次執行都會確認自己在 pfSense 上執行且所需的檔案與函式齊全，缺少時會在讀取設定之前停止。
- 套件程式碼需要 PHP 8.1 或更新版本。
- 發行的套件標示為適用於任何 FreeBSD 版本（`FreeBSD:*`）並標示為 vital，因此同一個套件可以安裝在所有受支援的 pfSense 版本上，pfSense 升級時也會保留它。

## 位址需求 \{#address-requirements}

- 每個<Terminology title="透過其位址揭示目前前綴的介面" to="/docs/reference/terminology#interfaces-and-detection">監控介面</Terminology>都必須具備作用中的<Terminology title="位於 2000::/3 內的公用 IPv6 位址，唯一會用到的類型" to="/docs/reference/terminology#addresses-and-prefixes">全域單播位址</Terminology>。套件絕不會改用<Terminology title="以 fe80 開頭的位址，永遠不會作為來源位址" to="/docs/reference/terminology#addresses-and-prefixes">鏈路本機位址</Terminology>。
- 唯一本機位址（`fc00::/7`）、多播位址、迴路位址、未指定位址、IPv4 對映位址以及含區域識別碼的位址，都不能作為<Terminology title="每次執行讀取前綴所用的即時位址" to="/docs/reference/terminology#interfaces-and-detection">來源位址</Terminology>。
- <Terminology title="ISP 前綴的大小，例如 /56，由你設定" to="/docs/reference/terminology#addresses-and-prefixes">委派前綴長度</Terminology>必須介於 `/48` 到 `/64`。邊界落在某個十六進位數字內部的長度（例如 `/57`）同樣可以使用。

位址不符合條件時，該介面會以<Terminology title="執行在某個檢查或安全階段停止" to="/docs/reference/terminology#run-outcomes">失敗</Terminology>結束並提供原因，例如 `介面「lan」沒有作用中的全域 IPv6 位址。` [疑難排解](/docs/operate/troubleshooting#run-failed)列出了這些訊息。

## WAN 沒有全域位址時 \{#when-wan-has-no-global-address}

有些 ISP 只委派前綴，而不為 WAN 本身指派<Terminology title="位於 2000::/3 內的公用 IPv6 位址，唯一會用到的類型" to="/docs/reference/terminology#addresses-and-prefixes">全域位址</Terminology>。此時，LAN 等<Terminology title="以另一個介面的前綴產生 IPv6 的介面" to="/docs/reference/terminology#interfaces-and-detection">追蹤介面</Terminology>會持有來自<Terminology title="ISP 分配給你的 IPv6 網路，可能會變動" to="/docs/reference/terminology#addresses-and-prefixes">委派前綴</Terminology>的位址，應該監控的就是它。

**Status → Interfaces**（狀態 → 介面）會顯示哪些介面具有<Terminology title="位於 2000::/3 內的公用 IPv6 位址，唯一會用到的類型" to="/docs/reference/terminology#addresses-and-prefixes">全域位址</Terminology>。

## 套件能辨識的內容 \{#what-the-package-recognizes}

套件會更新<Terminology title="允許套件改寫的設定" to="/docs/reference/terminology#fields-and-change-plans">已核准欄位</Terminology>中以字面形式寫出的 IPv6 位址與網路。主機名稱、URL、IPv4 值與其他文字則維持不變。

由 pfSense 產生的位址（例如<Terminology title="以另一個介面的前綴產生 IPv6 的介面" to="/docs/reference/terminology#interfaces-and-detection">追蹤介面</Terminology>上的位址）絕不會被變更。描述其他裝置的位址（例如遠端 VPN 網路與 WireGuard 對等端）只有在您於[其他設定](/docs/configure/configuration-scopes#other-settings)中勾選後才會變更。

## 選用相依項目 \{#optional-dependencies}

- **WireGuard 套件**：只有在需要變更 <Terminology title="WireGuard 通道介面上的位址" to="/docs/reference/terminology#pfsense-features">WireGuard 通道位址</Terminology>時才需要。若未安裝，包含 WireGuard 變更的實際執行會在備份之前停止。

## 已知限制 \{#known-limits}

- 新增<Terminology title="透過其位址揭示目前前綴的介面" to="/docs/reference/terminology#interfaces-and-detection">監控介面</Terminology>或將某一列切換為其他介面時，會為它記錄新的<Terminology title="記錄下來的起始前綴，變更以它為準" to="/docs/reference/terminology#baselines-and-transitions">基準</Terminology>；變更某一列的<Terminology title="ISP 前綴的大小，例如 /56，由你設定" to="/docs/reference/terminology#addresses-and-prefixes">委派前綴長度</Terminology>則會視為一次<Terminology title="前綴變了，套件開始工作" to="/docs/reference/terminology#baselines-and-transitions">前綴變更</Terminology>。
- <Terminology title="預覽改動，但不寫入任何內容" to="/docs/reference/terminology#running-checks">試執行</Terminology>無法模擬前綴變更，因此只有在實際發生變更後才會出現規劃的變更。
- 高可用性（CARP）配對不會得到特殊處理。
- 由於這是<Terminology title="從 GitHub 安裝，而非來自 Netgate 套件存放庫" to="/docs/reference/terminology#package-origins">非官方套件</Terminology>，新版本需要使用 `pkg` 安裝，詳見[更新或移除](/docs/reference/package-lifecycle)。

如何選擇位址來源請參閱[介面與前綴](/docs/configure/interface-and-prefix)，套件可變更的欄位請參閱[欄位](/docs/configure/configuration-scopes)頁面。
