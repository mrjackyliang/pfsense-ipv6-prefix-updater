在 pfSense shell 中检查已安装的版本、安装新版本或移除软件包。

## 检查已安装的版本 \{#check-the-installed-version}

```shell
pkg info pfSense-pkg-Ipv6PrefixUpdater
```

将报告的版本与 [GitHub 上的最新发布版本](https://github.com/mrjackyliang/pfsense-ipv6-prefix-updater/releases/latest)进行比较。

## 更新软件包 \{#update-the-package}

建议先在 **Diagnostics → Backup & Restore**（诊断 → 备份与恢复）中下载一份配置副本。然后在现有软件包之上安装最新版本：

```shell
pkg add -f https://github.com/mrjackyliang/pfsense-ipv6-prefix-updater/releases/latest/download/pfSense-pkg-Ipv6PrefixUpdater.pkg
```

安装步骤会再次根据已保存的设置同步前缀检查和版本检查这两个 cron 条目，并保留每个<Terminology title="记录下来的起始前缀，变化以它为准" to="/docs/reference/terminology#baselines-and-transitions">基线</Terminology>。[安装软件包](/docs/installation#verify-the-download-first)中的校验和步骤同样适用于更新。

更新之后：

1. 打开 **Services → IPv6 Prefix Updater** 的 **设置** 选项卡，确认已保存的值。
2. 在“状态”选项卡中查看 **当前状态**。每个接口都会保留其<Terminology title="记录下来的起始前缀，变化以它为准" to="/docs/reference/terminology#baselines-and-transitions">基线</Terminology>。

如果某一行显示 `尚未初始化`，**立即运行** 会为它记录新的<Terminology title="记录下来的起始前缀，变化以它为准" to="/docs/reference/terminology#baselines-and-transitions">基线</Terminology>。这样一来，仍在使用该基线之前旧前缀的地址将保持不变。

## 移除软件包 \{#remove-the-package}

如果 pfSense 保留了已保存的设置，先取消勾选 **<Terminology title="按计划自动检查，启用前一直关闭" to="/docs/reference/terminology#running-checks">启用计划更新</Terminology>** 可以避免日后重新安装时立即启动计划更新。然后运行：

```shell
pkg delete -f pfSense-pkg-Ipv6PrefixUpdater
```

该软件包标记为 `vital`，因此 pfSense 自身升级会将其保持为已安装状态，而普通的 `pkg delete` 会拒绝删除 vital 软件包。

移除操作会删除两个 cron 条目（前缀检查和版本检查），关闭有可用更新的通知，并在没有操作持有相应锁时删除每个操作锁文件。它会保留 `/cf/conf/ipv6-prefix-updater` 中的<Terminology title="保存每条基线的文件，重装后依然保留" to="/docs/reference/terminology#running-checks">软件包状态</Terminology>、`updates.json`、`update-status.json` 和 **备份** 选项卡中的副本。

pfSense 自身升级会保留该软件包（它是 `vital` 软件包），而保留的软件包状态意味着移除并重新安装时绝不会丢失<Terminology title="记录下来的起始前缀，变化以它为准" to="/docs/reference/terminology#baselines-and-transitions">基线</Terminology>。

移除操作不会撤销已保存到配置中的地址，软件包产生的修订版本也会保留在<Terminology title="pfSense 保存的可供恢复的配置修订" to="/docs/reference/terminology#backups-and-service-reloads">配置历史</Terminology>中。如果还要删除保留的文件，请在移除软件包后运行 `rm -rf /cf/conf/ipv6-prefix-updater`。

## 日后重新安装 \{#reinstall-later}

重新安装时会找到保留的<Terminology title="保存每条基线的文件，重装后依然保留" to="/docs/reference/terminology#running-checks">软件包状态</Terminology>，因此首次运行会与每个已保存的<Terminology title="记录下来的起始前缀，变化以它为准" to="/docs/reference/terminology#baselines-and-transitions">基线</Terminology>进行比较，并更新仍停留在更旧前缀上的字段。如果之前的设置仍然存在且勾选了 **<Terminology title="按计划自动检查，启用前一直关闭" to="/docs/reference/terminology#running-checks">启用计划更新</Terminology>**，安装步骤会立即开启计划更新。

如果想从头开始，请在重新安装之前删除 `/cf/conf/ipv6-prefix-updater`。这样首次运行会记录新的<Terminology title="记录下来的起始前缀，变化以它为准" to="/docs/reference/terminology#baselines-and-transitions">基线</Terminology>并报告<Terminology title="初次检查：记录基线，不做任何改动" to="/docs/reference/terminology#run-outcomes">已初始化</Terminology>，不会更改配置。

维护之前请阅读[备份与恢复](/docs/operate/backups-and-recovery)，重新安装之后请阅读[建立基线](/docs/first-run)。
