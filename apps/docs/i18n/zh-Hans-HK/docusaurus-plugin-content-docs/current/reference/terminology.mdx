解释“设置”“状态”和“字段”选项卡以及本指南中有关地址、前缀、运行和 pfSense 功能的术语。

## 委派前缀 \{#delegated-prefix}

ISP 路由到防火墙的 IPv6 网络，通常通过 DHCPv6 前缀委派（Prefix Delegation）获得。软件包会跟随这个前缀，但从不请求、续订或更改它。

## 前缀长度 \{#prefix-length}

标识网络的前导位数，写作斜杠加数字，例如 `/56`。配置值上的 CIDR 后缀（如 `/64`）在软件包改写地址时保持原样。

## 委派前缀长度 \{#delegated-prefix-length}

**委派前缀长度** 设置，保存 ISP 委派的前缀大小，范围为 `/48` 到 `/64`。它的初始值为 `/56`，软件包从不自动检测；在基线已存在后更改它，会被视为一次前缀变化。

## 全局单播地址 \{#global-unicast-address}

位于 `2000::/3` 内的 IPv6 地址，也是软件包唯一会读取为源地址或进行改写的地址类型。链路本地、唯一本地（`fc00::/7`）、组播、环回、未指定和 IPv4 映射地址都不会被接受为源地址，在配置中也保持不变。

## 链路本地地址 \{#link-local-address}

仅在单条网络链路上有效、以 `fe80` 开头的地址。软件包从不回退使用这种地址，因此接口没有全局地址时，运行会失败。

## 主机部分 \{#host-portion}

地址中位于委派前缀长度之后的所有位，也称为主机位。软件包会将这些位原样复制到新地址中，即使边界落在某个十六进制位内部也是如此。

## 规范形式 \{#canonical-form}

IPv6 地址标准的小写、最短写法，例如 `2001:0DB8:0:0::1` 的规范形式是 `2001:db8::1`。软件包以这种形式比较地址，也以这种形式写入改写后的值，因此某个值看起来可能不同，但表示的是同一地址。

## 跟踪接口 \{#tracked-interface}

通过 **Track Interface**（跟踪接口）配置类型、从另一个接口的委派前缀获得 IPv6 地址的 pfSense 接口。当 WAN 没有全局地址时，它往往就是合适的监控接口；由于其地址由 pfSense 生成，软件包从不改写它。

## 监控接口 \{#monitored-interface}

**监控接口** 设置中的一行，指定一个全局地址能反映当前前缀的接口。“状态”选项卡会显示该接口的描述，后接 pfSense 对该接口的内部名称，例如 `LAN (lan)`。

添加接口后，下一次运行会为它记录新的基线，而不是比较前缀。

## 源地址 \{#source-address}

pfSense 为监控接口报告的主要全局地址，每次运行都会重新读取。“状态”选项卡以规范形式将其显示为 **观察到的源地址** 和 **上次成功源地址**。

## 观察到的前缀 \{#observed-prefix}

根据源地址和委派前缀长度计算出的网络，在“状态”选项卡中连同其长度一起显示。每次运行都会将它与上次成功前缀进行比较。

## 基线 \{#baseline}

软件包记录为起点的前缀和源地址，记录时不会更改配置。每个监控接口首次运行时、软件包状态缺失时、操作员明确接受当前活动前缀时，以及迁移期间根据旧版更新器保存的前缀，都会记录基线。

## 上次成功前缀 \{#last-successful-prefix}

已保存的前缀和长度，下一次检查会与之比较。只有“已初始化”“已接受”和“成功”这三种结果会更改它，其他结果都会让它保持原样。

## 前缀变化 \{#prefix-transition}

上次成功前缀与观察到的前缀之间的差异，包括网络相同但前缀长度不同的情况。只有发生前缀变化时，软件包才会扫描配置、规划更改并写入。

## 字段组 \{#field-group}

“字段”选项卡上由一个开关控制的一组字段。十一个 pfSense 组为静态接口、虚拟 IP 地址、别名、防火墙规则、NAT 和 NPt、DHCPv6 服务器、路由器通告、DNS 主机覆盖、IPsec、OpenVPN 和 WireGuard，它们默认开启。其他每个软件包的设置各有一个默认关闭的单独组，其余所有值都属于同样默认关闭的“其他设置”组。开启的组涵盖该类型的所有字段，包括以后添加的字段。

## 已批准字段 \{#approved-field}

允许软件包改写的具体配置字段：开启的组中未被取消勾选的字段，或关闭的组中已勾选的字段。已批准字段之外的值绝不会被更改。

## 字段例外 \{#field-exception}

在“字段”选项卡上，勾选状态与所在组开关相反的单个字段：开启的组中被取消勾选的字段，或关闭的组中被勾选的字段。每个例外都通过条目本身（例如防火墙规则的跟踪 ID）而不是列表位置来指明条目。

## 变更计划 \{#change-plan}

将要更改的已批准字段的完整列表，包含每个字段的旧值、新值以及需要重新加载的服务。软件包会在更改任何内容之前生成完整的计划。

## 计划更新 \{#scheduled-updates}

由 **启用计划更新**（默认关闭）和 **计划**（默认每小时）控制的自动检查。保存设置时会添加或删除一个由 pfSense 管理的 cron 条目，因此不需要 Cron 软件包。

## 手动运行 \{#manual-run}

在“状态”选项卡中通过 **立即运行** 或 **试运行** 启动的检查。即使计划更新已关闭，它也会运行。

## 试运行 \{#dry-run}

通过 **试运行** 启动的预览，从不创建备份，也从不写入配置。如果它发现了前缀变化且有字段需要更改，结果为 **试运行**，并列出计划更改的字段数。

前缀未变化时，试运行会报告“无变化”，且不扫描配置。

## 命令输出 \{#command-output}

执行“立即运行”“试运行”或“接受当前前缀”后，出现在 **命令输出** 下的只读 **最新运行** 文本框。它显示该次运行从 `状态` 到 `摘要` 的各行内容，在试运行或成功之后还会接着显示 `字段变更`；操作失败或另一次运行持有锁时，则只显示一行。

## 运行锁 \{#run-lock}

确保同一时间只有一个检查运行的锁。第二个检查会直接退出而不读取配置；正在运行的检查一结束，锁就会释放。

## 软件包状态 \{#package-state}

文件 `/cf/conf/ipv6-prefix-updater/state.json`，软件包在 pfSense 配置之外用它保存每个基线和最近一次运行。只有 root 可以读取它；它在重启、启用 RAM 磁盘和移除软件包后都会保留，因此重新安装后每个基线依然存在。

## 已初始化 \{#initialized}

记录新基线的运行所得到的结果。它不会创建备份、更改配置或发送通知。

## 初始化预览 \{#initialization-preview}

在尚无基线时进行试运行所得到的结果。它会显示正常运行将记录的基线，但并不实际记录。

## 无变化 \{#no-change}

观察到的前缀及其长度与上次成功前缀一致时的结果，也称为空操作运行。此类运行不会扫描配置、创建备份、重新加载服务或发送通知。

## 警告 \{#warning}

发现了前缀变化，但没有已批准字段属于旧前缀时的结果。不会写入任何内容，基线保持原位，每次警告都会添加一条 WebGUI 通知。

## 已接受 \{#accepted}

操作员选择 **接受当前前缀** 并确认已保存的地址已在使用当前活动前缀后的结果。软件包会移动基线，但不扫描已批准字段、不创建备份、不写入配置，也不重新加载服务。

## 成功 \{#success}

备份、单次配置写入、服务重新加载和值检查全部完成后的结果。基线移到新前缀；如果已开启变化通知，还会发送通知。

## 失败 \{#failure}

检查或安全阶段中止运行时的结果。如果在配置保存之后才停止，新值会保持已保存状态，基线则停留在旧前缀上。

## 已禁用 \{#disabled}

在 **启用计划更新** 关闭时运行的计划检查所得到的结果。它会在读取任何接口或软件包状态之前停止，并且只出现在命令自身的输出中。

## 变化通知 \{#change-notification}

勾选 **发送变化通知**（默认已勾选）时，在“成功”之后发送的消息。它会发送到 pfSense 中配置的通知渠道，同时也以 WebGUI 通知的形式出现。

## 通知渠道 \{#notification-channels}

在 **System → Advanced → Notifications**（系统 → 高级 → 通知）中设置的远程提醒服务，例如电子邮件。变化通知使用这些渠道，而警告和失败通知只保留在本地。

## WebGUI 通知 \{#webgui-notice}

pfSense WebGUI 通知列表中的一条提醒，链接到软件包的“状态”选项卡；从旧版更新器迁移后则链接到“清理”选项卡。即使未勾选 **发送变化通知**，警告和失败结果也总会添加一条。

## 系统日志 \{#system-log}

位于 **Status → System Logs → System → General**（状态 → 系统日志 → 系统 → 常规）下的 pfSense 常规日志。软件包写入的每一行都以 `IPv6 Prefix Updater:` 开头。

## 配置备份 \{#configuration-backup}

使用 pfSense 备份功能制作的、写入之前的配置副本，同时也保存在 **备份** 选项卡中。软件包在每次需要写入的运行中、更改任何字段之前都会创建一份，不写入的运行则不会创建。

## 配置历史 \{#config-history}

**Diagnostics → Backup & Restore → Config History**（诊断 → 备份与恢复 → 配置历史）下已保存配置修订版本的列表。描述为 `IPv6 前缀更新器为接口 ... 更改了 ...` 的修订版本保存的是更新后的配置，因此应恢复的是在它之前保存的修订版本。

## 服务重新加载 \{#service-reload}

将更改后的设置应用到正在运行的服务上的 pfSense 操作。软件包只重新加载字段有更改的服务，并在 **已重新加载的服务** 下列出它们。

## 虚拟 IP \{#virtual-ip}

在 **Firewall → Virtual IPs**（防火墙 → 虚拟 IP）中分配给接口的额外地址。“虚拟 IP 地址”组只更新 CARP 和 IP Alias 类型的条目。

## IPsec 阶段 2 \{#ipsec-phase-2}

定义隧道本地网络和远程网络的 IPsec 条目（Phase 2）。IPsec 组涵盖 Tunnel IPv6 和 Routed (VTI) 模式条目的本地端，远程端则属于“其他设置”组。

## 客户端特定覆盖 \{#client-specific-override}

位于 **VPN → OpenVPN → Client Specific Overrides**（VPN → OpenVPN → 客户端特定覆盖）下、为单个客户端设置选项的 OpenVPN 条目。软件包可以更新其 IPv6 隧道网络和 IPv6 本地网络。

## WireGuard 隧道地址 \{#wireguard-tunnel-address}

在 pfSense 上分配给 WireGuard 隧道的接口地址。更新它需要 WireGuard 软件包，对等端的允许 IP 和端点属于“其他设置”组。

## 旧版更新器 \{#legacy-updater}

本项目的 1.x 版本，即安装在 `/root` 中、由 Cron 软件包条目运行的 `update.php` 脚本。它会替换配置中任何位置出现的旧前缀文本。

## 非官方软件包 \{#unofficial-package}

通过 `pkg add` 从 GitHub 而非 Netgate 软件包仓库安装的软件包。Netgate 不会审核或支持它，其更新也需要你自行安装。
