在 shell 中运行软件包命令，并查找它使用的文件、日志和通知。

## 用法 \{#usage}

```text
用法：ipv6-prefix-updater [--manual] [--dry-run] [--accept-current-prefix [--interface=NAME]] [--migrate-legacy]
更新选项：--check-updates [--no-notice]、--self-update。
```

由 pfSense 管理的前缀检查 cron 条目以 `root` 身份不带选项运行该命令，另一个独立的版本检查条目则以 `--check-updates` 运行它。每次检查之前，它还会将<Terminology title="1.x 版本：由 Cron 软件包运行的 update.php 脚本" to="/docs/reference/terminology#package-origins">旧版更新器</Terminology>的所有遗留内容迁移到软件包中。“状态”选项卡在 **立即运行** 时使用 `--manual`，在 **<Terminology title="预览改动，但不写入任何内容" to="/docs/reference/terminology#running-checks">试运行</Terminology>** 时使用 `--dry-run`，在基线恢复时使用 `--accept-current-prefix`；“清理”选项卡则使用 `--migrate-legacy`。

不带选项时，该命令的行为与计划检查相同；**<Terminology title="按计划自动检查，启用前一直关闭" to="/docs/reference/terminology#running-checks">启用计划更新</Terminology>** 关闭时会报告<Terminology title="因计划更新已关闭而跳过的计划检查" to="/docs/reference/terminology#run-outcomes">已禁用</Terminology>。

## 选项 \{#options}

| 参数                        | 说明                                                                                                                                                                      |
|---------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `--manual`                | 即使<Terminology title="按计划自动检查，启用前一直关闭" to="/docs/reference/terminology#running-checks">计划更新</Terminology>已关闭也会运行。                                                       |
| `--dry-run`               | 只预览，不备份也不写入，并隐含 `--manual`。                                                                                                                                             |
| `--accept-current-prefix` | 将当前活动的源地址、前缀和长度记录为基线，不扫描已批准字段、不创建备份、不写入配置，也不重新加载服务。它隐含 `--manual`，且不能与 `--dry-run` 同时使用。                                                                                |
| `--interface=NAME`        | 将 `--accept-current-prefix` 限定于一个监控接口，以其内部名称（如 `lan`）指定。不带此选项时，所有具有地址的监控接口都会被接受。                                                                                        |
| `--migrate-legacy`        | 立即将<Terminology title="1.x 版本：由 Cron 软件包运行的 update.php 脚本" to="/docs/reference/terminology#package-origins">旧版更新器</Terminology>迁移到软件包中并打印每个步骤，不运行前缀检查。迁移报告了警告时以 `2` 退出。 |
| `--check-updates`         | 在 GitHub 上检查最新的软件包版本，并将结果保存到 `/cf/conf/ipv6-prefix-updater/updates.json`。[更新](/docs/reference/updates)介绍了该检查。                                                           |
| `--no-notice`             | 使 `--check-updates` 不创建更新通知，并将最新版本记录为已通知。仅可与 `--check-updates` 一起使用。                                                                                                    |
| `--self-update`           | 下载、验证并安装最新版本，并将进度记录到 `/cf/conf/ipv6-prefix-updater/update-status.json`。                                                                                                 |
| `--help`                  | 打印用法行和更新选项行，并以 `0` 退出。这两行都不列出 `--help` 本身。                                                                                                                              |

任何其他选项都会向标准错误输出 `未知选项：<option>` 并以 `64` 退出。将 `--accept-current-prefix` 与 `--dry-run` 组合使用同样会以 `64` 退出；将 `--check-updates` 与 `--self-update` 组合使用，或将二者之一与任何前缀选项组合使用，也是如此。不与 `--check-updates` 一起使用 `--no-notice` 时同样会以 `64` 退出。

## 输出 \{#output}

监控一个接口的运行完成后，会向标准输出打印九行；在<Terminology title="预览改动，但不写入任何内容" to="/docs/reference/terminology#running-checks">试运行</Terminology>或<Terminology title="前缀变了，所有已批准字段都已更新" to="/docs/reference/terminology#run-outcomes">成功</Terminology>之后，还会接着打印字段变更：

```text
状态: 成功
接口: lan
观察到的源地址: 2001:db8:abcd:88aa::1
旧前缀: 2001:db8:abcd:7800::
当前前缀: 2001:db8:abcd:8800::/56
计划或已更改字段: 1
配置备份: 已创建
已重新加载的服务: 防火墙过滤器
摘要: 已在接口 lan 上将 1 个已批准字段从 2001:db8:abcd:7800::/56 更新为 2001:db8:abcd:8800::/56。
字段变更:
- aliases/alias/0/address: 2001:db8:abcd:78aa::10 → 2001:db8:abcd:88aa::10
```

- `旧前缀`不带长度；在<Terminology title="初次检查：记录基线，不做任何改动" to="/docs/reference/terminology#run-outcomes">已初始化</Terminology>或<Terminology title="显示将会记录的基线的试运行" to="/docs/reference/terminology#run-outcomes">初始化预览</Terminology>之后，它显示为 `不可用`。
- `已重新加载的服务`列出各服务的状态标签，没有时显示 `无`。<Terminology title="预览改动，但不写入任何内容" to="/docs/reference/terminology#running-checks">试运行</Terminology>之后，它列出的是将会重新加载的服务。
- `字段变更`为每个被替换的地址输出一行，格式为 `- <path>: <old> → <new>`，最多列出 200 个字段。
- 如果运行重新应用了其他软件包的设置，或跳过了已不存在的已勾选字段，随后会针对每一项各输出一行，措辞与“状态”选项卡上的相同。
- 当另一个检查持有<Terminology title="确保两次检查不会同时运行" to="/docs/reference/terminology#running-checks">运行锁</Terminology>时，唯一的输出是 `另一次运行持有软件包锁；本次调用未读取配置便已退出。`
- 监控多个接口时，输出以总体的 `状态`、`摘要`、软件包行和跳过字段行开头，随后是每个接口各自的各行内容，各组之间以空行分隔。
- 如果检查之前进行了<Terminology title="1.x 版本：由 Cron 软件包运行的 update.php 脚本" to="/docs/reference/terminology#package-origins">旧版更新器</Terminology>迁移，会先打印迁移的各个步骤。
- 标签和消息跟随 pfSense 的语言设置。

## 软件包状态格式 \{#package-state-format}

| 键                     | 说明                                                                                                                                                                                                                                                                                                                                                                             |
|-----------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `schema_version`      | 始终为 `1`。                                                                                                                                                                                                                                                                                                                                                                       |
| `targets.<interface>` | 每个监控接口一个<Terminology title="记录下来的起始前缀，变化以它为准" to="/docs/reference/terminology#baselines-and-transitions">基线</Terminology>，以接口的内部名称为键，包含 `interface`、`source_address`、`prefix`、`prefix_length` 和 `updated_at`。从<Terminology title="1.x 版本：由 Cron 软件包运行的 update.php 脚本" to="/docs/reference/terminology#package-origins">旧版更新器</Terminology>接管的基线还会将 `source` 设为 `legacy_cache`。 |
| `last_run`            | 最近记录的一次运行，包含 `status`、`timestamp`、`interface`、`observed_address`、`previous_prefix`、`current_prefix`、`current_prefix_length`、`change_count`、`backup_created`、`services`、`message`、`message_key` 和 `message_arguments`。                                                                                                                                                          |
| `legacy_migration`    | 在<Terminology title="1.x 版本：由 Cron 软件包运行的 update.php 脚本" to="/docs/reference/terminology#package-origins">旧版更新器</Terminology>迁移之后出现，包含 `status`、`steps`、`warnings` 和 `recorded_at`。“清理”选项卡会显示它。                                                                                                                                                                                |

- `status` 的取值为 `initialized`、`initialization_preview`、`no_change`、`dry_run`、`warning`、`accepted`、`success` 或 `failure` 之一。
- <Terminology title="前缀变了，所有已批准字段都已更新" to="/docs/reference/terminology#run-outcomes">成功</Terminology>之后，如果通知已关闭，`last_run.notification` 为 `disabled`；尝试发送后则为 `sent` 或 `failed`。
- 在<Terminology title="预览改动，但不写入任何内容" to="/docs/reference/terminology#running-checks">试运行</Terminology>或<Terminology title="前缀变了，所有已批准字段都已更新" to="/docs/reference/terminology#run-outcomes">成功</Terminology>之后，每条结果还包含 `changes`，列出最多 200 个字段的 `path` 和 `replacements`，其中每个替换项由一个旧地址和一个新地址组成。
- `package_reapply` 列出运行重新应用了其设置的每个软件包的 `section`、`package`、`status` 和 `error`，`skipped_fields` 列出已不存在的已勾选字段。两者都只在非空时出现。
- 监控多个接口时，`last_run` 保存总计以及一个 `targets` 列表，其中每个接口一条结果。
- 时间戳采用 UTC 的 ISO 8601 格式。如果文件无法解析，或其架构版本不同，每次运行都会停止，并显示 `IPv6 前缀更新器状态无效或不受支持。`

## 设置的存储 \{#settings-storage}

设置保存在 pfSense 配置中的 `installedpackages/ipv6prefixupdater/config/0` 下。

| 键                             | 说明                                                                                                                          |
|-------------------------------|-----------------------------------------------------------------------------------------------------------------------------|
| `enabled`                     | **<Terminology title="按计划自动检查，启用前一直关闭" to="/docs/reference/terminology#running-checks">启用计划更新</Terminology>**，勾选时为 `on`。    |
| `row`                         | **监控接口**，一个列表，每行包含一个 `interface`（接口键，例如 `lan`）和一个 `prefix_length`（`48` 到 `64`）。                                             |
| `update_frequency`            | **计划**，取值为 `every_fifteen_minutes`、`hourly`、`every_six_hours` 或 `daily` 之一。                                                 |
| `notifications`               | **<Terminology title="地址更新后发送的通知" to="/docs/reference/terminology#notifications-and-logs">发送变化通知</Terminology>**，勾选时为 `on`。 |
| `update_check_frequency`      | **更新检查**，取值为 `daily`、`weekly`、`monthly` 或 `never` 之一。                                                                       |
| `update_remote_notifications` | **远程通知**，勾选时为 `on`。                                                                                                         |

固定的版本检查计划保存在设置记录旁边的 `installedpackages/ipv6prefixupdater/update_schedule` 下，其中 `minute` 为 0 到 59，`hour` 为 0 到 23，`weekday` 为 0 到 6，`monthday` 为 1 到 28。缺失、格式错误或超出范围的值会重新生成并保存。

### 字段选择 \{#field-selection}

“字段”选项卡上的选择保存在设置记录旁边的 `installedpackages/ipv6prefixupdater/fields` 下，因此保存“设置”选项卡（这会替换 `config/0`）绝不会清除它们。

| 键                      | 说明                                                                      |
|------------------------|-------------------------------------------------------------------------|
| `schema`               | 始终为 `1`。它表示这是从“字段”选项卡保存的选择，即使选择为空也是如此。                                  |
| `enabled_groups/item`  | 处于开启状态的组，例如 `firewall_rules`、`dhcpv6`，或表示另一个软件包设置的 `package:<section>`。 |
| `disabled_groups/item` | 处于关闭状态的 pfSense 组。pfSense 组如果不在任一列表中则为开启，另一个软件包的组则为关闭。                  |
| `include/item`         | 在关闭的组中被勾选的字段的标识。                                                        |
| `exclude/item`         | 在开启的组中被取消勾选的字段的标识。                                                      |

- pfSense 组的键为 `interfaces`、`virtual_ips`、`aliases`、`firewall_rules`、`nat`、`dhcpv6`、`router_advertisements`、`dns_host_overrides`、`ipsec`、`openvpn` 和 `wireguard`。
- `include` 和 `exclude` 各自最多保存 1000 个标识，每个标识都遵循[字段标识](/docs/reference/approved-fields#field-identities)中的格式。

## Cron 条目 \{#cron-entry}

保存设置时会删除该命令已有的条目；当 `enabled` 为 `on` 时，会通过 pfSense 的 `install_cron_job()` 为 `root` 安装一个新条目。

| 计划值                     | Cron 字段        |
|-------------------------|----------------|
| `every_fifteen_minutes` | `*/15 * * * *` |
| `hourly`                | `0 * * * *`    |
| `every_six_hours`       | `0 */6 * * *`  |
| `daily`                 | `0 0 * * *`    |

未知的值会回退为每小时一次的字段。在<Terminology title="1.x 版本：由 Cron 软件包运行的 update.php 脚本" to="/docs/reference/terminology#package-origins">旧版更新器</Terminology>迁移等待旧版脚本运行结束期间，软件包会保留一个 `*/15 * * * *` 条目，以便即使计划更新已关闭也会重试迁移。

另一个条目按 **更新检查** 的频率，在固定的随机分钟、小时、星期和月中日期，以 `root` 身份运行 `/usr/local/sbin/ipv6-prefix-updater --check-updates`。保存设置会替换该条目，选择 `never` 则会删除它。

## 日志与通知 \{#logs-and-notices}

每一行<Terminology title="pfSense 的常规日志，每次运行都会留下记录" to="/docs/reference/terminology#notifications-and-logs">系统日志</Terminology>都通过 pfSense 的 `log_error()` 写入，并以 `IPv6 Prefix Updater:` 开头。通知通过 `file_notice()` 创建。运行通知链接到 `/ipv6-prefix-updater-status.php`，迁移通知链接到 `/ipv6-prefix-updater-cleanup.php`，有可用更新的通知则链接到 `/ipv6-prefix-updater-about.php`。

| 通知 ID                                   | 创建时机                                                                                                                                                 | 发送方式                                                                                                                                               |
|-----------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------|
| `ipv6-prefix-updater-success`           | <Terminology title="前缀变了，所有已批准字段都已更新" to="/docs/reference/terminology#run-outcomes">成功</Terminology>且 `notifications` 设为 `on`                        | WebGUI 和<Terminology title="pfSense 的邮件等远程通知服务" to="/docs/reference/terminology#notifications-and-logs">通知渠道</Terminology>                         |
| `ipv6-prefix-updater-no-matches`        | <Terminology title="前缀变了，但没有已批准字段使用旧前缀" to="/docs/reference/terminology#run-outcomes">警告</Terminology>                                               | 仅 WebGUI                                                                                                                                           |
| `ipv6-prefix-updater-failure`           | <Terminology title="运行在某个检查或安全阶段停止" to="/docs/reference/terminology#run-outcomes">失败</Terminology>                                                   | 仅 WebGUI                                                                                                                                           |
| `ipv6-prefix-updater-package-<section>` | 运行更改了另一个软件包的设置，且没有已安装的软件包拥有该配置节，或重新应用其设置失败                                                                                                           | 仅 WebGUI                                                                                                                                           |
| `ipv6-prefix-updater-legacy-migration`  | 至少执行了一个步骤的<Terminology title="1.x 版本：由 Cron 软件包运行的 update.php 脚本" to="/docs/reference/terminology#package-origins">旧版更新器</Terminology>迁移，或在安装期间失败的迁移 | 仅 WebGUI                                                                                                                                           |
| `ipv6-prefix-updater-update-available`  | 版本检查发现尚未通知过的新版本                                                                                                                                      | 仅 WebGUI；勾选 **远程通知** 时为 WebGUI 和<Terminology title="pfSense 的邮件等远程通知服务" to="/docs/reference/terminology#notifications-and-logs">通知渠道</Terminology> |

如果命令自身的环境检查失败，或无法打开其锁文件，原因只会输出到标准错误。每次需要写入的运行还会保存一个配置修订版本，描述为 `IPv6 前缀更新器为接口 <interface> 更改了 <count> 个已批准字段`。

## 页面权限 \{#page-privileges}

软件包的每个页面都声明了各自的 pfSense 权限，因此可以按页面授予访问权限：

- **状态**：`page-services-ipv6-prefix-updater-status`，其名称为 `Services: IPv6 Prefix Updater: Status`。
- **字段**：`page-services-ipv6-prefix-updater-fields`，其名称为 `Services: IPv6 Prefix Updater: Fields`。它可以更改运行会改写哪些字段，因此建议只授予管理员。
- **备份**：`page-services-ipv6-prefix-updater-backups`，其名称为 `Services: IPv6 Prefix Updater: Backups`。它允许下载完整的配置副本，因此建议只授予管理员。
- **清理**：`page-services-ipv6-prefix-updater-cleanup`，其名称为 `Services: IPv6 Prefix Updater: Cleanup`。
- **关于**：`page-services-ipv6-prefix-updater-about`，其名称为 `Services: IPv6 Prefix Updater: About`。
