Ele não é registrado, então a guia Status nunca o mostra.

## Estado atual versus Última execução \{#current-state-versus-last-run}

O **Estado atual** só muda com <Terminology title="Primeira olhada: a referência é registrada e nada muda" to="/docs/reference/terminology#run-outcomes">Inicializado</Terminology>, **Aceito** e <Terminology title="O prefixo mudou e cada campo aprovado foi atualizado" to="/docs/reference/terminology#run-outcomes">Sucesso</Terminology>. Uma tentativa que falhou nunca vira o próximo ponto de comparação, a menos que um operador confira depois os valores salvos e aceite explicitamente o prefixo ativo; a **Última execução** registra a execução mais recente de qualquer resultado da tabela.

A **Última execução** continua igual quando outra verificação detém o <Terminology title="Impede que duas verificações rodem ao mesmo tempo" to="/docs/reference/terminology#running-checks">bloqueio de execução</Terminology> ou quando uma execução para antes de ler o <Terminology title="O arquivo com cada referência, mantido mesmo após reinstalar" to="/docs/reference/terminology#running-checks">estado do pacote</Terminology>, por exemplo quando nenhuma interface monitorada tem um <Terminology title="Um endereço IPv6 público em 2000::/3, o único tipo usado" to="/docs/reference/terminology#addresses-and-prefixes">endereço global</Terminology>. Essas execuções deixam o motivo na <Terminology title="As linhas da última execução, exibidas logo após o início" to="/docs/reference/terminology#running-checks">Saída do comando</Terminology> e no <Terminology title="O log geral do pfSense, onde cada execução deixa linhas" to="/docs/reference/terminology#notifications-and-logs">log do sistema</Terminology>.

## Aviso: nenhum campo correspondente \{#warning-no-matching-fields}

Um <Terminology title="O prefixo mudou, mas nenhum campo aprovado usava o antigo" to="/docs/reference/terminology#run-outcomes">Aviso</Terminology> significa que o prefixo mudou, mas nenhum dos <Terminology title="Uma configuração que o pacote pode reescrever" to="/docs/reference/terminology#fields-and-change-plans">campos aprovados</Terminology> pertencia ao prefixo antigo. Nada é gravado e a <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> permanece no prefixo antigo, então a próxima execução verifica a mesma <Terminology title="Seu prefixo mudou, então o pacote entra em ação" to="/docs/reference/terminology#baselines-and-transitions">transição de prefixo</Terminology> de novo.

Cada <Terminology title="O prefixo mudou, mas nenhum campo aprovado usava o antigo" to="/docs/reference/terminology#run-outcomes">Aviso</Terminology> adiciona um <Terminology title="Um alerta na lista de alertas do próprio pfSense" to="/docs/reference/terminology#notifications-and-logs">alerta da WebGUI</Terminology>, inclusive o de uma <Terminology title="Uma prévia das alterações que não grava nada" to="/docs/reference/terminology#running-checks">simulação</Terminology>. Uma causa não corrigida adiciona um novo alerta a cada execução agendada.

Causas comuns:

- O <Terminology title="Um único botão para um tipo inteiro de configuração" to="/docs/reference/terminology#fields-and-change-plans">grupo de campos</Terminology> que contém os endereços está desativado, ou os campos estão desmarcados.
- Os endereços já foram alterados fora do pacote.
- Os endereços estão no grupo [Outras configurações](/docs/configure/configuration-scopes#other-settings), que continua desativado até você marcá-los.
- Uma <Terminology title="A execução parou em uma verificação ou etapa de segurança" to="/docs/reference/terminology#run-outcomes">Falha</Terminology> anterior salvou os novos valores, mas manteve a <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> antiga.
- O <Terminology title="O tamanho do prefixo do seu provedor, como /56; você define" to="/docs/reference/terminology#addresses-and-prefixes">Comprimento do prefixo delegado</Terminology> foi [ampliado](/docs/configure/interface-and-prefix#changing-the-prefix-length) sem uma mudança de prefixo.

A página [Solução de problemas](/docs/operate/troubleshooting#warning-on-every-run) trata de cada causa.

Se os endereços já foram alterados corretamente, use **Status → Ações → Recuperação da referência → Aceitar prefixo atual** depois de conferir os endereços salvos e os serviços afetados. Isso registra um resultado **Aceito** sem analisar campos aprovados nem alterar a configuração do firewall; não use essa ação quando campos aprovados ainda contiverem o prefixo antigo.

## Falhas depois da gravação \{#failures-after-the-save}

Uma <Terminology title="A execução parou em uma verificação ou etapa de segurança" to="/docs/reference/terminology#run-outcomes">Falha</Terminology> durante as conferências de valores ou os <Terminology title="Aplica as configurações alteradas a um serviço em execução" to="/docs/reference/terminology#backups-and-service-reloads">recarregamentos de serviços</Terminology> que vêm depois da gravação deixa os novos valores salvos. Nada é revertido automaticamente, e a <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> permanece no prefixo antigo.

**<Terminology title="Uma cópia da configuração feita logo antes de qualquer gravação" to="/docs/reference/terminology#backups-and-service-reloads">Cópia de segurança da configuração criada</Terminology>** mostra Sim nessas execuções. [Backups e recuperação](/docs/operate/backups-and-recovery#after-a-failed-run) explica como restaurar e tentar de novo, ou como manter os valores salvos já conferidos com **Aceitar prefixo atual**.

## Falhas de notificação \{#notification-failures}

Se uma <Terminology title="O alerta enviado depois que seus endereços foram atualizados" to="/docs/reference/terminology#notifications-and-logs">notificação de alteração</Terminology> não puder ser enviada, o resultado continua sendo <Terminology title="O prefixo mudou e cada campo aprovado foi atualizado" to="/docs/reference/terminology#run-outcomes">Sucesso</Terminology> e a <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> ainda passa para o novo prefixo. A guia Status não mostra o status da entrega, e o <Terminology title="O log geral do pfSense, onde cada execução deixa linhas" to="/docs/reference/terminology#notifications-and-logs">log do sistema</Terminology> registra `A configuração foi bem-sucedida, mas a notificação da alteração falhou.`

Consulte [Status e ações](/docs/operate/status-and-actions) para ver os campos de cada resultado e [Como as atualizações funcionam](/docs/safety/how-updates-work) para a ordem das etapas.
