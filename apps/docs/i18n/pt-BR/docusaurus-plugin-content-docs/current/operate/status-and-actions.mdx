Veja o que a referência atual e a execução mais recente registraram e inicie uma verificação, uma prévia ou uma recuperação da referência na guia Status.

## Estado atual \{#current-state}

A guia **Status** em **Services → IPv6 Prefix Updater** começa com esta tabela, que tem uma linha por interface monitorada e descreve a <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> usada na comparação da próxima verificação:

- **<Terminology title="A interface cujo endereço revela seu prefixo atual" to="/docs/reference/terminology#interfaces-and-detection">Interface monitorada</Terminology>**: a descrição da interface seguida do nome interno no pfSense, como `LAN (lan)`.
- **<Terminology title="O prefixo salvo com o qual cada verificação compara" to="/docs/reference/terminology#baselines-and-transitions">Último prefixo bem-sucedido</Terminology>**: o prefixo e o comprimento dele, como `2001:db8:abcd:7800::/56`.
- **<Terminology title="O endereço ao vivo do qual cada execução lê o prefixo" to="/docs/reference/terminology#interfaces-and-detection">Último endereço de origem bem-sucedido</Terminology>**: o endereço na <Terminology title="A grafia curta em minúsculas, como 2001:db8::1" to="/docs/reference/terminology#addresses-and-prefixes">forma canônica</Terminology>. Uma execução com resultado <Terminology title="Mesmo prefixo da última vez, então não há nada a fazer" to="/docs/reference/terminology#run-outcomes">Sem alteração</Terminology> também o atualiza.
- **Última atualização bem-sucedida**: o horário UTC em que a <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> foi inicializada, aceita ou movida após o último <Terminology title="O prefixo mudou e cada campo aprovado foi atualizado" to="/docs/reference/terminology#run-outcomes">Sucesso</Terminology>, como `2026-10-24T14:00:00+00:00`.

Antes da primeira execução de uma interface, a linha dela mostra `Não inicializado. Execute uma verificação normal uma vez para estabelecer uma referência segura.` Uma <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> herdada do atualizador legado mostra `Não registrado por esta versão do pacote` como endereço de origem até a primeira verificação.

## Última execução \{#last-run}

Este painel registra a execução mais recente. Quando você monitora apenas uma interface, ele mostra diretamente o resultado dessa interface:

- **Resultado**: o desfecho da execução, explicado em [Resultados da execução](/docs/operate/run-outcomes).
- **Data e hora (UTC)**: quando a execução terminou.
- **<Terminology title="O endereço ao vivo do qual cada execução lê o prefixo" to="/docs/reference/terminology#interfaces-and-detection">Endereço de origem observado</Terminology>**: o endereço que o pfSense retornou para a <Terminology title="A interface cujo endereço revela seu prefixo atual" to="/docs/reference/terminology#interfaces-and-detection">Interface monitorada</Terminology>.
- **<Terminology title="O prefixo visto agora, comparado com o anterior" to="/docs/reference/terminology#interfaces-and-detection">Prefixo observado</Terminology>**: a rede calculada a partir desse endereço e do <Terminology title="O tamanho do prefixo do seu provedor, como /56; você define" to="/docs/reference/terminology#addresses-and-prefixes">Comprimento do prefixo delegado</Terminology>.
- **Campos alterados**: a quantidade de <Terminology title="Uma configuração que o pacote pode reescrever" to="/docs/reference/terminology#fields-and-change-plans">campos aprovados</Terminology> que a execução alterou, ou alteraria no caso de uma <Terminology title="Uma prévia das alterações que não grava nada" to="/docs/reference/terminology#running-checks">simulação</Terminology>.
- **<Terminology title="Uma cópia da configuração feita logo antes de qualquer gravação" to="/docs/reference/terminology#backups-and-service-reloads">Cópia de segurança da configuração criada</Terminology>**: `Sim` ou `Não — esta execução não escreveu a configuração`.
- **<Terminology title="Aplica as configurações alteradas a um serviço em execução" to="/docs/reference/terminology#backups-and-service-reloads">Serviços recarregados</Terminology>**: os serviços que a execução recarregou, ou recarregaria no caso de uma <Terminology title="Uma prévia das alterações que não grava nada" to="/docs/reference/terminology#running-checks">simulação</Terminology>.
- **Resumo**: uma frase sobre o resultado, incluindo o prefixo anterior após uma <Terminology title="Seu prefixo mudou, então o pacote entra em ação" to="/docs/reference/terminology#baselines-and-transitions">transição de prefixo</Terminology>.
- **Pacotes**: aparece quando a execução alterou as configurações de outro pacote, com uma linha por pacote, como `As configurações do pacote <package> foram aplicadas novamente.` A página [Campos](/docs/configure/configuration-scopes#other-packages-settings) lista cada mensagem.
- **Campos ignorados**: aparece quando campos marcados não existem mais, com `Estes campos selecionados não existem mais, então a execução os ignorou. Revise-os na guia Campos.` e a identidade de cada campo.

É recomendável conferir primeiro o endereço e o prefixo observados. Eles mostram se o pfSense retornou o endereço pretendido e se o comprimento gerou a rede esperada.

A **Última execução** não é atualizada quando outra verificação detém o <Terminology title="Impede que duas verificações rodem ao mesmo tempo" to="/docs/reference/terminology#running-checks">bloqueio de execução</Terminology> ou quando uma execução para antes de ler o <Terminology title="O arquivo com cada referência, mantido mesmo após reinstalar" to="/docs/reference/terminology#running-checks">estado do pacote</Terminology>, por exemplo quando nenhuma interface monitorada tem um <Terminology title="Um endereço IPv6 público em 2000::/3, o único tipo usado" to="/docs/reference/terminology#addresses-and-prefixes">endereço global</Terminology>. Uma <Terminology title="A execução parou em uma verificação ou etapa de segurança" to="/docs/reference/terminology#run-outcomes">Falha</Terminology> sempre mostra `0` campos alterados, como explica [Resultados da execução](/docs/operate/run-outcomes#failures-after-the-save).

### Última execução por interface \{#last-run-by-interface}

Quando você monitora mais de uma interface, a **Última execução** mostra os totais e o **Resumo** conta as interfaces que foram atualizadas, que ficaram sem alterações ou que precisam de atenção. A tabela **Última execução por interface**, logo abaixo, lista cada interface com o próprio resultado, prefixo observado, campos alterados e resumo.

- **Campos alterados**, em **Última execução**, conta cada campo uma única vez, mesmo quando duas interfaces que compartilham um <Terminology title="A rede IPv6 que seu provedor entrega, e que pode mudar" to="/docs/reference/terminology#addresses-and-prefixes">prefixo delegado</Terminology> o planejaram.
- Uma interface sem <Terminology title="Um endereço IPv6 público em 2000::/3, o único tipo usado" to="/docs/reference/terminology#addresses-and-prefixes">endereço global</Terminology> informa <Terminology title="A execução parou em uma verificação ou etapa de segurança" to="/docs/reference/terminology#run-outcomes">Falha</Terminology> na própria linha, enquanto as outras interfaces continuam sendo verificadas.
- Se duas interfaces planejarem valores diferentes para o mesmo campo, a execução para antes de gravar qualquer coisa e informa em qual campo elas divergiram.

## Ações \{#actions}

| Ação                                                                                                                                      | O que faz                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
|-------------------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Executar agora                                                                                                                            | Executa uma verificação completa, mesmo com as <Terminology title="Verificações automáticas agendadas, desligadas até você ativar" to="/docs/reference/terminology#running-checks">atualizações agendadas</Terminology> desativadas. Registra uma <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> quando ainda não existe nenhuma e aplica uma <Terminology title="Seu prefixo mudou, então o pacote entra em ação" to="/docs/reference/terminology#baselines-and-transitions">transição de prefixo</Terminology> quando encontra uma. |
| <Terminology title="Uma prévia das alterações que não grava nada" to="/docs/reference/terminology#running-checks">Simulação</Terminology> | Executa a mesma verificação sem backup e sem gravação. Antes de existir uma <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology>, informa <Terminology title="Uma simulação que mostra a referência que seria registrada" to="/docs/reference/terminology#run-outcomes">Pré-visualização da inicialização</Terminology>.                                                                                                                                                                                                                    |
| Aceitar prefixo atual                                                                                                                     | Após a confirmação, registra o endereço de origem, o prefixo e o comprimento ativos como a nova <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology>. Não inspeciona campos aprovados, não cria backup, não grava a configuração e não recarrega serviços.                                                                                                                                                                                                                                                                                  |

Executar agora e <Terminology title="Uma prévia das alterações que não grava nada" to="/docs/reference/terminology#running-checks">Simulação</Terminology> são <Terminology title="Uma verificação que você inicia, mesmo com o agendamento desligado" to="/docs/reference/terminology#running-checks">execuções manuais</Terminology>. **Aceitar prefixo atual** é uma ação de recuperação e só deve ser usada depois que os endereços salvos e os serviços afetados forem conferidos.

Cada ação exibe um banner de conclusão ou de aviso. A confirmação em **Aceitar prefixo atual** é a última proteção antes que o pacote substitua a referência de comparação.

Uma verificação que encontra outra execução em andamento também exibe o banner de conclusão, por isso é recomendável ler também a <Terminology title="As linhas da última execução, exibidas logo após o início" to="/docs/reference/terminology#running-checks">Saída do comando</Terminology>.

## Saída do comando \{#command-output}

Depois de uma ação, uma caixa somente leitura **Execução mais recente** aparece em **<Terminology title="As linhas da última execução, exibidas logo após o início" to="/docs/reference/terminology#running-checks">Saída do comando</Terminology>**:

```text
Estado: Sem alteração
Interface: lan
Endereço de origem observado: 2001:db8:abcd:78aa::1
Prefixo anterior: 2001:db8:abcd:7800::
Prefixo atual: 2001:db8:abcd:7800::/56
Campos planejados ou alterados: 0
Cópia de segurança da configuração: Não criada
Serviços recarregados: Nenhum
Resumo: O prefixo IPv6 ativo não foi alterado; nenhum destino de configuração aprovado foi lido ou escrito.
```

O prefixo anterior é exibido sem o comprimento. Em vez disso, uma execução que falhou mostra uma única linha que começa com `O Atualizador de prefixo IPv6 falhou:`.

Depois de uma <Terminology title="Uma prévia das alterações que não grava nada" to="/docs/reference/terminology#running-checks">simulação</Terminology> ou de uma alteração, vem `Alterações de campos:` com cada endereço que a execução substituiu, ou substituiria, e o campo a que ele pertence:

```text
Alterações de campos:
- aliases/alias/0/address: 2001:db8:abcd:78aa::10 → 2001:db8:abcd:88aa::10
```

## Escolher os campos \{#choosing-fields}

Os campos que uma execução atualiza são escolhidos na guia **Campos**, que lista todos os endereços dentro do prefixo de cada <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology>. A página [Campos](/docs/configure/configuration-scopes) explica os grupos, as exceções de campos individuais e o grupo Outras configurações.
