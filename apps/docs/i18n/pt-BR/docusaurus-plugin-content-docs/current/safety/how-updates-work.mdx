Acompanhe uma execução desde a leitura dos endereços das interfaces até o registro do resultado, incluindo cada ponto em que ela pode parar.

## 1. Ler e validar \{#1-read-and-validate}

- Uma verificação agendada para imediatamente como <Terminology title="Verificação agendada ignorada porque o agendamento está desligado" to="/docs/reference/terminology#run-outcomes">Desativado</Terminology> quando **<Terminology title="Verificações automáticas agendadas, desligadas até você ativar" to="/docs/reference/terminology#running-checks">Ativar atualizações agendadas</Terminology>** está desmarcada. Uma <Terminology title="Uma verificação que você inicia, mesmo com o agendamento desligado" to="/docs/reference/terminology#running-checks">execução manual</Terminology> continua.
- A execução confere as configurações salvas de novo, porque elas podem ter mudado desde que o formulário foi salvo.
- Ela lê novamente o <Terminology title="Um endereço IPv6 público em 2000::/3, o único tipo usado" to="/docs/reference/terminology#addresses-and-prefixes">endereço global</Terminology> de cada <Terminology title="A interface cujo endereço revela seu prefixo atual" to="/docs/reference/terminology#interfaces-and-detection">Interface monitorada</Terminology>, sem recorrer a um <Terminology title="Um endereço fe80 que nunca é usado como origem" to="/docs/reference/terminology#addresses-and-prefixes">endereço link-local</Terminology>, e o converte para a <Terminology title="A grafia curta em minúsculas, como 2001:db8::1" to="/docs/reference/terminology#addresses-and-prefixes">forma canônica</Terminology>.
- Ela aplica a cada endereço a máscara do <Terminology title="O tamanho do prefixo do seu provedor, como /56; você define" to="/docs/reference/terminology#addresses-and-prefixes">Comprimento do prefixo delegado</Terminology> da linha dele para obter o <Terminology title="O prefixo visto agora, comparado com o anterior" to="/docs/reference/terminology#interfaces-and-detection">prefixo observado</Terminology>.

## 2. Comparar \{#2-compare}

- Sem <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> para a interface, a execução registra uma e termina como <Terminology title="Primeira olhada: a referência é registrada e nada muda" to="/docs/reference/terminology#run-outcomes">Inicializado</Terminology>.
- Quando o prefixo e o comprimento dele correspondem ao <Terminology title="O prefixo salvo com o qual cada verificação compara" to="/docs/reference/terminology#baselines-and-transitions">último prefixo bem-sucedido</Terminology>, a execução termina como <Terminology title="Mesmo prefixo da última vez, então não há nada a fazer" to="/docs/reference/terminology#run-outcomes">Sem alteração</Terminology> sem analisar a configuração.
- Um prefixo ou comprimento diferente é uma <Terminology title="Seu prefixo mudou, então o pacote entra em ação" to="/docs/reference/terminology#baselines-and-transitions">transição de prefixo</Terminology>, e a execução continua.

## 3. Planejar \{#3-plan}

- A execução lê a configuração pelas funções de configuração do pfSense e mantém apenas os campos selecionados na guia Campos. Campos selecionados que não existem mais são ignorados e listados em **Campos ignorados**.
- Cada endereço de um <Terminology title="Uma configuração que o pacote pode reescrever" to="/docs/reference/terminology#fields-and-change-plans">campo aprovado</Terminology> que pertence ao prefixo antigo, no comprimento armazenado, recebe os bits do novo prefixo no comprimento atual e preserva a <Terminology title="Os bits depois do prefixo, sempre copiados sem alteração" to="/docs/reference/terminology#addresses-and-prefixes">parte de host</Terminology>. Juntas, essas alterações formam o <Terminology title="Cada reescrita prevista, montada antes de qualquer mudança" to="/docs/reference/terminology#fields-and-change-plans">plano de alterações</Terminology> completo.
- Sem nada para alterar, a execução termina como <Terminology title="O prefixo mudou, mas nenhum campo aprovado usava o antigo" to="/docs/reference/terminology#run-outcomes">Aviso</Terminology>. Uma <Terminology title="Uma prévia das alterações que não grava nada" to="/docs/reference/terminology#running-checks">simulação</Terminology> com alterações termina aqui como <Terminology title="Uma prévia das alterações que não grava nada" to="/docs/reference/terminology#running-checks">Simulação</Terminology>.

## 4. Verificação prévia \{#4-preflight}

- A execução confirma que o pfSense consegue recarregar todos os serviços do plano. Os <Terminology title="O endereço de uma interface de túnel WireGuard" to="/docs/reference/terminology#pfsense-features">endereços de túnel WireGuard</Terminology> precisam do pacote WireGuard para isso.
- Ela confirma que cada campo planejado ainda tem o valor que tinha quando o plano foi montado.

## 5. Fazer backup e gravar uma vez \{#5-back-up-and-write-once}

- O pfSense cria um <Terminology title="Uma cópia da configuração feita logo antes de qualquer gravação" to="/docs/reference/terminology#backups-and-service-reloads">backup da configuração</Terminology>, e a execução para se o pfSense não confirmá-lo.
- A execução aplica todas as alterações e salva uma única vez, com a descrição `O Atualizador de prefixo IPv6 alterou <count> campo(s) aprovado(s) para a interface <interface>`.
- Se o pfSense informar que a gravação falhou, a execução restaura os valores originais na memória e para.

## 6. Conferir, recarregar, conferir \{#6-verify-reload-verify}

- A execução confere se os valores salvos correspondem ao plano, recarrega os serviços afetados e confere os valores de novo.
- Os serviços são recarregados na ordem fixa que [Ações de recarregamento](/docs/reference/approved-fields#reload-actions) lista, de Interfaces a WireGuard. Um recarregamento de Interfaces é seguido por um recarregamento do filtro do firewall, que depois não se repete.
- Os recarregamentos do filtro do firewall, do DNS Resolver e do DNS Forwarder fazem a execução falhar quando retornam uma falha. Os outros recarregamentos só a fazem falhar quando geram um erro.
- As configurações de outros pacotes são aplicadas novamente por último, depois dos recarregamentos e da verificação deles. Um pacote cujas configurações não podem ser aplicadas é informado, e os valores salvos continuam.
- Uma falha nesta etapa deixa os novos valores salvos.

## 7. Registrar e notificar \{#7-record-and-notify}

- A <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> passa para o novo prefixo, e a **Última execução** registra o <Terminology title="O prefixo mudou e cada campo aprovado foi atualizado" to="/docs/reference/terminology#run-outcomes">Sucesso</Terminology> com a quantidade de campos alterados e os <Terminology title="Aplica as configurações alteradas a um serviço em execução" to="/docs/reference/terminology#backups-and-service-reloads">serviços recarregados</Terminology>.
- A execução grava uma linha no <Terminology title="O log geral do pfSense, onde cada execução deixa linhas" to="/docs/reference/terminology#notifications-and-logs">log do sistema</Terminology> e envia uma <Terminology title="O alerta enviado depois que seus endereços foram atualizados" to="/docs/reference/terminology#notifications-and-logs">notificação de alteração</Terminology>, se ela estiver ativada. Uma notificação que falha não muda o resultado.
