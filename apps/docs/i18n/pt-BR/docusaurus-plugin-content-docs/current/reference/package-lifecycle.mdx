Confira a versão instalada, instale uma versão mais nova ou remova o pacote em um shell do pfSense.

## Conferir a versão instalada \{#check-the-installed-version}

```shell
pkg info pfSense-pkg-Ipv6PrefixUpdater
```

Compare a versão informada com a [versão mais recente no GitHub](https://github.com/mrjackyliang/pfsense-ipv6-prefix-updater/releases/latest).

## Atualizar o pacote \{#update-the-package}

É recomendável baixar antes uma cópia da configuração em **Diagnostics → Backup & Restore**. Depois, instale a versão mais recente por cima do pacote existente:

```shell
pkg add -f https://github.com/mrjackyliang/pfsense-ipv6-prefix-updater/releases/latest/download/pfSense-pkg-Ipv6PrefixUpdater.pkg
```

A etapa de instalação sincroniza de novo as duas entradas cron, a verificação do prefixo e a verificação de versões, com as configurações salvas e mantém todas as <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referências</Terminology>. As etapas de checksum de [Instalar o pacote](/docs/installation#verify-the-download-first) também funcionam para atualizações.

Depois da atualização:

1. Abra **Services → IPv6 Prefix Updater → Configurações** e confirme os valores salvos.
2. Na guia Status, confira o **Estado atual**. Cada interface mantém a própria <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology>.

Se uma linha mostrar `Não inicializado`, **Executar agora** registra uma nova <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> para ela. Os endereços que ainda usam um prefixo anterior a essa referência continuam inalterados.

## Remover o pacote \{#remove-the-package}

Desmarcar antes **<Terminology title="Verificações automáticas agendadas, desligadas até você ativar" to="/docs/reference/terminology#running-checks">Ativar atualizações agendadas</Terminology>** impede que uma reinstalação posterior inicie o agendamento de imediato, caso o pfSense mantenha as configurações salvas. Depois, execute:

```shell
pkg delete -f pfSense-pkg-Ipv6PrefixUpdater
```

O pacote é marcado como `vital`, então as próprias atualizações do pfSense o mantêm instalado, e um `pkg delete` simples recusa pacotes vitais.

A remoção exclui as duas entradas cron (verificação do prefixo e verificação de versões), fecha o alerta de nova versão disponível e remove o arquivo do <Terminology title="Impede que duas verificações rodem ao mesmo tempo" to="/docs/reference/terminology#running-checks">bloqueio de execução</Terminology> quando nenhuma execução o detém. Ela mantém o <Terminology title="O arquivo com cada referência, mantido mesmo após reinstalar" to="/docs/reference/terminology#running-checks">estado do pacote</Terminology>, `updates.json`, `update-status.json` e as cópias da guia **Backups** em `/cf/conf/ipv6-prefix-updater`.

As próprias atualizações do pfSense mantêm o pacote instalado (ele é `vital`), e o estado mantido faz com que uma remoção e reinstalação nunca perca uma <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology>.

A remoção não desfaz endereços já salvos na configuração, e as revisões do pacote continuam no <Terminology title="As revisões de configuração salvas pelo pfSense para restaurar" to="/docs/reference/terminology#backups-and-service-reloads">Config History</Terminology>. Para remover também os arquivos mantidos, execute `rm -rf /cf/conf/ipv6-prefix-updater` depois de remover o pacote.

## Reinstalar depois \{#reinstall-later}

Uma reinstalação encontra o <Terminology title="O arquivo com cada referência, mantido mesmo após reinstalar" to="/docs/reference/terminology#running-checks">estado do pacote</Terminology> mantido, então a primeira execução compara com cada <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> salva e atualiza os campos que ficaram em um prefixo mais antigo. Se as configurações anteriores ainda existirem com **<Terminology title="Verificações automáticas agendadas, desligadas até você ativar" to="/docs/reference/terminology#running-checks">Ativar atualizações agendadas</Terminology>** marcada, a etapa de instalação ativa o agendamento de imediato.

Para começar do zero, exclua `/cf/conf/ipv6-prefix-updater` antes de reinstalar. A primeira execução então registra uma nova <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> e informa <Terminology title="Primeira olhada: a referência é registrada e nada muda" to="/docs/reference/terminology#run-outcomes">Inicializado</Terminology> sem alterar a configuração.

Consulte [Backups e recuperação](/docs/operate/backups-and-recovery) antes da manutenção e [Estabelecer a referência](/docs/first-run) depois de uma reinstalação.
