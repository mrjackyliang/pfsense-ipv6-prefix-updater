Confirme se o seu firewall, a interface e a delegação do provedor atendem aos requisitos do pacote antes de depender das <Terminology title="Verificações automáticas agendadas, desligadas até você ativar" to="/docs/reference/terminology#running-checks">atualizações agendadas</Terminology>.

## Versões compatíveis \{#supported-releases}

- O pacote foi testado no pfSense CE 2.9.0 e 2.8.1 e no pfSense Plus 26.07 e 26.03.1. A aba **Sobre** lista as versões em que cada versão do pacote foi testada e marca a correspondente como **Este firewall**.
- O pacote não verifica a versão do pfSense. Cada execução confere se está rodando no pfSense com os arquivos e as funções que usa e para antes de ler as configurações se algum deles estiver faltando.
- O código do pacote exige PHP 8.1 ou posterior.
- Os pacotes de cada versão são marcados para qualquer versão do FreeBSD (`FreeBSD:*`) e como vital, então um único pacote é instalado em todas as versões compatíveis do pfSense e as atualizações do pfSense o mantêm instalado.

## Requisitos de endereço \{#address-requirements}

- Cada <Terminology title="A interface cujo endereço revela seu prefixo atual" to="/docs/reference/terminology#interfaces-and-detection">Interface monitorada</Terminology> precisa de um <Terminology title="Um endereço IPv6 público em 2000::/3, o único tipo usado" to="/docs/reference/terminology#addresses-and-prefixes">endereço unicast global</Terminology> ativo. O pacote nunca recorre a um <Terminology title="Um endereço fe80 que nunca é usado como origem" to="/docs/reference/terminology#addresses-and-prefixes">endereço link-local</Terminology>.
- Endereços locais únicos (`fc00::/7`), multicast, de loopback, não especificados, mapeados de IPv4 e com identificador de zona não podem ser o <Terminology title="O endereço ao vivo do qual cada execução lê o prefixo" to="/docs/reference/terminology#interfaces-and-detection">endereço de origem</Terminology>.
- O <Terminology title="O tamanho do prefixo do seu provedor, como /56; você define" to="/docs/reference/terminology#addresses-and-prefixes">Comprimento do prefixo delegado</Terminology> precisa estar entre `/48` e `/64`. Comprimentos que terminam no meio de um dígito hexadecimal, como `/57`, também funcionam.

Quando um endereço não atende aos requisitos, essa interface termina em <Terminology title="A execução parou em uma verificação ou etapa de segurança" to="/docs/reference/terminology#run-outcomes">Falha</Terminology> com um motivo como `A interface "lan" não tem um endereço IPv6 global ativo.` A página [Solução de problemas](/docs/operate/troubleshooting#run-failed) lista as mensagens.

## Quando a WAN não tem endereço global \{#when-wan-has-no-global-address}

Alguns provedores delegam um prefixo sem dar à WAN um <Terminology title="Um endereço IPv6 público em 2000::/3, o único tipo usado" to="/docs/reference/terminology#addresses-and-prefixes">endereço global</Terminology> próprio. Nesse caso, uma <Terminology title="Uma interface que monta o IPv6 a partir do prefixo de outra" to="/docs/reference/terminology#interfaces-and-detection">interface rastreada</Terminology>, como a LAN, recebe um endereço do <Terminology title="A rede IPv6 que seu provedor entrega, e que pode mudar" to="/docs/reference/terminology#addresses-and-prefixes">prefixo delegado</Terminology> e é ela que deve ser monitorada.

**Status → Interfaces** mostra quais interfaces têm um <Terminology title="Um endereço IPv6 público em 2000::/3, o único tipo usado" to="/docs/reference/terminology#addresses-and-prefixes">endereço global</Terminology>.

## O que o pacote reconhece \{#what-the-package-recognizes}

O pacote atualiza endereços e redes IPv6 literais em <Terminology title="Uma configuração que o pacote pode reescrever" to="/docs/reference/terminology#fields-and-change-plans">campos aprovados</Terminology>. Nomes de host, URLs, valores IPv4 e outros textos continuam como estão.

Endereços gerados pelo pfSense, como os de <Terminology title="Uma interface que monta o IPv6 a partir do prefixo de outra" to="/docs/reference/terminology#interfaces-and-detection">interfaces rastreadas</Terminology>, nunca são alterados. Endereços que descrevem outros dispositivos, como redes VPN remotas e peers do WireGuard, só mudam quando você os marca em [Outras configurações](/docs/configure/configuration-scopes#other-settings).

## Dependências opcionais \{#optional-dependencies}

- **Pacote WireGuard**: necessário apenas quando os <Terminology title="O endereço de uma interface de túnel WireGuard" to="/docs/reference/terminology#pfsense-features">endereços de túnel WireGuard</Terminology> precisam mudar. Sem ele, uma execução real com alterações no WireGuard para antes do backup.

## Limitações conhecidas \{#known-limits}

- Adicionar uma <Terminology title="A interface cujo endereço revela seu prefixo atual" to="/docs/reference/terminology#interfaces-and-detection">Interface monitorada</Terminology>, ou trocar uma linha para outra interface, registra uma nova <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> para ela, e alterar o <Terminology title="O tamanho do prefixo do seu provedor, como /56; você define" to="/docs/reference/terminology#addresses-and-prefixes">Comprimento do prefixo delegado</Terminology> de uma linha conta como <Terminology title="Seu prefixo mudou, então o pacote entra em ação" to="/docs/reference/terminology#baselines-and-transitions">transição de prefixo</Terminology>.
- Uma <Terminology title="Uma prévia das alterações que não grava nada" to="/docs/reference/terminology#running-checks">simulação</Terminology> não consegue simular uma mudança de prefixo, por isso as alterações planejadas só aparecem depois de uma mudança real.
- Pares de alta disponibilidade (CARP) não recebem tratamento especial.
- Como se trata de um <Terminology title="Instalado pelo GitHub, não pelo repositório de pacotes da Netgate" to="/docs/reference/terminology#package-origins">pacote não oficial</Terminology>, as versões mais novas são instaladas com o `pkg`, conforme descrito em [Atualizar ou remover](/docs/reference/package-lifecycle).

Consulte [Interface e prefixo](/docs/configure/interface-and-prefix) para escolher a origem e [Campos](/docs/configure/configuration-scopes) para ver os campos que o pacote pode alterar.
