Verifique, prepare e empacote o pfSense IPv6 Prefix Updater e depois publique o pacote em uma release do GitHub.

## Requisitos \{#requirements}

- **Node.js 22 ou 24** — Os manifestos da raiz e do workspace aceitam `^22 || ^24`.
- **PHP ou Docker** — As suítes PHP usam um `php` local quando existe, ou a imagem `php:8.3-cli-alpine` pelo Docker. `PHP_TEST_IMAGE` substitui a imagem.
- **FreeBSD para o empacotamento** — `npm run deploy` só roda no FreeBSD, com `PFSENSE_PORTS_DIR` apontando para um checkout do FreeBSD-ports do pfSense.

## Verificar, preparar e empacotar \{#check-stage-and-package}

Execute estes comandos a partir da raiz do repositório:

```bash
# Lint and type-check the scripts, run the PHP and Vitest suites, and validate the port.
npm run check --workspace pfsense-pkg-ipv6-prefix-updater

# Copy the port into packages/ipv6-prefix-updater/build/port with the workspace version.
npm run build --workspace pfsense-pkg-ipv6-prefix-updater

# Build the package on FreeBSD into packages/ipv6-prefix-updater/build/release.
PFSENSE_PORTS_DIR=/path/to/FreeBSD-ports npm run deploy --workspace pfsense-pkg-ipv6-prefix-updater
```

- A preparação transforma `port/Makefile.template` em `build/port/Makefile` e grava nele a `version` de `packages/ipv6-prefix-updater/package.json`.
- O empacotamento copia o port preparado para `sysutils/pfSense-pkg-Ipv6PrefixUpdater` no checkout dos ports, executa `make package` e remove essa cópia em seguida. Ele para se o destino já existir.
- Depois disso, `build/release` contém o `.pkg` com versão, uma cópia chamada `pfSense-pkg-Ipv6PrefixUpdater.pkg` e um arquivo `.sha256` para cada um, contendo apenas o hash.

## Workflow de release \{#release-workflow}

`.github/workflows/pfsense-ipv6-prefix-updater.yml` roda quando uma release do GitHub é publicada, ou manualmente com a tag de uma release existente:

1. Valida e prepara o port em um runner Ubuntu.
2. Inicia uma VM FreeBSD cuja versão vem da variável de repositório `PFSENSE_FREEBSD_VERSION`, ou `15` quando ela não está definida.
3. Faz checkout do branch `devel` do repositório FreeBSD-ports do pfSense e executa o build do pacote.
4. Envia `build/release` como artefato do workflow, mantido por 7 dias, e anexa os mesmos arquivos à release, substituindo os assets existentes.

É recomendável definir `PFSENSE_FREEBSD_VERSION` com a versão principal do FreeBSD da versão do pfSense que você tem como alvo, e não publicar um pacote compilado para outra versão principal. O comando `pkg add` do guia de instalação baixa `pfSense-pkg-Ipv6PrefixUpdater.pkg` da release que o GitHub marca como mais recente.

## Suítes de testes PHP \{#php-test-suites}

- **`tests/domain.php`**: <Terminology title="grafia padrão mais curta de um endereço, em minúsculas" to="/docs/reference/terminology#canonical-form">forma canônica</Terminology>, os limites `/48` e `/64`, aplicação de máscara, <Terminology title="bits do endereço após o prefixo delegado" to="/docs/reference/terminology#host-portion">bits de host</Terminology> em `/53`, endereços rejeitados, planejamento no-op, filtragem pelo prefixo anterior e uma alteração de comprimento tratada como <Terminology title="mudança em relação ao último prefixo ou comprimento bem-sucedido" to="/docs/reference/terminology#prefix-transition">transição de prefixo</Terminology>.
- **`tests/runtime.php`**: análise de todos os <Terminology title="grupo de campos com uma única chave na guia Campos" to="/docs/reference/terminology#field-group">grupos de campos</Terminology>, exceções de campos individuais, reaplicação das configurações de outros pacotes, <Terminology title="arquivo do pacote com referência e última execução" to="/docs/reference/terminology#package-state">estado do pacote</Terminology> atômico, o <Terminology title="proteção que impede duas verificações ao mesmo tempo" to="/docs/reference/terminology#run-lock">bloqueio de execução</Terminology>, plataformas não suportadas e verificações agendadas desativadas. Também cobre a ordem da transação e as falhas na gravação, no backup, na verificação prévia de recarregamento, nos recarregamentos e na notificação, além do <Terminology title="resultado: o prefixo mudou, mas nenhum campo aprovado correspondeu" to="/docs/reference/terminology#warning">Aviso</Terminology> sem correspondências.
- **`tests/pfsense-adapter.php`**: uma atualização forçada do endereço sem fallback para <Terminology title="endereço fe80:: que só funciona em um link" to="/docs/reference/terminology#link-local-address">link-local</Terminology>, o backup antes de uma gravação que não cria outro backup e um backup com falha que para antes da gravação.
- **`tests/translations.php`** e **`tests/webgui-localization.php`**: catálogos completos para cada identificador de idioma do pfSense, além do formulário de Configurações e das mensagens de validação traduzidos.

## Site de documentação \{#documentation-site}

Em `apps/docs`, `npm run check` executa o ESLint, a verificação da árvore de traduções, três verificações de tipos e as suítes do Vitest para arquivos `.env`, frontmatter, links, tabelas, links do glossário e declarações de tipos. `npm run build` gera o build de todos os idiomas.

As páginas de documentação traduzidas de cada idioma ficam em `apps/docs/i18n/<locale>/docusaurus-plugin-content-docs/current/` e espelham as páginas em inglês, então atualize-as quando uma página em inglês mudar. O texto da interface (página inicial, barra de navegação, rodapé, blog e rótulos da barra lateral) vem de `scripts/generate-locales.mjs`, que lê `scripts/locale-copies.json` e as traduções do pacote. `npm run i18n` executa esse gerador primeiro, e ele preserva as páginas de documentação traduzidas.

`.github/workflows/nova-publish-project.yml` gera o build do site e o publica no GitHub Pages quando uma release é publicada.
