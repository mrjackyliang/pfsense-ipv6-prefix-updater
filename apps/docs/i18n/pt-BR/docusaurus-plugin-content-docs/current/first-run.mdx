Registre o prefixo atual como <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> e confira-o antes de ativar as <Terminology title="Verificações automáticas agendadas, desligadas até você ativar" to="/docs/reference/terminology#running-checks">atualizações agendadas</Terminology>.

## Salvar as configurações iniciais \{#save-the-initial-settings}

1. Abra **Services → IPv6 Prefix Updater** e depois a guia **Configurações**.
2. Deixe a opção **<Terminology title="Verificações automáticas agendadas, desligadas até você ativar" to="/docs/reference/terminology#running-checks">Ativar atualizações agendadas</Terminology>** desmarcada.
3. Adicione uma linha em **<Terminology title="A interface cujo endereço revela seu prefixo atual" to="/docs/reference/terminology#interfaces-and-detection">Interfaces monitoradas</Terminology>** para cada interface cujo <Terminology title="Um endereço IPv6 público em 2000::/3, o único tipo usado" to="/docs/reference/terminology#addresses-and-prefixes">endereço global</Terminology> vem do <Terminology title="A rede IPv6 que seu provedor entrega, e que pode mudar" to="/docs/reference/terminology#addresses-and-prefixes">prefixo delegado</Terminology>, conforme descrito em [Interface e prefixo](/docs/configure/interface-and-prefix).
4. Em cada linha, selecione o **<Terminology title="O tamanho do prefixo do seu provedor, como /56; você define" to="/docs/reference/terminology#addresses-and-prefixes">Comprimento do prefixo delegado</Terminology>** que o seu provedor delega.
5. Salve e confirme a mensagem `Configurações salvas.`

## Executar a primeira verificação \{#run-the-first-check}

Na guia **Status**, clique em **Executar agora**. Como ainda não há <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology>, a execução registra o <Terminology title="O endereço ao vivo do qual cada execução lê o prefixo" to="/docs/reference/terminology#interfaces-and-detection">endereço de origem</Terminology> e o prefixo de cada interface e informa <Terminology title="Primeira olhada: a referência é registrada e nada muda" to="/docs/reference/terminology#run-outcomes">Inicializado</Terminology>.

Registrar uma <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> não altera a configuração, não cria backup e não envia notificação.

## Conferir o resultado \{#verify-the-result}

Confira estes valores em cada linha de **Estado atual**:

- **<Terminology title="A interface cujo endereço revela seu prefixo atual" to="/docs/reference/terminology#interfaces-and-detection">Interface monitorada</Terminology>** mostra a interface pretendida pela descrição e pelo nome interno, como `LAN (lan)`.
- **<Terminology title="O endereço ao vivo do qual cada execução lê o prefixo" to="/docs/reference/terminology#interfaces-and-detection">Último endereço de origem bem-sucedido</Terminology>** corresponde ao endereço dessa interface em **Status → Interfaces**.
- **<Terminology title="O prefixo salvo com o qual cada verificação compara" to="/docs/reference/terminology#baselines-and-transitions">Último prefixo bem-sucedido</Terminology>** corresponde ao prefixo que o seu provedor delega.
- **Última atualização bem-sucedida** mostra o horário desta execução em UTC.

A <Terminology title="As linhas da última execução, exibidas logo após o início" to="/docs/reference/terminology#running-checks">Saída do comando</Terminology> deve mostrar `Estado: Inicializado`, `Campos planejados ou alterados: 0` e `Cópia de segurança da configuração: Não criada`. Por exemplo, o endereço de documentação `2001:db8:abcd:78aa::1` com comprimento `/56` pertence a `2001:db8:abcd:7800::/56`.

:::warning

Se a interface ou o comprimento estiverem errados, é recomendável corrigir as Configurações antes de ativar o agendamento. Uma interface diferente registra uma nova <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology>, enquanto um comprimento diferente conta como <Terminology title="Seu prefixo mudou, então o pacote entra em ação" to="/docs/reference/terminology#baselines-and-transitions">transição de prefixo</Terminology>, como explica [Interface e prefixo](/docs/configure/interface-and-prefix#changing-the-prefix-length).

:::

## Revisar os campos \{#review-the-fields}

Abra a guia **Campos**. Com a <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> registrada, ela lista todos os endereços dentro do prefixo e quais deles a próxima mudança atualizaria.

1. Desative os <Terminology title="Um único botão para um tipo inteiro de configuração" to="/docs/reference/terminology#fields-and-change-plans">grupos de campos</Terminology> que o firewall não usa. Os onze grupos do pfSense começam ativados.
2. Desmarque os campos individuais que devem manter o valor e marque qualquer campo de outro pacote que deva acompanhar o prefixo.
3. Marque em **Outras configurações** qualquer campo que deva acompanhar o prefixo, como um gateway ou uma rota estática.
4. Clique em **Salvar** e confirme a mensagem `Seleção de campos salva.`

A página [Campos](/docs/configure/configuration-scopes) explica cada grupo e cada controle.

## O que uma simulação mostra agora \{#what-a-dry-run-shows-now}

Com o prefixo inalterado, a **<Terminology title="Uma prévia das alterações que não grava nada" to="/docs/reference/terminology#running-checks">Simulação</Terminology>** informa <Terminology title="Mesmo prefixo da última vez, então não há nada a fazer" to="/docs/reference/terminology#run-outcomes">Sem alteração</Terminology> sem analisar a configuração, porque o planejamento só começa depois de uma <Terminology title="Seu prefixo mudou, então o pacote entra em ação" to="/docs/reference/terminology#baselines-and-transitions">transição de prefixo</Terminology> real. A guia Campos mostra quais campos uma alteração futura afetaria.

Uma <Terminology title="Uma prévia das alterações que não grava nada" to="/docs/reference/terminology#running-checks">simulação</Terminology> feita antes de existir uma <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> informa <Terminology title="Uma simulação que mostra a referência que seria registrada" to="/docs/reference/terminology#run-outcomes">Pré-visualização da inicialização</Terminology> e não registra nada.

## Ativar o agendamento \{#turn-on-the-schedule}

Quando os valores estiverem corretos, marque **<Terminology title="Verificações automáticas agendadas, desligadas até você ativar" to="/docs/reference/terminology#running-checks">Ativar atualizações agendadas</Terminology>**, escolha um **Agendamento** e salve. [Agendamento e notificações](/docs/configure/schedule-and-notifications) explica cada opção.

Depois do primeiro horário agendado, **Data e hora (UTC)** em **Última execução** mostra quando essa verificação rodou.

Siga para [Verificar antes de automatizar](/docs/safety/testing-and-verification) para ver um checklist completo.
