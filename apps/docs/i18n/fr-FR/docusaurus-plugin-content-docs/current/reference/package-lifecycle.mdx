Vérifiez la version installée, installez une version plus récente ou supprimez le paquet depuis un shell pfSense.

## Vérifier la version installée \{#check-the-installed-version}

```shell
pkg info pfSense-pkg-Ipv6PrefixUpdater
```

Comparez la version indiquée avec la [dernière version publiée sur GitHub](https://github.com/mrjackyliang/pfsense-ipv6-prefix-updater/releases/latest).

## Mettre à jour le paquet \{#update-the-package}

Il est recommandé de télécharger d’abord une copie de la configuration depuis **Diagnostics → Backup & Restore**. Installez ensuite la dernière version par-dessus le paquet existant :

```shell
pkg add -f https://github.com/mrjackyliang/pfsense-ipv6-prefix-updater/releases/latest/download/pfSense-pkg-Ipv6PrefixUpdater.pkg
```

L’étape d’installation resynchronise les deux entrées cron, celle de la vérification du préfixe et celle de la recherche de mises à jour, avec les paramètres enregistrés et conserve chaque <Terminology title="Le préfixe de départ enregistré, qui sert à mesurer les changements" to="/docs/reference/terminology#baselines-and-transitions">référence</Terminology>. Les étapes de vérification de la somme de contrôle décrites dans [Installer le paquet](/docs/installation#verify-the-download-first) valent aussi pour les mises à jour.

Après la mise à jour :

1. Ouvrez **Services → IPv6 Prefix Updater → Paramètres** et vérifiez les valeurs enregistrées.
2. Dans l’onglet État, contrôlez **État actuel**. Chaque interface conserve sa <Terminology title="Le préfixe de départ enregistré, qui sert à mesurer les changements" to="/docs/reference/terminology#baselines-and-transitions">référence</Terminology>.

Si une ligne affiche `Non initialisé`, **Exécuter maintenant** enregistre une nouvelle <Terminology title="Le préfixe de départ enregistré, qui sert à mesurer les changements" to="/docs/reference/terminology#baselines-and-transitions">référence</Terminology> pour celle-ci. Les adresses qui utilisent encore un préfixe antérieur à cette référence restent alors inchangées.

## Supprimer le paquet \{#remove-the-package}

Décocher d’abord **<Terminology title="Vérifications automatiques planifiées, désactivées par défaut" to="/docs/reference/terminology#running-checks">Activer les mises à jour planifiées</Terminology>** évite qu’une réinstallation ultérieure lance aussitôt la planification si pfSense conserve les paramètres enregistrés. Exécutez ensuite :

```shell
pkg delete -f pfSense-pkg-Ipv6PrefixUpdater
```

Le paquet est marqué `vital`, donc les mises à niveau de pfSense le conservent et un simple `pkg delete` refuse les paquets marqués `vital`.

La suppression efface les deux entrées cron (vérification du préfixe et recherche de mises à jour), ferme l’alerte de nouvelle version disponible et supprime le fichier de <Terminology title="Empêche deux vérifications de tourner en même temps" to="/docs/reference/terminology#running-checks">verrou d’exécution</Terminology> quand aucune exécution ne le détient. Elle conserve l’<Terminology title="Le fichier qui garde chaque référence, même après réinstallation" to="/docs/reference/terminology#running-checks">état du paquet</Terminology>, `updates.json`, `update-status.json` et les copies de l’onglet **Sauvegardes** dans `/cf/conf/ipv6-prefix-updater`.

Les mises à niveau de pfSense conservent le paquet installé (il est `vital`), et l’état conservé évite qu’une suppression suivie d’une réinstallation ne fasse perdre une <Terminology title="Le préfixe de départ enregistré, qui sert à mesurer les changements" to="/docs/reference/terminology#baselines-and-transitions">référence</Terminology>.

La suppression n’annule pas les adresses déjà enregistrées dans la configuration, et les révisions du paquet restent dans <Terminology title="Les révisions de configuration enregistrées par pfSense, à restaurer" to="/docs/reference/terminology#backups-and-service-reloads">Config History</Terminology>. Pour effacer aussi les fichiers conservés, exécutez `rm -rf /cf/conf/ipv6-prefix-updater` après avoir supprimé le paquet.

## Réinstaller plus tard \{#reinstall-later}

Une réinstallation retrouve l’<Terminology title="Le fichier qui garde chaque référence, même après réinstallation" to="/docs/reference/terminology#running-checks">état du paquet</Terminology> conservé ; la première exécution se compare donc à chaque <Terminology title="Le préfixe de départ enregistré, qui sert à mesurer les changements" to="/docs/reference/terminology#baselines-and-transitions">référence</Terminology> enregistrée et met à jour les champs restés sur un ancien préfixe. Si les anciens paramètres sont toujours présents avec la case **<Terminology title="Vérifications automatiques planifiées, désactivées par défaut" to="/docs/reference/terminology#running-checks">Activer les mises à jour planifiées</Terminology>** cochée, l’étape d’installation active aussitôt la planification.

Pour repartir de zéro, supprimez `/cf/conf/ipv6-prefix-updater` avant la réinstallation. La première exécution enregistre alors une nouvelle <Terminology title="Le préfixe de départ enregistré, qui sert à mesurer les changements" to="/docs/reference/terminology#baselines-and-transitions">référence</Terminology> et signale <Terminology title="Premier passage : la référence est enregistrée, rien ne change" to="/docs/reference/terminology#run-outcomes">Initialisé</Terminology> sans modifier la configuration.

Consultez [Sauvegardes et récupération](/docs/operate/backups-and-recovery) avant une maintenance et [Établir la référence](/docs/first-run) après une réinstallation.
