Lancez la commande du paquet depuis un shell et retrouvez les fichiers, journaux et alertes qu’elle utilise.

## Utilisation \{#usage}

```shell
/usr/local/sbin/ipv6-prefix-updater [--manual] [--dry-run] [--accept-current-prefix [--interface=NAME]] [--migrate-legacy] [--help]
```

L’entrée cron gérée par pfSense lance la commande en tant que `root`, sans option. Avant chaque vérification, la commande déplace aussi dans le paquet les éventuels restes de l’<Terminology title="script update.php d’origine lancé par le paquet Cron" to="/docs/reference/terminology#legacy-updater">ancien script de mise à jour</Terminology>. L’onglet État utilise `--manual` pour **Exécuter maintenant**, `--dry-run` pour **<Terminology title="aperçu qui ne sauvegarde ni n’écrit jamais" to="/docs/reference/terminology#dry-run">Simulation</Terminology>** et `--accept-current-prefix` pour la récupération de la référence, et l’onglet Nettoyage utilise `--migrate-legacy`.

Sans option, la commande se comporte comme une vérification planifiée et signale <Terminology title="résultat : vérification planifiée ignorée, mises à jour désactivées" to="/docs/reference/terminology#disabled">Désactivé</Terminology> quand la case **<Terminology title="vérifications automatiques via une entrée cron gérée par pfSense" to="/docs/reference/terminology#scheduled-updates">Activer les mises à jour planifiées</Terminology>** est décochée.

## Options \{#options}

| Option                    | Description                                                                                                                                                                                                                                                                                                                                             |
|---------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `--manual`                | S’exécute même quand les <Terminology title="vérifications automatiques via une entrée cron gérée par pfSense" to="/docs/reference/terminology#scheduled-updates">mises à jour planifiées</Terminology> sont désactivées.                                                                                                                               |
| `--dry-run`               | Prévisualise sans sauvegarde ni écriture, et implique `--manual`.                                                                                                                                                                                                                                                                                       |
| `--accept-current-prefix` | Enregistre l’adresse source, le préfixe et la longueur actifs comme référence, sans analyser les champs approuvés, créer de sauvegarde, écrire la configuration ni recharger de service. Implique `--manual` et ne peut pas être combinée avec `--dry-run`.                                                                                             |
| `--interface=NAME`        | Limite `--accept-current-prefix` à une seule interface surveillée, désignée par son nom interne, comme `lan`. Sans cette option, chaque interface surveillée qui a une adresse est acceptée.                                                                                                                                                            |
| `--migrate-legacy`        | Déplace immédiatement l’<Terminology title="script update.php d’origine lancé par le paquet Cron" to="/docs/reference/terminology#legacy-updater">ancien script de mise à jour</Terminology> dans le paquet et affiche chaque étape, sans lancer de vérification du préfixe. Se termine avec le code `2` quand la migration a signalé un avertissement. |
| `--help`                  | Affiche la ligne d’utilisation et se termine avec le code `0`. La ligne d’utilisation ne mentionne pas `--help` elle-même.                                                                                                                                                                                                                              |

Toute autre option affiche `Option inconnue : <option>` sur la sortie d’erreur standard et se termine avec le code `64`. Combiner `--accept-current-prefix` avec `--dry-run` se termine aussi avec le code `64`.

|------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `0`  | <Terminology title="résultat : référence enregistrée, configuration inchangée" to="/docs/reference/terminology#initialized">Initialisé</Terminology>, <Terminology title="résultat : simulation lancée avant toute référence" to="/docs/reference/terminology#initialization-preview">Aperçu de l’initialisation</Terminology>, <Terminology title="résultat : préfixe inchangé, rien d’analysé ni d’écrit" to="/docs/reference/terminology#no-change">Aucun changement</Terminology>, <Terminology title="aperçu qui ne sauvegarde ni n’écrit jamais" to="/docs/reference/terminology#dry-run">Simulation</Terminology>, **Accepté**, <Terminology title="résultat : champs mis à jour, enregistrés, rechargés et vérifiés" to="/docs/reference/terminology#success">Réussite</Terminology> ou <Terminology title="résultat : vérification planifiée ignorée, mises à jour désactivées" to="/docs/reference/terminology#disabled">Désactivé</Terminology>. | `1`  | <Terminology title="résultat : une vérification ou une étape de sécurité a arrêté l’exécution" to="/docs/reference/terminology#failure">Échec</Terminology>. | `2`  | <Terminology title="résultat : préfixe changé, mais aucun champ approuvé correspondant" to="/docs/reference/terminology#warning">Avertissement</Terminology>.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `64` | Option inconnue.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

## Sortie \{#output}

Une exécution terminée qui surveille une seule interface affiche neuf lignes sur la sortie standard, suivies des modifications des champs après une <Terminology title="aperçu qui ne sauvegarde ni n’écrit jamais" to="/docs/reference/terminology#dry-run">simulation</Terminology> ou une <Terminology title="résultat : champs mis à jour, enregistrés, rechargés et vérifiés" to="/docs/reference/terminology#success">Réussite</Terminology> :

```text
État: Réussite
Interface: lan
Adresse source observée: 2001:db8:abcd:88aa::1
Préfixe précédent: 2001:db8:abcd:7800::
Préfixe actuel: 2001:db8:abcd:8800::/56
Champs planifiés ou modifiés: 1
Sauvegarde de configuration: Créée
Services rechargés: Filtre du pare-feu
Résumé: 1 champ(s) approuvé(s) ont été mis à jour de 2001:db8:abcd:7800::/56 vers 2001:db8:abcd:8800::/56 sur l’interface lan.
Modifications des champs:
- aliases/alias/0/address: 2001:db8:abcd:78aa::10 → 2001:db8:abcd:88aa::10
```

- La ligne `Préfixe précédent` n’indique pas de longueur et affiche `Non disponible` après <Terminology title="résultat : référence enregistrée, configuration inchangée" to="/docs/reference/terminology#initialized">Initialisé</Terminology> ou <Terminology title="résultat : simulation lancée avant toute référence" to="/docs/reference/terminology#initialization-preview">Aperçu de l’initialisation</Terminology>.
- La ligne `Services rechargés` liste les libellés de l’onglet État ou `Aucun`. Après une <Terminology title="aperçu qui ne sauvegarde ni n’écrit jamais" to="/docs/reference/terminology#dry-run">simulation</Terminology>, elle liste les services qui seraient rechargés.
- La partie `Modifications des champs` comporte une ligne par adresse remplacée, au format `- <path>: <old> → <new>`, pour 200 champs au maximum.
- Quand l’exécution a appliqué de nouveau les paramètres d’un autre paquet ou ignoré un champ coché qui n’existe plus, une ligne s’ajoute pour chaque cas, rédigée comme dans l’onglet État.
- Quand une autre vérification détient le <Terminology title="verrou qui empêche deux vérifications simultanées" to="/docs/reference/terminology#run-lock">verrou d’exécution</Terminology>, la seule sortie est `Une autre exécution détient le verrou du paquet ; cet appel s’est arrêté sans lire la configuration.`
- Avec plusieurs interfaces surveillées, la sortie commence par les lignes globales `État` et `Résumé` et par les lignes des paquets et des champs ignorés, suivies des lignes de chaque interface, chaque bloc étant séparé par une ligne vide.
- Quand une migration de l’<Terminology title="script update.php d’origine lancé par le paquet Cron" to="/docs/reference/terminology#legacy-updater">ancien script de mise à jour</Terminology> a eu lieu avant la vérification, ses étapes sont affichées en premier.
- Les libellés et les messages suivent la langue configurée dans pfSense.

## Format de l’état du paquet \{#package-state-format}

| Clé                   | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
|-----------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `schema_version`      | Toujours `1`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `targets.<interface>` | Une <Terminology title="préfixe de départ enregistré sans modifier la configuration" to="/docs/reference/terminology#baseline">référence</Terminology> par interface surveillée, indexée par son nom interne, avec `interface`, `source_address`, `prefix`, `prefix_length` et `updated_at`. Une référence reprise de l’<Terminology title="script update.php d’origine lancé par le paquet Cron" to="/docs/reference/terminology#legacy-updater">ancien script de mise à jour</Terminology> contient aussi `source`, qui vaut `legacy_cache`. |
| `last_run`            | La dernière exécution enregistrée, avec `status`, `timestamp`, `interface`, `observed_address`, `previous_prefix`, `current_prefix`, `current_prefix_length`, `change_count`, `backup_created`, `services`, `message`, `message_key` et `message_arguments`.                                                                                                                                                                                                                                                                                   |
| `legacy_migration`    | Présent après une migration de l’<Terminology title="script update.php d’origine lancé par le paquet Cron" to="/docs/reference/terminology#legacy-updater">ancien script de mise à jour</Terminology>, avec `status`, `steps`, `warnings` et `recorded_at`. L’onglet Nettoyage l’affiche.                                                                                                                                                                                                                                                      |

- `status` vaut `initialized`, `initialization_preview`, `no_change`, `dry_run`, `warning`, `accepted`, `success` ou `failure`.
- Après une <Terminology title="résultat : champs mis à jour, enregistrés, rechargés et vérifiés" to="/docs/reference/terminology#success">Réussite</Terminology>, `last_run.notification` vaut `disabled` quand les notifications sont désactivées, ou `sent` ou `failed` après une tentative d’envoi.
- Après une <Terminology title="aperçu qui ne sauvegarde ni n’écrit jamais" to="/docs/reference/terminology#dry-run">simulation</Terminology> ou une <Terminology title="résultat : champs mis à jour, enregistrés, rechargés et vérifiés" to="/docs/reference/terminology#success">Réussite</Terminology>, chaque résultat contient aussi `changes`, qui liste le `path` et les `replacements` de 200 champs au maximum, chaque remplacement étant une ancienne et une nouvelle adresse.
- `package_reapply` indique, pour chaque paquet dont l’exécution a appliqué de nouveau les paramètres, ses clés `section`, `package`, `status` et `error`, et `skipped_fields` liste les champs cochés qui n’existent plus. Chacune de ces listes n’apparaît que si elle n’est pas vide.
- Avec plusieurs interfaces surveillées, `last_run` contient les totaux et une liste `targets` avec un résultat par interface.
- Les horodatages utilisent le format ISO 8601 en UTC. Un fichier illisible, ou dont la version de schéma est différente, arrête chaque exécution avec `L’état d’IPv6 Prefix Updater est invalide ou non pris en charge.`

## Stockage des paramètres \{#settings-storage}

Les paramètres se trouvent dans la configuration de pfSense, à `installedpackages/ipv6prefixupdater/config/0`.

| Clé                | Description                                                                                                                                                                                                    |
|--------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `enabled`          | **<Terminology title="vérifications automatiques via une entrée cron gérée par pfSense" to="/docs/reference/terminology#scheduled-updates">Activer les mises à jour planifiées</Terminology>**, `on` si coché. |
| `row`              | **Interfaces surveillées**, une liste avec, pour chaque ligne, un champ `interface` (une clé d’interface comme `lan`) et un champ `prefix_length` (de `48` à `64`).                                            |
| `update_frequency` | **Planification**, parmi `every_fifteen_minutes`, `hourly`, `every_six_hours` ou `daily`.                                                                                                                      |
| `notifications`    | **<Terminology title="alerte envoyée après une mise à jour réussie et vérifiée" to="/docs/reference/terminology#change-notification">Envoyer les notifications de changement</Terminology>**, `on` si coché.   |

### Sélection des champs \{#field-selection}

Les choix de l’onglet Champs se trouvent à côté de l’enregistrement des paramètres, à `installedpackages/ipv6prefixupdater/fields` ; enregistrer l’onglet Paramètres, qui remplace `config/0`, ne les efface donc jamais.

| Clé                    | Description                                                                                                                    |
|------------------------|--------------------------------------------------------------------------------------------------------------------------------|
| `schema`               | Toujours `1`. Marque une sélection enregistrée depuis l’onglet Champs, même vide.                                              |
| `enabled_groups/item`  | Groupes activés, comme `firewall_rules`, `dhcpv6` ou `package:<section>` pour les paramètres d’un autre paquet.                |
| `disabled_groups/item` | Groupes pfSense désactivés. Un groupe pfSense absent des deux listes est activé, et le groupe d’un autre paquet est désactivé. |
| `include/item`         | Identités des champs cochés dans un groupe désactivé.                                                                          |
| `exclude/item`         | Identités des champs décochés dans un groupe activé.                                                                           |

- Les clés des groupes pfSense sont `interfaces`, `virtual_ips`, `aliases`, `firewall_rules`, `nat`, `dhcpv6`, `router_advertisements`, `dns_host_overrides`, `ipsec`, `openvpn` et `wireguard`.
- `include` et `exclude` conservent chacune au plus 1 000 identités, et chaque identité suit le format décrit dans [Identités des champs](/docs/reference/approved-fields#field-identities).

## Entrée cron \{#cron-entry}

L’enregistrement des paramètres supprime toute entrée existante pour la commande et, quand `enabled` vaut `on`, en installe une nouvelle pour `root` avec la fonction `install_cron_job()` de pfSense.

| Valeur de planification | Champs cron    |
|-------------------------|----------------|
| `every_fifteen_minutes` | `*/15 * * * *` |
| `hourly`                | `0 * * * *`    |
| `every_six_hours`       | `0 */6 * * *`  |
| `daily`                 | `0 0 * * *`    |

Une valeur inconnue se rabat sur les champs horaires. Tant qu’une migration de l’<Terminology title="script update.php d’origine lancé par le paquet Cron" to="/docs/reference/terminology#legacy-updater">ancien script de mise à jour</Terminology> attend la fin de l’ancien script, le paquet conserve une entrée `*/15 * * * *` afin que la migration soit retentée même si les mises à jour planifiées sont désactivées.

## Journaux et alertes \{#logs-and-notices}

Chaque ligne du <Terminology title="journal général de pfSense dans lequel écrit le paquet" to="/docs/reference/terminology#system-log">journal système</Terminology> est écrite avec la fonction `log_error()` de pfSense et commence par `IPv6 Prefix Updater:`. Les alertes sont créées avec `file_notice()` et renvoient vers `/ipv6-prefix-updater-status.php`, sauf l’alerte de migration, qui renvoie vers `/ipv6-prefix-updater-cleanup.php`.

| ID de l’alerte                          | Créée quand                                                                                                                                                                                                                                                                     | Diffusion                                                                                                                                                                     |
|-----------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `ipv6-prefix-updater-success`           | <Terminology title="résultat : champs mis à jour, enregistrés, rechargés et vérifiés" to="/docs/reference/terminology#success">Réussite</Terminology> avec `notifications` à `on`                                                                                               | WebGUI et <Terminology title="services d’alerte distants configurés dans pfSense" to="/docs/reference/terminology#notification-channels">canaux de notification</Terminology> |
| `ipv6-prefix-updater-no-matches`        | <Terminology title="résultat : préfixe changé, mais aucun champ approuvé correspondant" to="/docs/reference/terminology#warning">Avertissement</Terminology>                                                                                                                    | WebGUI uniquement                                                                                                                                                             |
| `ipv6-prefix-updater-failure`           | <Terminology title="résultat : une vérification ou une étape de sécurité a arrêté l’exécution" to="/docs/reference/terminology#failure">Échec</Terminology>                                                                                                                     | WebGUI uniquement                                                                                                                                                             |
| `ipv6-prefix-updater-package-<section>` | Une exécution a modifié les paramètres d’un autre paquet, et aucun paquet installé ne possède la section ou la nouvelle application de ses paramètres a échoué                                                                                                                  | WebGUI uniquement                                                                                                                                                             |
| `ipv6-prefix-updater-legacy-migration`  | Une migration de l’<Terminology title="script update.php d’origine lancé par le paquet Cron" to="/docs/reference/terminology#legacy-updater">ancien script de mise à jour</Terminology> qui a effectué au moins une étape, ou une migration qui a échoué pendant l’installation | WebGUI uniquement                                                                                                                                                             |

Si la vérification d’environnement de la commande échoue, ou si son fichier de verrou ne peut pas être ouvert, le motif n’est envoyé que sur la sortie d’erreur standard. Chaque exécution qui écrit enregistre aussi une révision de configuration décrite par `L’outil de mise à jour du préfixe IPv6 a modifié <nombre> champ(s) approuvé(s) pour l’interface <interface>`.

## Privilèges des pages \{#page-privileges}

Chaque page du paquet déclare son propre privilège pfSense, ce qui permet d’accorder l’accès page par page :

- **État** : `page-services-ipv6-prefix-updater-status`, nommé `Services: IPv6 Prefix Updater: Status`.
- **Champs** : `page-services-ipv6-prefix-updater-fields`, nommé `Services: IPv6 Prefix Updater: Fields`. Il permet de changer les champs qu’une exécution réécrit ; il est donc recommandé de ne l’accorder qu’aux administrateurs.
- **Sauvegardes** : `page-services-ipv6-prefix-updater-backups`, nommé `Services: IPv6 Prefix Updater: Backups`. Il permet de télécharger des copies complètes de la configuration ; il est donc recommandé de ne l’accorder qu’aux administrateurs.
- **Nettoyage** : `page-services-ipv6-prefix-updater-cleanup`, nommé `Services: IPv6 Prefix Updater: Cleanup`.
