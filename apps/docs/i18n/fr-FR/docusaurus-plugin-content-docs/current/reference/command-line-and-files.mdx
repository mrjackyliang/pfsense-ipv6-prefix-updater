Lancez la commande du paquet depuis un shell et retrouvez les fichiers, journaux et alertes qu’elle utilise.

## Utilisation \{#usage}

```text
Usage: ipv6-prefix-updater [--manual] [--dry-run] [--accept-current-prefix [--interface=NAME]] [--migrate-legacy]
Options de mise à jour : --check-updates [--no-notice], --self-update.
```

L’entrée cron de vérification du préfixe gérée par pfSense lance la commande en tant que `root`, sans option, tandis qu’une entrée distincte de recherche de mises à jour la lance avec `--check-updates`. Avant chaque vérification, la commande déplace aussi dans le paquet les éventuels restes de l’<Terminology title="Version 1.x : le script update.php lancé par le paquet Cron" to="/docs/reference/terminology#package-origins">ancien script de mise à jour</Terminology>. L’onglet État utilise `--manual` pour **Exécuter maintenant**, `--dry-run` pour **<Terminology title="Un aperçu des modifications qui n’écrit rien" to="/docs/reference/terminology#running-checks">Simulation</Terminology>** et `--accept-current-prefix` pour la récupération de la référence, et l’onglet Nettoyage utilise `--migrate-legacy`.

Sans option, la commande se comporte comme une vérification planifiée et signale <Terminology title="Vérification planifiée ignorée car la planification est désactivée" to="/docs/reference/terminology#run-outcomes">Désactivé</Terminology> quand la case **<Terminology title="Vérifications automatiques planifiées, désactivées par défaut" to="/docs/reference/terminology#running-checks">Activer les mises à jour planifiées</Terminology>** est décochée.

## Options \{#options}

| Option                    | Description                                                                                                                                                                                                                                                                                                                                                     |
|---------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `--manual`                | S’exécute même quand les <Terminology title="Vérifications automatiques planifiées, désactivées par défaut" to="/docs/reference/terminology#running-checks">mises à jour planifiées</Terminology> sont désactivées.                                                                                                                                             |
| `--dry-run`               | Prévisualise sans sauvegarde ni écriture, et implique `--manual`.                                                                                                                                                                                                                                                                                               |
| `--accept-current-prefix` | Enregistre l’adresse source, le préfixe et la longueur actifs comme référence, sans analyser les champs approuvés, créer de sauvegarde, écrire la configuration ni recharger de service. Implique `--manual` et ne peut pas être combinée avec `--dry-run`.                                                                                                     |
| `--interface=NAME`        | Limite `--accept-current-prefix` à une seule interface surveillée, désignée par son nom interne, comme `lan`. Sans cette option, chaque interface surveillée qui a une adresse est acceptée.                                                                                                                                                                    |
| `--migrate-legacy`        | Déplace immédiatement l’<Terminology title="Version 1.x : le script update.php lancé par le paquet Cron" to="/docs/reference/terminology#package-origins">ancien script de mise à jour</Terminology> dans le paquet et affiche chaque étape, sans lancer de vérification du préfixe. Se termine avec le code `2` quand la migration a signalé un avertissement. |
| `--check-updates`         | Recherche sur GitHub la dernière version du paquet et enregistre le résultat dans `/cf/conf/ipv6-prefix-updater/updates.json`. [Mises à jour](/docs/reference/updates) décrit cette recherche.                                                                                                                                                                  |
| `--no-notice`             | Supprime la notification de mise à jour pour `--check-updates` et marque la dernière version comme déjà signalée. Valide uniquement avec `--check-updates`.                                                                                                                                                                                                     |
| `--self-update`           | Télécharge, vérifie et installe la dernière version, en enregistrant la progression dans `/cf/conf/ipv6-prefix-updater/update-status.json`.                                                                                                                                                                                                                     |
| `--help`                  | Affiche la ligne d’utilisation et la ligne des options de mise à jour, puis se termine avec le code `0`. Aucune des deux lignes ne mentionne `--help` elle-même.                                                                                                                                                                                                |

Toute autre option affiche `Option inconnue : <option>` sur la sortie d’erreur standard et se termine avec le code `64`. Combiner `--accept-current-prefix` avec `--dry-run` se termine aussi avec le code `64`, tout comme combiner `--check-updates` et `--self-update` entre elles ou avec une option de préfixe. Utiliser `--no-notice` sans `--check-updates` se termine aussi avec le code `64`.

## Sortie \{#output}

Une exécution terminée qui surveille une seule interface affiche neuf lignes sur la sortie standard, suivies des modifications des champs après une <Terminology title="Un aperçu des modifications qui n’écrit rien" to="/docs/reference/terminology#running-checks">simulation</Terminology> ou une <Terminology title="Le préfixe a changé et chaque champ approuvé a été mis à jour" to="/docs/reference/terminology#run-outcomes">Réussite</Terminology> :

```text
État: Réussite
Interface: lan
Adresse source observée: 2001:db8:abcd:88aa::1
Préfixe précédent: 2001:db8:abcd:7800::
Préfixe actuel: 2001:db8:abcd:8800::/56
Champs planifiés ou modifiés: 1
Sauvegarde de configuration: Créée
Services rechargés: Filtre du pare-feu
Résumé: 1 champ(s) approuvé(s) ont été mis à jour de 2001:db8:abcd:7800::/56 vers 2001:db8:abcd:8800::/56 sur l’interface lan.
Modifications des champs:
- aliases/alias/0/address: 2001:db8:abcd:78aa::10 → 2001:db8:abcd:88aa::10
```

- La ligne `Préfixe précédent` n’indique pas de longueur et affiche `Non disponible` après <Terminology title="Premier passage : la référence est enregistrée, rien ne change" to="/docs/reference/terminology#run-outcomes">Initialisé</Terminology> ou <Terminology title="Une simulation qui montre la référence qu’elle enregistrerait" to="/docs/reference/terminology#run-outcomes">Aperçu de l’initialisation</Terminology>.
- La ligne `Services rechargés` liste les libellés de l’onglet État ou `Aucun`. Après une <Terminology title="Un aperçu des modifications qui n’écrit rien" to="/docs/reference/terminology#running-checks">simulation</Terminology>, elle liste les services qui seraient rechargés.
- La partie `Modifications des champs` comporte une ligne par adresse remplacée, au format `- <path>: <old> → <new>`, pour 200 champs au maximum.
- Quand l’exécution a appliqué de nouveau les paramètres d’un autre paquet ou ignoré un champ coché qui n’existe plus, une ligne s’ajoute pour chaque cas, rédigée comme dans l’onglet État.
- Quand une autre vérification détient le <Terminology title="Empêche deux vérifications de tourner en même temps" to="/docs/reference/terminology#running-checks">verrou d’exécution</Terminology>, la seule sortie est `Une autre exécution détient le verrou du paquet ; cet appel s’est arrêté sans lire la configuration.`
- Avec plusieurs interfaces surveillées, la sortie commence par les lignes globales `État` et `Résumé` et par les lignes des paquets et des champs ignorés, suivies des lignes de chaque interface, chaque bloc étant séparé par une ligne vide.
- Quand une migration de l’<Terminology title="Version 1.x : le script update.php lancé par le paquet Cron" to="/docs/reference/terminology#package-origins">ancien script de mise à jour</Terminology> a eu lieu avant la vérification, ses étapes sont affichées en premier.
- Les libellés et les messages suivent la langue configurée dans pfSense.

## Format de l’état du paquet \{#package-state-format}

| Clé                   | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
|-----------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `schema_version`      | Toujours `1`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `targets.<interface>` | Une <Terminology title="Le préfixe de départ enregistré, qui sert à mesurer les changements" to="/docs/reference/terminology#baselines-and-transitions">référence</Terminology> par interface surveillée, indexée par son nom interne, avec `interface`, `source_address`, `prefix`, `prefix_length` et `updated_at`. Une référence reprise de l’<Terminology title="Version 1.x : le script update.php lancé par le paquet Cron" to="/docs/reference/terminology#package-origins">ancien script de mise à jour</Terminology> contient aussi `source`, qui vaut `legacy_cache`. |
| `last_run`            | La dernière exécution enregistrée, avec `status`, `timestamp`, `interface`, `observed_address`, `previous_prefix`, `current_prefix`, `current_prefix_length`, `change_count`, `backup_created`, `services`, `message`, `message_key` et `message_arguments`.                                                                                                                                                                                                                                                                                                                    |
| `legacy_migration`    | Présent après une migration de l’<Terminology title="Version 1.x : le script update.php lancé par le paquet Cron" to="/docs/reference/terminology#package-origins">ancien script de mise à jour</Terminology>, avec `status`, `steps`, `warnings` et `recorded_at`. L’onglet Nettoyage l’affiche.                                                                                                                                                                                                                                                                               |

- `status` vaut `initialized`, `initialization_preview`, `no_change`, `dry_run`, `warning`, `accepted`, `success` ou `failure`.
- Après une <Terminology title="Le préfixe a changé et chaque champ approuvé a été mis à jour" to="/docs/reference/terminology#run-outcomes">Réussite</Terminology>, `last_run.notification` vaut `disabled` quand les notifications sont désactivées, ou `sent` ou `failed` après une tentative d’envoi.
- Après une <Terminology title="Un aperçu des modifications qui n’écrit rien" to="/docs/reference/terminology#running-checks">simulation</Terminology> ou une <Terminology title="Le préfixe a changé et chaque champ approuvé a été mis à jour" to="/docs/reference/terminology#run-outcomes">Réussite</Terminology>, chaque résultat contient aussi `changes`, qui liste le `path` et les `replacements` de 200 champs au maximum, chaque remplacement étant une ancienne et une nouvelle adresse.
- `package_reapply` indique, pour chaque paquet dont l’exécution a appliqué de nouveau les paramètres, ses clés `section`, `package`, `status` et `error`, et `skipped_fields` liste les champs cochés qui n’existent plus. Chacune de ces listes n’apparaît que si elle n’est pas vide.
- Avec plusieurs interfaces surveillées, `last_run` contient les totaux et une liste `targets` avec un résultat par interface.
- Les horodatages utilisent le format ISO 8601 en UTC. Un fichier illisible, ou dont la version de schéma est différente, arrête chaque exécution avec `L’état d’IPv6 Prefix Updater est invalide ou non pris en charge.`

## Stockage des paramètres \{#settings-storage}

Les paramètres se trouvent dans la configuration de pfSense, à `installedpackages/ipv6prefixupdater/config/0`.

| Clé                           | Description                                                                                                                                                                                                  |
|-------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `enabled`                     | **<Terminology title="Vérifications automatiques planifiées, désactivées par défaut" to="/docs/reference/terminology#running-checks">Activer les mises à jour planifiées</Terminology>**, `on` si coché.     |
| `row`                         | **Interfaces surveillées**, une liste avec, pour chaque ligne, un champ `interface` (une clé d’interface comme `lan`) et un champ `prefix_length` (de `48` à `64`).                                          |
| `update_frequency`            | **Planification**, parmi `every_fifteen_minutes`, `hourly`, `every_six_hours` ou `daily`.                                                                                                                    |
| `notifications`               | **<Terminology title="L’alerte envoyée après la mise à jour de vos adresses" to="/docs/reference/terminology#notifications-and-logs">Envoyer les notifications de changement</Terminology>**, `on` si coché. |
| `update_check_frequency`      | **Recherche de mises à jour**, parmi `daily`, `weekly`, `monthly` ou `never`.                                                                                                                                |
| `update_remote_notifications` | **Notifications distantes**, `on` si coché.                                                                                                                                                                  |

La planification stable de la recherche de mises à jour se trouve à côté de l’enregistrement des paramètres, à `installedpackages/ipv6prefixupdater/update_schedule`, avec `minute` de 0 à 59, `hour` de 0 à 23, `weekday` de 0 à 6 et `monthday` de 1 à 28. Une valeur absente, mal formée ou hors limites est générée de nouveau et enregistrée.

### Sélection des champs \{#field-selection}

Les choix de l’onglet Champs se trouvent à côté de l’enregistrement des paramètres, à `installedpackages/ipv6prefixupdater/fields` ; enregistrer l’onglet Paramètres, qui remplace `config/0`, ne les efface donc jamais.

| Clé                    | Description                                                                                                                    |
|------------------------|--------------------------------------------------------------------------------------------------------------------------------|
| `schema`               | Toujours `1`. Marque une sélection enregistrée depuis l’onglet Champs, même vide.                                              |
| `enabled_groups/item`  | Groupes activés, comme `firewall_rules`, `dhcpv6` ou `package:<section>` pour les paramètres d’un autre paquet.                |
| `disabled_groups/item` | Groupes pfSense désactivés. Un groupe pfSense absent des deux listes est activé, et le groupe d’un autre paquet est désactivé. |
| `include/item`         | Identités des champs cochés dans un groupe désactivé.                                                                          |
| `exclude/item`         | Identités des champs décochés dans un groupe activé.                                                                           |

- Les clés des groupes pfSense sont `interfaces`, `virtual_ips`, `aliases`, `firewall_rules`, `nat`, `dhcpv6`, `router_advertisements`, `dns_host_overrides`, `ipsec`, `openvpn` et `wireguard`.
- `include` et `exclude` conservent chacune au plus 1 000 identités, et chaque identité suit le format décrit dans [Identités des champs](/docs/reference/approved-fields#field-identities).

## Entrée cron \{#cron-entry}

L’enregistrement des paramètres supprime toute entrée existante pour la commande et, quand `enabled` vaut `on`, en installe une nouvelle pour `root` avec la fonction `install_cron_job()` de pfSense.

| Valeur de planification | Champs cron    |
|-------------------------|----------------|
| `every_fifteen_minutes` | `*/15 * * * *` |
| `hourly`                | `0 * * * *`    |
| `every_six_hours`       | `0 */6 * * *`  |
| `daily`                 | `0 0 * * *`    |

Une valeur inconnue se rabat sur les champs horaires. Tant qu’une migration de l’<Terminology title="Version 1.x : le script update.php lancé par le paquet Cron" to="/docs/reference/terminology#package-origins">ancien script de mise à jour</Terminology> attend la fin de l’ancien script, le paquet conserve une entrée `*/15 * * * *` afin que la migration soit retentée même si les mises à jour planifiées sont désactivées.

Une seconde entrée lance `/usr/local/sbin/ipv6-prefix-updater --check-updates` en tant que `root` selon la fréquence **Recherche de mises à jour**, à une minute, une heure, un jour de la semaine et un jour du mois aléatoires mais stables. L’enregistrement des paramètres la remplace, et `never` la supprime.

## Journaux et alertes \{#logs-and-notices}

Chaque ligne du <Terminology title="Le journal général de pfSense, où chaque exécution laisse des lignes" to="/docs/reference/terminology#notifications-and-logs">journal système</Terminology> est écrite avec la fonction `log_error()` de pfSense et commence par `IPv6 Prefix Updater:`. Les alertes sont créées avec `file_notice()`. Les alertes d’exécution renvoient vers `/ipv6-prefix-updater-status.php`, l’alerte de migration vers `/ipv6-prefix-updater-cleanup.php` et l’alerte de nouvelle version disponible vers `/ipv6-prefix-updater-about.php`.

| ID de l’alerte                          | Créée quand                                                                                                                                                                                                                                                                             | Diffusion                                                                                                                                                                                                                                                      |
|-----------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `ipv6-prefix-updater-success`           | <Terminology title="Le préfixe a changé et chaque champ approuvé a été mis à jour" to="/docs/reference/terminology#run-outcomes">Réussite</Terminology> avec `notifications` à `on`                                                                                                     | WebGUI et <Terminology title="L’e-mail et les autres services d’alerte distants de pfSense" to="/docs/reference/terminology#notifications-and-logs">canaux de notification</Terminology>                                                                       |
| `ipv6-prefix-updater-no-matches`        | <Terminology title="Le préfixe a changé, mais aucun champ approuvé n’utilisait l’ancien" to="/docs/reference/terminology#run-outcomes">Avertissement</Terminology>                                                                                                                      | WebGUI uniquement                                                                                                                                                                                                                                              |
| `ipv6-prefix-updater-failure`           | <Terminology title="L’exécution s’est arrêtée à une vérification ou une étape de sécurité" to="/docs/reference/terminology#run-outcomes">Échec</Terminology>                                                                                                                            | WebGUI uniquement                                                                                                                                                                                                                                              |
| `ipv6-prefix-updater-package-<section>` | Une exécution a modifié les paramètres d’un autre paquet, et aucun paquet installé ne possède la section ou la nouvelle application de ses paramètres a échoué                                                                                                                          | WebGUI uniquement                                                                                                                                                                                                                                              |
| `ipv6-prefix-updater-legacy-migration`  | Une migration de l’<Terminology title="Version 1.x : le script update.php lancé par le paquet Cron" to="/docs/reference/terminology#package-origins">ancien script de mise à jour</Terminology> qui a effectué au moins une étape, ou une migration qui a échoué pendant l’installation | WebGUI uniquement                                                                                                                                                                                                                                              |
| `ipv6-prefix-updater-update-available`  | Une recherche de mises à jour trouve une version plus récente qui n’a pas encore été annoncée                                                                                                                                                                                           | WebGUI uniquement, ou WebGUI et les <Terminology title="L’e-mail et les autres services d’alerte distants de pfSense" to="/docs/reference/terminology#notifications-and-logs">canaux de notification</Terminology> quand **Notifications distantes** est coché |

Si la vérification d’environnement de la commande échoue, ou si son fichier de verrou ne peut pas être ouvert, le motif n’est envoyé que sur la sortie d’erreur standard. Chaque exécution qui écrit enregistre aussi une révision de configuration décrite par `L’outil de mise à jour du préfixe IPv6 a modifié <nombre> champ(s) approuvé(s) pour l’interface <interface>`.

## Privilèges des pages \{#page-privileges}

Chaque page du paquet déclare son propre privilège pfSense, ce qui permet d’accorder l’accès page par page :

- **État** : `page-services-ipv6-prefix-updater-status`, nommé `Services: IPv6 Prefix Updater: Status`.

- **Nettoyage** : `page-services-ipv6-prefix-updater-cleanup`, nommé `Services: IPv6 Prefix Updater: Cleanup`.
- **À propos** : `page-services-ipv6-prefix-updater-about`, nommé `Services: IPv6 Prefix Updater: About`.
