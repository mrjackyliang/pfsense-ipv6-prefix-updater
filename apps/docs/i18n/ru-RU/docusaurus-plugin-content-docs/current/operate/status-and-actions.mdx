Посмотрите, что записали текущее базовое значение и последний запуск, и запустите проверку, предварительный просмотр или восстановление базового значения с вкладки «Состояние».

## Текущее состояние \{#current-state}

Вкладка **Состояние** в **Services → IPv6 Prefix Updater** начинается с этой таблицы, в которой по одной строке на каждый контролируемый интерфейс. Она описывает <Terminology title="начальный префикс, записанный без изменения конфигурации" to="/docs/reference/terminology#baseline">базовое значение</Terminology>, с которым сравнивает следующая проверка:

- **<Terminology title="интерфейс, по адресу которого определяется текущий префикс" to="/docs/reference/terminology#monitored-interface">Контролируемый интерфейс</Terminology>**: описание интерфейса и за ним внутреннее имя в pfSense, например `LAN (lan)`.
- **<Terminology title="префикс, с которым сравнивает следующая проверка" to="/docs/reference/terminology#last-successful-prefix">Последний успешный префикс</Terminology>**: префикс и его длина, например `2001:db8:abcd:7800::/56`.
- **<Terminology title="глобальный адрес контролируемого интерфейса по данным pfSense" to="/docs/reference/terminology#source-address">Последний успешный исходный адрес</Terminology>**: адрес в <Terminology title="стандартная краткая запись адреса строчными буквами" to="/docs/reference/terminology#canonical-form">канонической форме</Terminology>. Запуск с результатом «<Terminology title="результат: префикс прежний, ничего не просмотрено и не записано" to="/docs/reference/terminology#no-change">Без изменений</Terminology>» тоже обновляет это значение.
- **Последнее успешное обновление**: время в UTC, когда <Terminology title="начальный префикс, записанный без изменения конфигурации" to="/docs/reference/terminology#baseline">базовое значение</Terminology> было инициализировано, принято или перенесено после последнего результата «<Terminology title="результат: поля обновлены, сохранены, перезагружены и проверены" to="/docs/reference/terminology#success">Успешно</Terminology>», например `2026-10-24T14:00:00+00:00`.

До первого запуска интерфейса его строка показывает `Не инициализировано. Выполните обычную проверку один раз, чтобы установить безопасное базовое значение.` У <Terminology title="начальный префикс, записанный без изменения конфигурации" to="/docs/reference/terminology#baseline">базового значения</Terminology>, перенятого у устаревшего скрипта обновления, до первой проверки вместо исходного адреса отображается `Не записано этой версией пакета`.

## Последний запуск \{#last-run}

Этот раздел описывает последний запуск. Если контролируемый интерфейс один, раздел сразу показывает результат этого интерфейса:

- **Результат**: итог запуска, описанный в разделе [Результаты запусков](/docs/operate/run-outcomes).
- **Время (UTC)**: когда завершился запуск.
- **<Terminology title="глобальный адрес контролируемого интерфейса по данным pfSense" to="/docs/reference/terminology#source-address">Обнаруженный исходный адрес</Terminology>**: адрес, который pfSense вернул для <Terminology title="интерфейс, по адресу которого определяется текущий префикс" to="/docs/reference/terminology#monitored-interface">контролируемого интерфейса</Terminology>.
- **<Terminology title="исходный адрес, маскированный по длине префикса" to="/docs/reference/terminology#observed-prefix">Обнаруженный префикс</Terminology>**: сеть, вычисленная по этому адресу и <Terminology title="размер префикса провайдера, от /48 до /64" to="/docs/reference/terminology#delegated-prefix-length">длине делегированного префикса</Terminology>.
- **Изменённые поля**: число <Terminology title="конкретное поле конфигурации, которое пакет может перезаписать" to="/docs/reference/terminology#approved-field">разрешённых полей</Terminology>, которые изменил запуск, а после <Terminology title="предварительный просмотр без резервной копии и записи" to="/docs/reference/terminology#dry-run">пробного запуска</Terminology> — которые были бы изменены.
- **<Terminology title="копия конфигурации, сохранённая перед записью" to="/docs/reference/terminology#configuration-backup">Создана резервная копия конфигурации</Terminology>**: `Да` или `Нет — этот запуск не записывал конфигурацию`.
- **<Terminology title="действие pfSense, применяющее изменённые настройки" to="/docs/reference/terminology#service-reload">Перезагруженные службы</Terminology>**: службы, которые перезагрузил запуск, а после <Terminology title="предварительный просмотр без резервной копии и записи" to="/docs/reference/terminology#dry-run">пробного запуска</Terminology> — которые были бы перезагружены.
- **Сводка**: одно предложение о результате, включая прежний префикс после <Terminology title="отличие от последнего успешного префикса или длины" to="/docs/reference/terminology#prefix-transition">смены префикса</Terminology>.
- **Пакеты**: показывается, когда запуск изменил настройки другого пакета, по одной строке на пакет, например `Настройки пакета <package> применены повторно.` Все сообщения перечислены в разделе [Поля](/docs/configure/configuration-scopes#other-packages-settings).
- **Пропущенные поля**: показывается, когда отмеченных полей больше нет, с сообщением `Этих выбранных полей больше нет, поэтому запуск их пропустил. Проверьте их на вкладке «Поля».` и идентификатором каждого поля.

Рекомендуется сначала проверить обнаруженные адрес и префикс. Они показывают, вернул ли pfSense нужный адрес и дала ли длина ожидаемую сеть.

Раздел **Последний запуск** не обновляется, когда <Terminology title="защита от одновременного выполнения двух проверок" to="/docs/reference/terminology#run-lock">блокировку запуска</Terminology> удерживает другая проверка или когда запуск останавливается до чтения <Terminology title="файл пакета с базовым значением и последним запуском" to="/docs/reference/terminology#package-state">состояния пакета</Terminology>, например если ни у одного контролируемого интерфейса нет <Terminology title="публичный IPv6-адрес из диапазона 2000::/3" to="/docs/reference/terminology#global-unicast-address">глобального адреса</Terminology>. При результате «<Terminology title="результат: проверка или этап безопасности остановили запуск" to="/docs/reference/terminology#failure">Ошибка</Terminology>» всегда отображается `0` изменённых полей, как объясняется в разделе [Результаты запусков](/docs/operate/run-outcomes#failures-after-the-save).

### Последний запуск по интерфейсам \{#last-run-by-interface}

Если контролируемых интерфейсов несколько, раздел **Последний запуск** показывает итоговые значения, а поле **Сводка** подсчитывает интерфейсы, которые были обновлены, остались без изменений или требуют внимания. Таблица **Последний запуск по интерфейсам** под ним перечисляет каждый интерфейс с его собственным результатом, обнаруженным префиксом, изменёнными полями и сводкой.

- Поле **Изменённые поля** в разделе **Последний запуск** учитывает каждое поле один раз, даже если его запланировали оба интерфейса с общим <Terminology title="сеть IPv6, которую провайдер направляет на межсетевой экран" to="/docs/reference/terminology#delegated-prefix">делегированным префиксом</Terminology>.
- Интерфейс без <Terminology title="публичный IPv6-адрес из диапазона 2000::/3" to="/docs/reference/terminology#global-unicast-address">глобального адреса</Terminology> сообщает «<Terminology title="результат: проверка или этап безопасности остановили запуск" to="/docs/reference/terminology#failure">Ошибка</Terminology>» в своей строке, а остальные интерфейсы всё равно проверяются.
- Если два интерфейса планируют разные значения для одного и того же поля, запуск останавливается до какой-либо записи и сообщает, в каком поле возникло расхождение.

## Действия \{#actions}

| Действие                                                                                                                                         | Что делает                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
|--------------------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Запустить сейчас                                                                                                                                 | Выполняет полную проверку, даже когда <Terminology title="автоматические проверки через запись cron под управлением pfSense" to="/docs/reference/terminology#scheduled-updates">обновления по расписанию</Terminology> выключены. Записывает <Terminology title="начальный префикс, записанный без изменения конфигурации" to="/docs/reference/terminology#baseline">базовое значение</Terminology>, если его нет, и применяет <Terminology title="отличие от последнего успешного префикса или длины" to="/docs/reference/terminology#prefix-transition">смену префикса</Terminology>, если она обнаружена. |
| <Terminology title="предварительный просмотр без резервной копии и записи" to="/docs/reference/terminology#dry-run">Пробный запуск</Terminology> | Выполняет ту же проверку без резервной копии и записи. Пока <Terminology title="начальный префикс, записанный без изменения конфигурации" to="/docs/reference/terminology#baseline">базового значения</Terminology> нет, сообщает «<Terminology title="результат: пробный запуск до появления базового значения" to="/docs/reference/terminology#initialization-preview">Предварительная инициализация</Terminology>».                                                                                                                                                                                       |
| Принять текущий префикс                                                                                                                          | После подтверждения записывает активный исходный адрес, префикс и длину как новое <Terminology title="начальный префикс, записанный без изменения конфигурации" to="/docs/reference/terminology#baseline">базовое значение</Terminology>. Не проверяет разрешённые поля, не создаёт резервную копию, не записывает конфигурацию и не перезагружает службы.                                                                                                                                                                                                                                                   |

«Запустить сейчас» и «<Terminology title="предварительный просмотр без резервной копии и записи" to="/docs/reference/terminology#dry-run">Пробный запуск</Terminology>» — это <Terminology title="проверка, запущенная с вкладки «Состояние»" to="/docs/reference/terminology#manual-run">ручные запуски</Terminology>. **Принять текущий префикс** — действие для восстановления, и использовать его следует только после проверки сохранённых адресов и затронутых служб.

Каждое действие показывает баннер о завершении или предупреждение. Подтверждение для **Принять текущий префикс** — последняя мера защиты перед тем, как пакет заменит базовое значение для сравнения.

Проверка, которая обнаружила уже выполняющийся запуск, тоже показывает баннер о завершении, поэтому рекомендуется просматривать и «<Terminology title="результаты только для чтения после ручного или пробного запуска" to="/docs/reference/terminology#command-output">Вывод команды</Terminology>».

## Вывод команды \{#command-output}

После действия в разделе **<Terminology title="результаты только для чтения после ручного или пробного запуска" to="/docs/reference/terminology#command-output">Вывод команды</Terminology>** появляется поле только для чтения **Последний запуск**:

```text
Состояние: Без изменений
Интерфейс: lan
Обнаруженный исходный адрес: 2001:db8:abcd:78aa::1
Предыдущий префикс: 2001:db8:abcd:7800::
Текущий префикс: 2001:db8:abcd:7800::/56
Запланированные или изменённые поля: 0
Резервная копия конфигурации: Не создана
Перезагруженные службы: Нет
Сводка: Активный префикс IPv6 не изменился; разрешённые цели конфигурации не читались и не записывались.
```

Предыдущий префикс выводится без длины. Неудачный запуск вместо этого показывает одну строку, которая начинается с `Ошибка обновления префикса IPv6:`.

После <Terminology title="предварительный просмотр без резервной копии и записи" to="/docs/reference/terminology#dry-run">пробного запуска</Terminology> или изменения далее следует `Изменения полей:` с каждым адресом, который запуск заменил или заменил бы, и полем, к которому он относится:

```text
Изменения полей:
- aliases/alias/0/address: 2001:db8:abcd:78aa::10 → 2001:db8:abcd:88aa::10
```

## Выбор полей \{#choosing-fields}

Какие поля обновляет запуск, выбирается на вкладке **Поля**, которая перечисляет все адреса внутри префикса каждого <Terminology title="начальный префикс, записанный без изменения конфигурации" to="/docs/reference/terminology#baseline">базового значения</Terminology>. Группы, исключения для отдельных полей и группа «Другие настройки» описаны в разделе [Поля](/docs/configure/configuration-scopes).
