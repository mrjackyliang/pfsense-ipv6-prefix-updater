IPv6 Prefix Updater проверяет свои выпуски на GitHub, потому что менеджер пакетов pfSense не показывает пакеты, установленные непосредственно с GitHub.

## Что проверяется \{#what-is-checked}

Проверка запрашивает у GitHub метаданные последнего выпуска и сравнивает его версию с версией установленного пакета. Время проверки, последняя версия, ссылка на выпуск, время публикации, состояние уведомления и последняя ошибка сохраняются в `/cf/conf/ipv6-prefix-updater/updates.json`. Конфигурация межсетевого экрана никогда не передаётся на GitHub.

Выберите периодичность в **Services → IPv6 Prefix Updater → Настройки → Обновления пакета**:

- **Ежедневно** — один раз в день во время, случайно выбранное при установке.
- **Еженедельно** — значение по умолчанию; также выбирается один постоянный день недели и время.
- **Ежемесячно** — выбирается один постоянный день с 1 по 28 и одно постоянное время.
- **Никогда** — удаляет плановую проверку выпусков.

Случайное расписание хранится в конфигурации pfSense, поэтому сохранение настроек или переустановка пакета его не сдвигают. **Проверить сейчас** на вкладке «О пакете» всегда выполняет ручную проверку, в том числе при периодичности **Никогда**.

Ручную проверку на вкладке «О пакете» можно выполнять во время обновления префикса. Она не создаёт уведомление и помечает показанную версию как уже объявленную, поэтому последующая проверка по расписанию не объявляет её снова.

## Сетевые назначения \{#network-destinations}

Проверка или обновление может обращаться к следующим узлам, которые обслуживает GitHub:

- `api.github.com` — за метаданными последнего выпуска и опубликованным дайджестом SHA-256.
- `github.com` — за URL файла выпуска.
- `release-assets.githubusercontent.com` — узел загрузки выпусков GitHub, после перенаправления запроса файла.

Запросы проверяют сертификаты TLS, используют короткие тайм-ауты, собственный User-Agent пакета и прокси, настроенный в pfSense. Ответ `403` или `429` считается ограничением частоты и не стирает последние действительные сведения о выпуске.

## Уведомления \{#notices}

Когда впервые появляется более новая версия, пакет добавляет одно уведомление в колокольчик pfSense для этой версии. Уведомление ссылается на вкладку «О пакете» и по умолчанию остаётся локальным.

Установите флажок **Удалённые уведомления**, чтобы дополнительно отправлять его через настроенные в pfSense электронную почту, Telegram, Pushover или другие удалённые каналы. Пакет по-прежнему создаёт только одно уведомление на каждую новую версию. Он закрывает уведомление после установки этой версии или когда очередная проверка показывает, что установленный пакет актуален.

## Установка обновления \{#install-an-update}

Откройте **Services → IPv6 Prefix Updater → О пакете**. Если доступна более новая версия, кнопка **Обновить до _версии_** запускает фоновое задание, а страница показывает его ход.

Если обновление префикса уже выполняется, фоновое задание показывает ожидание и даёт ему до 30 минут на завершение, после чего установка завершается с ошибкой.

Задание повторно получает сведения о выпуске и загружает файл `.pkg` с версией в имени. Оно проверяет пакет по дайджесту `sha256:<hex>` файла в API GitHub; если такого дайджеста нет, задание вместо этого загружает соответствующий файл `.pkg.sha256` из того же выпуска.

Пакеты выпусков содержат открытые ключи подписи рабочего процесса выпуска в `/usr/local/share/pfSense-pkg-Ipv6PrefixUpdater/release-signing.pub`. Если в этом файле указан хотя бы один ключ, установленная копия принимает только обновления, подписанные одним из них; если файла нет или в нём только комментарии, проверка подписи выключена и обновления опираются только на проверку SHA-256.

После проверки SHA-256, если в установленном файле ключей указан ключ, задание загружает соответствующий `.pkg.sig` из того же выпуска и проверяет его командой `ssh-keygen -Y verify` до чтения архива. Выпуск без этой подписи или подписанный другим ключом отклоняется, а установленная версия сохраняется.

Затем задание проверяет имя и версию пакета в архиве и только после этого запускает `pkg add -f`. Если нет ни одного источника контрольной суммы, обновление отклоняется и установленная версия сохраняется; блокировка пакета не даёт запуску проверки префикса и обновлению пересечься.

## Установка вручную \{#install-manually}

Администратор по-прежнему может установить файл выпуска из оболочки pfSense:

```shell
pkg add -f https://github.com/mrjackyliang/pfsense-ipv6-prefix-updater/releases/latest/download/pfSense-pkg-Ipv6PrefixUpdater.pkg
```

Эта ручная команда обходит и проверку SHA-256, и проверку подписи выпуска на вкладке «О пакете». Перед использованием проверьте выпуск, контрольную сумму и подпись.

## Отключение проверок \{#turn-checks-off}

Установите для **Проверка обновлений** значение **Никогда** и сохраните вкладку «Настройки». Пакет удаляет свою запись cron для проверки обновлений и больше не отправляет плановых исходящих запросов об обновлениях. Контроль префикса работает по собственному независимому расписанию, а **Проверить сейчас** остаётся доступной для запросов, запускаемых администратором.
