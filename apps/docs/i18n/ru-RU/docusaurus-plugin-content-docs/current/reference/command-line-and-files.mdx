Запускайте команду пакета из командной оболочки и находите файлы, журналы и уведомления, которые она использует.

## Использование \{#usage}

```text
Использование: ipv6-prefix-updater [--manual] [--dry-run] [--accept-current-prefix [--interface=NAME]] [--migrate-legacy]
Параметры обновления: --check-updates, --self-update.
```

Запись cron для проверки префикса под управлением pfSense запускает команду от имени `root` без параметров, а отдельная запись для проверки выпусков запускает её с `--check-updates`. Перед каждой проверкой команда также переносит в пакет все остатки <Terminology title="Версия 1.x: скрипт update.php, запускаемый пакетом Cron" to="/docs/reference/terminology#package-origins">устаревшего скрипта обновления</Terminology>. Вкладка «Состояние» использует `--manual` для кнопки **Запустить сейчас**, `--dry-run` для кнопки **<Terminology title="Предпросмотр изменений, который ничего не записывает" to="/docs/reference/terminology#running-checks">Пробный запуск</Terminology>** и `--accept-current-prefix` для восстановления базового значения, а вкладка «Очистка» — `--migrate-legacy`.

Без параметров команда ведёт себя как проверка по расписанию и сообщает «<Terminology title="Плановая проверка пропущена, потому что обновления по расписанию выключены" to="/docs/reference/terminology#run-outcomes">Отключено</Terminology>», если флажок **<Terminology title="Автоматические проверки по расписанию, выключены, пока вы их не включите" to="/docs/reference/terminology#running-checks">Включить обновления по расписанию</Terminology>** снят.

## Параметры \{#options}

| Флаг                      | Описание                                                                                                                                                                                                                                                                                                                     |
|---------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `--manual`                | Выполняется, даже когда <Terminology title="Автоматические проверки по расписанию, выключены, пока вы их не включите" to="/docs/reference/terminology#running-checks">обновления по расписанию</Terminology> выключены.                                                                                                      |
| `--dry-run`               | Выполняет предварительный просмотр без резервной копии и записи и подразумевает `--manual`.                                                                                                                                                                                                                                  |
| `--accept-current-prefix` | Записывает активный исходный адрес, префикс и длину как базовое значение, не просматривая разрешённые поля, не создавая резервную копию, не записывая конфигурацию и не перезагружая службы. Подразумевает `--manual` и не может сочетаться с `--dry-run`.                                                                   |
| `--interface=NAME`        | Ограничивает `--accept-current-prefix` одним контролируемым интерфейсом, который задаётся внутренним именем, например `lan`. Без этого параметра текущий префикс принимается для каждого контролируемого интерфейса, у которого есть адрес.                                                                                  |
| `--migrate-legacy`        | Сразу переносит <Terminology title="Версия 1.x: скрипт update.php, запускаемый пакетом Cron" to="/docs/reference/terminology#package-origins">устаревший скрипт обновления</Terminology> в пакет и выводит каждый шаг, не выполняя проверку префикса. Завершается с кодом `2`, если при переносе было выдано предупреждение. |
| `--check-updates`         | Проверяет на GitHub последний выпуск пакета и сохраняет результат в `/cf/conf/ipv6-prefix-updater/updates.json`. Проверка описана в разделе [Обновления](/docs/reference/updates).                                                                                                                                           |
| `--self-update`           | Загружает, проверяет и устанавливает последний выпуск, записывая ход выполнения в `/cf/conf/ipv6-prefix-updater/update-status.json`.                                                                                                                                                                                         |
| `--help`                  | Выводит строку использования и строку параметров обновления и завершается с кодом `0`. Ни одна из этих строк не упоминает сам `--help`.                                                                                                                                                                                      |

Любой другой параметр выводит `Неизвестный параметр: <option>` в стандартный поток ошибок и завершается с кодом `64`. Сочетание `--accept-current-prefix` с `--dry-run` также завершается с кодом `64`, как и сочетание `--check-updates` или `--self-update` друг с другом или с любым параметром префикса.

## Вывод \{#output}

Завершённый запуск с одним контролируемым интерфейсом выводит девять строк в стандартный вывод, а после <Terminology title="Предпросмотр изменений, который ничего не записывает" to="/docs/reference/terminology#running-checks">пробного запуска</Terminology> или результата «<Terminology title="Префикс сменился, и все разрешённые поля обновлены" to="/docs/reference/terminology#run-outcomes">Успешно</Terminology>» за ними следуют изменения полей:

```text
Состояние: Успешно
Интерфейс: lan
Обнаруженный исходный адрес: 2001:db8:abcd:88aa::1
Предыдущий префикс: 2001:db8:abcd:7800::
Текущий префикс: 2001:db8:abcd:8800::/56
Запланированные или изменённые поля: 1
Резервная копия конфигурации: Создана
Перезагруженные службы: Фильтр межсетевого экрана
Сводка: Обновлено 1 разрешённое поле с 2001:db8:abcd:7800::/56 на 2001:db8:abcd:8800::/56 на интерфейсе lan.
Изменения полей:
- aliases/alias/0/address: 2001:db8:abcd:78aa::10 → 2001:db8:abcd:88aa::10
```

- `Предыдущий префикс` выводится без длины, а после «<Terminology title="Первый взгляд: базовое значение записано, ничего не меняется" to="/docs/reference/terminology#run-outcomes">Инициализировано</Terminology>» или «<Terminology title="Пробный запуск, показывающий базовое значение, которое он записал бы" to="/docs/reference/terminology#run-outcomes">Предварительная инициализация</Terminology>» показывает `Недоступно`.
- `Перезагруженные службы` перечисляет подписи с вкладки «Состояние» или `Нет`. После <Terminology title="Предпросмотр изменений, который ничего не записывает" to="/docs/reference/terminology#running-checks">пробного запуска</Terminology> перечисляются службы, которые были бы перезагружены.
- `Изменения полей` содержит по одной строке на каждый заменённый адрес в виде `- <path>: <old> → <new>`, не более чем для 200 полей.
- Если запуск повторно применил настройки другого пакета или пропустил отмеченное поле, которого больше нет, далее следует по одной строке о каждом таком случае с той же формулировкой, что и на вкладке «Состояние».
- Когда <Terminology title="Не даёт двум проверкам идти одновременно" to="/docs/reference/terminology#running-checks">блокировку запуска</Terminology> удерживает другая проверка, выводится только `Другой запуск удерживает блокировку пакета; этот вызов завершён без чтения конфигурации.`
- При нескольких контролируемых интерфейсах вывод начинается с общих строк `Состояние` и `Сводка`, а также строк о пакетах и пропущенных полях, за которыми следуют строки каждого интерфейса, разделённые пустыми строками.
- Если перед проверкой выполнялся перенос <Terminology title="Версия 1.x: скрипт update.php, запускаемый пакетом Cron" to="/docs/reference/terminology#package-origins">устаревшего скрипта обновления</Terminology>, сначала выводятся его шаги.
- Подписи и сообщения следуют языку, выбранному в pfSense.

## Формат состояния пакета \{#package-state-format}

| Ключ                  | Описание                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
|-----------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `schema_version`      | Всегда `1`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `targets.<interface>` | Одно <Terminology title="Записанный исходный префикс, от которого отсчитываются изменения" to="/docs/reference/terminology#baselines-and-transitions">базовое значение</Terminology> на каждый контролируемый интерфейс с ключом по его внутреннему имени и полями `interface`, `source_address`, `prefix`, `prefix_length` и `updated_at`. У базового значения, взятого у <Terminology title="Версия 1.x: скрипт update.php, запускаемый пакетом Cron" to="/docs/reference/terminology#package-origins">устаревшего скрипта обновления</Terminology>, также есть поле `source` со значением `legacy_cache`. |
| `last_run`            | Последний записанный запуск с полями `status`, `timestamp`, `interface`, `observed_address`, `previous_prefix`, `current_prefix`, `current_prefix_length`, `change_count`, `backup_created`, `services`, `message`, `message_key` и `message_arguments`.                                                                                                                                                                                                                                                                                                                                                     |
| `legacy_migration`    | Появляется после переноса <Terminology title="Версия 1.x: скрипт update.php, запускаемый пакетом Cron" to="/docs/reference/terminology#package-origins">устаревшего скрипта обновления</Terminology> и содержит поля `status`, `steps`, `warnings` и `recorded_at`. Его показывает вкладка «Очистка».                                                                                                                                                                                                                                                                                                        |

- `status` принимает одно из значений `initialized`, `initialization_preview`, `no_change`, `dry_run`, `warning`, `accepted`, `success` или `failure`.
- После результата «<Terminology title="Префикс сменился, и все разрешённые поля обновлены" to="/docs/reference/terminology#run-outcomes">Успешно</Terminology>» поле `last_run.notification` равно `disabled`, если уведомления выключены, либо `sent` или `failed` после попытки доставки.
- После <Terminology title="Предпросмотр изменений, который ничего не записывает" to="/docs/reference/terminology#running-checks">пробного запуска</Terminology> или результата «<Terminology title="Префикс сменился, и все разрешённые поля обновлены" to="/docs/reference/terminology#run-outcomes">Успешно</Terminology>» каждый результат также содержит поле `changes` со значениями `path` и `replacements` не более чем для 200 полей, где каждая замена — это прежний и новый адрес.
- `package_reapply` перечисляет `section`, `package`, `status` и `error` каждого пакета, настройки которого запуск применил повторно, а `skipped_fields` перечисляет отмеченные поля, которых больше нет. Каждое из этих полей появляется, только если оно не пустое.
- При нескольких контролируемых интерфейсах `last_run` содержит итоговые значения и список `targets` с одним результатом на каждый интерфейс.
- Метки времени используют ISO 8601 в UTC. Файл, который не удаётся разобрать или у которого другая версия схемы, останавливает каждый запуск с сообщением `Состояние Обновления префикса IPv6 недопустимо или не поддерживается.`

## Хранение настроек \{#settings-storage}

Настройки хранятся в конфигурации pfSense по пути `installedpackages/ipv6prefixupdater/config/0`.

| Ключ                          | Описание                                                                                                                                                                                                                         |
|-------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `enabled`                     | **<Terminology title="Автоматические проверки по расписанию, выключены, пока вы их не включите" to="/docs/reference/terminology#running-checks">Включить обновления по расписанию</Terminology>**; `on`, если флажок установлен. |
| `row`                         | **Контролируемые интерфейсы** — список, в каждой строке которого одно значение `interface` (ключ интерфейса, например `lan`) и одно значение `prefix_length` (от `48` до `64`).                                                  |
| `update_frequency`            | **Расписание**: одно из значений `every_fifteen_minutes`, `hourly`, `every_six_hours` или `daily`.                                                                                                                               |
| `notifications`               | **<Terminology title="Оповещение после обновления ваших адресов" to="/docs/reference/terminology#notifications-and-logs">Отправлять уведомления об изменениях</Terminology>**; `on`, если флажок установлен.                     |
| `update_check_frequency`      | **Проверка обновлений**: одно из значений `daily`, `weekly`, `monthly` или `never`.                                                                                                                                              |
| `update_remote_notifications` | **Удалённые уведомления**; `on`, если флажок установлен.                                                                                                                                                                         |

Постоянное расписание проверки выпусков хранится рядом с записью настроек, по пути `installedpackages/ipv6prefixupdater/update_schedule`, с полями `minute` от 0 до 59, `hour` от 0 до 23, `weekday` от 0 до 6 и `monthday` от 1 до 28. Отсутствующее, повреждённое или выходящее за пределы значение создаётся заново и сохраняется.

### Выбор полей \{#field-selection}

Выбор на вкладке «Поля» хранится рядом с записью настроек, по пути `installedpackages/ipv6prefixupdater/fields`, поэтому сохранение вкладки «Настройки», которое заменяет `config/0`, никогда его не сбрасывает.

| Ключ                   | Описание                                                                                                                           |
|------------------------|------------------------------------------------------------------------------------------------------------------------------------|
| `schema`               | Всегда `1`. Отмечает выбор, сохранённый на вкладке «Поля», даже пустой.                                                            |
| `enabled_groups/item`  | Включённые группы, например `firewall_rules`, `dhcpv6` или `package:<section>` для настроек другого пакета.                        |
| `disabled_groups/item` | Выключенные группы pfSense. Группа pfSense, которой нет ни в одном из этих списков, включена, а группа другого пакета — выключена. |
| `include/item`         | Идентификаторы полей, отмеченных в выключенной группе.                                                                             |
| `exclude/item`         | Идентификаторы полей, с которых снята отметка во включённой группе.                                                                |

- Ключи групп pfSense: `interfaces`, `virtual_ips`, `aliases`, `firewall_rules`, `nat`, `dhcpv6`, `router_advertisements`, `dns_host_overrides`, `ipsec`, `openvpn` и `wireguard`.
- `include` и `exclude` хранят не более 1000 идентификаторов каждый, и каждый идентификатор имеет формат из раздела [Идентификаторы полей](/docs/reference/approved-fields#field-identities).

## Запись cron \{#cron-entry}

При сохранении настроек удаляется любая существующая запись для этой команды, а если `enabled` равно `on`, функция pfSense `install_cron_job()` устанавливает новую запись для `root`.

| Значение расписания     | Поля cron      |
|-------------------------|----------------|
| `every_fifteen_minutes` | `*/15 * * * *` |
| `hourly`                | `0 * * * *`    |
| `every_six_hours`       | `0 */6 * * *`  |
| `daily`                 | `0 0 * * *`    |

Неизвестное значение заменяется полями для ежечасного запуска. Пока перенос <Terminology title="Версия 1.x: скрипт update.php, запускаемый пакетом Cron" to="/docs/reference/terminology#package-origins">устаревшего скрипта обновления</Terminology> ожидает завершения работы этого скрипта, пакет держит запись `*/15 * * * *`, чтобы перенос повторялся, даже если обновления по расписанию выключены.

Вторая запись запускает `/usr/local/sbin/ipv6-prefix-updater --check-updates` от имени `root` с периодичностью **Проверка обновлений**, в постоянные случайно выбранные минуту, час, день недели и день месяца. Сохранение настроек заменяет её, а значение `never` её удаляет.

## Журналы и уведомления \{#logs-and-notices}

Каждая строка <Terminology title="Общий журнал pfSense, где каждый запуск оставляет строки" to="/docs/reference/terminology#notifications-and-logs">системного журнала</Terminology> записывается функцией pfSense `log_error()` и начинается с `IPv6 Prefix Updater:`. Уведомления создаются функцией `file_notice()`. Уведомления о запусках ссылаются на `/ipv6-prefix-updater-status.php`, уведомление о переносе — на `/ipv6-prefix-updater-cleanup.php`, а уведомление о доступном обновлении — на `/ipv6-prefix-updater-about.php`.

| Идентификатор уведомления               | Когда создаётся                                                                                                                                                                                                                                                         | Доставка                                                                                                                                                                                                                                       |

## Привилегии страниц \{#page-privileges}

Каждая страница пакета объявляет собственную привилегию pfSense, поэтому доступ можно выдавать для каждой страницы отдельно:

- **Состояние**: `page-services-ipv6-prefix-updater-status` с именем `Services: IPv6 Prefix Updater: Status`.
- **Поля**: `page-services-ipv6-prefix-updater-fields` с именем `Services: IPv6 Prefix Updater: Fields`. Она позволяет изменить, какие поля перезаписывает запуск, поэтому рекомендуется выдавать её только администраторам.
- **Резервные копии**: `page-services-ipv6-prefix-updater-backups` с именем `Services: IPv6 Prefix Updater: Backups`. Она позволяет скачивать полные копии конфигурации, поэтому рекомендуется выдавать её только администраторам.
- **Очистка**: `page-services-ipv6-prefix-updater-cleanup` с именем `Services: IPv6 Prefix Updater: Cleanup`.
- **О пакете**: `page-services-ipv6-prefix-updater-about` с именем `Services: IPv6 Prefix Updater: About`.
