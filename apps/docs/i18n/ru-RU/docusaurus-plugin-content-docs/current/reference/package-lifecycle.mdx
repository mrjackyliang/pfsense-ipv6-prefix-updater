Проверьте установленную версию, установите новый выпуск или удалите пакет из командной оболочки pfSense.

## Проверка установленной версии \{#check-the-installed-version}

```shell
pkg info pfSense-pkg-Ipv6PrefixUpdater
```

Сравните показанную версию с [последним выпуском на GitHub](https://github.com/mrjackyliang/pfsense-ipv6-prefix-updater/releases/latest).

## Обновление пакета \{#update-the-package}

Рекомендуется сначала загрузить копию конфигурации в **Diagnostics → Backup & Restore**. Затем установите последний выпуск поверх существующего пакета:

```shell
pkg add -f https://github.com/mrjackyliang/pfsense-ipv6-prefix-updater/releases/latest/download/pfSense-pkg-Ipv6PrefixUpdater.pkg
```

Этап установки снова синхронизирует обе записи cron — проверку префикса и проверку выпусков — с сохранёнными настройками и сохраняет все <Terminology title="Записанный исходный префикс, от которого отсчитываются изменения" to="/docs/reference/terminology#baselines-and-transitions">базовые значения</Terminology>. Шаги проверки контрольной суммы из раздела [Установка пакета](/docs/installation#verify-the-download-first) подходят и для обновлений.

После обновления:

1. Откройте **Services → IPv6 Prefix Updater → Настройки** и проверьте сохранённые значения.
2. На вкладке «Состояние» проверьте раздел **Текущее состояние**. Каждый интерфейс сохраняет своё <Terminology title="Записанный исходный префикс, от которого отсчитываются изменения" to="/docs/reference/terminology#baselines-and-transitions">базовое значение</Terminology>.

Если в строке отображается `Не инициализировано`, **Запустить сейчас** запишет для этого интерфейса новое <Terminology title="Записанный исходный префикс, от которого отсчитываются изменения" to="/docs/reference/terminology#baselines-and-transitions">базовое значение</Terminology>. Адреса, которые всё ещё используют префикс, действовавший до этого базового значения, тогда останутся без изменений.

## Удаление пакета \{#remove-the-package}

Если сначала снять флажок **<Terminology title="Автоматические проверки по расписанию, выключены, пока вы их не включите" to="/docs/reference/terminology#running-checks">Включить обновления по расписанию</Terminology>**, последующая переустановка не запустит расписание сразу, если pfSense сохранит настройки. Затем выполните:

```shell
pkg delete -f pfSense-pkg-Ipv6PrefixUpdater
```

Пакет помечен как `vital`, поэтому собственные обновления pfSense оставляют его установленным, а обычная команда `pkg delete` отказывается удалять пакеты с этой пометкой.

Удаление стирает обе записи cron (проверку префикса и проверку выпусков), закрывает уведомление о доступном обновлении и удаляет файл <Terminology title="Не даёт двум проверкам идти одновременно" to="/docs/reference/terminology#running-checks">блокировки запуска</Terminology>, если её не удерживает ни один запуск. <Terminology title="Файл с каждым базовым значением, переживает переустановку" to="/docs/reference/terminology#running-checks">Состояние пакета</Terminology>, `updates.json`, `update-status.json` и копии с вкладки **Резервные копии** в `/cf/conf/ipv6-prefix-updater` сохраняются.

Собственные обновления pfSense оставляют пакет установленным (он помечен как `vital`), а сохранённое состояние означает, что удаление и повторная установка никогда не приводят к потере <Terminology title="Записанный исходный префикс, от которого отсчитываются изменения" to="/docs/reference/terminology#baselines-and-transitions">базового значения</Terminology>.

Удаление не отменяет адреса, уже сохранённые в конфигурации, а ревизии пакета остаются в <Terminology title="Сохранённые в pfSense ревизии конфигурации для восстановления" to="/docs/reference/terminology#backups-and-service-reloads">Config History</Terminology>. Чтобы удалить и сохранённые файлы, после удаления пакета выполните `rm -rf /cf/conf/ipv6-prefix-updater`.

## Последующая переустановка \{#reinstall-later}

Переустановленный пакет находит сохранённое <Terminology title="Файл с каждым базовым значением, переживает переустановку" to="/docs/reference/terminology#running-checks">состояние пакета</Terminology>, поэтому первый запуск сравнивает префиксы с каждым сохранённым <Terminology title="Записанный исходный префикс, от которого отсчитываются изменения" to="/docs/reference/terminology#baselines-and-transitions">базовым значением</Terminology> и обновляет поля, оставшиеся на более старом префиксе. Если прежние настройки сохранились с установленным флажком **<Terminology title="Автоматические проверки по расписанию, выключены, пока вы их не включите" to="/docs/reference/terminology#running-checks">Включить обновления по расписанию</Terminology>**, этап установки сразу включает расписание.

Чтобы начать с чистого листа, удалите `/cf/conf/ipv6-prefix-updater` перед переустановкой. Тогда первый запуск запишет новое <Terminology title="Записанный исходный префикс, от которого отсчитываются изменения" to="/docs/reference/terminology#baselines-and-transitions">базовое значение</Terminology> и сообщит «<Terminology title="Первый взгляд: базовое значение записано, ничего не меняется" to="/docs/reference/terminology#run-outcomes">Инициализировано</Terminology>», не изменяя конфигурацию.

Перед обслуживанием изучите раздел [Резервные копии и восстановление](/docs/operate/backups-and-recovery), а после переустановки — раздел [Создание базового значения](/docs/first-run).
