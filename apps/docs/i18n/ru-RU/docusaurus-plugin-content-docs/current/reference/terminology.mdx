Определяет термины, которыми вкладки «Настройки», «Состояние» и «Поля» и эти руководства обозначают адреса, префиксы, запуски и функции pfSense.

## Делегированный префикс \{#delegated-prefix}

Сеть IPv6, которую провайдер направляет на межсетевой экран, обычно через DHCPv6 Prefix Delegation. Пакет следует за этим префиксом, но никогда не запрашивает, не продлевает и не изменяет его.

## Длина префикса \{#prefix-length}

Число начальных битов, которые определяют сеть; записывается как косая черта и число, например `/56`. Суффикс CIDR в настроенном значении, например `/64`, сохраняется в исходном виде, когда пакет перезаписывает адрес.

## Длина делегированного префикса \{#delegated-prefix-length}

Настройка **Длина делегированного префикса**, которая задаёт размер делегируемого провайдером префикса от `/48` до `/64`. Начальное значение — `/56`; пакет никогда не определяет его сам, а изменение после появления базового значения считается сменой префикса.

## Глобальный одноадресный адрес \{#global-unicast-address}

IPv6-адрес из диапазона `2000::/3` — единственный тип адреса, который пакет читает как исходный или перезаписывает. Адреса link-local, уникальные локальные (`fc00::/7`), многоадресные, петлевые, неопределённые и IPv4-отображённые адреса отклоняются как исходные и остаются в конфигурации без изменений.

## Адрес link-local \{#link-local-address}

Адрес, который действует только в пределах одного сетевого канала и начинается с `fe80`. Пакет никогда не переключается на такой адрес, поэтому на интерфейсе без глобального адреса запуск завершается ошибкой.

## Узловая часть \{#host-portion}

Все биты адреса после длины делегированного префикса, также называемые битами узла. Пакет копирует эти биты в новый адрес без изменений, даже если граница проходит внутри шестнадцатеричной цифры.

## Каноническая форма \{#canonical-form}

Стандартная краткая запись IPv6-адреса строчными буквами, например `2001:db8::1` для `2001:0DB8:0:0::1`. Пакет сравнивает адреса в этой форме и в ней же записывает перезаписанные значения, поэтому значение может выглядеть иначе, но обозначать тот же адрес.

## Интерфейс в режиме Track Interface \{#tracked-interface}

Интерфейс pfSense, который получает IPv6-адрес из делегированного префикса другого интерфейса через тип конфигурации **Track Interface**. Он часто подходит как контролируемый интерфейс, когда у WAN нет глобального адреса, а его адрес пакет никогда не перезаписывает, потому что этот адрес формирует pfSense.

## Контролируемый интерфейс \{#monitored-interface}

Одна строка настройки **Контролируемые интерфейсы**, которая указывает интерфейс, чей глобальный адрес показывает текущий префикс. Вкладка «Состояние» показывает описание интерфейса и за ним внутреннее имя в pfSense, например `LAN (lan)`.

После добавления интерфейса следующий запуск записывает для него новое базовое значение вместо сравнения префиксов.

## Исходный адрес \{#source-address}

Основной глобальный адрес, который pfSense сообщает для контролируемого интерфейса; он считывается заново при каждом запуске. Вкладка «Состояние» показывает его в канонической форме в полях **Обнаруженный исходный адрес** и **Последний успешный исходный адрес**.

## Обнаруженный префикс \{#observed-prefix}

Сеть, вычисленная по исходному адресу и длине делегированного префикса; вкладка «Состояние» показывает её вместе с длиной. Каждый запуск сравнивает её с последним успешным префиксом.

## Базовое значение \{#baseline}

Префикс и исходный адрес, которые пакет записывает как точку отсчёта, не изменяя конфигурацию. Базовое значение записывается при первом запуске для каждого контролируемого интерфейса, при отсутствии состояния пакета, когда оператор явно принимает активный префикс, а также при переходе — из префикса, сохранённого устаревшим скриптом обновления.

## Последний успешный префикс \{#last-successful-prefix}

Сохранённые префикс и длина, с которыми сравнивает следующая проверка. Их изменяют только результаты «Инициализировано», «Принято» и «Успешно», а все остальные результаты оставляют их прежними.

## Смена префикса \{#prefix-transition}

Различие между последним успешным префиксом и обнаруженным префиксом, в том числе та же сеть с другой длиной префикса. Только при смене префикса пакет просматривает конфигурацию, планирует изменения и выполняет запись.

## Группа полей \{#field-group}

Группа полей с одним переключателем на вкладке «Поля». Одиннадцать групп pfSense — «Статические интерфейсы», «Виртуальные IP-адреса», «Псевдонимы», «Правила межсетевого экрана», «NAT и NPt», «DHCPv6-сервер», «Объявления маршрутизатора», «Переопределения узлов DNS», IPsec, OpenVPN и WireGuard — изначально включены. Настройки каждого другого пакета получают собственную группу, которая изначально выключена, а все остальные значения относятся к группе «Другие настройки», которая тоже изначально выключена. Включённая группа охватывает каждое поле своего вида, в том числе добавленные позже.

## Разрешённое поле \{#approved-field}

Конкретное поле конфигурации, которое пакету разрешено перезаписывать: поле во включённой группе, с которого не снята отметка, или отмеченное поле в выключенной группе. Значения вне разрешённых полей никогда не изменяются.

## Исключение для поля \{#field-exception}

Отдельное поле, отметка которого на вкладке «Поля» расходится с переключателем его группы: поле без отметки во включённой группе или отмеченное поле в выключенной группе. Каждое исключение указывает свою запись по идентификатору, например по идентификатору отслеживания (tracker ID) правила межсетевого экрана, а не по позиции в списке.

## План изменений \{#change-plan}

Полный список разрешённых полей, которые будут изменены, с прежним и новым значением каждого поля и службой для перезагрузки. Пакет составляет весь план до того, как что-либо изменить.

## Обновления по расписанию \{#scheduled-updates}

Автоматические проверки, которыми управляют флажок **Включить обновления по расписанию** (по умолчанию снят) и поле **Расписание** (по умолчанию «Ежечасно»). При сохранении настроек добавляется или удаляется запись cron под управлением pfSense, поэтому пакет Cron не нужен.

## Ручной запуск \{#manual-run}

Проверка, запущенная кнопкой **Запустить сейчас** или **Пробный запуск** на вкладке «Состояние». Она выполняется, даже когда обновления по расписанию выключены.

## Пробный запуск \{#dry-run}

Предварительный просмотр, запускаемый кнопкой **Пробный запуск**, который никогда не создаёт резервную копию и не записывает конфигурацию. Если он находит смену префикса с полями для изменения, его результат — **Пробный запуск**, и он показывает число запланированных полей.

Если префикс не изменился, пробный запуск сообщает «Без изменений», не просматривая конфигурацию.

## Вывод команды \{#command-output}

Поле только для чтения **Последний запуск** в разделе **Вывод команды**, которое появляется после действий «Запустить сейчас», «Пробный запуск» или «Принять текущий префикс». Оно показывает строки запуска от `Состояние` до `Сводка`, а после пробного запуска или результата «Успешно» за ними следует `Изменения полей`. Если действие завершилось ошибкой или блокировку удерживает другой запуск, оно показывает одну строку.

## Блокировка запуска \{#run-lock}

Блокировка, которая позволяет выполнять только одну проверку за раз. Вторая проверка завершается, не читая конфигурацию, а блокировка снимается сразу после окончания текущей проверки.

## Состояние пакета \{#package-state}

Файл `/cf/conf/ipv6-prefix-updater/state.json`, в котором пакет хранит все базовые значения и последний запуск вне конфигурации pfSense. Читать его может только root, а при перезагрузках, использовании RAM-дисков и удалении пакета файл сохраняется, поэтому после переустановки все базовые значения остаются на месте.

## Инициализировано \{#initialized}

Результат запуска, который записывает новое базовое значение. Такой запуск не создаёт резервную копию, не изменяет конфигурацию и не отправляет уведомление.

## Предварительная инициализация \{#initialization-preview}

Результат пробного запуска, выполненного, пока базового значения нет. Он показывает базовое значение, которое записал бы обычный запуск, но не записывает его.

## Без изменений \{#no-change}

Результат, когда обнаруженный префикс и его длина совпадают с последним успешным префиксом; такой запуск также называют холостым. Он не просматривает конфигурацию, не создаёт резервную копию, не перезагружает службы и не отправляет уведомление.

## Предупреждение \{#warning}

Результат, когда смена префикса обнаружена, но ни одно разрешённое поле не относится к прежнему префиксу. Ничего не записывается, базовое значение остаётся на месте, а каждое предупреждение добавляет уведомление WebGUI.

## Принято \{#accepted}

Результат после того, как оператор выбирает **Принять текущий префикс** и подтверждает, что сохранённые адреса уже используют активный префикс. Пакет переносит базовое значение, не просматривая разрешённые поля, не создавая резервную копию, не записывая конфигурацию и не перезагружая службы.

## Успешно \{#success}

Результат после того, как резервное копирование, единственная запись конфигурации, перезагрузка служб и проверка значений завершены. Базовое значение переносится на новый префикс, а если уведомление об изменении включено, оно отправляется.

## Ошибка \{#failure}

Результат, когда проверка или этап безопасности останавливает запуск. Если остановка произошла после сохранения конфигурации, новые значения остаются сохранёнными, а базовое значение остаётся на прежнем префиксе.

## Отключено \{#disabled}

Результат проверки по расписанию, запущенной при снятом флажке **Включить обновления по расписанию**. Она останавливается до чтения какого-либо интерфейса и состояния пакета и отображается только в собственном выводе команды.

## Уведомление об изменении \{#change-notification}

Сообщение, которое отправляется после результата «Успешно», если выбран флажок **Отправлять уведомления об изменениях** (по умолчанию он выбран). Оно уходит в каналы уведомлений, настроенные в pfSense, и также появляется как уведомление WebGUI.

## Каналы уведомлений \{#notification-channels}

Внешние службы оповещений, настроенные в **System → Advanced → Notifications**, например электронная почта. Уведомления об изменениях используют эти каналы, а уведомления о предупреждениях и ошибках остаются локальными.

## Уведомление WebGUI \{#webgui-notice}

Запись в списке уведомлений WebGUI pfSense со ссылкой на вкладку «Состояние» пакета, а после переноса устаревшего скрипта обновления — на вкладку «Очистка». Результаты «Предупреждение» и «Ошибка» всегда добавляют такую запись, даже если флажок **Отправлять уведомления об изменениях** снят.

## Системный журнал \{#system-log}

Общий журнал pfSense в **Status → System Logs → System → General**. Каждая строка, которую пишет пакет, начинается с `IPv6 Prefix Updater:`.

## Резервная копия конфигурации \{#configuration-backup}

Копия конфигурации в том виде, в каком она была до записи, созданная функцией резервного копирования pfSense и также сохраняемая на вкладке **Резервные копии**. Пакет создаёт её при каждом запуске с записью до изменения полей и не создаёт при запусках без записи.

## Config History (история конфигурации) \{#config-history}

Список сохранённых ревизий конфигурации в **Diagnostics → Backup & Restore → Config History**. Ревизия с описанием `Обновление префикса IPv6 изменило ...` содержит обновлённую конфигурацию, поэтому восстанавливать нужно ревизию, сохранённую перед ней.

## Перезагрузка службы \{#service-reload}

Действие pfSense, которое применяет изменённые настройки к работающей службе. Пакет перезагружает только службы, поля которых изменились, и перечисляет их в поле **Перезагруженные службы**.

## Виртуальный IP-адрес \{#virtual-ip}

Дополнительный адрес, назначенный интерфейсу в **Firewall → Virtual IPs**. Группа «Виртуальные IP-адреса» обновляет только записи CARP и IP Alias.

## Фаза 2 IPsec \{#ipsec-phase-2}

Запись IPsec, которая определяет локальную и удалённую сети туннеля. Группа IPsec охватывает локальную сторону записей Tunnel IPv6 и Routed (VTI), а удалённая сторона относится к группе «Другие настройки».

## Переопределение для клиента \{#client-specific-override}

Запись OpenVPN в **VPN → OpenVPN → Client Specific Overrides**, которая задаёт параметры для одного клиента. Пакет может обновлять её туннельную сеть IPv6 и локальные сети IPv6.

## Адрес туннеля WireGuard \{#wireguard-tunnel-address}

Адрес интерфейса, назначенный туннелю WireGuard в pfSense. Для его обновления нужен пакет WireGuard, а разрешённые IP-адреса и конечные точки пиров относятся к группе «Другие настройки».

## Устаревший скрипт обновления \{#legacy-updater}

Версия 1.x этого проекта — скрипт `update.php`, установленный в `/root` и запускаемый записью пакета Cron. Он заменял текст старого префикса в любом месте конфигурации.

## Неофициальный пакет \{#unofficial-package}

Пакет, установленный командой `pkg add` с GitHub, а не из репозитория пакетов Netgate. Netgate его не проверяет и не поддерживает, а обновления вы устанавливаете сами.
