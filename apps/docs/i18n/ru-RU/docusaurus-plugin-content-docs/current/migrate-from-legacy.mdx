## Установка пакета \{#install-the-package}

[Установите пакет](/docs/installation) командой `pkg add`, не удаляя устаревший скрипт обновления. Предварительно ничего удалять не нужно, и не рекомендуется самостоятельно удалять записи Cron или каталоги в `/root`: пакет читает их при переносе.

Повторный запуск старой команды установки не переустанавливает скрипт. Начиная с версии 2, она выводит ошибку с командой `pkg add` и ничего не изменяет.

## Что происходит автоматически \{#what-happens-automatically}

Этап установки находит устаревший скрипт обновления и переносит его в пакет в следующем порядке:

1. **Резервная копия**: сохраняет <Terminology title="копия конфигурации, сохранённая перед записью" to="/docs/reference/terminology#configuration-backup">резервную копию конфигурации</Terminology> до каких-либо изменений.
2. **Интерфейсы**: превращает каждую запись Cron в строку поля **Контролируемые интерфейсы**, сопоставляя её устройство, например `igb1.10`, с интерфейсом pfSense, который его использует, и сохраняет её <Terminology title="число начальных битов сети, например /56" to="/docs/reference/terminology#prefix-length">длину префикса</Terminology>.
3. **Расписание**: выбирает в поле **Расписание** пакета вариант, при котором проверки выполняются не реже, чем запускались записи Cron, и включает <Terminology title="автоматические проверки через запись cron под управлением pfSense" to="/docs/reference/terminology#scheduled-updates">обновления по расписанию</Terminology>.
4. **Базовые значения**: записывает каждый сохранённый префикс как <Terminology title="начальный префикс, записанный без изменения конфигурации" to="/docs/reference/terminology#baseline">базовое значение</Terminology> для его интерфейса, чтобы ни одна смена префикса не потерялась.
5. **Записи Cron**: удаляет только записи, которые запускают `update.php`, в той же операции записи конфигурации, что и новые настройки, поэтому два средства обновления никогда не работают одновременно.
6. **Резервные копии**: копирует каждую резервную копию устаревшего скрипта на вкладку **Резервные копии**, где их может читать только root, и удаляет оригинал после проверки копии.
7. **Старые файлы**: удаляет из `/root` скрипт, его сохранённые префиксы, загруженный архив и сохранённый установщик.

После завершения переноса появляется уведомление WebGUI со ссылкой на вкладку «Очистка». Если в этот момент устаревший скрипт выполняется, пакет ждёт и завершает перенос при следующей проверке по расписанию.

### Несколько записей Cron \{#several-cron-entries}

Каждая запись Cron с другим устройством становится отдельной строкой, и один запуск проверяет их все. Интерфейсы с общим <Terminology title="сеть IPv6, которую провайдер направляет на межсетевой экран" to="/docs/reference/terminology#delegated-prefix">делегированным префиксом</Terminology> обновляют общие поля один раз, одной записью с резервной копией.

Запись Cron, устройство которой больше не принадлежит ни одному интерфейсу pfSense, удаляется и отображается как предупреждение: скрипт всё равно не мог ничего обновить через неё.

### Устаревшие сохранённые префиксы \{#saved-prefixes-that-are-out-of-date}

Если провайдер сменил префикс после последнего запуска устаревшего скрипта обновления, его сохранённый префикс остаётся <Terminology title="начальный префикс, записанный без изменения конфигурации" to="/docs/reference/terminology#baseline">базовым значением</Terminology>. Тогда первая проверка пакета находит поля, которые всё ещё используют старый префикс, и обновляет их.

Если ни одно разрешённое поле не использует старый сохранённый префикс, базовым значением вместо него становится текущий префикс, поэтому первая проверка не сообщает «<Terminology title="результат: префикс сменился, но подходящих разрешённых полей нет" to="/docs/reference/terminology#warning">Предупреждение</Terminology>».

Откройте **Services → IPv6 Prefix Updater → Очистка**, чтобы увидеть все остатки устаревшего скрипта и то, что произошло с каждым из них.

## Проверка охвата \{#check-coverage}

После первой реальной <Terminology title="отличие от последнего успешного префикса или длины" to="/docs/reference/terminology#prefix-transition">смены префикса</Terminology> сравните поля **Изменённые поля** и **Сводка** с тем, что раньше изменял <Terminology title="исходный скрипт update.php, запускаемый пакетом Cron" to="/docs/reference/terminology#legacy-updater">устаревший скрипт обновления</Terminology>. Устаревший скрипт обновления также перезаписывал шлюзы, статические маршруты, описания и значения в кодировке Base64. Пакет изменяет их, только если они отмечены в группе **Другие настройки** на вкладке **Поля**, поэтому рекомендуется отметить их до смены префикса.

После переноса все <Terminology title="группа полей с одним переключателем на вкладке «Поля»" to="/docs/reference/terminology#field-group">группы полей</Terminology> pfSense включены — так же, как их включает кнопка **Выбрать автоматически**. Все группы и способ выключить любую из них описаны в разделе [Поля](/docs/configure/configuration-scopes).
