Проследите один запуск от чтения адресов интерфейсов до записи результата, включая все места, где он может остановиться.

## 1. Чтение и проверка \{#1-read-and-validate}

- Проверка по расписанию сразу останавливается с результатом «<Terminology title="Плановая проверка пропущена, потому что обновления по расписанию выключены" to="/docs/reference/terminology#run-outcomes">Отключено</Terminology>», если флажок **<Terminology title="Автоматические проверки по расписанию, выключены, пока вы их не включите" to="/docs/reference/terminology#running-checks">Включить обновления по расписанию</Terminology>** снят. <Terminology title="Проверка, которую вы запускаете сами, даже без расписания" to="/docs/reference/terminology#running-checks">Ручной запуск</Terminology> продолжается.
- Запуск снова проверяет сохранённые настройки, потому что они могли измениться после сохранения формы.
- Он заново считывает <Terminology title="Публичный адрес IPv6 из 2000::/3, единственный используемый вид" to="/docs/reference/terminology#addresses-and-prefixes">глобальный адрес</Terminology> каждого <Terminology title="Контролируемый интерфейс, адрес которого выдаёт текущий префикс" to="/docs/reference/terminology#interfaces-and-detection">контролируемого интерфейса</Terminology> без перехода на <Terminology title="Адрес fe80, который никогда не служит источником" to="/docs/reference/terminology#addresses-and-prefixes">адрес link-local</Terminology> и приводит его к <Terminology title="Короткая запись строчными буквами, например 2001:db8::1" to="/docs/reference/terminology#addresses-and-prefixes">канонической форме</Terminology>.
- Он маскирует каждый адрес по <Terminology title="Размер префикса от провайдера, например /56; задаёте его вы" to="/docs/reference/terminology#addresses-and-prefixes">длине делегированного префикса</Terminology> из его строки и получает <Terminology title="Префикс, видимый сейчас, в сравнении с прошлым" to="/docs/reference/terminology#interfaces-and-detection">обнаруженный префикс</Terminology>.

## 2. Сравнение \{#2-compare}

- Если для интерфейса нет <Terminology title="Записанный исходный префикс, от которого отсчитываются изменения" to="/docs/reference/terminology#baselines-and-transitions">базового значения</Terminology>, запуск записывает его и завершается с результатом «<Terminology title="Первый взгляд: базовое значение записано, ничего не меняется" to="/docs/reference/terminology#run-outcomes">Инициализировано</Terminology>».
- Если префикс и его длина совпадают с <Terminology title="Сохранённый префикс, с которым сравнивает каждая проверка" to="/docs/reference/terminology#baselines-and-transitions">последним успешным префиксом</Terminology>, запуск завершается с результатом «<Terminology title="Тот же префикс, что и в прошлый раз, делать нечего" to="/docs/reference/terminology#run-outcomes">Без изменений</Terminology>», не просматривая конфигурацию.
- Другой префикс или другая длина — это <Terminology title="Префикс сменился, и пакет берётся за работу" to="/docs/reference/terminology#baselines-and-transitions">смена префикса</Terminology>, и запуск продолжается.

## 3. Планирование \{#3-plan}

- Запуск читает конфигурацию через функции конфигурации pfSense и оставляет только поля, выбранные на вкладке «Поля». Выбранные поля, которых больше нет, пропускаются и указываются в строке **Пропущенные поля**.
- Каждый адрес в <Terminology title="Настройка, которую пакету разрешено переписывать" to="/docs/reference/terminology#fields-and-change-plans">разрешённом поле</Terminology>, который относится к прежнему префиксу при сохранённой длине, получает биты нового префикса при текущей длине и сохраняет свою <Terminology title="Биты после префикса, всегда копируются без изменений" to="/docs/reference/terminology#addresses-and-prefixes">узловую часть</Terminology>. Вместе эти изменения образуют полный <Terminology title="Все запланированные замены, собранные до любых изменений" to="/docs/reference/terminology#fields-and-change-plans">план изменений</Terminology>.
- Если менять нечего, запуск завершается с результатом «<Terminology title="Префикс сменился, но ни одно разрешённое поле не использовало старый" to="/docs/reference/terminology#run-outcomes">Предупреждение</Terminology>». <Terminology title="Предпросмотр изменений, который ничего не записывает" to="/docs/reference/terminology#running-checks">Пробный запуск</Terminology> с изменениями завершается здесь с результатом «<Terminology title="Предпросмотр изменений, который ничего не записывает" to="/docs/reference/terminology#running-checks">Пробный запуск</Terminology>».

## 4. Предварительная проверка \{#4-preflight}

- Запуск убеждается, что pfSense может перезагрузить каждую службу из плана. Для этого <Terminology title="Адрес на интерфейсе туннеля WireGuard" to="/docs/reference/terminology#pfsense-features">адресам туннелей WireGuard</Terminology> нужен пакет WireGuard.
- Он убеждается, что каждое запланированное поле всё ещё содержит то значение, которое было при составлении плана.

## 5. Резервная копия и единственная запись \{#5-back-up-and-write-once}

- pfSense создаёт <Terminology title="Копия конфигурации, снятая прямо перед любой записью" to="/docs/reference/terminology#backups-and-service-reloads">резервную копию конфигурации</Terminology>, и запуск останавливается, если pfSense её не подтверждает.
- Запуск применяет все изменения и сохраняет конфигурацию один раз с описанием `Обновление префикса IPv6 изменило <count> разрешённых полей для интерфейса <interface>`.
- Если pfSense сообщает о неудачном сохранении, запуск возвращает исходные значения в памяти и останавливается.

## 6. Проверка, перезагрузка, проверка \{#6-verify-reload-verify}

- Запуск проверяет, что сохранённые значения соответствуют плану, перезагружает затронутые службы и снова проверяет значения.
- Службы перезагружаются в фиксированном порядке из раздела [Действия перезагрузки](/docs/reference/approved-fields#reload-actions): от службы «Интерфейсы» до WireGuard. За перезагрузкой интерфейсов следует перезагрузка фильтра межсетевого экрана, которая затем не повторяется.
- Перезагрузки фильтра межсетевого экрана, DNS Resolver и DNS Forwarder приводят к ошибке запуска, если возвращают признак сбоя. Остальные перезагрузки приводят к ошибке запуска, только если выбрасывают исключение.
- Настройки других пакетов применяются повторно в последнюю очередь, после перезагрузок и их проверки. О пакете, настройки которого не удалось применить, сообщается отдельно, а сохранённые значения остаются.
- Ошибка на этом этапе оставляет новые значения сохранёнными.

## 7. Запись результата и уведомление \{#7-record-and-notify}

- <Terminology title="Записанный исходный префикс, от которого отсчитываются изменения" to="/docs/reference/terminology#baselines-and-transitions">Базовое значение</Terminology> переносится на новый префикс, а раздел **Последний запуск** записывает результат «<Terminology title="Префикс сменился, и все разрешённые поля обновлены" to="/docs/reference/terminology#run-outcomes">Успешно</Terminology>» с числом изменённых полей и <Terminology title="Применяет изменённые настройки к работающей службе" to="/docs/reference/terminology#backups-and-service-reloads">перезагруженными службами</Terminology>.
- Запуск пишет строку в <Terminology title="Общий журнал pfSense, где каждый запуск оставляет строки" to="/docs/reference/terminology#notifications-and-logs">системный журнал</Terminology> и, если включено, отправляет <Terminology title="Оповещение после обновления ваших адресов" to="/docs/reference/terminology#notifications-and-logs">уведомление об изменении</Terminology>. Неудачное уведомление не меняет результат.
