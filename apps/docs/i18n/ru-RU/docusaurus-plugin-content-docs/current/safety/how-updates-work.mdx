Проследите один запуск от чтения адресов интерфейсов до записи результата, включая все места, где он может остановиться.

## 1. Чтение и проверка \{#1-read-and-validate}

- Проверка по расписанию сразу останавливается с результатом «<Terminology title="результат: проверка по расписанию пропущена, обновления выключены" to="/docs/reference/terminology#disabled">Отключено</Terminology>», если флажок **<Terminology title="автоматические проверки через запись cron под управлением pfSense" to="/docs/reference/terminology#scheduled-updates">Включить обновления по расписанию</Terminology>** снят. <Terminology title="проверка, запущенная с вкладки «Состояние»" to="/docs/reference/terminology#manual-run">Ручной запуск</Terminology> продолжается.
- Запуск снова проверяет сохранённые настройки, потому что они могли измениться после сохранения формы.
- Он заново считывает <Terminology title="публичный IPv6-адрес из диапазона 2000::/3" to="/docs/reference/terminology#global-unicast-address">глобальный адрес</Terminology> каждого <Terminology title="интерфейс, по адресу которого определяется текущий префикс" to="/docs/reference/terminology#monitored-interface">контролируемого интерфейса</Terminology> без перехода на <Terminology title="адрес fe80::, действующий только в одном канале" to="/docs/reference/terminology#link-local-address">адрес link-local</Terminology> и приводит его к <Terminology title="стандартная краткая запись адреса строчными буквами" to="/docs/reference/terminology#canonical-form">канонической форме</Terminology>.
- Он маскирует каждый адрес по <Terminology title="размер префикса провайдера, от /48 до /64" to="/docs/reference/terminology#delegated-prefix-length">длине делегированного префикса</Terminology> из его строки и получает <Terminology title="исходный адрес, маскированный по длине префикса" to="/docs/reference/terminology#observed-prefix">обнаруженный префикс</Terminology>.

## 2. Сравнение \{#2-compare}

- Если для интерфейса нет <Terminology title="начальный префикс, записанный без изменения конфигурации" to="/docs/reference/terminology#baseline">базового значения</Terminology>, запуск записывает его и завершается с результатом «<Terminology title="результат: базовое значение записано, конфигурация не изменена" to="/docs/reference/terminology#initialized">Инициализировано</Terminology>».
- Если префикс и его длина совпадают с <Terminology title="префикс, с которым сравнивает следующая проверка" to="/docs/reference/terminology#last-successful-prefix">последним успешным префиксом</Terminology>, запуск завершается с результатом «<Terminology title="результат: префикс прежний, ничего не просмотрено и не записано" to="/docs/reference/terminology#no-change">Без изменений</Terminology>», не просматривая конфигурацию.
- Другой префикс или другая длина — это <Terminology title="отличие от последнего успешного префикса или длины" to="/docs/reference/terminology#prefix-transition">смена префикса</Terminology>, и запуск продолжается.

## 3. Планирование \{#3-plan}

- Запуск читает конфигурацию через функции конфигурации pfSense и оставляет только поля, выбранные на вкладке «Поля». Выбранные поля, которых больше нет, пропускаются и указываются в строке **Пропущенные поля**.
- Каждый адрес в <Terminology title="конкретное поле конфигурации, которое пакет может перезаписать" to="/docs/reference/terminology#approved-field">разрешённом поле</Terminology>, который относится к прежнему префиксу при сохранённой длине, получает биты нового префикса при текущей длине и сохраняет свою <Terminology title="биты адреса после делегированного префикса" to="/docs/reference/terminology#host-portion">узловую часть</Terminology>. Вместе эти изменения образуют полный <Terminology title="полный список изменений полей, составленный до записи" to="/docs/reference/terminology#change-plan">план изменений</Terminology>.
- Если менять нечего, запуск завершается с результатом «<Terminology title="результат: префикс сменился, но подходящих разрешённых полей нет" to="/docs/reference/terminology#warning">Предупреждение</Terminology>». <Terminology title="предварительный просмотр без резервной копии и записи" to="/docs/reference/terminology#dry-run">Пробный запуск</Terminology> с изменениями завершается здесь с результатом «<Terminology title="предварительный просмотр без резервной копии и записи" to="/docs/reference/terminology#dry-run">Пробный запуск</Terminology>».

## 4. Предварительная проверка \{#4-preflight}

- Запуск убеждается, что pfSense может перезагрузить каждую службу из плана. Для этого <Terminology title="адрес, назначенный туннелю WireGuard в pfSense" to="/docs/reference/terminology#wireguard-tunnel-address">адресам туннелей WireGuard</Terminology> нужен пакет WireGuard.
- Он убеждается, что каждое запланированное поле всё ещё содержит то значение, которое было при составлении плана.

## 5. Резервная копия и единственная запись \{#5-back-up-and-write-once}

- pfSense создаёт <Terminology title="копия конфигурации, сохранённая перед записью" to="/docs/reference/terminology#configuration-backup">резервную копию конфигурации</Terminology>, и запуск останавливается, если pfSense её не подтверждает.
- Запуск применяет все изменения и сохраняет конфигурацию один раз с описанием `Обновление префикса IPv6 изменило <count> разрешённых полей для интерфейса <interface>`.
- Если pfSense сообщает о неудачном сохранении, запуск возвращает исходные значения в памяти и останавливается.

## 6. Проверка, перезагрузка, проверка \{#6-verify-reload-verify}

- Запуск проверяет, что сохранённые значения соответствуют плану, перезагружает затронутые службы и снова проверяет значения.
- Службы перезагружаются в фиксированном порядке из раздела [Действия перезагрузки](/docs/reference/approved-fields#reload-actions): от службы «Интерфейсы» до WireGuard. За перезагрузкой интерфейсов следует перезагрузка фильтра межсетевого экрана, которая затем не повторяется.
- Перезагрузки фильтра межсетевого экрана, DNS Resolver и DNS Forwarder приводят к ошибке запуска, если возвращают признак сбоя. Остальные перезагрузки приводят к ошибке запуска, только если выбрасывают исключение.
- Настройки других пакетов применяются повторно в последнюю очередь, после перезагрузок и их проверки. О пакете, настройки которого не удалось применить, сообщается отдельно, а сохранённые значения остаются.
- Ошибка на этом этапе оставляет новые значения сохранёнными.

## 7. Запись результата и уведомление \{#7-record-and-notify}

- <Terminology title="начальный префикс, записанный без изменения конфигурации" to="/docs/reference/terminology#baseline">Базовое значение</Terminology> переносится на новый префикс, а раздел **Последний запуск** записывает результат «<Terminology title="результат: поля обновлены, сохранены, перезагружены и проверены" to="/docs/reference/terminology#success">Успешно</Terminology>» с числом изменённых полей и <Terminology title="действие pfSense, применяющее изменённые настройки" to="/docs/reference/terminology#service-reload">перезагруженными службами</Terminology>.
- Запуск пишет строку в <Terminology title="общий журнал pfSense, в который пишет пакет" to="/docs/reference/terminology#system-log">системный журнал</Terminology> и, если включено, отправляет <Terminology title="оповещение после проверенного успешного обновления" to="/docs/reference/terminology#change-notification">уведомление об изменении</Terminology>. Неудачное уведомление не меняет результат.
