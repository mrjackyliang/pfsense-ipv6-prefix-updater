Выберите интерфейсы, по которым видны текущие префиксы, и укажите для каждого <Terminology title="число начальных битов сети, например /56" to="/docs/reference/terminology#prefix-length">длину префикса</Terminology>, которую делегирует провайдер.

## Выбор контролируемых интерфейсов \{#choose-the-monitored-interfaces}

Добавьте в поле **Контролируемые интерфейсы** строку для каждого интерфейса, <Terminology title="публичный IPv6-адрес из диапазона 2000::/3" to="/docs/reference/terminology#global-unicast-address">глобальный адрес</Terminology> которого получен из <Terminology title="сеть IPv6, которую провайдер направляет на межсетевой экран" to="/docs/reference/terminology#delegated-prefix">делегированного префикса</Terminology>. Пакет заново считывает все эти адреса при каждом запуске и никогда не переключается на <Terminology title="адрес fe80::, действующий только в одном канале" to="/docs/reference/terminology#link-local-address">адрес link-local</Terminology>.

Если WAN получает только <Terminology title="сеть IPv6, которую провайдер направляет на межсетевой экран" to="/docs/reference/terminology#delegated-prefix">делегированный префикс</Terminology>, <Terminology title="публичный IPv6-адрес из диапазона 2000::/3" to="/docs/reference/terminology#global-unicast-address">глобальный адрес</Terminology> из него обычно есть у <Terminology title="интерфейс с адресом из делегированного префикса другого интерфейса" to="/docs/reference/terminology#tracked-interface">интерфейса в режиме Track Interface</Terminology>, например LAN, и именно его стоит выбрать.

<img src={monitoredInterfaces} alt="Вкладка «Настройки» пакета IPv6 Prefix Updater с двумя строками в поле «Контролируемые интерфейсы», LAN и LAB, у каждой из которых длина делегированного префикса /56, и указанием на вкладку «Поля»" width={1024} height={768} style={{maxWidth: '100%', height: 'auto'}} />

- **Добавить**: добавляет строку. Каждый интерфейс может быть только в одной строке, а сохранить настройки без строк нельзя.
- **Удалить**: удаляет строку. pfSense скрывает эту кнопку, пока остаётся только одна строка.
- **Один запуск для всех строк**: каждая проверка по расписанию считывает все контролируемые интерфейсы и сохраняет их изменения одной записью с резервной копией.

Большинству межсетевых экранов достаточно одной строки. Добавляйте строки, если несколько интерфейсов получают собственный делегированный префикс, например при двух подключениях WAN, или если нужно проверять адрес каждого сегмента LAN.

Чтобы проверить выбор:

1. Сохраните настройки со снятым флажком **<Terminology title="автоматические проверки через запись cron под управлением pfSense" to="/docs/reference/terminology#scheduled-updates">Включить обновления по расписанию</Terminology>**.
2. На вкладке «Состояние» выберите **Запустить сейчас**.
3. Сравните **<Terminology title="глобальный адрес контролируемого интерфейса по данным pfSense" to="/docs/reference/terminology#source-address">Обнаруженный исходный адрес</Terminology>** с адресом в **Status → Interfaces**.
4. Если адрес относится не к той сети, выберите другой интерфейс и повторите проверку.

Вкладка «Состояние» показывает описание каждого интерфейса и за ним внутреннее имя в pfSense, например `LAN (lan)`.

## Указание длины делегированного префикса \{#enter-the-delegated-prefix-length}

Выберите длину по сведениям об услуге провайдера или по размеру делегирования префикса DHCPv6 на интерфейсе WAN. Поле **<Terminology title="размер префикса провайдера, от /48 до /64" to="/docs/reference/terminology#delegated-prefix-length">Длина делегированного префикса</Terminology>** принимает значения от `/48` до `/64`, начальное значение — `/56`, и оно никогда не определяется автоматически.

:::tip

Рекомендуется проверить длину до первого запуска кнопкой **Запустить сейчас**, потому что <Terminology title="начальный префикс, записанный без изменения конфигурации" to="/docs/reference/terminology#baseline">базовое значение</Terminology> хранит длину вместе с префиксом.

:::

## Проверка вычисленной сети \{#check-the-calculated-network}

После запуска поле **<Terminology title="исходный адрес, маскированный по длине префикса" to="/docs/reference/terminology#observed-prefix">Обнаруженный префикс</Terminology>** показывает вычисленную сеть. Длины, граница которых приходится на середину шестнадцатеричной цифры, например `/57` или `/63`, работают так же, потому что пакет маскирует адреса побитово.

Для делегирования `/56`, которое меняется с `2001:db8:abcd:7800::/56` на `2001:db8:abcd:8800::/56`:

```text
Source address:    2001:db8:abcd:88aa::1
Current prefix:    2001:db8:abcd:8800::/56
Previous address:  2001:db8:abcd:78aa::42
Updated address:   2001:db8:abcd:88aa::42
```

Меняются только первые 56 бит, а <Terminology title="биты адреса после делегированного префикса" to="/docs/reference/terminology#host-portion">узловая часть</Terminology> `aa::42` остаётся прежней. Адреса из `2001:db8::/32` в этих руководствах — примеры для документации.

## Смена интерфейсов \{#changing-the-interfaces}

:::warning

Если добавить <Terminology title="интерфейс, по адресу которого определяется текущий префикс" to="/docs/reference/terminology#monitored-interface">контролируемый интерфейс</Terminology> или выбрать в строке другой интерфейс, следующий запуск запишет для него новое <Terminology title="начальный префикс, записанный без изменения конфигурации" to="/docs/reference/terminology#baseline">базовое значение</Terminology>, не изменяя конфигурацию. Если его префикс уже сменился, а пакет ещё не применил это изменение, оно будет пропущено.

:::

При удалении строки <Terminology title="начальный префикс, записанный без изменения конфигурации" to="/docs/reference/terminology#baseline">базовое значение</Terminology> этого интерфейса сохраняется в <Terminology title="файл пакета с базовым значением и последним запуском" to="/docs/reference/terminology#package-state">состоянии пакета</Terminology>. Если позже снова добавить этот интерфейс, пакет будет сравнивать префикс с сохранённым базовым значением, а не записывать новое.

## Изменение длины префикса \{#changing-the-prefix-length}

Изменение поля **<Terminology title="размер префикса провайдера, от /48 до /64" to="/docs/reference/terminology#delegated-prefix-length">Длина делегированного префикса</Terminology>** после появления <Terminology title="начальный префикс, записанный без изменения конфигурации" to="/docs/reference/terminology#baseline">базового значения</Terminology> считается <Terminology title="отличие от последнего успешного префикса или длины" to="/docs/reference/terminology#prefix-transition">сменой префикса</Terminology>, даже если сама сеть остаётся прежней. Пакет сопоставляет адреса по длине, сохранённой в <Terminology title="начальный префикс, записанный без изменения конфигурации" to="/docs/reference/terminology#baseline">базовом значении</Terminology>, и заменяет биты по новой длине.

:::danger

Увеличение длины (сужение сети) перезаписывает биты подсети в каждом совпадающем адресе. Если <Terminology title="глобальный адрес контролируемого интерфейса по данным pfSense" to="/docs/reference/terminology#source-address">исходный адрес</Terminology> — `2001:db8:1234:ab00::1`, а <Terminology title="начальный префикс, записанный без изменения конфигурации" to="/docs/reference/terminology#baseline">базовое значение</Terminology> имеет длину `/56`, переход на `/64` превращает `2001:db8:1234:abcc::42` в `2001:db8:1234:ab00::42`.

:::

Уменьшение длины (расширение сети), например с `/64` до `/56`, может оставить запуск без изменений. Тогда каждый запуск сообщает «<Terminology title="результат: префикс сменился, но подходящих разрешённых полей нет" to="/docs/reference/terminology#warning">Предупреждение</Terminology>», пока не сменится сам префикс или пока вы не проверите сохранённые адреса и не [примете текущий префикс](/docs/operate/backups-and-recovery#after-a-failed-run) как новое базовое значение.

Перед изменением длины рекомендуется в том же сохранении снять флажок **<Terminology title="автоматические проверки через запись cron под управлением pfSense" to="/docs/reference/terminology#scheduled-updates">Включить обновления по расписанию</Terminology>**. Тогда **<Terminology title="предварительный просмотр без резервной копии и записи" to="/docs/reference/terminology#dry-run">Пробный запуск</Terminology>** покажет число запланированных полей, каждое запланированное изменение в разделе `Изменения полей` и поле **Сводка** до того, как вы выберете **Запустить сейчас**.

Далее [создайте базовое значение](/docs/first-run), а затем выберите поля на вкладке [Поля](/docs/configure/configuration-scopes).
