Ejecuta el comando del paquete desde una shell y localiza los archivos, registros y avisos que utiliza.

## Uso \{#usage}

```text
Uso: ipv6-prefix-updater [--manual] [--dry-run] [--accept-current-prefix [--interface=NAME]] [--migrate-legacy]
Opciones de actualización: --check-updates, --self-update.
```

La entrada de cron de comprobación del prefijo gestionada por pfSense ejecuta el comando como `root` sin opciones, mientras que otra entrada independiente, de comprobación de versiones, lo ejecuta con `--check-updates`. Antes de cada comprobación, también traslada al paquete cualquier resto del <Terminology title="Versión 1.x: el script update.php ejecutado por el paquete Cron" to="/docs/reference/terminology#package-origins">actualizador heredado</Terminology>. La pestaña Estado usa `--manual` para **Ejecutar ahora**, `--dry-run` para **<Terminology title="Una vista previa de los cambios que no escribe nada" to="/docs/reference/terminology#running-checks">Simulación</Terminology>** y `--accept-current-prefix` para la recuperación de la referencia, y la pestaña Limpieza usa `--migrate-legacy`.

Sin opciones, el comando se comporta como una comprobación programada y devuelve <Terminology title="Comprobación programada omitida porque el horario está apagado" to="/docs/reference/terminology#run-outcomes">Desactivado</Terminology> cuando **<Terminology title="Comprobaciones automáticas programadas, apagadas por defecto" to="/docs/reference/terminology#running-checks">Activar actualizaciones programadas</Terminology>** está desactivada.

## Opciones \{#options}

| Opción                    | Descripción                                                                                                                                                                                                                                                                                                                                |
|---------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `--manual`                | Se ejecuta aunque las <Terminology title="Comprobaciones automáticas programadas, apagadas por defecto" to="/docs/reference/terminology#running-checks">actualizaciones programadas</Terminology> estén desactivadas.                                                                                                                      |
| `--dry-run`               | Muestra una vista previa sin copia de seguridad ni escritura, e implica `--manual`.                                                                                                                                                                                                                                                        |
| `--accept-current-prefix` | Registra la dirección de origen, el prefijo y la longitud activos como referencia sin analizar los campos aprobados, crear una copia de seguridad, escribir la configuración ni recargar servicios. Implica `--manual` y no se puede combinar con `--dry-run`.                                                                             |
| `--interface=NAME`        | Limita `--accept-current-prefix` a una sola interfaz supervisada, indicada por su nombre interno, como `lan`. Sin esta opción, se aceptan todas las interfaces supervisadas que tienen dirección.                                                                                                                                          |
| `--migrate-legacy`        | Traslada de inmediato el <Terminology title="Versión 1.x: el script update.php ejecutado por el paquete Cron" to="/docs/reference/terminology#package-origins">actualizador heredado</Terminology> al paquete y muestra cada paso, sin ejecutar una comprobación del prefijo. Sale con `2` cuando la migración informó de una advertencia. |
| `--check-updates`         | Busca en GitHub la última versión del paquete y guarda el resultado en `/cf/conf/ipv6-prefix-updater/updates.json`. [Actualizaciones](/docs/reference/updates) describe la comprobación.                                                                                                                                                   |
| `--self-update`           | Descarga, comprueba e instala la última versión, y registra el progreso en `/cf/conf/ipv6-prefix-updater/update-status.json`.                                                                                                                                                                                                              |
| `--help`                  | Muestra la línea de uso y la línea de opciones de actualización, y sale con `0`. Ninguna de las dos líneas incluye el propio `--help`.                                                                                                                                                                                                     |

Cualquier otra opción muestra `Opción desconocida: <opción>` en la salida de error estándar y sale con `64`. Combinar `--accept-current-prefix` con `--dry-run` también sale con `64`, al igual que combinar `--check-updates` o `--self-update` entre sí o con cualquier opción de prefijo.

## Salida \{#output}

Una ejecución completada que supervisa una sola interfaz muestra nueve líneas en la salida estándar, seguidas de los cambios de campos después de una <Terminology title="Una vista previa de los cambios que no escribe nada" to="/docs/reference/terminology#running-checks">simulación</Terminology> o de un resultado <Terminology title="El prefijo cambió y se actualizó cada campo aprobado" to="/docs/reference/terminology#run-outcomes">Correcto</Terminology>:

```text
Estado: Correcto
Interfaz: lan
Dirección de origen observada: 2001:db8:abcd:88aa::1
Prefijo anterior: 2001:db8:abcd:7800::
Prefijo actual: 2001:db8:abcd:8800::/56
Campos planificados o modificados: 1
Copia de seguridad de la configuración: Creada
Servicios recargados: Filtro del cortafuegos
Resumen: Se actualizaron 1 campo(s) aprobado(s) de 2001:db8:abcd:7800::/56 a 2001:db8:abcd:8800::/56 en la interfaz lan.
Cambios de campos:
- aliases/alias/0/address: 2001:db8:abcd:78aa::10 → 2001:db8:abcd:88aa::10
```

- `Prefijo anterior` no tiene longitud, y muestra `No disponible` tras <Terminology title="Primer vistazo: se registra la referencia y nada cambia" to="/docs/reference/terminology#run-outcomes">Inicializado</Terminology> o <Terminology title="Una simulación que muestra la referencia que registraría" to="/docs/reference/terminology#run-outcomes">Vista previa de la inicialización</Terminology>.
- `Servicios recargados` enumera las etiquetas de la pestaña Estado o `Ninguno`. Tras una <Terminology title="Una vista previa de los cambios que no escribe nada" to="/docs/reference/terminology#running-checks">simulación</Terminology>, enumera los servicios que se recargarían.
- `Cambios de campos` tiene una línea por cada dirección sustituida, escrita como `- <ruta>: <antigua> → <nueva>`, para un máximo de 200 campos.
- Cuando la ejecución volvió a aplicar los ajustes de otro paquete u omitió un campo marcado que ya no existe, sigue una línea por cada caso, redactada como en la pestaña Estado.
- Cuando otra comprobación tiene el <Terminology title="Impide que dos comprobaciones se ejecuten a la vez" to="/docs/reference/terminology#running-checks">bloqueo de ejecución</Terminology>, la única salida es `Otra ejecución posee el bloqueo del paquete; esta invocación salió sin leer la configuración.`
- Con varias interfaces supervisadas, la salida empieza con las líneas generales de `Estado`, `Resumen`, paquetes y campos omitidos, seguidas de las líneas de cada interfaz, separadas por líneas en blanco.
- Cuando hubo una migración del <Terminology title="Versión 1.x: el script update.php ejecutado por el paquete Cron" to="/docs/reference/terminology#package-origins">actualizador heredado</Terminology> antes de la comprobación, sus pasos se muestran primero.
- Las etiquetas y los mensajes siguen el ajuste de idioma de pfSense.

## Formato del estado del paquete \{#package-state-format}

| Clave                 | Descripción                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
|-----------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `schema_version`      | Siempre `1`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `targets.<interface>` | Una <Terminology title="El prefijo inicial registrado con el que se miden los cambios" to="/docs/reference/terminology#baselines-and-transitions">referencia</Terminology> por cada interfaz supervisada, con su nombre interno como clave y con `interface`, `source_address`, `prefix`, `prefix_length` y `updated_at`. Una referencia tomada del <Terminology title="Versión 1.x: el script update.php ejecutado por el paquete Cron" to="/docs/reference/terminology#package-origins">actualizador heredado</Terminology> también tiene `source` con el valor `legacy_cache`. |
| `last_run`            | La última ejecución registrada, con `status`, `timestamp`, `interface`, `observed_address`, `previous_prefix`, `current_prefix`, `current_prefix_length`, `change_count`, `backup_created`, `services`, `message`, `message_key` y `message_arguments`.                                                                                                                                                                                                                                                                                                                           |
| `legacy_migration`    | Existe después de una migración del <Terminology title="Versión 1.x: el script update.php ejecutado por el paquete Cron" to="/docs/reference/terminology#package-origins">actualizador heredado</Terminology>, con `status`, `steps`, `warnings` y `recorded_at`. La pestaña Limpieza lo muestra.                                                                                                                                                                                                                                                                                 |

- `status` es uno de estos valores: `initialized`, `initialization_preview`, `no_change`, `dry_run`, `warning`, `accepted`, `success` o `failure`.
- Tras un resultado <Terminology title="El prefijo cambió y se actualizó cada campo aprobado" to="/docs/reference/terminology#run-outcomes">Correcto</Terminology>, `last_run.notification` es `disabled` cuando las notificaciones están desactivadas, o `sent` o `failed` tras un intento de envío.
- Tras una <Terminology title="Una vista previa de los cambios que no escribe nada" to="/docs/reference/terminology#running-checks">simulación</Terminology> o un resultado <Terminology title="El prefijo cambió y se actualizó cada campo aprobado" to="/docs/reference/terminology#run-outcomes">Correcto</Terminology>, cada resultado también tiene `changes`, que enumera la `path` y los `replacements` de un máximo de 200 campos, donde cada sustitución es una dirección antigua y una nueva.
- `package_reapply` enumera la `section`, el `package`, el `status` y el `error` de cada paquete cuyos ajustes volvió a aplicar la ejecución, y `skipped_fields` enumera los campos marcados que ya no existen. Cada uno solo aparece cuando no está vacío.
- Con varias interfaces supervisadas, `last_run` contiene los totales y una lista `targets` con un resultado por interfaz.
- Las marcas de tiempo usan ISO 8601 en UTC. Un archivo que no se puede analizar, o que tiene otra versión de esquema, detiene cada ejecución con `El estado del Actualizador de prefijo IPv6 no es válido o no es compatible.`

## Almacenamiento de los ajustes \{#settings-storage}

Los ajustes se guardan en la configuración de pfSense, en `installedpackages/ipv6prefixupdater/config/0`.

| Clave                         | Descripción                                                                                                                                                                                                            |
|-------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `enabled`                     | **<Terminology title="Comprobaciones automáticas programadas, apagadas por defecto" to="/docs/reference/terminology#running-checks">Activar actualizaciones programadas</Terminology>**, `on` cuando está marcada.     |
| `row`                         | **Interfaces supervisadas**, una lista con un `interface` (una clave de interfaz, como `lan`) y un `prefix_length` (de `48` a `64`) por fila.                                                                          |
| `update_frequency`            | **Programación**, uno de `every_fifteen_minutes`, `hourly`, `every_six_hours` o `daily`.                                                                                                                               |
| `notifications`               | **<Terminology title="El aviso que se envía después de actualizar tus direcciones" to="/docs/reference/terminology#notifications-and-logs">Enviar notificaciones de cambios</Terminology>**, `on` cuando está marcada. |
| `update_check_frequency`      | **Comprobaciones de actualizaciones**, uno de `daily`, `weekly`, `monthly` o `never`.                                                                                                                                  |
| `update_remote_notifications` | **Notificaciones remotas**, `on` cuando está marcada.                                                                                                                                                                  |

La programación estable de la comprobación de versiones se guarda junto al registro de ajustes en `installedpackages/ipv6prefixupdater/update_schedule`, con `minute` de 0 a 59, `hour` de 0 a 23, `weekday` de 0 a 6 y `monthday` de 1 a 28. Un valor que falta, mal formado o fuera de rango se vuelve a generar y se guarda.

### Selección de campos \{#field-selection}

Las elecciones de la pestaña Campos se guardan junto al registro de ajustes, en `installedpackages/ipv6prefixupdater/fields`, así que guardar la pestaña Configuración, que sustituye `config/0`, nunca las borra.

| Clave                  | Descripción                                                                                                                                              |
|------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------|
| `schema`               | Siempre `1`. Indica una selección guardada desde la pestaña Campos, aunque esté vacía.                                                                   |
| `enabled_groups/item`  | Grupos activados, como `firewall_rules`, `dhcpv6` o `package:<section>` para los ajustes de otro paquete.                                                |
| `disabled_groups/item` | Grupos de pfSense desactivados. Un grupo de pfSense que no está en ninguna de las dos listas está activado, y el grupo de otro paquete está desactivado. |
| `include/item`         | Identidades de los campos marcados en un grupo desactivado.                                                                                              |
| `exclude/item`         | Identidades de los campos desmarcados en un grupo activado.                                                                                              |

- Las claves de los grupos de pfSense son `interfaces`, `virtual_ips`, `aliases`, `firewall_rules`, `nat`, `dhcpv6`, `router_advertisements`, `dns_host_overrides`, `ipsec`, `openvpn` y `wireguard`.
- `include` y `exclude` guardan como máximo 1000 identidades cada una, y cada identidad sigue [Identidades de campos](/docs/reference/approved-fields#field-identities).

## Entrada de cron \{#cron-entry}

Al guardar los ajustes se elimina cualquier entrada existente del comando y, cuando `enabled` es `on`, se instala una nueva para `root` con `install_cron_job()` de pfSense.

| Valor de programación   | Campos de cron |
|-------------------------|----------------|
| `every_fifteen_minutes` | `*/15 * * * *` |
| `hourly`                | `0 * * * *`    |
| `every_six_hours`       | `0 */6 * * *`  |
| `daily`                 | `0 0 * * *`    |

Si el valor es desconocido, se usan los campos de cada hora. Mientras una migración del <Terminology title="Versión 1.x: el script update.php ejecutado por el paquete Cron" to="/docs/reference/terminology#package-origins">actualizador heredado</Terminology> espera a que termine el script heredado, el paquete mantiene una entrada `*/15 * * * *` para que la migración se reintente aunque las actualizaciones programadas estén desactivadas.

Una segunda entrada ejecuta `/usr/local/sbin/ipv6-prefix-updater --check-updates` como `root` con la frecuencia de **Comprobaciones de actualizaciones**, en un minuto, hora, día de la semana y día del mes aleatorios y estables. Guardar los ajustes la sustituye, y `never` la elimina.

## Registros y avisos \{#logs-and-notices}

Cada línea del <Terminology title="El registro general de pfSense, donde cada ejecución deja líneas" to="/docs/reference/terminology#notifications-and-logs">registro del sistema</Terminology> se escribe con `log_error()` de pfSense y empieza por `IPv6 Prefix Updater:`. Los avisos se crean con `file_notice()`. Los avisos de ejecución enlazan con `/ipv6-prefix-updater-status.php`, el aviso de migración enlaza con `/ipv6-prefix-updater-cleanup.php` y el aviso de actualización disponible enlaza con `/ipv6-prefix-updater-about.php`.

| ID del aviso                            | Se crea cuando                                                                                                                                                                                                                                                         | Entrega                                                                                                                                                                                                                                                |
|-----------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `ipv6-prefix-updater-success`           | <Terminology title="El prefijo cambió y se actualizó cada campo aprobado" to="/docs/reference/terminology#run-outcomes">Correcto</Terminology> con `notifications` en `on`                                                                                             | WebGUI y <Terminology title="El correo y otros servicios de alerta remotos de pfSense" to="/docs/reference/terminology#notifications-and-logs">canales de notificación</Terminology>                                                                   |
| `ipv6-prefix-updater-no-matches`        | <Terminology title="El prefijo cambió, pero ningún campo aprobado usaba el anterior" to="/docs/reference/terminology#run-outcomes">Advertencia</Terminology>                                                                                                           | Solo WebGUI                                                                                                                                                                                                                                            |
| `ipv6-prefix-updater-failure`           | <Terminology title="La ejecución se detuvo en una comprobación o etapa de seguridad" to="/docs/reference/terminology#run-outcomes">Fallo</Terminology>                                                                                                                 | Solo WebGUI                                                                                                                                                                                                                                            |
| `ipv6-prefix-updater-package-<section>` | Una ejecución cambió los ajustes de otro paquete, y ningún paquete instalado es dueño de la sección o falló la nueva aplicación de sus ajustes                                                                                                                         | Solo WebGUI                                                                                                                                                                                                                                            |
| `ipv6-prefix-updater-legacy-migration`  | Una migración del <Terminology title="Versión 1.x: el script update.php ejecutado por el paquete Cron" to="/docs/reference/terminology#package-origins">actualizador heredado</Terminology> que dio al menos un paso, o una migración que falló durante la instalación | Solo WebGUI                                                                                                                                                                                                                                            |
| `ipv6-prefix-updater-update-available`  | Una comprobación de versiones encuentra una versión más reciente que aún no se ha anunciado                                                                                                                                                                            | Solo WebGUI, o WebGUI y los <Terminology title="El correo y otros servicios de alerta remotos de pfSense" to="/docs/reference/terminology#notifications-and-logs">canales de notificación</Terminology> cuando **Notificaciones remotas** está marcada |

Si falla la comprobación del entorno del propio comando, o no se puede abrir su archivo de bloqueo, el motivo solo va a la salida de error estándar. Cada ejecución que escribe también guarda una revisión de la configuración descrita como `El Actualizador de prefijo IPv6 cambió <cantidad> campo(s) aprobado(s) para la interfaz <interfaz>`.

## Privilegios de las páginas \{#page-privileges}

Cada página del paquete declara su propio privilegio de pfSense, así que el acceso se puede conceder página por página:

- **Estado**: `page-services-ipv6-prefix-updater-status`, llamado `Services: IPv6 Prefix Updater: Status`.
- **Campos**: `page-services-ipv6-prefix-updater-fields`, llamado `Services: IPv6 Prefix Updater: Fields`. Puede cambiar qué campos reescribe una ejecución, así que se recomienda concederlo solo a administradores.
- **Copias de seguridad**: `page-services-ipv6-prefix-updater-backups`, llamado `Services: IPv6 Prefix Updater: Backups`. Permite descargar copias completas de la configuración, así que se recomienda concederlo solo a administradores.
- **Limpieza**: `page-services-ipv6-prefix-updater-cleanup`, llamado `Services: IPv6 Prefix Updater: Cleanup`.
- **Acerca de**: `page-services-ipv6-prefix-updater-about`, llamado `Services: IPv6 Prefix Updater: About`.
