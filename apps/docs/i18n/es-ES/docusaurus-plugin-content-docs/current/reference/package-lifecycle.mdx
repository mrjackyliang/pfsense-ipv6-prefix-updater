Comprueba la versión instalada, instala una versión más reciente o desinstala el paquete desde una shell de pfSense.

## Comprobar la versión instalada \{#check-the-installed-version}

```shell
pkg info pfSense-pkg-Ipv6PrefixUpdater
```

Compara la versión que se muestra con la [última versión de GitHub](https://github.com/mrjackyliang/pfsense-ipv6-prefix-updater/releases/latest).

## Actualizar el paquete \{#update-the-package}

Se recomienda descargar antes una copia de la configuración desde **Diagnostics → Backup & Restore**. Después, instala la última versión sobre el paquete existente:

```shell
pkg add -f https://github.com/mrjackyliang/pfsense-ipv6-prefix-updater/releases/latest/download/pfSense-pkg-Ipv6PrefixUpdater.pkg
```

El paso de instalación vuelve a sincronizar las dos entradas de cron, la comprobación del prefijo y la comprobación de versiones, con los ajustes guardados y conserva todas las <Terminology title="El prefijo inicial registrado con el que se miden los cambios" to="/docs/reference/terminology#baselines-and-transitions">referencias</Terminology>. Los pasos de la suma de comprobación de [Instalar el paquete](/docs/installation#verify-the-download-first) también sirven para las actualizaciones.

Después de la actualización:

1. Abre la pestaña **Configuración** de **Services → IPv6 Prefix Updater** y confirma los valores guardados.
2. En la pestaña Estado, revisa **Estado actual**. Cada interfaz conserva su <Terminology title="El prefijo inicial registrado con el que se miden los cambios" to="/docs/reference/terminology#baselines-and-transitions">referencia</Terminology>.

Si una fila muestra `No inicializado`, **Ejecutar ahora** registra una nueva <Terminology title="El prefijo inicial registrado con el que se miden los cambios" to="/docs/reference/terminology#baselines-and-transitions">referencia</Terminology> para ella. En ese caso, las direcciones que todavía usan un prefijo anterior a esa referencia no cambian.

## Desinstalar el paquete \{#remove-the-package}

Desmarcar antes **<Terminology title="Comprobaciones automáticas programadas, apagadas por defecto" to="/docs/reference/terminology#running-checks">Activar actualizaciones programadas</Terminology>** evita que una reinstalación posterior inicie la programación de inmediato si pfSense conserva los ajustes guardados. Después, ejecuta:

```shell
pkg delete -f pfSense-pkg-Ipv6PrefixUpdater
```

El paquete está marcado como `vital`, por lo que las actualizaciones propias de pfSense lo mantienen instalado y `pkg delete` sin `-f` rechaza los paquetes vitales.

La desinstalación elimina las dos entradas de cron (comprobación del prefijo y comprobación de versiones), cierra el aviso de actualización disponible y elimina el archivo de <Terminology title="Impide que dos comprobaciones se ejecuten a la vez" to="/docs/reference/terminology#running-checks">bloqueo de ejecución</Terminology> cuando ninguna ejecución lo tiene. Conserva el <Terminology title="El archivo con cada referencia, que sobrevive a una reinstalación" to="/docs/reference/terminology#running-checks">estado del paquete</Terminology>, `updates.json`, `update-status.json` y las copias de la pestaña **Copias de seguridad** en `/cf/conf/ipv6-prefix-updater`.

Las actualizaciones propias de pfSense mantienen el paquete instalado (es `vital`), y el estado conservado hace que una desinstalación y reinstalación nunca pierda una <Terminology title="El prefijo inicial registrado con el que se miden los cambios" to="/docs/reference/terminology#baselines-and-transitions">referencia</Terminology>.

La desinstalación no deshace las direcciones ya guardadas en la configuración, y las revisiones del paquete se quedan en el <Terminology title="Las revisiones de configuración guardadas en pfSense que puedes restaurar" to="/docs/reference/terminology#backups-and-service-reloads">historial de configuración</Terminology>. Para eliminar también los archivos conservados, ejecuta `rm -rf /cf/conf/ipv6-prefix-updater` después de desinstalar el paquete.

## Reinstalar más adelante \{#reinstall-later}

Una reinstalación encuentra el <Terminology title="El archivo con cada referencia, que sobrevive a una reinstalación" to="/docs/reference/terminology#running-checks">estado del paquete</Terminology> conservado, así que la primera ejecución compara con cada <Terminology title="El prefijo inicial registrado con el que se miden los cambios" to="/docs/reference/terminology#baselines-and-transitions">referencia</Terminology> guardada y actualiza los campos que se quedaron en un prefijo más antiguo. Si los ajustes anteriores siguen presentes con **<Terminology title="Comprobaciones automáticas programadas, apagadas por defecto" to="/docs/reference/terminology#running-checks">Activar actualizaciones programadas</Terminology>** marcada, el paso de instalación activa la programación de inmediato.

Para empezar de cero, elimina `/cf/conf/ipv6-prefix-updater` antes de reinstalar. Así, la primera ejecución registra una nueva <Terminology title="El prefijo inicial registrado con el que se miden los cambios" to="/docs/reference/terminology#baselines-and-transitions">referencia</Terminology> y devuelve <Terminology title="Primer vistazo: se registra la referencia y nada cambia" to="/docs/reference/terminology#run-outcomes">Inicializado</Terminology> sin cambiar la configuración.

Consulta [Copias de seguridad y recuperación](/docs/operate/backups-and-recovery) antes del mantenimiento y [Establecer la referencia](/docs/first-run) después de una reinstalación.
