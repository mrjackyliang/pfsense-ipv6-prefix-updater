## Estado atual versus Última execução \{#current-state-versus-last-run}

O painel **Estado atual** só muda com <Terminology title="Primeiro olhar: a referência é registada e nada muda" to="/docs/reference/terminology#run-outcomes">Inicializado</Terminology>, **Aceite** e <Terminology title="O prefixo mudou e cada campo aprovado foi atualizado" to="/docs/reference/terminology#run-outcomes">Sucesso</Terminology>. Uma tentativa falhada nunca passa a ser o próximo ponto de comparação, a menos que um operador verifique depois os valores guardados e aceite explicitamente o prefixo ativo; a **Última execução** regista a execução mais recente com qualquer resultado da tabela.

A **Última execução** mantém-se quando outra verificação detém o <Terminology title="Impede que duas verificações corram ao mesmo tempo" to="/docs/reference/terminology#running-checks">bloqueio de execução</Terminology> ou quando uma execução para antes de ler o <Terminology title="O ficheiro com cada referência, mantido mesmo após reinstalar" to="/docs/reference/terminology#running-checks">estado do pacote</Terminology>, por exemplo quando nenhuma interface monitorizada tem um <Terminology title="Um endereço IPv6 público em 2000::/3, o único tipo usado" to="/docs/reference/terminology#addresses-and-prefixes">endereço global</Terminology>. Essas execuções deixam o motivo na <Terminology title="As linhas da última execução, mostradas logo após o início" to="/docs/reference/terminology#running-checks">Saída do comando</Terminology> e no <Terminology title="O registo geral do pfSense, onde cada execução deixa linhas" to="/docs/reference/terminology#notifications-and-logs">registo do sistema</Terminology>.

## Aviso: nenhum campo correspondente \{#warning-no-matching-fields}

Um <Terminology title="O prefixo mudou, mas nenhum campo aprovado usava o antigo" to="/docs/reference/terminology#run-outcomes">Aviso</Terminology> significa que o prefixo mudou, mas nenhum dos <Terminology title="Uma configuração que o pacote pode reescrever" to="/docs/reference/terminology#fields-and-change-plans">campos aprovados</Terminology> pertencia ao prefixo antigo. Nada é gravado e a <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> fica no prefixo antigo, pelo que a execução seguinte volta a verificar a mesma <Terminology title="O seu prefixo mudou, por isso o pacote entra em ação" to="/docs/reference/terminology#baselines-and-transitions">transição de prefixo</Terminology>.

Cada <Terminology title="O prefixo mudou, mas nenhum campo aprovado usava o antigo" to="/docs/reference/terminology#run-outcomes">Aviso</Terminology> adiciona um <Terminology title="Um alerta na lista de alertas do próprio pfSense" to="/docs/reference/terminology#notifications-and-logs">alerta da WebGUI</Terminology>, incluindo o de uma <Terminology title="Uma pré-visualização das alterações que não grava nada" to="/docs/reference/terminology#running-checks">simulação</Terminology>. Uma causa por corrigir adiciona um novo alerta em cada execução agendada.

Causas comuns:

- O <Terminology title="Um único botão para um tipo inteiro de configuração" to="/docs/reference/terminology#fields-and-change-plans">grupo de campos</Terminology> que contém os endereços está desativado, ou os campos estão desmarcados.
- Os endereços já foram alterados fora do pacote.
- Os endereços estão no grupo [Outras definições](/docs/configure/configuration-scopes#other-settings), que continua desativado até os marcar.
- Uma <Terminology title="A execução parou em uma verificação ou etapa de segurança" to="/docs/reference/terminology#run-outcomes">Falha</Terminology> anterior guardou os novos valores, mas manteve a <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> antiga.
- O <Terminology title="O tamanho do prefixo do seu fornecedor, como /56; definido por si" to="/docs/reference/terminology#addresses-and-prefixes">Comprimento do prefixo delegado</Terminology> foi [alargado](/docs/configure/interface-and-prefix#changing-the-prefix-length) sem uma mudança de prefixo.

A [Resolução de problemas](/docs/operate/troubleshooting#warning-on-every-run) aborda cada causa.

Se os endereços já foram alterados corretamente, use **Estado → Ações → Recuperação da referência → Aceitar prefixo atual** depois de verificar os endereços guardados e os serviços afetados. Esta ação regista um resultado **Aceite** sem analisar campos aprovados nem alterar a configuração da firewall; não a use quando os campos aprovados ainda contêm o prefixo antigo.

## Falhas após a gravação \{#failures-after-the-save}

Uma <Terminology title="A execução parou em uma verificação ou etapa de segurança" to="/docs/reference/terminology#run-outcomes">Falha</Terminology> durante as verificações de valores ou os <Terminology title="Aplica as configurações alteradas a um serviço em execução" to="/docs/reference/terminology#backups-and-service-reloads">recarregamentos de serviços</Terminology> que se seguem à gravação deixa os novos valores guardados. Nada é revertido automaticamente, e a <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> fica no prefixo antigo.

**<Terminology title="Uma cópia da configuração feita mesmo antes de qualquer gravação" to="/docs/reference/terminology#backups-and-service-reloads">Cópia de segurança da configuração criada</Terminology>** mostra Sim nessas execuções. [Cópias de segurança e recuperação](/docs/operate/backups-and-recovery#after-a-failed-run) explica como restaurar e repetir, ou como manter os valores guardados já verificados com **Aceitar prefixo atual**.

## Falhas de notificação \{#notification-failures}

Se não for possível enviar uma <Terminology title="O alerta enviado depois de os seus endereços serem atualizados" to="/docs/reference/terminology#notifications-and-logs">notificação de alteração</Terminology>, o resultado continua a ser <Terminology title="O prefixo mudou e cada campo aprovado foi atualizado" to="/docs/reference/terminology#run-outcomes">Sucesso</Terminology> e a <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> passa na mesma para o novo prefixo. O separador Estado não mostra o estado da entrega, e o <Terminology title="O registo geral do pfSense, onde cada execução deixa linhas" to="/docs/reference/terminology#notifications-and-logs">registo do sistema</Terminology> regista `A configuração foi bem-sucedida, mas a notificação da alteração falhou.`

Consulte [Estado e ações](/docs/operate/status-and-actions) para conhecer os campos de cada resultado e [Como funcionam as atualizações](/docs/safety/how-updates-work) para a ordem das etapas.
