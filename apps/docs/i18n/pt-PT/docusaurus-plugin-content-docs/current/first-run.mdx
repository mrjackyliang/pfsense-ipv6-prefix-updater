Registe o prefixo atual como <Terminology title="prefixo inicial registado sem alterar a configuração" to="/docs/reference/terminology#baseline">referência</Terminology> e verifique-o antes de ativar as <Terminology title="verificações automáticas por entrada cron gerida pelo pfSense" to="/docs/reference/terminology#scheduled-updates">atualizações agendadas</Terminology>.

## Guardar as definições iniciais \{#save-the-initial-settings}

1. Abra **Services → IPv6 Prefix Updater** e depois o separador **Definições**.
2. Deixe a opção **<Terminology title="verificações automáticas por entrada cron gerida pelo pfSense" to="/docs/reference/terminology#scheduled-updates">Ativar atualizações agendadas</Terminology>** desmarcada.
3. Adicione uma linha em **<Terminology title="interface cujo endereço revela o prefixo atual" to="/docs/reference/terminology#monitored-interface">Interfaces monitorizadas</Terminology>** por cada interface cujo <Terminology title="endereço IPv6 público dentro de 2000::/3" to="/docs/reference/terminology#global-unicast-address">endereço global</Terminology> provém do <Terminology title="rede IPv6 que o ISP encaminha para a firewall" to="/docs/reference/terminology#delegated-prefix">prefixo delegado</Terminology>, como descrito em [Interface e prefixo](/docs/configure/interface-and-prefix).
4. Em cada linha, selecione o **<Terminology title="definição do tamanho do prefixo do ISP (/48 a /64)" to="/docs/reference/terminology#delegated-prefix-length">Comprimento do prefixo delegado</Terminology>** que o seu ISP delega.
5. Guarde e confirme a mensagem `Definições guardadas.`

## Executar a primeira verificação \{#run-the-first-check}

No separador **Estado**, selecione **Executar agora**. Como ainda não existe <Terminology title="prefixo inicial registado sem alterar a configuração" to="/docs/reference/terminology#baseline">referência</Terminology>, a execução regista o <Terminology title="endereço global indicado pelo pfSense para a interface monitorizada" to="/docs/reference/terminology#source-address">endereço de origem</Terminology> e o prefixo de cada interface e indica <Terminology title="resultado: referência registada, configuração inalterada" to="/docs/reference/terminology#initialized">Inicializado</Terminology>.

Registar uma <Terminology title="prefixo inicial registado sem alterar a configuração" to="/docs/reference/terminology#baseline">referência</Terminology> não altera a configuração, não cria uma cópia de segurança nem envia uma notificação.

## Verificar o resultado \{#verify-the-result}

Confirme estes valores em cada linha de **Estado atual**:

- **<Terminology title="interface cujo endereço revela o prefixo atual" to="/docs/reference/terminology#monitored-interface">Interface monitorizada</Terminology>** mostra a interface pretendida pela descrição e pelo nome interno, como `LAN (lan)`.
- **<Terminology title="endereço global indicado pelo pfSense para a interface monitorizada" to="/docs/reference/terminology#source-address">Último endereço de origem bem-sucedido</Terminology>** coincide com o endereço dessa interface em **Status → Interfaces**.
- **<Terminology title="prefixo com que a próxima verificação compara" to="/docs/reference/terminology#last-successful-prefix">Último prefixo bem-sucedido</Terminology>** coincide com o prefixo que o seu ISP delega.
- **Última atualização bem-sucedida** mostra a hora desta execução em UTC.

A <Terminology title="resultados só de leitura após Executar agora ou Simulação" to="/docs/reference/terminology#command-output">Saída do comando</Terminology> deve mostrar `Estado: Inicializado`, `Campos planeados ou alterados: 0` e `Cópia de segurança da configuração: Não criada`. Por exemplo, o endereço de documentação `2001:db8:abcd:78aa::1` com um comprimento `/56` pertence a `2001:db8:abcd:7800::/56`.

:::warning

Se a interface ou o comprimento estiverem errados, recomenda-se corrigir as Definições antes de ativar o agendamento. Uma interface diferente regista uma nova <Terminology title="prefixo inicial registado sem alterar a configuração" to="/docs/reference/terminology#baseline">referência</Terminology>, enquanto um comprimento diferente conta como <Terminology title="mudança face ao último prefixo ou comprimento bem-sucedido" to="/docs/reference/terminology#prefix-transition">transição de prefixo</Terminology>, como explica [Interface e prefixo](/docs/configure/interface-and-prefix#changing-the-prefix-length).

:::

## Rever os campos \{#review-the-fields}

Abra o separador **Campos**. Com a <Terminology title="prefixo inicial registado sem alterar a configuração" to="/docs/reference/terminology#baseline">referência</Terminology> registada, o separador lista todos os endereços contidos no prefixo e indica quais deles a próxima mudança atualizaria.

1. Desative os <Terminology title="grupo de campos com um só interruptor no separador Campos" to="/docs/reference/terminology#field-group">grupos de campos</Terminology> que a firewall não usa. Os onze grupos do pfSense começam ativados.
2. Desmarque os campos individuais que devem manter o valor e marque qualquer campo de outro pacote que deva acompanhar o prefixo.
3. Marque em **Outras definições** qualquer campo que deva acompanhar o prefixo, como um gateway ou uma rota estática.
4. Selecione **Guardar** e confirme a mensagem `Seleção de campos guardada.`

A página [Campos](/docs/configure/configuration-scopes) explica cada grupo e cada controlo.

## O que uma simulação mostra agora \{#what-a-dry-run-shows-now}

Com o prefixo inalterado, a **<Terminology title="pré-visualização que nunca cria cópias de segurança nem grava" to="/docs/reference/terminology#dry-run">Simulação</Terminology>** indica <Terminology title="resultado: prefixo inalterado, nada analisado nem gravado" to="/docs/reference/terminology#no-change">Sem alteração</Terminology> sem analisar a configuração, porque o planeamento só começa após uma <Terminology title="mudança face ao último prefixo ou comprimento bem-sucedido" to="/docs/reference/terminology#prefix-transition">transição de prefixo</Terminology> real. O separador Campos mostra que campos uma alteração futura afetaria.

Uma <Terminology title="pré-visualização que nunca cria cópias de segurança nem grava" to="/docs/reference/terminology#dry-run">simulação</Terminology> feita antes de existir qualquer <Terminology title="prefixo inicial registado sem alterar a configuração" to="/docs/reference/terminology#baseline">referência</Terminology> indica <Terminology title="resultado: simulação feita antes de existir uma referência" to="/docs/reference/terminology#initialization-preview">Pré-visualização da inicialização</Terminology> e não regista nada.

## Ativar o agendamento \{#turn-on-the-schedule}

Quando os valores coincidirem, selecione **<Terminology title="verificações automáticas por entrada cron gerida pelo pfSense" to="/docs/reference/terminology#scheduled-updates">Ativar atualizações agendadas</Terminology>**, escolha uma **Agenda** e guarde. [Agendamento e notificações](/docs/configure/schedule-and-notifications) explica cada opção.

Após a primeira hora agendada, **Data e hora (UTC)** em **Última execução** mostra quando essa verificação foi executada.

Continue com [Verificar antes de automatizar](/docs/safety/testing-and-verification) para seguir uma lista de verificação completa.
