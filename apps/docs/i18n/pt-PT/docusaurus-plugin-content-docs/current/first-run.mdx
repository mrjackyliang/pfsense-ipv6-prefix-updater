Registe o prefixo atual como <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> e verifique-o antes de ativar as <Terminology title="Verificações automáticas agendadas, desligadas até as ativar" to="/docs/reference/terminology#running-checks">atualizações agendadas</Terminology>.

## Guardar as definições iniciais \{#save-the-initial-settings}

1. Abra **Services → IPv6 Prefix Updater** e depois o separador **Definições**.
2. Deixe a opção **<Terminology title="Verificações automáticas agendadas, desligadas até as ativar" to="/docs/reference/terminology#running-checks">Ativar atualizações agendadas</Terminology>** desmarcada.
3. Adicione uma linha em **<Terminology title="A interface cujo endereço revela o seu prefixo atual" to="/docs/reference/terminology#interfaces-and-detection">Interfaces monitorizadas</Terminology>** por cada interface cujo <Terminology title="Um endereço IPv6 público em 2000::/3, o único tipo usado" to="/docs/reference/terminology#addresses-and-prefixes">endereço global</Terminology> provém do <Terminology title="A rede IPv6 que o seu fornecedor lhe atribui, e que pode mudar" to="/docs/reference/terminology#addresses-and-prefixes">prefixo delegado</Terminology>, como descrito em [Interface e prefixo](/docs/configure/interface-and-prefix).
4. Em cada linha, selecione o **<Terminology title="O tamanho do prefixo do seu fornecedor, como /56; definido por si" to="/docs/reference/terminology#addresses-and-prefixes">Comprimento do prefixo delegado</Terminology>** que o seu ISP delega.
5. Guarde e confirme a mensagem `Definições guardadas.`

## Executar a primeira verificação \{#run-the-first-check}

No separador **Estado**, selecione **Executar agora**. Como ainda não existe <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology>, a execução regista o <Terminology title="O endereço em direto do qual cada execução lê o prefixo" to="/docs/reference/terminology#interfaces-and-detection">endereço de origem</Terminology> e o prefixo de cada interface e indica <Terminology title="Primeiro olhar: a referência é registada e nada muda" to="/docs/reference/terminology#run-outcomes">Inicializado</Terminology>.

Registar uma <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> não altera a configuração, não cria uma cópia de segurança nem envia uma notificação.

## Verificar o resultado \{#verify-the-result}

Confirme estes valores em cada linha de **Estado atual**:

- **<Terminology title="A interface cujo endereço revela o seu prefixo atual" to="/docs/reference/terminology#interfaces-and-detection">Interface monitorizada</Terminology>** mostra a interface pretendida pela descrição e pelo nome interno, como `LAN (lan)`.
- **<Terminology title="O endereço em direto do qual cada execução lê o prefixo" to="/docs/reference/terminology#interfaces-and-detection">Último endereço de origem bem-sucedido</Terminology>** coincide com o endereço dessa interface em **Status → Interfaces**.
- **<Terminology title="O prefixo guardado com o qual cada verificação compara" to="/docs/reference/terminology#baselines-and-transitions">Último prefixo bem-sucedido</Terminology>** coincide com o prefixo que o seu ISP delega.
- **Última atualização bem-sucedida** mostra a hora desta execução em UTC.

A <Terminology title="As linhas da última execução, mostradas logo após o início" to="/docs/reference/terminology#running-checks">Saída do comando</Terminology> deve mostrar `Estado: Inicializado`, `Campos planeados ou alterados: 0` e `Cópia de segurança da configuração: Não criada`. Por exemplo, o endereço de documentação `2001:db8:abcd:78aa::1` com um comprimento `/56` pertence a `2001:db8:abcd:7800::/56`.

:::warning

Se a interface ou o comprimento estiverem errados, recomenda-se corrigir as Definições antes de ativar o agendamento. Uma interface diferente regista uma nova <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology>, enquanto um comprimento diferente conta como <Terminology title="O seu prefixo mudou, por isso o pacote entra em ação" to="/docs/reference/terminology#baselines-and-transitions">transição de prefixo</Terminology>, como explica [Interface e prefixo](/docs/configure/interface-and-prefix#changing-the-prefix-length).

:::

## Rever os campos \{#review-the-fields}

Abra o separador **Campos**. Com a <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> registada, o separador lista todos os endereços contidos no prefixo e indica quais deles a próxima mudança atualizaria.

1. Desative os <Terminology title="Um único botão para um tipo inteiro de configuração" to="/docs/reference/terminology#fields-and-change-plans">grupos de campos</Terminology> que a firewall não usa. Os onze grupos do pfSense começam ativados.
2. Desmarque os campos individuais que devem manter o valor e marque qualquer campo de outro pacote que deva acompanhar o prefixo.
3. Marque em **Outras definições** qualquer campo que deva acompanhar o prefixo, como um gateway ou uma rota estática.
4. Selecione **Guardar** e confirme a mensagem `Seleção de campos guardada.`

A página [Campos](/docs/configure/configuration-scopes) explica cada grupo e cada controlo.

## O que uma simulação mostra agora \{#what-a-dry-run-shows-now}

Com o prefixo inalterado, a **<Terminology title="Uma pré-visualização das alterações que não grava nada" to="/docs/reference/terminology#running-checks">Simulação</Terminology>** indica <Terminology title="O mesmo prefixo da última vez, por isso não há nada a fazer" to="/docs/reference/terminology#run-outcomes">Sem alteração</Terminology> sem analisar a configuração, porque o planeamento só começa após uma <Terminology title="O seu prefixo mudou, por isso o pacote entra em ação" to="/docs/reference/terminology#baselines-and-transitions">transição de prefixo</Terminology> real. O separador Campos mostra que campos uma alteração futura afetaria.

Uma <Terminology title="Uma pré-visualização das alterações que não grava nada" to="/docs/reference/terminology#running-checks">simulação</Terminology> feita antes de existir qualquer <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> indica <Terminology title="Uma simulação que mostra a referência que seria registada" to="/docs/reference/terminology#run-outcomes">Pré-visualização da inicialização</Terminology> e não regista nada.

## Ativar o agendamento \{#turn-on-the-schedule}

Quando os valores coincidirem, selecione **<Terminology title="Verificações automáticas agendadas, desligadas até as ativar" to="/docs/reference/terminology#running-checks">Ativar atualizações agendadas</Terminology>**, escolha uma **Agenda** e guarde. [Agendamento e notificações](/docs/configure/schedule-and-notifications) explica cada opção.

Após a primeira hora agendada, **Data e hora (UTC)** em **Última execução** mostra quando essa verificação foi executada.

Continue com [Verificar antes de automatizar](/docs/safety/testing-and-verification) para seguir uma lista de verificação completa.
