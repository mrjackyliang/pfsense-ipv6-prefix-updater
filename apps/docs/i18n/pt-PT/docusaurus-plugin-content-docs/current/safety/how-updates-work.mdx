Acompanhe uma execução desde a leitura dos endereços das interfaces até ao registo do resultado, incluindo todos os pontos em que pode parar.

## 1. Ler e validar \{#1-read-and-validate}

- Uma verificação agendada para de imediato como <Terminology title="Verificação agendada ignorada porque o agendamento está desligado" to="/docs/reference/terminology#run-outcomes">Desativado</Terminology> quando a opção **<Terminology title="Verificações automáticas agendadas, desligadas até as ativar" to="/docs/reference/terminology#running-checks">Ativar atualizações agendadas</Terminology>** está desmarcada. Uma <Terminology title="Uma verificação iniciada por si, mesmo com o agendamento desligado" to="/docs/reference/terminology#running-checks">execução manual</Terminology> continua.
- A execução volta a verificar as definições guardadas, porque podem ter mudado desde que o formulário foi guardado.
- Lê de novo o <Terminology title="Um endereço IPv6 público em 2000::/3, o único tipo usado" to="/docs/reference/terminology#addresses-and-prefixes">endereço global</Terminology> de cada <Terminology title="A interface cujo endereço revela o seu prefixo atual" to="/docs/reference/terminology#interfaces-and-detection">Interface monitorizada</Terminology>, sem recorrer a um <Terminology title="Um endereço fe80 que nunca é usado como origem" to="/docs/reference/terminology#addresses-and-prefixes">endereço link-local</Terminology>, e converte-o para a <Terminology title="A grafia curta em minúsculas, como 2001:db8::1" to="/docs/reference/terminology#addresses-and-prefixes">forma canónica</Terminology>.
- Aplica a cada endereço a máscara do <Terminology title="O tamanho do prefixo do seu fornecedor, como /56; definido por si" to="/docs/reference/terminology#addresses-and-prefixes">Comprimento do prefixo delegado</Terminology> da respetiva linha para obter o <Terminology title="O prefixo visto agora, comparado com o anterior" to="/docs/reference/terminology#interfaces-and-detection">prefixo observado</Terminology>.

## 2. Comparar \{#2-compare}

- Sem <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> para a interface, a execução regista uma e termina como <Terminology title="Primeiro olhar: a referência é registada e nada muda" to="/docs/reference/terminology#run-outcomes">Inicializado</Terminology>.
- Quando o prefixo e o respetivo comprimento coincidem com o <Terminology title="O prefixo guardado com o qual cada verificação compara" to="/docs/reference/terminology#baselines-and-transitions">último prefixo bem-sucedido</Terminology>, a execução termina como <Terminology title="O mesmo prefixo da última vez, por isso não há nada a fazer" to="/docs/reference/terminology#run-outcomes">Sem alteração</Terminology> sem analisar a configuração.
- Um prefixo ou um comprimento diferente é uma <Terminology title="O seu prefixo mudou, por isso o pacote entra em ação" to="/docs/reference/terminology#baselines-and-transitions">transição de prefixo</Terminology>, e a execução continua.

## 3. Planear \{#3-plan}

- A execução lê a configuração através das funções de configuração do pfSense e mantém apenas os campos selecionados no separador Campos. Os campos selecionados que já não existem são ignorados e listados em **Campos ignorados**.
- Cada endereço de um <Terminology title="Uma configuração que o pacote pode reescrever" to="/docs/reference/terminology#fields-and-change-plans">campo aprovado</Terminology> que pertence ao prefixo antigo, com o comprimento guardado, recebe os bits do novo prefixo com o comprimento atual e mantém a <Terminology title="Os bits depois do prefixo, sempre copiados sem alteração" to="/docs/reference/terminology#addresses-and-prefixes">parte de anfitrião</Terminology>. Em conjunto, estas alterações formam o <Terminology title="Cada reescrita prevista, preparada antes de qualquer mudança" to="/docs/reference/terminology#fields-and-change-plans">plano de alterações</Terminology> completo.
- Sem nada para alterar, a execução termina como <Terminology title="O prefixo mudou, mas nenhum campo aprovado usava o antigo" to="/docs/reference/terminology#run-outcomes">Aviso</Terminology>. Uma <Terminology title="Uma pré-visualização das alterações que não grava nada" to="/docs/reference/terminology#running-checks">simulação</Terminology> com alterações termina aqui como <Terminology title="Uma pré-visualização das alterações que não grava nada" to="/docs/reference/terminology#running-checks">Simulação</Terminology>.

## 4. Verificação prévia \{#4-preflight}

- A execução confirma que o pfSense consegue recarregar todos os serviços do plano. Os <Terminology title="O endereço de uma interface de túnel WireGuard" to="/docs/reference/terminology#pfsense-features">endereços de túnel WireGuard</Terminology> precisam do pacote WireGuard para isso.
- Confirma que cada campo planeado ainda tem o valor que tinha quando o plano foi criado.

## 5. Criar a cópia de segurança e gravar uma vez \{#5-back-up-and-write-once}

- O pfSense cria uma <Terminology title="Uma cópia da configuração feita mesmo antes de qualquer gravação" to="/docs/reference/terminology#backups-and-service-reloads">cópia de segurança da configuração</Terminology>, e a execução para se o pfSense não a confirmar.
- A execução aplica todas as alterações e guarda uma única vez, com a descrição `O Atualizador de prefixo IPv6 alterou <count> campo(s) aprovado(s) para a interface <interface>`.
- Se o pfSense indicar que a gravação falhou, a execução repõe os valores originais em memória e para.

## 6. Verificar, recarregar, verificar \{#6-verify-reload-verify}

- A execução confirma que os valores guardados correspondem ao plano, recarrega os serviços afetados e volta a verificar os valores.
- Os serviços são recarregados pela ordem fixa que [Ações de recarregamento](/docs/reference/approved-fields#reload-actions) indica, de Interfaces a WireGuard. Um recarregamento de Interfaces é seguido de um recarregamento do filtro da firewall, que depois não se repete.
- Os recarregamentos do filtro da firewall, do DNS Resolver e do DNS Forwarder fazem falhar a execução quando devolvem uma falha. Os outros recarregamentos só a fazem falhar quando geram um erro.
- As definições de outros pacotes são aplicadas novamente no fim, depois dos recarregamentos e da respetiva verificação. Um pacote cujas definições não podem ser aplicadas é comunicado, e os valores guardados mantêm-se.
- Uma falha nesta etapa deixa os novos valores guardados.

## 7. Registar e notificar \{#7-record-and-notify}

- A <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> passa para o novo prefixo, e a **Última execução** regista o <Terminology title="O prefixo mudou e cada campo aprovado foi atualizado" to="/docs/reference/terminology#run-outcomes">Sucesso</Terminology> com o número de campos alterados e os <Terminology title="Aplica as configurações alteradas a um serviço em execução" to="/docs/reference/terminology#backups-and-service-reloads">serviços recarregados</Terminology>.
- A execução escreve uma linha no <Terminology title="O registo geral do pfSense, onde cada execução deixa linhas" to="/docs/reference/terminology#notifications-and-logs">registo do sistema</Terminology> e envia uma <Terminology title="O alerta enviado depois de os seus endereços serem atualizados" to="/docs/reference/terminology#notifications-and-logs">notificação de alteração</Terminology>, se estiver ativada. Uma notificação falhada não altera o resultado.
