Confirme que a sua firewall, a interface e a delegação do ISP cumprem os requisitos do pacote antes de confiar nas <Terminology title="verificações automáticas por entrada cron gerida pelo pfSense" to="/docs/reference/terminology#scheduled-updates">atualizações agendadas</Terminology>.

## Versões suportadas \{#supported-releases}

- O projeto ainda não publicou uma lista de versões do pfSense testadas.
- O pacote não verifica a versão do pfSense. Cada execução confirma que está a correr no pfSense com os ficheiros e as funções que utiliza, e para antes de ler as definições se faltar algum.
- O código do pacote requer PHP 8.1 ou posterior.
- O ficheiro `.pkg` tem de ser compilado para a versão do FreeBSD usada pela sua versão do pfSense, caso contrário o `pkg` indica uma incompatibilidade de ABI.

## Requisitos de endereço \{#address-requirements}

- Cada <Terminology title="interface cujo endereço revela o prefixo atual" to="/docs/reference/terminology#monitored-interface">Interface monitorizada</Terminology> precisa de um <Terminology title="endereço IPv6 público dentro de 2000::/3" to="/docs/reference/terminology#global-unicast-address">endereço unicast global</Terminology> ativo. O pacote nunca recorre a um <Terminology title="endereço fe80:: que só funciona numa ligação" to="/docs/reference/terminology#link-local-address">endereço link-local</Terminology>.
- Os endereços locais únicos (`fc00::/7`), multicast, de loopback, não especificados, mapeados de IPv4 e com identificador de zona não podem ser o <Terminology title="endereço global indicado pelo pfSense para a interface monitorizada" to="/docs/reference/terminology#source-address">endereço de origem</Terminology>.
- O <Terminology title="definição do tamanho do prefixo do ISP (/48 a /64)" to="/docs/reference/terminology#delegated-prefix-length">Comprimento do prefixo delegado</Terminology> tem de estar entre `/48` e `/64`. Os comprimentos que terminam a meio de um dígito hexadecimal, como `/57`, também funcionam.

Quando um endereço não é elegível, essa interface termina em <Terminology title="resultado: verificação ou etapa de segurança parou a execução" to="/docs/reference/terminology#failure">Falha</Terminology> com um motivo como `A interface «lan» não tem um endereço IPv6 global ativo.` A secção [Resolução de problemas](/docs/operate/troubleshooting#run-failed) lista as mensagens.

## Quando a WAN não tem endereço global \{#when-wan-has-no-global-address}

Alguns ISP delegam um prefixo sem atribuírem à WAN um <Terminology title="endereço IPv6 público dentro de 2000::/3" to="/docs/reference/terminology#global-unicast-address">endereço global</Terminology> próprio. Nesse caso, uma <Terminology title="interface endereçada a partir do prefixo delegado de outra" to="/docs/reference/terminology#tracked-interface">interface rastreada</Terminology>, como a LAN, recebe um endereço do <Terminology title="rede IPv6 que o ISP encaminha para a firewall" to="/docs/reference/terminology#delegated-prefix">prefixo delegado</Terminology> e é essa que deve ser monitorizada.

**Status → Interfaces** mostra que interfaces têm um <Terminology title="endereço IPv6 público dentro de 2000::/3" to="/docs/reference/terminology#global-unicast-address">endereço global</Terminology>.

## O que o pacote reconhece \{#what-the-package-recognizes}

O pacote atualiza endereços e redes IPv6 literais em <Terminology title="campo de configuração exato que o pacote pode reescrever" to="/docs/reference/terminology#approved-field">campos aprovados</Terminology>. Os nomes de anfitrião, os URL, os valores IPv4 e o restante texto ficam como estão.

Os endereços gerados pelo pfSense, como os das <Terminology title="interface endereçada a partir do prefixo delegado de outra" to="/docs/reference/terminology#tracked-interface">interfaces rastreadas</Terminology>, nunca são alterados. Os endereços que descrevem outros dispositivos, como as redes VPN remotas e os pares do WireGuard, só mudam quando os marcar em [Outras definições](/docs/configure/configuration-scopes#other-settings).

## Dependências opcionais \{#optional-dependencies}

- **Pacote WireGuard**: só é necessário quando os <Terminology title="endereço atribuído a um túnel WireGuard do pfSense" to="/docs/reference/terminology#wireguard-tunnel-address">endereços de túnel WireGuard</Terminology> têm de mudar. Sem ele, uma execução real com alterações no WireGuard para antes da cópia de segurança.

## Limites conhecidos \{#known-limits}

- Adicionar uma <Terminology title="interface cujo endereço revela o prefixo atual" to="/docs/reference/terminology#monitored-interface">Interface monitorizada</Terminology>, ou mudar uma linha para outra interface, regista uma nova <Terminology title="prefixo inicial registado sem alterar a configuração" to="/docs/reference/terminology#baseline">referência</Terminology> para ela, e alterar o <Terminology title="definição do tamanho do prefixo do ISP (/48 a /64)" to="/docs/reference/terminology#delegated-prefix-length">Comprimento do prefixo delegado</Terminology> de uma linha conta como <Terminology title="mudança face ao último prefixo ou comprimento bem-sucedido" to="/docs/reference/terminology#prefix-transition">transição de prefixo</Terminology>.
- Uma <Terminology title="pré-visualização que nunca cria cópias de segurança nem grava" to="/docs/reference/terminology#dry-run">simulação</Terminology> não consegue simular uma mudança de prefixo, pelo que as alterações planeadas só aparecem após uma mudança real.
- Os pares de alta disponibilidade (CARP) não têm tratamento especial.
- Por ser um <Terminology title="pacote instalado do GitHub, não do repositório da Netgate" to="/docs/reference/terminology#unofficial-package">pacote não oficial</Terminology>, as versões mais recentes são instaladas com o `pkg`, como descrito em [Atualizar ou remover](/docs/reference/package-lifecycle).

Consulte [Interface e prefixo](/docs/configure/interface-and-prefix) para escolher a origem e [Campos](/docs/configure/configuration-scopes) para conhecer os campos que o pacote pode alterar.
