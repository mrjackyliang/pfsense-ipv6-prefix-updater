Confirme que a sua firewall, a interface e a delegação do ISP cumprem os requisitos do pacote antes de confiar nas <Terminology title="Verificações automáticas agendadas, desligadas até as ativar" to="/docs/reference/terminology#running-checks">atualizações agendadas</Terminology>.

## Versões suportadas \{#supported-releases}

- O pacote foi testado no pfSense CE 2.9.0 e 2.8.1 e no pfSense Plus 26.07 e 26.03.1. O separador **Sobre** lista as versões em que cada versão do pacote foi testada e assinala a correspondente como **Esta firewall**.
- O pacote não verifica a versão do pfSense. Cada execução confirma que está a correr no pfSense com os ficheiros e as funções que utiliza, e para antes de ler as definições se faltar algum.
- O código do pacote requer PHP 8.1 ou posterior.
- Os pacotes de cada versão estão assinalados para qualquer versão do FreeBSD (`FreeBSD:*`) e como vital, pelo que um único pacote é instalado em todas as versões suportadas do pfSense e as atualizações do pfSense mantêm-no instalado.

## Requisitos de endereço \{#address-requirements}

- Cada <Terminology title="A interface cujo endereço revela o seu prefixo atual" to="/docs/reference/terminology#interfaces-and-detection">Interface monitorizada</Terminology> precisa de um <Terminology title="Um endereço IPv6 público em 2000::/3, o único tipo usado" to="/docs/reference/terminology#addresses-and-prefixes">endereço unicast global</Terminology> ativo. O pacote nunca recorre a um <Terminology title="Um endereço fe80 que nunca é usado como origem" to="/docs/reference/terminology#addresses-and-prefixes">endereço link-local</Terminology>.
- Os endereços locais únicos (`fc00::/7`), multicast, de loopback, não especificados, mapeados de IPv4 e com identificador de zona não podem ser o <Terminology title="O endereço em direto do qual cada execução lê o prefixo" to="/docs/reference/terminology#interfaces-and-detection">endereço de origem</Terminology>.
- O <Terminology title="O tamanho do prefixo do seu fornecedor, como /56; definido por si" to="/docs/reference/terminology#addresses-and-prefixes">Comprimento do prefixo delegado</Terminology> tem de estar entre `/48` e `/64`. Os comprimentos que terminam a meio de um dígito hexadecimal, como `/57`, também funcionam.

Quando um endereço não é elegível, essa interface termina em <Terminology title="A execução parou em uma verificação ou etapa de segurança" to="/docs/reference/terminology#run-outcomes">Falha</Terminology> com um motivo como `A interface «lan» não tem um endereço IPv6 global ativo.` A secção [Resolução de problemas](/docs/operate/troubleshooting#run-failed) lista as mensagens.

## Quando a WAN não tem endereço global \{#when-wan-has-no-global-address}

Alguns ISP delegam um prefixo sem atribuírem à WAN um <Terminology title="Um endereço IPv6 público em 2000::/3, o único tipo usado" to="/docs/reference/terminology#addresses-and-prefixes">endereço global</Terminology> próprio. Nesse caso, uma <Terminology title="Uma interface que forma o IPv6 a partir do prefixo de outra" to="/docs/reference/terminology#interfaces-and-detection">interface rastreada</Terminology>, como a LAN, recebe um endereço do <Terminology title="A rede IPv6 que o seu fornecedor lhe atribui, e que pode mudar" to="/docs/reference/terminology#addresses-and-prefixes">prefixo delegado</Terminology> e é essa que deve ser monitorizada.

**Status → Interfaces** mostra que interfaces têm um <Terminology title="Um endereço IPv6 público em 2000::/3, o único tipo usado" to="/docs/reference/terminology#addresses-and-prefixes">endereço global</Terminology>.

## O que o pacote reconhece \{#what-the-package-recognizes}

O pacote atualiza endereços e redes IPv6 literais em <Terminology title="Uma configuração que o pacote pode reescrever" to="/docs/reference/terminology#fields-and-change-plans">campos aprovados</Terminology>. Os nomes de anfitrião, os URL, os valores IPv4 e o restante texto ficam como estão.

Os endereços gerados pelo pfSense, como os das <Terminology title="Uma interface que forma o IPv6 a partir do prefixo de outra" to="/docs/reference/terminology#interfaces-and-detection">interfaces rastreadas</Terminology>, nunca são alterados. Os endereços que descrevem outros dispositivos, como as redes VPN remotas e os pares do WireGuard, só mudam quando os marcar em [Outras definições](/docs/configure/configuration-scopes#other-settings).

## Dependências opcionais \{#optional-dependencies}

- **Pacote WireGuard**: só é necessário quando os <Terminology title="O endereço de uma interface de túnel WireGuard" to="/docs/reference/terminology#pfsense-features">endereços de túnel WireGuard</Terminology> têm de mudar. Sem ele, uma execução real com alterações no WireGuard para antes da cópia de segurança.

## Limites conhecidos \{#known-limits}

- Adicionar uma <Terminology title="A interface cujo endereço revela o seu prefixo atual" to="/docs/reference/terminology#interfaces-and-detection">Interface monitorizada</Terminology>, ou mudar uma linha para outra interface, regista uma nova <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> para ela, e alterar o <Terminology title="O tamanho do prefixo do seu fornecedor, como /56; definido por si" to="/docs/reference/terminology#addresses-and-prefixes">Comprimento do prefixo delegado</Terminology> de uma linha conta como <Terminology title="O seu prefixo mudou, por isso o pacote entra em ação" to="/docs/reference/terminology#baselines-and-transitions">transição de prefixo</Terminology>.
- Uma <Terminology title="Uma pré-visualização das alterações que não grava nada" to="/docs/reference/terminology#running-checks">simulação</Terminology> não consegue simular uma mudança de prefixo, pelo que as alterações planeadas só aparecem após uma mudança real.
- Os pares de alta disponibilidade (CARP) não têm tratamento especial.
- Por ser um <Terminology title="Instalado pelo GitHub, não pelo repositório de pacotes da Netgate" to="/docs/reference/terminology#package-origins">pacote não oficial</Terminology>, as versões mais recentes são instaladas com o `pkg`, como descrito em [Atualizar ou remover](/docs/reference/package-lifecycle).

Consulte [Interface e prefixo](/docs/configure/interface-and-prefix) para escolher a origem e [Campos](/docs/configure/configuration-scopes) para conhecer os campos que o pacote pode alterar.
