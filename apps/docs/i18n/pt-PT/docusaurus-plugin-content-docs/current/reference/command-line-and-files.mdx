Execute o comando do pacote a partir de uma shell e encontre os ficheiros, os registos e os alertas que utiliza.

## Utilização \{#usage}

```text
Utilização: ipv6-prefix-updater [--manual] [--dry-run] [--accept-current-prefix [--interface=NAME]] [--migrate-legacy]
Opções de atualização: --check-updates [--no-notice], --self-update.
```

A entrada cron de verificação do prefixo gerida pelo pfSense executa o comando como `root` sem opções, enquanto uma entrada separada de verificação de releases o executa com `--check-updates`. Antes de cada verificação, também move para o pacote quaisquer restos do <Terminology title="Versão 1.x: o script update.php executado pelo pacote Cron" to="/docs/reference/terminology#package-origins">atualizador legado</Terminology>. O separador Estado usa `--manual` para **Executar agora**, `--dry-run` para **<Terminology title="Uma pré-visualização das alterações que não grava nada" to="/docs/reference/terminology#running-checks">Simulação</Terminology>** e `--accept-current-prefix` para a recuperação da referência, e o separador Limpeza usa `--migrate-legacy`.

Sem opções, o comando comporta-se como uma verificação agendada e indica <Terminology title="Verificação agendada ignorada porque o agendamento está desligado" to="/docs/reference/terminology#run-outcomes">Desativado</Terminology> quando a opção **<Terminology title="Verificações automáticas agendadas, desligadas até as ativar" to="/docs/reference/terminology#running-checks">Ativar atualizações agendadas</Terminology>** está desmarcada.

## Opções \{#options}

| Opção                     | Descrição                                                                                                                                                                                                                                                                                                            |
|---------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `--manual`                | Executa mesmo com as <Terminology title="Verificações automáticas agendadas, desligadas até as ativar" to="/docs/reference/terminology#running-checks">atualizações agendadas</Terminology> desativadas.                                                                                                             |
| `--dry-run`               | Faz uma pré-visualização sem cópia de segurança nem gravação, e implica `--manual`.                                                                                                                                                                                                                                  |
| `--accept-current-prefix` | Regista o endereço de origem, o prefixo e o comprimento ativos como referência, sem analisar campos aprovados, criar uma cópia de segurança, gravar a configuração nem recarregar serviços. Implica `--manual` e não pode ser combinado com `--dry-run`.                                                             |
| `--interface=NAME`        | Limita `--accept-current-prefix` a uma única interface monitorizada, indicada pelo nome interno, como `lan`. Sem esta opção, são aceites todas as interfaces monitorizadas que tenham um endereço.                                                                                                                   |
| `--migrate-legacy`        | Move de imediato o <Terminology title="Versão 1.x: o script update.php executado pelo pacote Cron" to="/docs/reference/terminology#package-origins">atualizador legado</Terminology> para o pacote e mostra cada passo, sem executar uma verificação do prefixo. Termina com `2` quando a migração indicou um aviso. |
| `--check-updates`         | Verifica no GitHub a release mais recente do pacote e guarda o resultado em `/cf/conf/ipv6-prefix-updater/updates.json`. [Atualizações](/docs/reference/updates) descreve a verificação.                                                                                                                             |
| `--no-notice`             | Suprime o aviso de atualização de `--check-updates` e regista a versão mais recente como já notificada. Válida apenas com `--check-updates`.                                                                                                                                                                         |
| `--self-update`           | Transfere, verifica e instala a release mais recente, registando o progresso em `/cf/conf/ipv6-prefix-updater/update-status.json`.                                                                                                                                                                                   |
| `--help`                  | Mostra a linha de utilização e a linha das opções de atualização, e termina com `0`. Nenhuma das linhas inclui o próprio `--help`.                                                                                                                                                                                   |

Qualquer outra opção escreve `Opção desconhecida: <option>` no erro padrão e termina com `64`. Combinar `--accept-current-prefix` com `--dry-run` também termina com `64`, tal como combinar `--check-updates` ou `--self-update` entre si ou com qualquer opção de prefixo. Usar `--no-notice` sem `--check-updates` também termina com `64`.

## Saída \{#output}

Uma execução concluída que monitoriza uma só interface escreve nove linhas na saída padrão, seguidas das alterações de campos após uma <Terminology title="Uma pré-visualização das alterações que não grava nada" to="/docs/reference/terminology#running-checks">simulação</Terminology> ou um <Terminology title="O prefixo mudou e cada campo aprovado foi atualizado" to="/docs/reference/terminology#run-outcomes">Sucesso</Terminology>:

```text
Estado: Sucesso
Interface: lan
Endereço de origem observado: 2001:db8:abcd:88aa::1
Prefixo anterior: 2001:db8:abcd:7800::
Prefixo atual: 2001:db8:abcd:8800::/56
Campos planeados ou alterados: 1
Cópia de segurança da configuração: Criada
Serviços recarregados: Filtro da firewall
Resumo: Foram atualizados 1 campo(s) aprovado(s) de 2001:db8:abcd:7800::/56 para 2001:db8:abcd:8800::/56 na interface lan.
Alterações de campos:
- aliases/alias/0/address: 2001:db8:abcd:78aa::10 → 2001:db8:abcd:88aa::10
```

- `Prefixo anterior` não tem comprimento e mostra `Não disponível` após <Terminology title="Primeiro olhar: a referência é registada e nada muda" to="/docs/reference/terminology#run-outcomes">Inicializado</Terminology> ou <Terminology title="Uma simulação que mostra a referência que seria registada" to="/docs/reference/terminology#run-outcomes">Pré-visualização da inicialização</Terminology>.
- `Serviços recarregados` lista as etiquetas do separador Estado ou `Nenhum`. Após uma <Terminology title="Uma pré-visualização das alterações que não grava nada" to="/docs/reference/terminology#running-checks">simulação</Terminology>, lista os serviços que seriam recarregados.
- `Alterações de campos` tem uma linha por endereço substituído, escrita como `- <path>: <old> → <new>`, para até 200 campos.
- Quando a execução aplicou novamente as definições de outro pacote ou ignorou um campo marcado que já não existe, segue-se uma linha para cada caso, com o mesmo texto do separador Estado.
- Quando outra verificação detém o <Terminology title="Impede que duas verificações corram ao mesmo tempo" to="/docs/reference/terminology#running-checks">bloqueio de execução</Terminology>, a única saída é `Outra execução detém o bloqueio do pacote; esta invocação terminou sem ler a configuração.`
- Com várias interfaces monitorizadas, a saída começa com as linhas globais de `Estado`, `Resumo`, pacotes e campos ignorados, seguidas das linhas de cada interface, separadas por linhas em branco.
- Quando houve uma migração do <Terminology title="Versão 1.x: o script update.php executado pelo pacote Cron" to="/docs/reference/terminology#package-origins">atualizador legado</Terminology> antes da verificação, os respetivos passos são mostrados primeiro.
- As etiquetas e as mensagens seguem a definição de idioma do pfSense.

## Formato do estado do pacote \{#package-state-format}

| Chave                 | Descrição                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
|-----------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `schema_version`      | Sempre `1`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `targets.<interface>` | Uma <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> por interface monitorizada, identificada pelo nome interno, com `interface`, `source_address`, `prefix`, `prefix_length` e `updated_at`. Uma referência obtida do <Terminology title="Versão 1.x: o script update.php executado pelo pacote Cron" to="/docs/reference/terminology#package-origins">atualizador legado</Terminology> tem também `source` definido como `legacy_cache`. |
| `last_run`            | A execução registada mais recente, com `status`, `timestamp`, `interface`, `observed_address`, `previous_prefix`, `current_prefix`, `current_prefix_length`, `change_count`, `backup_created`, `services`, `message`, `message_key` e `message_arguments`.                                                                                                                                                                                                                                                                                                   |
| `legacy_migration`    | Presente após uma migração do <Terminology title="Versão 1.x: o script update.php executado pelo pacote Cron" to="/docs/reference/terminology#package-origins">atualizador legado</Terminology>, com `status`, `steps`, `warnings` e `recorded_at`. O separador Limpeza mostra-o.                                                                                                                                                                                                                                                                            |

- `status` é um de `initialized`, `initialization_preview`, `no_change`, `dry_run`, `warning`, `accepted`, `success` ou `failure`.
- Após um <Terminology title="O prefixo mudou e cada campo aprovado foi atualizado" to="/docs/reference/terminology#run-outcomes">Sucesso</Terminology>, `last_run.notification` é `disabled` quando as notificações estão desativadas, ou `sent` ou `failed` após uma tentativa de entrega.
- Após uma <Terminology title="Uma pré-visualização das alterações que não grava nada" to="/docs/reference/terminology#running-checks">simulação</Terminology> ou um <Terminology title="O prefixo mudou e cada campo aprovado foi atualizado" to="/docs/reference/terminology#run-outcomes">Sucesso</Terminology>, cada resultado tem também `changes`, com o `path` e as `replacements` de até 200 campos, em que cada substituição é um endereço antigo e um endereço novo.
- `package_reapply` indica a `section`, o `package`, o `status` e o `error` de cada pacote cujas definições a execução aplicou novamente, e `skipped_fields` lista os campos marcados que já não existem. Cada um só aparece quando não está vazio.
- Com várias interfaces monitorizadas, `last_run` contém os totais e uma lista `targets` com um resultado por interface.
- As datas e horas usam ISO 8601 em UTC. Um ficheiro que não pode ser interpretado, ou que tem outra versão de esquema, para todas as execuções com `O estado do Atualizador de Prefixo IPv6 é inválido ou não suportado.`

## Armazenamento das definições \{#settings-storage}

As definições ficam na configuração do pfSense, em `installedpackages/ipv6prefixupdater/config/0`.

| Chave                         | Descrição                                                                                                                                                                                                                |
|-------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `enabled`                     | **<Terminology title="Verificações automáticas agendadas, desligadas até as ativar" to="/docs/reference/terminology#running-checks">Ativar atualizações agendadas</Terminology>**, `on` quando selecionada.              |
| `row`                         | **Interfaces monitorizadas**, uma lista com um `interface` (uma chave de interface, como `lan`) e um `prefix_length` (de `48` a `64`) por linha.                                                                         |
| `update_frequency`            | **Agenda**, um de `every_fifteen_minutes`, `hourly`, `every_six_hours` ou `daily`.                                                                                                                                       |
| `notifications`               | **<Terminology title="O alerta enviado depois de os seus endereços serem atualizados" to="/docs/reference/terminology#notifications-and-logs">Enviar notificações de alteração</Terminology>**, `on` quando selecionada. |
| `update_check_frequency`      | **Verificações de atualizações**, um de `daily`, `weekly`, `monthly` ou `never`.                                                                                                                                         |
| `update_remote_notifications` | **Notificações remotas**, `on` quando selecionada.                                                                                                                                                                       |

A agenda estável da verificação de releases fica ao lado do registo das definições, em `installedpackages/ipv6prefixupdater/update_schedule`, com `minute` de 0 a 59, `hour` de 0 a 23, `weekday` de 0 a 6 e `monthday` de 1 a 28. Um valor em falta, malformado ou fora do intervalo é gerado de novo e guardado.

### Seleção de campos \{#field-selection}

As escolhas do separador Campos ficam ao lado do registo de definições, em `installedpackages/ipv6prefixupdater/fields`, pelo que guardar o separador Definições, que substitui `config/0`, nunca as limpa.

| Chave                  | Descrição                                                                                                                                         |
|------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------|
| `schema`               | Sempre `1`. Indica uma seleção guardada a partir do separador Campos, mesmo que vazia.                                                            |
| `enabled_groups/item`  | Grupos ativados, como `firewall_rules`, `dhcpv6` ou `package:<section>` para as definições de outro pacote.                                       |
| `disabled_groups/item` | Grupos do pfSense desativados. Um grupo do pfSense que não conste de nenhuma das listas está ativado, e um grupo de outro pacote está desativado. |
| `include/item`         | Identidades dos campos marcados num grupo desativado.                                                                                             |
| `exclude/item`         | Identidades dos campos desmarcados num grupo ativado.                                                                                             |

- As chaves dos grupos do pfSense são `interfaces`, `virtual_ips`, `aliases`, `firewall_rules`, `nat`, `dhcpv6`, `router_advertisements`, `dns_host_overrides`, `ipsec`, `openvpn` e `wireguard`.
- `include` e `exclude` guardam no máximo 1000 identidades cada, e cada identidade segue as [Identidades dos campos](/docs/reference/approved-fields#field-identities).

## Entrada cron \{#cron-entry}

Guardar as Definições remove qualquer entrada existente do comando e, quando `enabled` é `on`, instala uma nova para `root` com a função `install_cron_job()` do pfSense.

| Valor da agenda         | Campos cron    |
|-------------------------|----------------|
| `every_fifteen_minutes` | `*/15 * * * *` |
| `hourly`                | `0 * * * *`    |
| `every_six_hours`       | `0 */6 * * *`  |
| `daily`                 | `0 0 * * *`    |

Um valor desconhecido recorre aos campos de hora a hora. Enquanto uma migração do <Terminology title="Versão 1.x: o script update.php executado pelo pacote Cron" to="/docs/reference/terminology#package-origins">atualizador legado</Terminology> aguarda que o script legado termine, o pacote mantém uma entrada `*/15 * * * *` para que a migração seja repetida mesmo com as atualizações agendadas desativadas.

Uma segunda entrada executa `/usr/local/sbin/ipv6-prefix-updater --check-updates` como `root` com a frequência de **Verificações de atualizações**, num minuto, hora, dia da semana e dia do mês aleatórios mas estáveis. Guardar as Definições substitui-a, e `never` remove-a.

## Registos e alertas \{#logs-and-notices}

Cada linha do <Terminology title="O registo geral do pfSense, onde cada execução deixa linhas" to="/docs/reference/terminology#notifications-and-logs">registo do sistema</Terminology> é escrita com a função `log_error()` do pfSense e começa por `IPv6 Prefix Updater:`. Os alertas são criados com `file_notice()`. Os alertas das execuções ligam a `/ipv6-prefix-updater-status.php`, o alerta da migração liga a `/ipv6-prefix-updater-cleanup.php` e o alerta de nova versão disponível liga a `/ipv6-prefix-updater-about.php`.

| ID do alerta                            | Criado quando                                                                                                                                                                                                                                                       | Entrega                                                                                                                                                                                                                                                 |
|-----------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `ipv6-prefix-updater-success`           | <Terminology title="O prefixo mudou e cada campo aprovado foi atualizado" to="/docs/reference/terminology#run-outcomes">Sucesso</Terminology> com `notifications` definido como `on`                                                                                | WebGUI e <Terminology title="O e-mail e outros serviços de alerta remotos do pfSense" to="/docs/reference/terminology#notifications-and-logs">canais de notificação</Terminology>                                                                       |
| `ipv6-prefix-updater-no-matches`        | <Terminology title="O prefixo mudou, mas nenhum campo aprovado usava o antigo" to="/docs/reference/terminology#run-outcomes">Aviso</Terminology>                                                                                                                    | Apenas WebGUI                                                                                                                                                                                                                                           |
| `ipv6-prefix-updater-failure`           | <Terminology title="A execução parou em uma verificação ou etapa de segurança" to="/docs/reference/terminology#run-outcomes">Falha</Terminology>                                                                                                                    | Apenas WebGUI                                                                                                                                                                                                                                           |
| `ipv6-prefix-updater-package-<section>` | Uma execução alterou as definições de outro pacote, e nenhum pacote instalado é dono da secção ou a nova aplicação das definições falhou                                                                                                                            | Apenas WebGUI                                                                                                                                                                                                                                           |
| `ipv6-prefix-updater-legacy-migration`  | Uma migração do <Terminology title="Versão 1.x: o script update.php executado pelo pacote Cron" to="/docs/reference/terminology#package-origins">atualizador legado</Terminology> que executou pelo menos um passo, ou uma migração que falhou durante a instalação | Apenas WebGUI                                                                                                                                                                                                                                           |
| `ipv6-prefix-updater-update-available`  | Uma verificação de releases encontra uma versão mais recente que ainda não foi anunciada                                                                                                                                                                            | Apenas WebGUI, ou WebGUI e os <Terminology title="O e-mail e outros serviços de alerta remotos do pfSense" to="/docs/reference/terminology#notifications-and-logs">canais de notificação</Terminology> quando **Notificações remotas** está selecionada |

Se a verificação do ambiente do próprio comando falhar, ou se não for possível abrir o ficheiro de bloqueio, o motivo vai apenas para o erro padrão. Cada execução que grava também guarda uma revisão da configuração com a descrição `O Atualizador de prefixo IPv6 alterou <count> campo(s) aprovado(s) para a interface <interface>`.

## Privilégios das páginas \{#page-privileges}

Cada página do pacote declara o seu próprio privilégio do pfSense, pelo que o acesso pode ser concedido página a página:

- **Estado**: `page-services-ipv6-prefix-updater-status`, com o nome `Services: IPv6 Prefix Updater: Status`.
- **Campos**: `page-services-ipv6-prefix-updater-fields`, com o nome `Services: IPv6 Prefix Updater: Fields`. Permite alterar os campos que uma execução reescreve, pelo que se recomenda concedê-lo apenas a administradores.
- **Cópias de segurança**: `page-services-ipv6-prefix-updater-backups`, com o nome `Services: IPv6 Prefix Updater: Backups`. Permite transferir cópias completas da configuração, pelo que se recomenda concedê-lo apenas a administradores.
- **Limpeza**: `page-services-ipv6-prefix-updater-cleanup`, com o nome `Services: IPv6 Prefix Updater: Cleanup`.
- **Sobre**: `page-services-ipv6-prefix-updater-about`, com o nome `Services: IPv6 Prefix Updater: About`.
