Execute o comando do pacote a partir de uma shell e encontre os ficheiros, os registos e os alertas que utiliza.

## Utilização \{#usage}

```shell
/usr/local/sbin/ipv6-prefix-updater [--manual] [--dry-run] [--accept-current-prefix [--interface=NAME]] [--migrate-legacy] [--help]
```

A entrada cron gerida pelo pfSense executa o comando como `root` sem opções. Antes de cada verificação, também move para o pacote quaisquer restos do <Terminology title="script update.php original executado pelo pacote Cron" to="/docs/reference/terminology#legacy-updater">atualizador legado</Terminology>. O separador Estado usa `--manual` para **Executar agora**, `--dry-run` para **<Terminology title="pré-visualização que nunca cria cópias de segurança nem grava" to="/docs/reference/terminology#dry-run">Simulação</Terminology>** e `--accept-current-prefix` para a recuperação da referência, e o separador Limpeza usa `--migrate-legacy`.

Sem opções, o comando comporta-se como uma verificação agendada e indica <Terminology title="resultado: verificação agendada ignorada com atualizações desativadas" to="/docs/reference/terminology#disabled">Desativado</Terminology> quando a opção **<Terminology title="verificações automáticas por entrada cron gerida pelo pfSense" to="/docs/reference/terminology#scheduled-updates">Ativar atualizações agendadas</Terminology>** está desmarcada.

## Opções \{#options}

| Opção                     | Descrição                                                                                                                                                                                                                                                                                                      |
|---------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `--manual`                | Executa mesmo com as <Terminology title="verificações automáticas por entrada cron gerida pelo pfSense" to="/docs/reference/terminology#scheduled-updates">atualizações agendadas</Terminology> desativadas.                                                                                                   |
| `--dry-run`               | Faz uma pré-visualização sem cópia de segurança nem gravação, e implica `--manual`.                                                                                                                                                                                                                            |
| `--accept-current-prefix` | Regista o endereço de origem, o prefixo e o comprimento ativos como referência, sem analisar campos aprovados, criar uma cópia de segurança, gravar a configuração nem recarregar serviços. Implica `--manual` e não pode ser combinado com `--dry-run`.                                                       |
| `--interface=NAME`        | Limita `--accept-current-prefix` a uma única interface monitorizada, indicada pelo nome interno, como `lan`. Sem esta opção, são aceites todas as interfaces monitorizadas que tenham um endereço.                                                                                                             |
| `--migrate-legacy`        | Move de imediato o <Terminology title="script update.php original executado pelo pacote Cron" to="/docs/reference/terminology#legacy-updater">atualizador legado</Terminology> para o pacote e mostra cada passo, sem executar uma verificação do prefixo. Termina com `2` quando a migração indicou um aviso. |
| `--help`                  | Mostra a linha de utilização e termina com `0`. A linha de utilização não inclui o próprio `--help`.                                                                                                                                                                                                           |

Qualquer outra opção escreve `Opção desconhecida: <option>` no erro padrão e termina com `64`. Combinar `--accept-current-prefix` com `--dry-run` também termina com `64`.

## Saída \{#output}

Uma execução concluída que monitoriza uma só interface escreve nove linhas na saída padrão, seguidas das alterações de campos após uma <Terminology title="pré-visualização que nunca cria cópias de segurança nem grava" to="/docs/reference/terminology#dry-run">simulação</Terminology> ou um <Terminology title="resultado: campos atualizados, guardados, recarregados e verificados" to="/docs/reference/terminology#success">Sucesso</Terminology>:

```text
Estado: Sucesso
Interface: lan
Endereço de origem observado: 2001:db8:abcd:88aa::1
Prefixo anterior: 2001:db8:abcd:7800::
Prefixo atual: 2001:db8:abcd:8800::/56
Campos planeados ou alterados: 1
Cópia de segurança da configuração: Criada
Serviços recarregados: Filtro da firewall
Resumo: Foram atualizados 1 campo(s) aprovado(s) de 2001:db8:abcd:7800::/56 para 2001:db8:abcd:8800::/56 na interface lan.
Alterações de campos:
- aliases/alias/0/address: 2001:db8:abcd:78aa::10 → 2001:db8:abcd:88aa::10
```

- `Prefixo anterior` não tem comprimento e mostra `Não disponível` após <Terminology title="resultado: referência registada, configuração inalterada" to="/docs/reference/terminology#initialized">Inicializado</Terminology> ou <Terminology title="resultado: simulação feita antes de existir uma referência" to="/docs/reference/terminology#initialization-preview">Pré-visualização da inicialização</Terminology>.
- `Serviços recarregados` lista as etiquetas do separador Estado ou `Nenhum`. Após uma <Terminology title="pré-visualização que nunca cria cópias de segurança nem grava" to="/docs/reference/terminology#dry-run">simulação</Terminology>, lista os serviços que seriam recarregados.
- `Alterações de campos` tem uma linha por endereço substituído, escrita como `- <path>: <old> → <new>`, para até 200 campos.
- Quando a execução aplicou novamente as definições de outro pacote ou ignorou um campo marcado que já não existe, segue-se uma linha para cada caso, com o mesmo texto do separador Estado.
- Quando outra verificação detém o <Terminology title="proteção que impede duas verificações em simultâneo" to="/docs/reference/terminology#run-lock">bloqueio de execução</Terminology>, a única saída é `Outra execução detém o bloqueio do pacote; esta invocação terminou sem ler a configuração.`
- Com várias interfaces monitorizadas, a saída começa com as linhas globais de `Estado`, `Resumo`, pacotes e campos ignorados, seguidas das linhas de cada interface, separadas por linhas em branco.
- Quando houve uma migração do <Terminology title="script update.php original executado pelo pacote Cron" to="/docs/reference/terminology#legacy-updater">atualizador legado</Terminology> antes da verificação, os respetivos passos são mostrados primeiro.
- As etiquetas e as mensagens seguem a definição de idioma do pfSense.

## Formato do estado do pacote \{#package-state-format}

| Chave                 | Descrição                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
|-----------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `schema_version`      | Sempre `1`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `targets.<interface>` | Uma <Terminology title="prefixo inicial registado sem alterar a configuração" to="/docs/reference/terminology#baseline">referência</Terminology> por interface monitorizada, identificada pelo nome interno, com `interface`, `source_address`, `prefix`, `prefix_length` e `updated_at`. Uma referência obtida do <Terminology title="script update.php original executado pelo pacote Cron" to="/docs/reference/terminology#legacy-updater">atualizador legado</Terminology> tem também `source` definido como `legacy_cache`. |
| `last_run`            | A execução registada mais recente, com `status`, `timestamp`, `interface`, `observed_address`, `previous_prefix`, `current_prefix`, `current_prefix_length`, `change_count`, `backup_created`, `services`, `message`, `message_key` e `message_arguments`.                                                                                                                                                                                                                                                                       |
| `legacy_migration`    | Presente após uma migração do <Terminology title="script update.php original executado pelo pacote Cron" to="/docs/reference/terminology#legacy-updater">atualizador legado</Terminology>, com `status`, `steps`, `warnings` e `recorded_at`. O separador Limpeza mostra-o.                                                                                                                                                                                                                                                      |

- `status` é um de `initialized`, `initialization_preview`, `no_change`, `dry_run`, `warning`, `accepted`, `success` ou `failure`.
- Após um <Terminology title="resultado: campos atualizados, guardados, recarregados e verificados" to="/docs/reference/terminology#success">Sucesso</Terminology>, `last_run.notification` é `disabled` quando as notificações estão desativadas, ou `sent` ou `failed` após uma tentativa de entrega.
- Após uma <Terminology title="pré-visualização que nunca cria cópias de segurança nem grava" to="/docs/reference/terminology#dry-run">simulação</Terminology> ou um <Terminology title="resultado: campos atualizados, guardados, recarregados e verificados" to="/docs/reference/terminology#success">Sucesso</Terminology>, cada resultado tem também `changes`, com o `path` e as `replacements` de até 200 campos, em que cada substituição é um endereço antigo e um endereço novo.
- `package_reapply` indica a `section`, o `package`, o `status` e o `error` de cada pacote cujas definições a execução aplicou novamente, e `skipped_fields` lista os campos marcados que já não existem. Cada um só aparece quando não está vazio.
- Com várias interfaces monitorizadas, `last_run` contém os totais e uma lista `targets` com um resultado por interface.
- As datas e horas usam ISO 8601 em UTC. Um ficheiro que não pode ser interpretado, ou que tem outra versão de esquema, para todas as execuções com `O estado do Atualizador de Prefixo IPv6 é inválido ou não suportado.`

## Armazenamento das definições \{#settings-storage}

As definições ficam na configuração do pfSense, em `installedpackages/ipv6prefixupdater/config/0`.

| Chave              | Descrição                                                                                                                                                                                                         |
|--------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `enabled`          | **<Terminology title="verificações automáticas por entrada cron gerida pelo pfSense" to="/docs/reference/terminology#scheduled-updates">Ativar atualizações agendadas</Terminology>**, `on` quando selecionada.   |
| `row`              | **Interfaces monitorizadas**, uma lista com um `interface` (uma chave de interface, como `lan`) e um `prefix_length` (de `48` a `64`) por linha.                                                                  |
| `update_frequency` | **Agenda**, um de `every_fifteen_minutes`, `hourly`, `every_six_hours` ou `daily`.                                                                                                                                |
| `notifications`    | **<Terminology title="alerta enviado após uma atualização verificada com sucesso" to="/docs/reference/terminology#change-notification">Enviar notificações de alteração</Terminology>**, `on` quando selecionada. |

### Seleção de campos \{#field-selection}

As escolhas do separador Campos ficam ao lado do registo de definições, em `installedpackages/ipv6prefixupdater/fields`, pelo que guardar o separador Definições, que substitui `config/0`, nunca as limpa.

| Chave                  | Descrição                                                                                                                                         |
|------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------|
| `schema`               | Sempre `1`. Indica uma seleção guardada a partir do separador Campos, mesmo que vazia.                                                            |
| `enabled_groups/item`  | Grupos ativados, como `firewall_rules`, `dhcpv6` ou `package:<section>` para as definições de outro pacote.                                       |
| `disabled_groups/item` | Grupos do pfSense desativados. Um grupo do pfSense que não conste de nenhuma das listas está ativado, e um grupo de outro pacote está desativado. |
| `include/item`         | Identidades dos campos marcados num grupo desativado.                                                                                             |
| `exclude/item`         | Identidades dos campos desmarcados num grupo ativado.                                                                                             |

- As chaves dos grupos do pfSense são `interfaces`, `virtual_ips`, `aliases`, `firewall_rules`, `nat`, `dhcpv6`, `router_advertisements`, `dns_host_overrides`, `ipsec`, `openvpn` e `wireguard`.
- `include` e `exclude` guardam no máximo 1000 identidades cada, e cada identidade segue as [Identidades dos campos](/docs/reference/approved-fields#field-identities).

## Entrada cron \{#cron-entry}

Guardar as Definições remove qualquer entrada existente do comando e, quando `enabled` é `on`, instala uma nova para `root` com a função `install_cron_job()` do pfSense.

| Valor da agenda         | Campos cron    |
|-------------------------|----------------|
| `every_fifteen_minutes` | `*/15 * * * *` |
| `hourly`                | `0 * * * *`    |
| `every_six_hours`       | `0 */6 * * *`  |
| `daily`                 | `0 0 * * *`    |

Um valor desconhecido recorre aos campos de hora a hora. Enquanto uma migração do <Terminology title="script update.php original executado pelo pacote Cron" to="/docs/reference/terminology#legacy-updater">atualizador legado</Terminology> aguarda que o script legado termine, o pacote mantém uma entrada `*/15 * * * *` para que a migração seja repetida mesmo com as atualizações agendadas desativadas.

## Registos e alertas \{#logs-and-notices}

Cada linha do <Terminology title="registo geral do pfSense onde o pacote escreve" to="/docs/reference/terminology#system-log">registo do sistema</Terminology> é escrita com a função `log_error()` do pfSense e começa por `IPv6 Prefix Updater:`. Os alertas são criados com `file_notice()` e ligam a `/ipv6-prefix-updater-status.php`, exceto o alerta da migração, que liga a `/ipv6-prefix-updater-cleanup.php`.

| ID do alerta                            | Criado quando                                                                                                                                                                                                                                                 | Entrega                                                                                                                                                                     |
|-----------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `ipv6-prefix-updater-success`           | <Terminology title="resultado: campos atualizados, guardados, recarregados e verificados" to="/docs/reference/terminology#success">Sucesso</Terminology> com `notifications` definido como `on`                                                               | WebGUI e <Terminology title="serviços de alerta remotos configurados no pfSense" to="/docs/reference/terminology#notification-channels">canais de notificação</Terminology> |
| `ipv6-prefix-updater-no-matches`        | <Terminology title="resultado: o prefixo mudou, mas nenhum campo aprovado correspondeu" to="/docs/reference/terminology#warning">Aviso</Terminology>                                                                                                          | Apenas WebGUI                                                                                                                                                               |
| `ipv6-prefix-updater-failure`           | <Terminology title="resultado: verificação ou etapa de segurança parou a execução" to="/docs/reference/terminology#failure">Falha</Terminology>                                                                                                               | Apenas WebGUI                                                                                                                                                               |
| `ipv6-prefix-updater-package-<section>` | Uma execução alterou as definições de outro pacote, e nenhum pacote instalado é dono da secção ou a nova aplicação das definições falhou                                                                                                                      | Apenas WebGUI                                                                                                                                                               |
| `ipv6-prefix-updater-legacy-migration`  | Uma migração do <Terminology title="script update.php original executado pelo pacote Cron" to="/docs/reference/terminology#legacy-updater">atualizador legado</Terminology> que executou pelo menos um passo, ou uma migração que falhou durante a instalação | Apenas WebGUI                                                                                                                                                               |

Se a verificação do ambiente do próprio comando falhar, ou se não for possível abrir o ficheiro de bloqueio, o motivo vai apenas para o erro padrão. Cada execução que grava também guarda uma revisão da configuração com a descrição `O Atualizador de prefixo IPv6 alterou <count> campo(s) aprovado(s) para a interface <interface>`.

## Privilégios das páginas \{#page-privileges}

Cada página do pacote declara o seu próprio privilégio do pfSense, pelo que o acesso pode ser concedido página a página:

- **Estado**: `page-services-ipv6-prefix-updater-status`, com o nome `Services: IPv6 Prefix Updater: Status`.
- **Campos**: `page-services-ipv6-prefix-updater-fields`, com o nome `Services: IPv6 Prefix Updater: Fields`. Permite alterar os campos que uma execução reescreve, pelo que se recomenda concedê-lo apenas a administradores.
- **Cópias de segurança**: `page-services-ipv6-prefix-updater-backups`, com o nome `Services: IPv6 Prefix Updater: Backups`. Permite transferir cópias completas da configuração, pelo que se recomenda concedê-lo apenas a administradores.
- **Limpeza**: `page-services-ipv6-prefix-updater-cleanup`, com o nome `Services: IPv6 Prefix Updater: Cleanup`.
