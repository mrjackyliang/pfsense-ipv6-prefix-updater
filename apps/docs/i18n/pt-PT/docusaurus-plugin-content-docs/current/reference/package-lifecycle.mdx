Confirme a versão instalada, instale uma versão mais recente ou remova o pacote a partir de uma shell do pfSense.

## Verificar a versão instalada \{#check-the-installed-version}

```shell
pkg info pfSense-pkg-Ipv6PrefixUpdater
```

Compare a versão indicada com a [versão mais recente no GitHub](https://github.com/mrjackyliang/pfsense-ipv6-prefix-updater/releases/latest).

## Atualizar o pacote \{#update-the-package}

Recomenda-se transferir primeiro uma cópia da configuração em **Diagnostics → Backup & Restore**. Depois, instale a versão mais recente sobre o pacote existente:

```shell
pkg add -f https://github.com/mrjackyliang/pfsense-ipv6-prefix-updater/releases/latest/download/pfSense-pkg-Ipv6PrefixUpdater.pkg
```

O passo de instalação volta a sincronizar ambas as entradas cron, a verificação do prefixo e a verificação de releases, com as definições guardadas e mantém todas as <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referências</Terminology>. Os passos de soma de verificação de [Instalar o pacote](/docs/installation#verify-the-download-first) também funcionam nas atualizações.

Após a atualização:

1. Abra **Services → IPv6 Prefix Updater → Definições** e confirme os valores guardados.
2. No separador Estado, verifique o **Estado atual**. Cada interface mantém a respetiva <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology>.

Se uma linha mostrar `Não inicializado`, **Executar agora** regista uma nova <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> para ela. Os endereços que ainda usam um prefixo anterior a essa referência ficam então inalterados.

## Remover o pacote \{#remove-the-package}

Desmarcar primeiro a opção **<Terminology title="Verificações automáticas agendadas, desligadas até as ativar" to="/docs/reference/terminology#running-checks">Ativar atualizações agendadas</Terminology>** evita que uma reinstalação posterior inicie logo o agendamento, caso o pfSense mantenha as definições guardadas. Depois, execute:

```shell
pkg delete -f pfSense-pkg-Ipv6PrefixUpdater
```

O pacote é marcado como `vital`, por isso as próprias atualizações do pfSense mantêm-no instalado e um simples `pkg delete` recusa pacotes vitais.

A remoção elimina ambas as entradas cron (verificação do prefixo e verificação de releases), fecha o alerta de nova versão disponível e remove cada ficheiro de bloqueio de operação quando nenhuma operação detém esse bloqueio. Mantém o <Terminology title="O ficheiro com cada referência, mantido mesmo após reinstalar" to="/docs/reference/terminology#running-checks">estado do pacote</Terminology>, `updates.json`, `update-status.json` e as cópias do separador **Cópias de segurança** em `/cf/conf/ipv6-prefix-updater`.

As próprias atualizações do pfSense mantêm o pacote instalado (é `vital`), e o estado mantido faz com que uma remoção e reinstalação nunca perca uma <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology>.

A remoção não desfaz os endereços já guardados na configuração, e as revisões do pacote ficam no <Terminology title="As revisões de configuração guardadas pelo pfSense para restaurar" to="/docs/reference/terminology#backups-and-service-reloads">Config History</Terminology>. Para remover também os ficheiros mantidos, execute `rm -rf /cf/conf/ipv6-prefix-updater` depois de remover o pacote.

## Reinstalar mais tarde \{#reinstall-later}

Uma reinstalação encontra o <Terminology title="O ficheiro com cada referência, mantido mesmo após reinstalar" to="/docs/reference/terminology#running-checks">estado do pacote</Terminology> mantido, pelo que a primeira execução compara com cada <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> guardada e atualiza os campos que ficaram num prefixo mais antigo. Se as definições anteriores ainda existirem com a opção **<Terminology title="Verificações automáticas agendadas, desligadas até as ativar" to="/docs/reference/terminology#running-checks">Ativar atualizações agendadas</Terminology>** selecionada, o passo de instalação ativa logo o agendamento.

Para começar do zero, elimine `/cf/conf/ipv6-prefix-updater` antes de reinstalar. A primeira execução regista então uma nova <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> e indica <Terminology title="Primeiro olhar: a referência é registada e nada muda" to="/docs/reference/terminology#run-outcomes">Inicializado</Terminology> sem alterar a configuração.

Consulte [Cópias de segurança e recuperação](/docs/operate/backups-and-recovery) antes da manutenção e [Estabelecer a referência](/docs/first-run) após uma reinstalação.
