Escolha as interfaces que revelam os prefixos atuais e indique o <Terminology title="O /56 ou /64 que diz quantos bits nomeiam a rede" to="/docs/reference/terminology#addresses-and-prefixes">comprimento do prefixo</Terminology> que o seu ISP delega para cada uma.

## Escolher as interfaces monitorizadas \{#choose-the-monitored-interfaces}

Adicione uma linha em **Interfaces monitorizadas** por cada interface cujo <Terminology title="Um endereço IPv6 público em 2000::/3, o único tipo usado" to="/docs/reference/terminology#addresses-and-prefixes">endereço global</Terminology> provém do <Terminology title="A rede IPv6 que o seu fornecedor lhe atribui, e que pode mudar" to="/docs/reference/terminology#addresses-and-prefixes">prefixo delegado</Terminology>. O pacote lê cada endereço de novo em cada execução e nunca recorre a um <Terminology title="Um endereço fe80 que nunca é usado como origem" to="/docs/reference/terminology#addresses-and-prefixes">endereço link-local</Terminology>.

Se a WAN receber apenas um <Terminology title="A rede IPv6 que o seu fornecedor lhe atribui, e que pode mudar" to="/docs/reference/terminology#addresses-and-prefixes">prefixo delegado</Terminology>, normalmente é uma <Terminology title="Uma interface que forma o IPv6 a partir do prefixo de outra" to="/docs/reference/terminology#interfaces-and-detection">interface rastreada</Terminology>, como a LAN, que tem um <Terminology title="Um endereço IPv6 público em 2000::/3, o único tipo usado" to="/docs/reference/terminology#addresses-and-prefixes">endereço global</Terminology> desse prefixo e que é a escolha certa.

<img src={monitoredInterfaces} alt="Separador Definições do IPv6 Prefix Updater com duas linhas em Interfaces monitorizadas, LAN e LAB, cada uma com um comprimento do prefixo delegado de /56, e uma nota que remete para o separador Campos" width={1024} height={768} style={{maxWidth: '100%', height: 'auto'}} />

- **Adicionar**: adiciona uma linha. Cada interface só pode aparecer numa única linha, e guardar sem nenhuma linha é rejeitado.
- **Eliminar**: remove uma linha. O pfSense oculta este botão enquanto só resta uma linha.
- **Uma execução para todas as linhas**: cada verificação agendada lê todas as interfaces monitorizadas e aplica as respetivas alterações numa única gravação com cópia de segurança.

A maioria das firewalls precisa de uma só linha. Adicione mais quando várias interfaces recebem o seu próprio prefixo delegado, como em duas ligações WAN, ou quando quiser verificar o endereço de cada segmento de LAN.

Para confirmar a escolha:

1. Guarde as Definições com a opção **<Terminology title="Verificações automáticas agendadas, desligadas até as ativar" to="/docs/reference/terminology#running-checks">Ativar atualizações agendadas</Terminology>** desmarcada.
2. No separador Estado, selecione **Executar agora**.
3. Compare **<Terminology title="O endereço em direto do qual cada execução lê o prefixo" to="/docs/reference/terminology#interfaces-and-detection">Endereço de origem observado</Terminology>** com o endereço apresentado em **Status → Interfaces**.
4. Se o endereço pertencer à rede errada, selecione outra interface e repita.

O separador Estado mostra a descrição de cada interface seguida do nome interno no pfSense, como `LAN (lan)`.

## Indicar o comprimento do prefixo delegado \{#enter-the-delegated-prefix-length}

Selecione o comprimento indicado nos dados do serviço do seu ISP ou o tamanho da delegação de prefixo DHCPv6 na interface WAN. O **<Terminology title="O tamanho do prefixo do seu fornecedor, como /56; definido por si" to="/docs/reference/terminology#addresses-and-prefixes">Comprimento do prefixo delegado</Terminology>** aceita valores de `/48` a `/64`, começa em `/56` e nunca é detetado automaticamente.

:::tip

Recomenda-se confirmar o comprimento antes da primeira execução de **Executar agora**, porque a <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> guarda o comprimento juntamente com o prefixo.

:::

## Verificar a rede calculada \{#check-the-calculated-network}

Após uma execução, **<Terminology title="O prefixo visto agora, comparado com o anterior" to="/docs/reference/terminology#interfaces-and-detection">Prefixo observado</Terminology>** mostra a rede calculada. Os comprimentos que terminam a meio de um dígito hexadecimal, como `/57` ou `/63`, funcionam da mesma forma, porque o pacote aplica a máscara aos endereços bit a bit.

Para uma delegação `/56` que muda de `2001:db8:abcd:7800::/56` para `2001:db8:abcd:8800::/56`:

```text
Source address:    2001:db8:abcd:88aa::1
Current prefix:    2001:db8:abcd:8800::/56
Previous address:  2001:db8:abcd:78aa::42
Updated address:   2001:db8:abcd:88aa::42
```

Só os primeiros 56 bits mudam, e a <Terminology title="Os bits depois do prefixo, sempre copiados sem alteração" to="/docs/reference/terminology#addresses-and-prefixes">parte de anfitrião</Terminology> `aa::42` mantém-se igual. Os endereços em `2001:db8::/32` destes guias são exemplos de documentação.

## Alterar as interfaces \{#changing-the-interfaces}

:::warning

Adicionar uma <Terminology title="A interface cujo endereço revela o seu prefixo atual" to="/docs/reference/terminology#interfaces-and-detection">Interface monitorizada</Terminology>, ou mudar uma linha para outra interface, faz com que a execução seguinte registe uma nova <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> para ela, sem alterar a configuração. Se o respetivo prefixo tiver mudado e o pacote ainda não tiver aplicado essa mudança, ela é ignorada.

:::

Eliminar uma linha mantém a <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> dessa interface no <Terminology title="O ficheiro com cada referência, mantido mesmo após reinstalar" to="/docs/reference/terminology#running-checks">estado do pacote</Terminology>. Voltar a adicionar a interface mais tarde compara com essa referência guardada, em vez de registar uma nova.

## Alterar o comprimento do prefixo \{#changing-the-prefix-length}

Alterar o **<Terminology title="O tamanho do prefixo do seu fornecedor, como /56; definido por si" to="/docs/reference/terminology#addresses-and-prefixes">Comprimento do prefixo delegado</Terminology>** depois de existir uma <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> conta como <Terminology title="O seu prefixo mudou, por isso o pacote entra em ação" to="/docs/reference/terminology#baselines-and-transitions">transição de prefixo</Terminology>, mesmo que a rede em si se mantenha. O pacote faz corresponder os endereços com o comprimento guardado na <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> e substitui os bits com o novo comprimento.

:::danger

Estreitar o prefixo substitui os bits de sub-rede de todos os endereços correspondentes. Com o <Terminology title="O endereço em direto do qual cada execução lê o prefixo" to="/docs/reference/terminology#interfaces-and-detection">endereço de origem</Terminology> `2001:db8:1234:ab00::1` e uma <Terminology title="O prefixo inicial registrado, base para medir as mudanças" to="/docs/reference/terminology#baselines-and-transitions">referência</Terminology> `/56`, mudar para `/64` transforma `2001:db8:1234:abcc::42` em `2001:db8:1234:ab00::42`.

:::

Alargar o prefixo, por exemplo de `/64` para `/56`, pode deixar a execução sem nada para alterar. Nesse caso, indica <Terminology title="O prefixo mudou, mas nenhum campo aprovado usava o antigo" to="/docs/reference/terminology#run-outcomes">Aviso</Terminology> em todas as execuções até o próprio prefixo mudar ou até verificar os endereços guardados e [aceitar o prefixo atual](/docs/operate/backups-and-recovery#after-a-failed-run) como nova referência.

Antes de alterar o comprimento, recomenda-se desmarcar a opção **<Terminology title="Verificações automáticas agendadas, desligadas até as ativar" to="/docs/reference/terminology#running-checks">Ativar atualizações agendadas</Terminology>** ao guardar essa mesma alteração. Uma **<Terminology title="Uma pré-visualização das alterações que não grava nada" to="/docs/reference/terminology#running-checks">Simulação</Terminology>** mostra então o número de campos planeados, cada alteração planeada em `Alterações de campos` e o **Resumo** antes de selecionar **Executar agora**.

A seguir, [estabeleça a referência](/docs/first-run) e depois escolha os campos no separador [Campos](/docs/configure/configuration-scopes).
