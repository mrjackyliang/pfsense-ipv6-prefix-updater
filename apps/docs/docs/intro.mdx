Keep the IPv6 addresses saved in pfSense on your current prefix when your ISP assigns a new <Terminology title="The IPv6 network your ISP hands you, which can change" to="/docs/reference/terminology#addresses-and-prefixes">delegated prefix</Terminology>.

## What It Does

IPv6 Prefix Updater for pfSense is a pfSense package that watches the interfaces you choose for a new prefix. When the prefix changes, it rewrites the matching addresses in the fields you select and keeps the <Terminology title="The bits after the prefix, always copied unchanged" to="/docs/reference/terminology#addresses-and-prefixes">host portion</Terminology> of each one.

## Why Use This Package?

1. Keeps the <Terminology title="The bits after the prefix, always copied unchanged" to="/docs/reference/terminology#addresses-and-prefixes">host portion</Terminology> of every address so each device keeps the same suffix after a prefix change.
2. Changes only the <Terminology title="A setting the package is allowed to rewrite" to="/docs/reference/terminology#fields-and-change-plans">approved fields</Terminology> you select on the Fields tab so remote VPN networks, peers, gateways, and routes stay as you set them.
3. Saves a <Terminology title="A copy of the config taken right before any write" to="/docs/reference/terminology#backups-and-service-reloads">configuration backup</Terminology> before every write so the previous configuration is ready in <Terminology title="pfSense's saved config revisions you can restore" to="/docs/reference/terminology#backups-and-service-reloads">Config History</Terminology>.
4. Runs on a schedule that pfSense manages so you don't need the Cron package or a script in a home directory.
5. Shows every result on the Status tab so you can see what changed, which services reloaded, and whether a backup was made.

## What It Updates

- **Aliases**: addresses and networks in Host and Network aliases.
- **Static Interfaces**: addresses of interfaces set to Static IPv6.
- **<Terminology title="An extra address on an interface, such as a CARP VIP" to="/docs/reference/terminology#pfsense-features">Virtual IP Addresses</Terminology>**: CARP and IP Alias <Terminology title="An extra address on an interface, such as a CARP VIP" to="/docs/reference/terminology#pfsense-features">virtual IPs</Terminology>.
- **IPsec**: the local side of Tunnel IPv6 and Routed (VTI) <Terminology title="The IPsec entry naming a tunnel's local and remote networks" to="/docs/reference/terminology#pfsense-features">Phase 2</Terminology> entries.
- **OpenVPN**: IPv6 tunnel and local networks on servers and <Terminology title="OpenVPN settings that apply to one client" to="/docs/reference/terminology#pfsense-features">client specific overrides</Terminology>, and IPv6 tunnel networks on clients.
- **WireGuard**: <Terminology title="The address on a WireGuard tunnel interface" to="/docs/reference/terminology#pfsense-features">tunnel addresses</Terminology>, when the WireGuard package is installed.
- **DHCPv6 Server**: address, prefix delegation, and pool ranges, static mappings, and the DNS and NTP servers handed to clients.
- **Router Advertisements**: advertised DNS servers and RA subnets.
- **DNS Host Overrides**: host overrides in the DNS Resolver and DNS Forwarder.
- **Firewall Rules**: source and destination addresses typed into rules.
- **NAT and NPt**: typed addresses in port forwards, outbound NAT, and 1:1 NAT, and NPt prefixes.
- **Other packages' settings**: only the fields you tick, after which the package applies that package's settings again.

The **Fields** tab lists every address inside your prefix with a switch for each <Terminology title="One switch for a whole kind of setting" to="/docs/reference/terminology#fields-and-change-plans">field group</Terminology> and a checkbox for each field.

## What Waits for You

The **Other Settings** group starts off, so these values change only when you tick them:

- The remote side of a VPN, such as IPsec and OpenVPN remote networks and WireGuard peers, allowed IPs, and endpoints.
- Gateways, static routes, DNS domain overrides, certificates, secrets, Base64-encoded values, and descriptions.
- Port, URL, and other alias types.

Interfaces that get their address from DHCPv6, SLAAC, or <Terminology title="An interface that builds its IPv6 from another's prefix" to="/docs/reference/terminology#interfaces-and-detection">Track Interface</Terminology> are never changed, because pfSense generates those addresses. Neither are IPv4 addresses, host names, and IPv6 addresses outside the old prefix. [Other Settings](/docs/configure/configuration-scopes#other-settings) has the full list.

## How a Check Works

1. Reads the <Terminology title="A public IPv6 address in 2000::/3, the only kind used" to="/docs/reference/terminology#addresses-and-prefixes">global address</Terminology> of each <Terminology title="The interface whose address reveals your current prefix" to="/docs/reference/terminology#interfaces-and-detection">Monitored Interface</Terminology> and calculates its prefix.
2. Compares it with the <Terminology title="The stored prefix each check compares against" to="/docs/reference/terminology#baselines-and-transitions">last successful prefix</Terminology> and stops with <Terminology title="Same prefix as last time, so there is nothing to do" to="/docs/reference/terminology#run-outcomes">No change</Terminology> if they match.
3. On a <Terminology title="Your prefix changed, so the package goes to work" to="/docs/reference/terminology#baselines-and-transitions">prefix transition</Terminology>, builds a <Terminology title="Every planned rewrite, built before anything changes" to="/docs/reference/terminology#fields-and-change-plans">change plan</Terminology> for the <Terminology title="A setting the package is allowed to rewrite" to="/docs/reference/terminology#fields-and-change-plans">approved fields</Terminology> that still use the old prefix.
4. Saves a <Terminology title="A copy of the config taken right before any write" to="/docs/reference/terminology#backups-and-service-reloads">configuration backup</Terminology>, writes every change in one save, reloads only the affected services, and checks the values again.
5. Records the result on the Status tab and sends a <Terminology title="The alert sent after your addresses were updated" to="/docs/reference/terminology#notifications-and-logs">change notification</Terminology> if it's turned on.

[Safety Model](/docs/operations) covers the protections at each step.

## Before You Start

:::warning

IPv6 Prefix Updater for pfSense is an <Terminology title="Installed from GitHub, not Netgate's package repository" to="/docs/reference/terminology#package-origins">unofficial package</Terminology>. You install it from GitHub with `pkg`, and Netgate doesn't review or support it.

:::

Package releases are published on the project's GitHub Releases page. Version 1.x releases contain only the <Terminology title="Version 1.x: the update.php script run by Cron" to="/docs/reference/terminology#package-origins">legacy updater</Terminology>, not this package.

## Languages

Every tab of the package, the <Terminology title="The latest run's lines, shown right after you start it" to="/docs/reference/terminology#running-checks">Command Output</Terminology>, and the package's messages follow the language selected in pfSense. The package includes translations for 18 pfSense language choices and falls back to English for any other language.
