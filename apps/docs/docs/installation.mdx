Install the package from a GitHub release with pfSense's `pkg` tool, then confirm that its pages appear in the WebGUI.

## Requirements

- **Administrator shell** — SSH or console access to the pfSense shell. **Diagnostics → Command Prompt** in the WebGUI can also run single commands.
- **HTTPS access to GitHub** — The firewall downloads the package from GitHub Releases.
- **Supported pfSense release** — Use pfSense CE 2.9.0 or 2.8.1, or pfSense Plus 26.07 or 26.03.1. The About tab lists the pfSense releases each package version was tested on.
- **A current backup** — Download a copy of the configuration from **Diagnostics → Backup & Restore** before you install.
- **The <Terminology title="Version 1.x: the update.php script run by Cron" to="/docs/reference/terminology#package-origins">legacy updater</Terminology> can stay** — If the version 1.x script still runs from the Cron package, leave it in place. The install step moves it into the package, as [Migrate From the Script](/docs/migrate-from-legacy) explains.

:::warning

IPv6 Prefix Updater for pfSense is an <Terminology title="Installed from GitHub, not Netgate's package repository" to="/docs/reference/terminology#package-origins">unofficial package</Terminology>. Installing a `.pkg` file from GitHub bypasses Netgate's package review and support, so it is recommended to try it on a backed-up or disposable firewall first.

:::

## Check the Release

Package releases are listed on the [GitHub Releases page](https://github.com/mrjackyliang/pfsense-ipv6-prefix-updater/releases). Each package release carries these files:

| File                                          | Description                                                        |
|-----------------------------------------------|--------------------------------------------------------------------|
| `pfSense-pkg-Ipv6PrefixUpdater.pkg`           | The package under a fixed name, used by the commands on this page. |
| `pfSense-pkg-Ipv6PrefixUpdater-<version>.pkg` | The same package with its version in the file name.                |
| `.sha256` files                               | One SHA-256 checksum for each package file.                        |

:::info

Version 1.x releases contain only the <Terminology title="Version 1.x: the update.php script run by Cron" to="/docs/reference/terminology#package-origins">legacy updater</Terminology>. If the latest release has no `.pkg` file, the commands on this page fail with a not-found (404) error.

:::

## Install the Package

Run this same command from the pfSense shell for a first installation, an update, or a reinstall:

```shell
pkg add -f https://github.com/mrjackyliang/pfsense-ipv6-prefix-updater/releases/latest/download/pfSense-pkg-Ipv6PrefixUpdater.pkg
```

`pkg` downloads the package from the latest release and runs its install step, which registers **Services → IPv6 Prefix Updater** with pfSense. The `-f` flag lets the same command install the package, update an older version, or reinstall the current version. Without it, pfSense CE 2.8 reports an update as already installed and leaves the installed version unchanged.

## Verify the Download First

To check the file against its checksum before installing, download both files to `/tmp` and print both values:

```shell
cd /tmp
fetch https://github.com/mrjackyliang/pfsense-ipv6-prefix-updater/releases/latest/download/pfSense-pkg-Ipv6PrefixUpdater.pkg
fetch https://github.com/mrjackyliang/pfsense-ipv6-prefix-updater/releases/latest/download/pfSense-pkg-Ipv6PrefixUpdater.pkg.sha256
sha256 -q pfSense-pkg-Ipv6PrefixUpdater.pkg
cat pfSense-pkg-Ipv6PrefixUpdater.pkg.sha256
```

The last two commands print the same value when the download is intact. You can then install or update from the checked file with `pkg add -f /tmp/pfSense-pkg-Ipv6PrefixUpdater.pkg`.

## Confirm in the WebGUI

1. Sign in to the pfSense WebGUI.
2. Open **Services → IPv6 Prefix Updater** and confirm that the **Settings**, **Status**, **Fields**, **Backups**, **Cleanup**, and **About** tabs appear.
3. On the Status tab, confirm that **Current State** shows `No monitored interfaces are saved yet. Add them on the Settings tab.` After a move from the legacy updater, it lists the moved interfaces instead.
4. Leave **<Terminology title="Automatic checks on a schedule, off until you enable them" to="/docs/reference/terminology#running-checks">Enable Scheduled Updates</Terminology>** cleared, as it is by default, until you [establish the baseline](/docs/first-run). After a move from the legacy updater, it is already on, matching the old Cron schedule.

## If Installation Fails

- **Not found (404)**: the latest release has no package file. [Check the Release](/docs/installation#check-the-release) explains which releases carry one.
- **Wrong architecture on pfSense CE 2.9.0**: releases through 2.0.1 were built only for FreeBSD 15, so pfSense CE 2.9.0 prints a wrong architecture message for them. Install the latest release.
- **DNS, TLS, or certificate errors**: pfSense needs to resolve `github.com`, reach it over HTTPS, and keep the correct time for certificate checks.

Continue with [Establish the Baseline](/docs/first-run) once the package appears in the WebGUI.
