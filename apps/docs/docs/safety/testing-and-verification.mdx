Check the interface, prefix, recovery path, and notifications on your firewall before you let the package run on a schedule.

## 1. Confirm the Source

With **<Terminology title="Automatic checks on a schedule, off until you enable them" to="/docs/reference/terminology#running-checks">Enable Scheduled Updates</Terminology>** cleared, save Settings and select **Run Now** once. Then check the Status tab:

- **<Terminology title="The interface whose address reveals your current prefix" to="/docs/reference/terminology#interfaces-and-detection">Monitored Interface</Terminology>** is the intended WAN or <Terminology title="An interface that builds its IPv6 from another's prefix" to="/docs/reference/terminology#interfaces-and-detection">tracked interface</Terminology>.
- **<Terminology title="The live address the prefix is read from on each run" to="/docs/reference/terminology#interfaces-and-detection">Last Successful Source Address</Terminology>** matches the address under **Status → Interfaces**.
- **<Terminology title="The stored prefix each check compares against" to="/docs/reference/terminology#baselines-and-transitions">Last Successful Prefix</Terminology>** matches the prefix your ISP delegates.
- **Outcome** under **Last Run** is <Terminology title="First look: a baseline is recorded, nothing changes" to="/docs/reference/terminology#run-outcomes">Initialized</Terminology>, and **Changed Fields** is `0`.

If any value is unexpected, it is recommended to correct it before you continue. [Interface and Prefix](/docs/configure/interface-and-prefix#changing-the-interfaces) explains what changing the interface or the length does once a <Terminology title="The recorded starting prefix that changes are measured from" to="/docs/reference/terminology#baselines-and-transitions">baseline</Terminology> exists.

## 2. Run a Preview

Select **<Terminology title="A preview of the changes that writes nothing" to="/docs/reference/terminology#running-checks">Dry Run</Terminology>**. With the prefix unchanged it reports <Terminology title="Same prefix as last time, so there is nothing to do" to="/docs/reference/terminology#run-outcomes">No change</Terminology>, and **<Terminology title="A copy of the config taken right before any write" to="/docs/reference/terminology#backups-and-service-reloads">Configuration Backup Created</Terminology>** shows No.

A <Terminology title="A preview of the changes that writes nothing" to="/docs/reference/terminology#running-checks">dry run</Terminology> can't simulate a prefix change, so it lists planned fields only after a real <Terminology title="Your prefix changed, so the package goes to work" to="/docs/reference/terminology#baselines-and-transitions">prefix transition</Terminology>.

## 3. Check Recovery

Open **Diagnostics → Backup & Restore → Config History** and confirm that pfSense keeps configuration history. A run that writes saves its <Terminology title="A copy of the config taken right before any write" to="/docs/reference/terminology#backups-and-service-reloads">configuration backup</Terminology> there before the first change.

It is recommended to read [Find the Right Revision](/docs/operate/backups-and-recovery#find-the-right-revision) now, because the revision named after the package holds the updated configuration. An off-device backup is also worth downloading, because <Terminology title="pfSense's saved config revisions you can restore" to="/docs/reference/terminology#backups-and-service-reloads">Config History</Terminology> lives on the firewall.

## 4. Test Notifications

If **<Terminology title="The alert sent after your addresses were updated" to="/docs/reference/terminology#notifications-and-logs">Send Change Notifications</Terminology>** is selected, it is recommended to send a test with pfSense's own buttons under **System → Advanced → Notifications**. The package uses the <Terminology title="pfSense's email and other remote alert services" to="/docs/reference/terminology#notifications-and-logs">notification channels</Terminology> already set up there.

<Terminology title="Prefix changed, but no approved field used the old one" to="/docs/reference/terminology#run-outcomes">Warning</Terminology> and <Terminology title="The run stopped at a check or safety stage" to="/docs/reference/terminology#run-outcomes">Failure</Terminology> notices stay in the WebGUI and don't use those channels.

## 5. Turn On the Schedule

Select **<Terminology title="Automatic checks on a schedule, off until you enable them" to="/docs/reference/terminology#running-checks">Enable Scheduled Updates</Terminology>** once the steps above show the expected address and prefix. **Hourly** is the default **Schedule**.

After the first scheduled time, it is recommended to check **Timestamp (UTC)** and **Outcome** under **Last Run**.

## What Needs a Real Prefix Change

The <Terminology title="Every planned rewrite, built before anything changes" to="/docs/reference/terminology#fields-and-change-plans">change plan</Terminology>, the <Terminology title="A copy of the config taken right before any write" to="/docs/reference/terminology#backups-and-service-reloads">configuration backup</Terminology>, the <Terminology title="Applies changed settings to a running service" to="/docs/reference/terminology#backups-and-service-reloads">service reloads</Terminology>, and the <Terminology title="The alert sent after your addresses were updated" to="/docs/reference/terminology#notifications-and-logs">change notification</Terminology> happen only after a real <Terminology title="Your prefix changed, so the package goes to work" to="/docs/reference/terminology#baselines-and-transitions">prefix transition</Terminology>. A lab firewall whose prefix can change is the safest place to watch a full run.

On your own firewall, it is recommended to review the first real change on the Status tab, starting with **Changed Fields**, **<Terminology title="Applies changed settings to a running service" to="/docs/reference/terminology#backups-and-service-reloads">Reloaded Services</Terminology>**, and **Summary**.

Review [Status and Actions](/docs/operate/status-and-actions) for every field shown after a run.
