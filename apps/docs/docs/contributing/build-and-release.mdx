Check, stage, and package pfSense IPv6 Prefix Updater, then publish the package to a GitHub release.

## Requirements

- **Node.js 22 or 24** — The root and workspace manifests accept `^22 || ^24`.
- **PHP or Docker** — The PHP suites use a local `php` when one exists, or the `php:8.3-cli-alpine` image through Docker. `PHP_TEST_IMAGE` overrides the image.
- **FreeBSD for packaging** — `npm run deploy` runs only on FreeBSD, with `PFSENSE_PORTS_DIR` pointing at a pfSense FreeBSD-ports checkout.

## Check, Stage, and Package

Run these commands from the repository root:

```bash
# Lint and type-check the scripts, run the PHP and Vitest suites, and validate the port.
npm run check --workspace pfsense-pkg-ipv6-prefix-updater

# Copy the port into packages/ipv6-prefix-updater/build/port with the workspace version.
npm run build --workspace pfsense-pkg-ipv6-prefix-updater

# Build the package on FreeBSD into packages/ipv6-prefix-updater/build/release.
PFSENSE_PORTS_DIR=/path/to/FreeBSD-ports npm run deploy --workspace pfsense-pkg-ipv6-prefix-updater
```

- Staging turns `port/Makefile.template` into `build/port/Makefile` and stamps it with the `version` from `packages/ipv6-prefix-updater/package.json`.
- Packaging copies the staged port to `sysutils/pfSense-pkg-Ipv6PrefixUpdater` in the ports checkout, runs `make package`, and removes that copy again. It stops if the destination already exists.
- `build/release` then holds the versioned `.pkg`, a copy named `pfSense-pkg-Ipv6PrefixUpdater.pkg`, and a `.sha256` file for each that contains only the hash.

## Release Workflow

`.github/workflows/pfsense-ipv6-prefix-updater.yml` runs when a GitHub release is published, or manually with the tag of an existing release:

1. Validates and stages the port on an Ubuntu runner.
2. Starts a FreeBSD VM whose release comes from the `PFSENSE_FREEBSD_VERSION` repository variable, or `15` when it isn't set.
3. Checks out the `devel` branch of pfSense's FreeBSD-ports repository and runs the package build.
4. Uploads `build/release` as a workflow artifact kept for 7 days and attaches the same files to the release, replacing existing assets.

It is recommended to set `PFSENSE_FREEBSD_VERSION` to the FreeBSD major of the pfSense release you target, and not to publish a package built against another major. The install guide's `pkg add` command fetches `pfSense-pkg-Ipv6PrefixUpdater.pkg` from whichever release GitHub marks as latest.

## Documentation Site

From `apps/docs`, `npm run check` runs ESLint, the translation tree check, three type checks, and the Vitest suites for `.env` files, frontmatter, links, tables, glossary links, and type declarations. `npm run build` builds every locale.

Each locale's translated docs pages live in `apps/docs/i18n/<locale>/docusaurus-plugin-content-docs/current/` and mirror the English pages, so update them when an English page changes. The interface text (homepage, navbar, footer, blog, and sidebar labels) comes from `scripts/generate-locales.mjs`, which reads `scripts/locale-copies.json` and the package translations. `npm run i18n` runs that generator first, and it leaves the translated docs pages in place.

`.github/workflows/nova-publish-project.yml` builds the site and deploys it to GitHub Pages when a release is published.
