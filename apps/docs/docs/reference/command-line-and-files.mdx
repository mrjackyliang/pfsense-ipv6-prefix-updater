Run the package command from a shell and find the files, logs, and notices it uses.

## Usage

```text
Usage: ipv6-prefix-updater [--manual] [--dry-run] [--accept-current-prefix [--interface=NAME]] [--migrate-legacy]
Update options: --check-updates, --self-update.
```

The pfSense-managed prefix-check cron entry runs the command as `root` without options, while a separate release-check entry runs it with `--check-updates`. Before each check it also moves any <Terminology title="Version 1.x: the update.php script run by Cron" to="/docs/reference/terminology#package-origins">legacy updater</Terminology> leftovers into the package. The Status tab uses `--manual` for **Run Now**, `--dry-run` for **<Terminology title="A preview of the changes that writes nothing" to="/docs/reference/terminology#running-checks">Dry Run</Terminology>**, and `--accept-current-prefix` for baseline recovery, and the Cleanup tab uses `--migrate-legacy`.

Without options, the command behaves like a scheduled check and reports <Terminology title="A scheduled check skipped because scheduled updates are off" to="/docs/reference/terminology#run-outcomes">Disabled</Terminology> when **<Terminology title="Automatic checks on a schedule, off until you enable them" to="/docs/reference/terminology#running-checks">Enable Scheduled Updates</Terminology>** is off.

## Options

| Flag                      | Description                                                                                                                                                                                                                                                                                       |
|---------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `--manual`                | Runs even while <Terminology title="Automatic checks on a schedule, off until you enable them" to="/docs/reference/terminology#running-checks">scheduled updates</Terminology> are off.                                                                                                           |
| `--dry-run`               | Previews without a backup or a write, and implies `--manual`.                                                                                                                                                                                                                                     |
| `--accept-current-prefix` | Records the active source address, prefix, and length as the baseline without scanning approved fields, creating a backup, writing configuration, or reloading services. It implies `--manual` and cannot be combined with `--dry-run`.                                                           |
| `--interface=NAME`        | Limits `--accept-current-prefix` to one monitored interface, given by its internal name such as `lan`. Without it, every monitored interface that has an address is accepted.                                                                                                                     |
| `--migrate-legacy`        | Moves the <Terminology title="Version 1.x: the update.php script run by Cron" to="/docs/reference/terminology#package-origins">legacy updater</Terminology> into the package right away and prints each step, without running a prefix check. It exits with `2` when the move reported a warning. |
| `--check-updates`         | Checks GitHub for the latest package release and saves the result in `/cf/conf/ipv6-prefix-updater/updates.json`. [Updates](/docs/reference/updates) describes the check.                                                                                                                         |
| `--self-update`           | Downloads, verifies, and installs the latest release, recording progress in `/cf/conf/ipv6-prefix-updater/update-status.json`.                                                                                                                                                                    |
| `--help`                  | Prints the usage line and the update options line, and exits with `0`. Neither line lists `--help` itself.                                                                                                                                                                                        |

Any other option prints `Unknown option: <option>` to standard error and exits with `64`. Combining `--accept-current-prefix` with `--dry-run` also exits with `64`, as does combining `--check-updates` or `--self-update` with each other or with any prefix option.

## Output

A completed run that monitors one interface prints nine lines to standard output, followed by the field changes after a <Terminology title="A preview of the changes that writes nothing" to="/docs/reference/terminology#running-checks">dry run</Terminology> or a <Terminology title="Prefix changed and every approved field was updated" to="/docs/reference/terminology#run-outcomes">Success</Terminology>:

```text
Status: Success
Interface: lan
Observed source address: 2001:db8:abcd:88aa::1
Previous prefix: 2001:db8:abcd:7800::
Current prefix: 2001:db8:abcd:8800::/56
Planned or changed fields: 1
Configuration backup: Created
Reloaded services: Firewall filter
Summary: Updated 1 approved field from 2001:db8:abcd:7800::/56 to 2001:db8:abcd:8800::/56 on interface lan.
Field changes:
- aliases/alias/0/address: 2001:db8:abcd:78aa::10 → 2001:db8:abcd:88aa::10
```

- `Previous prefix` has no length, and it shows `Not available` after <Terminology title="First look: a baseline is recorded, nothing changes" to="/docs/reference/terminology#run-outcomes">Initialized</Terminology> or <Terminology title="A dry run showing the baseline it would record" to="/docs/reference/terminology#run-outcomes">Initialization preview</Terminology>.
- `Reloaded services` lists the Status labels or `None`. After a <Terminology title="A preview of the changes that writes nothing" to="/docs/reference/terminology#running-checks">dry run</Terminology>, it lists the services that would reload.
- `Field changes` has one line per replaced address, written as `- <path>: <old> → <new>`, for up to 200 fields.
- When the run applied another package's settings again or skipped a ticked field that no longer exists, one line for each follows, worded as on the Status tab.
- When another check holds the <Terminology title="Keeps two checks from ever running at once" to="/docs/reference/terminology#running-checks">run lock</Terminology>, the only output is `Another run owns the package lock; this invocation exited without reading configuration.`
- With several monitored interfaces, the output starts with the overall `Status`, `Summary`, package, and skipped-field lines, followed by each interface's lines, separated by blank lines.
- When a <Terminology title="Version 1.x: the update.php script run by Cron" to="/docs/reference/terminology#package-origins">legacy updater</Terminology> move happened before the check, its steps are printed first.
- Labels and messages follow the pfSense language setting.

## Package State Format

| Key                   | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
|-----------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `schema_version`      | Always `1`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `targets.<interface>` | One <Terminology title="The recorded starting prefix that changes are measured from" to="/docs/reference/terminology#baselines-and-transitions">baseline</Terminology> per monitored interface, keyed by its internal name, with `interface`, `source_address`, `prefix`, `prefix_length`, and `updated_at`. A baseline taken from the <Terminology title="Version 1.x: the update.php script run by Cron" to="/docs/reference/terminology#package-origins">legacy updater</Terminology> also has `source` set to `legacy_cache`. |
| `last_run`            | The latest recorded run, with `status`, `timestamp`, `interface`, `observed_address`, `previous_prefix`, `current_prefix`, `current_prefix_length`, `change_count`, `backup_created`, `services`, `message`, `message_key`, and `message_arguments`.                                                                                                                                                                                                                                                                              |
| `legacy_migration`    | Present after a <Terminology title="Version 1.x: the update.php script run by Cron" to="/docs/reference/terminology#package-origins">legacy updater</Terminology> move, with `status`, `steps`, `warnings`, and `recorded_at`. The Cleanup tab shows it.                                                                                                                                                                                                                                                                          |

- `status` is one of `initialized`, `initialization_preview`, `no_change`, `dry_run`, `warning`, `accepted`, `success`, or `failure`.
- After a <Terminology title="Prefix changed and every approved field was updated" to="/docs/reference/terminology#run-outcomes">Success</Terminology>, `last_run.notification` is `disabled` when notifications are off, or `sent` or `failed` after a delivery attempt.
- After a <Terminology title="A preview of the changes that writes nothing" to="/docs/reference/terminology#running-checks">dry run</Terminology> or a <Terminology title="Prefix changed and every approved field was updated" to="/docs/reference/terminology#run-outcomes">Success</Terminology>, each result also has `changes`, listing the `path` and `replacements` of up to 200 fields, where each replacement is an old and a new address.
- `package_reapply` lists the `section`, `package`, `status`, and `error` of each package whose settings the run applied again, and `skipped_fields` lists ticked fields that no longer exist. Each appears only when it isn't empty.
- With several monitored interfaces, `last_run` holds the totals and a `targets` list with one result per interface.
- Timestamps use ISO 8601 in UTC. A file that can't be parsed, or that has another schema version, stops each run with `IPv6 Prefix Updater state is invalid or unsupported.`

## Settings Storage

Settings live in the pfSense configuration at `installedpackages/ipv6prefixupdater/config/0`.

| Key                           | Description                                                                                                                                                                                    |
|-------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `enabled`                     | **<Terminology title="Automatic checks on a schedule, off until you enable them" to="/docs/reference/terminology#running-checks">Enable Scheduled Updates</Terminology>**, `on` when selected. |
| `row`                         | **Monitored Interfaces**, a list with one `interface` (an interface key such as `lan`) and one `prefix_length` (`48` through `64`) per row.                                                    |
| `update_frequency`            | **Schedule**, one of `every_fifteen_minutes`, `hourly`, `every_six_hours`, or `daily`.                                                                                                         |
| `notifications`               | **<Terminology title="The alert sent after your addresses were updated" to="/docs/reference/terminology#notifications-and-logs">Send Change Notifications</Terminology>**, `on` when selected. |
| `update_check_frequency`      | **Update Checks**, one of `daily`, `weekly`, `monthly`, or `never`.                                                                                                                            |
| `update_remote_notifications` | **Remote Notifications**, `on` when selected.                                                                                                                                                  |

The stable release-check schedule lives beside the settings record at `installedpackages/ipv6prefixupdater/update_schedule`, with `minute` from 0 through 59, `hour` from 0 through 23, `weekday` from 0 through 6, and `monthday` from 1 through 28. A missing, malformed, or out-of-range value is generated again and saved.

### Field Selection

The choices on the Fields tab live beside the settings record at `installedpackages/ipv6prefixupdater/fields`, so saving the Settings tab, which replaces `config/0`, never clears them.

| Key                    | Description                                                                                                    |
|------------------------|----------------------------------------------------------------------------------------------------------------|
| `schema`               | Always `1`. It marks a selection saved from the Fields tab, even an empty one.                                 |
| `enabled_groups/item`  | Groups that are on, such as `firewall_rules`, `dhcpv6`, or `package:<section>` for another package's settings. |
| `disabled_groups/item` | pfSense groups that are off. A pfSense group in neither list is on, and another package's group is off.        |
| `include/item`         | Identities of fields ticked in a group that is off.                                                            |
| `exclude/item`         | Identities of fields unticked in a group that is on.                                                           |

- The pfSense group keys are `interfaces`, `virtual_ips`, `aliases`, `firewall_rules`, `nat`, `dhcpv6`, `router_advertisements`, `dns_host_overrides`, `ipsec`, `openvpn`, and `wireguard`.
- `include` and `exclude` keep at most 1,000 identities each, and every identity follows [Field Identities](/docs/reference/approved-fields#field-identities).

## Cron Entry

Saving Settings removes any existing entry for the command and, when `enabled` is `on`, installs a new one for `root` with pfSense's `install_cron_job()`.

| Schedule value          | Cron fields    |
|-------------------------|----------------|
| `every_fifteen_minutes` | `*/15 * * * *` |
| `hourly`                | `0 * * * *`    |
| `every_six_hours`       | `0 */6 * * *`  |
| `daily`                 | `0 0 * * *`    |

An unknown value falls back to the hourly fields. While a <Terminology title="Version 1.x: the update.php script run by Cron" to="/docs/reference/terminology#package-origins">legacy updater</Terminology> move waits for the legacy script to finish, the package keeps a `*/15 * * * *` entry so the move is retried even if scheduled updates are off.

A second entry runs `/usr/local/sbin/ipv6-prefix-updater --check-updates` as `root` on the **Update Checks** frequency, at a stable randomized minute, hour, weekday, and day of the month. Saving Settings replaces it, and `never` removes it.

## Logs and Notices

Every <Terminology title="pfSense's general log, where every run leaves lines" to="/docs/reference/terminology#notifications-and-logs">system log</Terminology> line is written with pfSense's `log_error()` and starts with `IPv6 Prefix Updater:`. Notices are created with `file_notice()`. Run notices link to `/ipv6-prefix-updater-status.php`, the migration notice links to `/ipv6-prefix-updater-cleanup.php`, and the update-available notice links to `/ipv6-prefix-updater-about.php`.

| Notice ID                               | Created when                                                                                                                                                                                                               | Delivery                                                                                                                                                                                                                                  |
|-----------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `ipv6-prefix-updater-success`           | <Terminology title="Prefix changed and every approved field was updated" to="/docs/reference/terminology#run-outcomes">Success</Terminology> with `notifications` set to `on`                                              | WebGUI and <Terminology title="pfSense's email and other remote alert services" to="/docs/reference/terminology#notifications-and-logs">notification channels</Terminology>                                                               |
| `ipv6-prefix-updater-no-matches`        | <Terminology title="Prefix changed, but no approved field used the old one" to="/docs/reference/terminology#run-outcomes">Warning</Terminology>                                                                            | WebGUI only                                                                                                                                                                                                                               |
| `ipv6-prefix-updater-failure`           | <Terminology title="The run stopped at a check or safety stage" to="/docs/reference/terminology#run-outcomes">Failure</Terminology>                                                                                        | WebGUI only                                                                                                                                                                                                                               |
| `ipv6-prefix-updater-package-<section>` | A run changed another package's settings, and no installed package owns the section or applying its settings again failed                                                                                                  | WebGUI only                                                                                                                                                                                                                               |
| `ipv6-prefix-updater-legacy-migration`  | A <Terminology title="Version 1.x: the update.php script run by Cron" to="/docs/reference/terminology#package-origins">legacy updater</Terminology> move that took at least one step, or a move that failed during install | WebGUI only                                                                                                                                                                                                                               |
| `ipv6-prefix-updater-update-available`  | A release check finds a newer version that hasn't been announced yet                                                                                                                                                       | WebGUI only, or WebGUI and the <Terminology title="pfSense's email and other remote alert services" to="/docs/reference/terminology#notifications-and-logs">notification channels</Terminology> when **Remote Notifications** is selected |

If the command's own environment check fails, or its lock file can't be opened, the reason goes to standard error only. Each run that writes also saves a configuration revision described as `IPv6 Prefix Updater changed <count> approved field(s) for interface <interface>`.

## Page Privileges

Each package page declares its own pfSense privilege, so access can be granted per page:

- **Status**: `page-services-ipv6-prefix-updater-status`, named `Services: IPv6 Prefix Updater: Status`.
- **Fields**: `page-services-ipv6-prefix-updater-fields`, named `Services: IPv6 Prefix Updater: Fields`. It can change which fields a run rewrites, so it is recommended to grant it only to administrators.
- **Backups**: `page-services-ipv6-prefix-updater-backups`, named `Services: IPv6 Prefix Updater: Backups`. It allows downloading full configuration copies, so it is recommended to grant it only to administrators.
- **Cleanup**: `page-services-ipv6-prefix-updater-cleanup`, named `Services: IPv6 Prefix Updater: Cleanup`.
- **About**: `page-services-ipv6-prefix-updater-about`, named `Services: IPv6 Prefix Updater: About`.
