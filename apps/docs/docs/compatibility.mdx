Check that your firewall, interface, and ISP delegation meet the package's requirements before you rely on <Terminology title="Automatic checks on a schedule, off until you enable them" to="/docs/reference/terminology#running-checks">scheduled updates</Terminology>.

## Supported Releases

- The package was tested on pfSense CE 2.9.1, 2.9.0 and 2.8.1 and pfSense Plus 26.07.1, 26.07 and 26.03.1. The About tab lists the releases each version was tested on and marks the matching one as **This firewall**.
- The package doesn't check the pfSense version. Each run checks that it is running on pfSense with the files and functions it uses, and stops before reading settings when they are missing.
- The package code needs PHP 8.1 or later.
- Release packages are marked for any FreeBSD version (`FreeBSD:*`) and as vital, so one package installs on every supported pfSense release and pfSense upgrades keep it installed.

## Address Requirements

- Each <Terminology title="The interface whose address reveals your current prefix" to="/docs/reference/terminology#interfaces-and-detection">Monitored Interface</Terminology> needs an active <Terminology title="A public IPv6 address in 2000::/3, the only kind used" to="/docs/reference/terminology#addresses-and-prefixes">global unicast address</Terminology>. The package never falls back to a <Terminology title="An fe80 address that is never used as a source" to="/docs/reference/terminology#addresses-and-prefixes">link-local address</Terminology>.
- Unique local (`fc00::/7`), multicast, loopback, unspecified, IPv4-mapped, and zone-qualified addresses can't be the <Terminology title="The live address the prefix is read from on each run" to="/docs/reference/terminology#interfaces-and-detection">source address</Terminology>.
- The <Terminology title="How big your ISP's prefix is, like /56; you set it" to="/docs/reference/terminology#addresses-and-prefixes">Delegated Prefix Length</Terminology> has to be from `/48` through `/64`. Lengths that end inside a hexadecimal digit, such as `/57`, work too.

When an address doesn't qualify, that interface ends in <Terminology title="The run stopped at a check or safety stage" to="/docs/reference/terminology#run-outcomes">Failure</Terminology> with a reason such as `Interface "lan" has no active global IPv6 address.` [Troubleshooting](/docs/operate/troubleshooting#run-failed) lists the messages.

## When WAN Has No Global Address

Some ISPs delegate a prefix without giving WAN a <Terminology title="A public IPv6 address in 2000::/3, the only kind used" to="/docs/reference/terminology#addresses-and-prefixes">global address</Terminology> of its own. A <Terminology title="An interface that builds its IPv6 from another's prefix" to="/docs/reference/terminology#interfaces-and-detection">tracked interface</Terminology> such as LAN then carries an address from the <Terminology title="The IPv6 network your ISP hands you, which can change" to="/docs/reference/terminology#addresses-and-prefixes">delegated prefix</Terminology> and is the one to monitor.

**Status → Interfaces** shows which interfaces have a <Terminology title="A public IPv6 address in 2000::/3, the only kind used" to="/docs/reference/terminology#addresses-and-prefixes">global address</Terminology>.

## What the Package Recognizes

The package updates literal IPv6 addresses and networks in <Terminology title="A setting the package is allowed to rewrite" to="/docs/reference/terminology#fields-and-change-plans">approved fields</Terminology>. Host names, URLs, IPv4 values, and other text stay as they are.

Addresses that pfSense generates, such as those on <Terminology title="An interface that builds its IPv6 from another's prefix" to="/docs/reference/terminology#interfaces-and-detection">tracked interfaces</Terminology>, are never changed. Addresses that describe other devices, such as remote VPN networks and WireGuard peers, change only when you tick them under [Other Settings](/docs/configure/configuration-scopes#other-settings).

## Optional Dependencies

- **WireGuard package**: needed only when <Terminology title="The address on a WireGuard tunnel interface" to="/docs/reference/terminology#pfsense-features">WireGuard tunnel addresses</Terminology> have to change. Without it, a real run with WireGuard changes stops before the backup.

## Known Limits

- Adding a <Terminology title="The interface whose address reveals your current prefix" to="/docs/reference/terminology#interfaces-and-detection">Monitored Interface</Terminology>, or switching a row to a different one, records a new <Terminology title="The recorded starting prefix that changes are measured from" to="/docs/reference/terminology#baselines-and-transitions">baseline</Terminology> for it, and changing a row's <Terminology title="How big your ISP's prefix is, like /56; you set it" to="/docs/reference/terminology#addresses-and-prefixes">Delegated Prefix Length</Terminology> counts as a <Terminology title="Your prefix changed, so the package goes to work" to="/docs/reference/terminology#baselines-and-transitions">prefix transition</Terminology>.
- A <Terminology title="A preview of the changes that writes nothing" to="/docs/reference/terminology#running-checks">dry run</Terminology> can't simulate a prefix change, so planned changes appear only after a real one.
- High-availability (CARP) pairs get no special handling.
- As an <Terminology title="Installed from GitHub, not Netgate's package repository" to="/docs/reference/terminology#package-origins">unofficial package</Terminology>, newer releases are installed with `pkg`, as described in [Update or Remove](/docs/reference/package-lifecycle).

Review [Interface and Prefix](/docs/configure/interface-and-prefix) for choosing the source and [Fields](/docs/configure/configuration-scopes) for the fields the package can change.
