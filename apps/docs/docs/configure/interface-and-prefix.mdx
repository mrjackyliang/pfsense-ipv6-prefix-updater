Choose the interfaces that reveal your current prefixes and enter the <Terminology title="The /56 or /64 that says how many bits name the network" to="/docs/reference/terminology#addresses-and-prefixes">prefix length</Terminology> your ISP delegates for each.

## Choose the Monitored Interfaces

Add a **Monitored Interfaces** row for each interface whose <Terminology title="A public IPv6 address in 2000::/3, the only kind used" to="/docs/reference/terminology#addresses-and-prefixes">global address</Terminology> comes from the <Terminology title="The IPv6 network your ISP hands you, which can change" to="/docs/reference/terminology#addresses-and-prefixes">delegated prefix</Terminology>. The package reads each address fresh on every run and never falls back to a <Terminology title="An fe80 address that is never used as a source" to="/docs/reference/terminology#addresses-and-prefixes">link-local address</Terminology>.

If WAN receives only a <Terminology title="The IPv6 network your ISP hands you, which can change" to="/docs/reference/terminology#addresses-and-prefixes">delegated prefix</Terminology>, a <Terminology title="An interface that builds its IPv6 from another's prefix" to="/docs/reference/terminology#interfaces-and-detection">tracked interface</Terminology> such as LAN usually holds a <Terminology title="A public IPv6 address in 2000::/3, the only kind used" to="/docs/reference/terminology#addresses-and-prefixes">global address</Terminology> from it and is the right choice.

<img src={monitoredInterfaces} alt="IPv6 Prefix Updater Settings tab with two Monitored Interfaces rows, LAN and LAB, each set to a /56 delegated prefix length, and a pointer to the Fields tab" width={1024} height={768} style={{maxWidth: '100%', height: 'auto'}} />

- **Add**: adds a row. Each interface can appear in only one row, and saving with no rows is rejected.
- **Delete**: removes a row. pfSense hides it while only one row is left.
- **One run for all rows**: every scheduled check reads all monitored interfaces and commits their changes in one backed-up write.

Most firewalls need one row. Add more when several interfaces receive their own delegated prefix, such as on two WAN connections, or when you want each LAN segment's address checked.

To confirm the choice:

1. Save Settings with **<Terminology title="Automatic checks on a schedule, off until you enable them" to="/docs/reference/terminology#running-checks">Enable Scheduled Updates</Terminology>** cleared.
2. On the Status tab, select **Run Now**.
3. Compare **<Terminology title="The live address the prefix is read from on each run" to="/docs/reference/terminology#interfaces-and-detection">Observed Source Address</Terminology>** with the address under **Status → Interfaces**.
4. If the address belongs to the wrong network, select another interface and repeat.

Status shows each interface's description followed by pfSense's internal name, such as `LAN (lan)`.

## Enter the Delegated Prefix Length

Select the length from your ISP's service details or the DHCPv6 prefix delegation size on the WAN interface. **<Terminology title="How big your ISP's prefix is, like /56; you set it" to="/docs/reference/terminology#addresses-and-prefixes">Delegated Prefix Length</Terminology>** accepts `/48` through `/64`, starts at `/56`, and is never detected for you.

:::tip

It is recommended to confirm the length before the first **Run Now**, because the <Terminology title="The recorded starting prefix that changes are measured from" to="/docs/reference/terminology#baselines-and-transitions">baseline</Terminology> stores the length along with the prefix.

:::

## Check the Calculated Network

After a run, **<Terminology title="The prefix seen right now, compared with the last one" to="/docs/reference/terminology#interfaces-and-detection">Observed Prefix</Terminology>** shows the calculated network. Lengths that end inside a hexadecimal digit, such as `/57` or `/63`, work the same way because the package masks addresses bit by bit.

For a `/56` delegation that changes from `2001:db8:abcd:7800::/56` to `2001:db8:abcd:8800::/56`:

```text
Source address:    2001:db8:abcd:88aa::1
Current prefix:    2001:db8:abcd:8800::/56
Previous address:  2001:db8:abcd:78aa::42
Updated address:   2001:db8:abcd:88aa::42
```

Only the first 56 bits change, and the <Terminology title="The bits after the prefix, always copied unchanged" to="/docs/reference/terminology#addresses-and-prefixes">host portion</Terminology> `aa::42` stays the same. Addresses under `2001:db8::/32` in these guides are documentation examples.

## Changing the Interfaces

:::warning

Adding a <Terminology title="The interface whose address reveals your current prefix" to="/docs/reference/terminology#interfaces-and-detection">Monitored Interface</Terminology>, or switching a row to a different one, makes the next run record a new <Terminology title="The recorded starting prefix that changes are measured from" to="/docs/reference/terminology#baselines-and-transitions">baseline</Terminology> for it without changing the configuration. If its prefix had changed and the package hadn't applied it yet, that change is skipped.

:::

Deleting a row keeps that interface's <Terminology title="The recorded starting prefix that changes are measured from" to="/docs/reference/terminology#baselines-and-transitions">baseline</Terminology> in the <Terminology title="The file holding each baseline, kept across reinstalls" to="/docs/reference/terminology#running-checks">package state</Terminology>. Adding the interface back later compares against that saved baseline instead of recording a new one.

## Changing the Prefix Length

Changing **<Terminology title="How big your ISP's prefix is, like /56; you set it" to="/docs/reference/terminology#addresses-and-prefixes">Delegated Prefix Length</Terminology>** after the <Terminology title="The recorded starting prefix that changes are measured from" to="/docs/reference/terminology#baselines-and-transitions">baseline</Terminology> exists counts as a <Terminology title="Your prefix changed, so the package goes to work" to="/docs/reference/terminology#baselines-and-transitions">prefix transition</Terminology>, even when the network itself stays the same. The package matches addresses with the length stored in the <Terminology title="The recorded starting prefix that changes are measured from" to="/docs/reference/terminology#baselines-and-transitions">baseline</Terminology> and replaces bits with the new length.

:::danger

Narrowing the length overwrites the subnet bits of every matching address. With the <Terminology title="The live address the prefix is read from on each run" to="/docs/reference/terminology#interfaces-and-detection">source address</Terminology> `2001:db8:1234:ab00::1` and a `/56` <Terminology title="The recorded starting prefix that changes are measured from" to="/docs/reference/terminology#baselines-and-transitions">baseline</Terminology>, changing to `/64` turns `2001:db8:1234:abcc::42` into `2001:db8:1234:ab00::42`.

:::

Widening the length, for example from `/64` to `/56`, can leave the run with nothing to change. It then reports <Terminology title="Prefix changed, but no approved field used the old one" to="/docs/reference/terminology#run-outcomes">Warning</Terminology> on every run until the prefix itself changes or you verify the saved addresses and [accept the current prefix](/docs/operate/backups-and-recovery#after-a-failed-run) as the new baseline.

Before changing the length, it is recommended to clear **<Terminology title="Automatic checks on a schedule, off until you enable them" to="/docs/reference/terminology#running-checks">Enable Scheduled Updates</Terminology>** in the same save. A **<Terminology title="A preview of the changes that writes nothing" to="/docs/reference/terminology#running-checks">Dry Run</Terminology>** then shows the planned field count, each planned change under `Field changes`, and the **Summary** before you select **Run Now**.
