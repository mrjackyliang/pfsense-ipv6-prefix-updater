A ninth outcome, <Terminology title="outcome: scheduled check skipped while updates are off" to="/docs/reference/terminology#disabled">Disabled</Terminology>, appears only when the package command runs from a shell without options while <Terminology title="automatic checks run from a pfSense-managed cron entry" to="/docs/reference/terminology#scheduled-updates">scheduled updates</Terminology> are off. It isn't recorded, so the Status tab never shows it.

## Current State Versus Last Run

**Current State** changes only on <Terminology title="outcome: baseline recorded, configuration unchanged" to="/docs/reference/terminology#initialized">Initialized</Terminology>, **Accepted**, and <Terminology title="outcome: fields updated, saved, reloaded, and verified" to="/docs/reference/terminology#success">Success</Terminology>. A failed attempt never becomes the next comparison point unless an operator later verifies the saved values and explicitly accepts the active prefix; **Last Run** records the latest run of every outcome in the table.

**Last Run** stays as it was when another check holds the <Terminology title="guard that stops two checks running at once" to="/docs/reference/terminology#run-lock">run lock</Terminology> or when a run stops before reading its <Terminology title="package file holding the baseline and last run" to="/docs/reference/terminology#package-state">package state</Terminology>, such as when no monitored interface has a <Terminology title="public IPv6 address inside 2000::/3" to="/docs/reference/terminology#global-unicast-address">global address</Terminology>. Those runs leave their reason in the <Terminology title="read-only results shown after Run Now or Dry Run" to="/docs/reference/terminology#command-output">Command Output</Terminology> and the <Terminology title="pfSense general log the package writes to" to="/docs/reference/terminology#system-log">system log</Terminology>.

## Warning: No Matching Fields

A <Terminology title="outcome: prefix changed, but no approved field matched" to="/docs/reference/terminology#warning">Warning</Terminology> means the prefix changed, but none of the <Terminology title="exact configuration field the package may rewrite" to="/docs/reference/terminology#approved-field">approved fields</Terminology> belonged to the old prefix. Nothing is written and the <Terminology title="starting prefix recorded without changing configuration" to="/docs/reference/terminology#baseline">baseline</Terminology> stays on the old prefix, so the next run checks the same <Terminology title="change from the last successful prefix or length" to="/docs/reference/terminology#prefix-transition">prefix transition</Terminology> again.

Each <Terminology title="outcome: prefix changed, but no approved field matched" to="/docs/reference/terminology#warning">Warning</Terminology> adds a <Terminology title="alert shown in the pfSense notices list" to="/docs/reference/terminology#webgui-notice">WebGUI notice</Terminology>, including one from a <Terminology title="preview that never backs up or writes" to="/docs/reference/terminology#dry-run">dry run</Terminology>. A cause that isn't fixed adds a new notice on every scheduled run.

Common causes:

- The <Terminology title="group of fields with one switch on the Fields tab" to="/docs/reference/terminology#field-group">field group</Terminology> that holds the addresses is off, or the fields are unticked.
- The addresses were already changed outside the package.
- The addresses are in [Other Settings](/docs/configure/configuration-scopes#other-settings), which stays off until you tick them.
- An earlier <Terminology title="outcome: a check or safety stage stopped the run" to="/docs/reference/terminology#failure">Failure</Terminology> saved the new values but kept the old <Terminology title="starting prefix recorded without changing configuration" to="/docs/reference/terminology#baseline">baseline</Terminology>.
- The <Terminology title="setting for the ISP prefix size, /48 to /64" to="/docs/reference/terminology#delegated-prefix-length">Delegated Prefix Length</Terminology> was [widened](/docs/configure/interface-and-prefix#changing-the-prefix-length) without a prefix change.

[Troubleshooting](/docs/operate/troubleshooting#warning-on-every-run) covers each cause.

If the addresses were already changed correctly, use **Status → Actions → Baseline Recovery → Accept Current Prefix** after verifying the saved addresses and affected services. This records an **Accepted** outcome without scanning approved fields or changing firewall configuration; do not use it when approved fields still contain the old prefix.

## Failures After the Save

A <Terminology title="outcome: a check or safety stage stopped the run" to="/docs/reference/terminology#failure">Failure</Terminology> during the value checks or <Terminology title="pfSense action that applies changed settings" to="/docs/reference/terminology#service-reload">service reloads</Terminology> that follow the save leaves the new values saved. Nothing is rolled back automatically, and the <Terminology title="starting prefix recorded without changing configuration" to="/docs/reference/terminology#baseline">baseline</Terminology> stays on the old prefix.

**<Terminology title="copy of the configuration saved before a write" to="/docs/reference/terminology#configuration-backup">Configuration Backup Created</Terminology>** shows Yes for these runs. [Backups and Recovery](/docs/operate/backups-and-recovery#after-a-failed-run) explains how to restore and retry or keep verified saved values with **Accept Current Prefix**.

## Notification Failures

If a <Terminology title="alert sent after a verified successful update" to="/docs/reference/terminology#change-notification">change notification</Terminology> can't be sent, the outcome is still <Terminology title="outcome: fields updated, saved, reloaded, and verified" to="/docs/reference/terminology#success">Success</Terminology> and the <Terminology title="starting prefix recorded without changing configuration" to="/docs/reference/terminology#baseline">baseline</Terminology> still moves to the new prefix. The Status tab doesn't show delivery status, and the <Terminology title="pfSense general log the package writes to" to="/docs/reference/terminology#system-log">system log</Terminology> records `Configuration succeeded, but the change notification failed.`

Review [Status and Actions](/docs/operate/status-and-actions) for the fields behind each outcome and [How Updates Work](/docs/safety/how-updates-work) for the order of the stages.
