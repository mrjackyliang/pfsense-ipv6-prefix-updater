Find the cause of an unexpected result from the outcome, the <Terminology title="The latest run's lines, shown right after you start it" to="/docs/reference/terminology#running-checks">Command Output</Terminology>, the <Terminology title="pfSense's general log, where every run leaves lines" to="/docs/reference/terminology#notifications-and-logs">system log</Terminology>, and pfSense's notices.

## Where to Look

- **Last Run** on the Status tab shows most outcomes.
- **<Terminology title="The latest run's lines, shown right after you start it" to="/docs/reference/terminology#running-checks">Command Output</Terminology>** appears after Run Now, <Terminology title="A preview of the changes that writes nothing" to="/docs/reference/terminology#running-checks">Dry Run</Terminology>, or **Accept Current Prefix**. It also shows actions that never reach **Last Run**.
- The <Terminology title="pfSense's general log, where every run leaves lines" to="/docs/reference/terminology#notifications-and-logs">system log</Terminology> under **Status → System Logs → System → General** holds the package's lines, each starting with `IPv6 Prefix Updater:`.
- **<Terminology title="An alert in pfSense's own notices list" to="/docs/reference/terminology#notifications-and-logs">WebGUI notices</Terminology>** appear for <Terminology title="Prefix changed, but no approved field used the old one" to="/docs/reference/terminology#run-outcomes">Warning</Terminology> and <Terminology title="The run stopped at a check or safety stage" to="/docs/reference/terminology#run-outcomes">Failure</Terminology> outcomes and link to the Status tab.

## Installation Fails

- **`pkg` reports 404 Not Found**: the latest GitHub release has no package file. [Install the Package](/docs/installation#check-the-release) explains which releases contain one.
- **`pkg` reports a wrong architecture or ABI mismatch**: releases through 2.0.1 were built only for FreeBSD 15. Install the latest release, which installs on any FreeBSD version.
- **DNS, TLS, or certificate errors**: pfSense needs to resolve `github.com`, reach it over HTTPS, and keep the correct time for certificate checks.

## Wrong Source Address

When WAN receives only a <Terminology title="The IPv6 network your ISP hands you, which can change" to="/docs/reference/terminology#addresses-and-prefixes">delegated prefix</Terminology>, the address that carries it sits on a <Terminology title="An interface that builds its IPv6 from another's prefix" to="/docs/reference/terminology#interfaces-and-detection">tracked interface</Terminology> such as LAN. That interface is then the right <Terminology title="The interface whose address reveals your current prefix" to="/docs/reference/terminology#interfaces-and-detection">Monitored Interface</Terminology>.

The <Terminology title="How big your ISP's prefix is, like /56; you set it" to="/docs/reference/terminology#addresses-and-prefixes">Delegated Prefix Length</Terminology> doesn't change which address is read, so changing it won't fix a wrong <Terminology title="The live address the prefix is read from on each run" to="/docs/reference/terminology#interfaces-and-detection">source address</Terminology>. It is recommended to compare **<Terminology title="The live address the prefix is read from on each run" to="/docs/reference/terminology#interfaces-and-detection">Observed Source Address</Terminology>** with **Status → Interfaces** after each change.

## Wrong Observed Prefix

Compare the <Terminology title="How big your ISP's prefix is, like /56; you set it" to="/docs/reference/terminology#addresses-and-prefixes">Delegated Prefix Length</Terminology> with your ISP's service details or the DHCPv6 prefix delegation size on WAN. For lengths such as `/57` or `/63`, an IPv6 subnet calculator makes the comparison easier.

:::warning

Changing the length after the <Terminology title="The recorded starting prefix that changes are measured from" to="/docs/reference/terminology#baselines-and-transitions">baseline</Terminology> exists counts as a <Terminology title="Your prefix changed, so the package goes to work" to="/docs/reference/terminology#baselines-and-transitions">prefix transition</Terminology> and can rewrite fields. [Changing the Prefix Length](/docs/configure/interface-and-prefix#changing-the-prefix-length) describes what happens.

:::

## Warning on Every Run

The **Summary** of a <Terminology title="Prefix changed, but no approved field used the old one" to="/docs/reference/terminology#run-outcomes">Warning</Terminology> names both prefixes, for example `Prefix changed from 2001:db8:abcd:7800::/56 to 2001:db8:abcd:8800::/56, but no approved fields matched the previous prefix.` The <Terminology title="The recorded starting prefix that changes are measured from" to="/docs/reference/terminology#baselines-and-transitions">baseline</Terminology> doesn't move, so the next run retries the same <Terminology title="Your prefix changed, so the package goes to work" to="/docs/reference/terminology#baselines-and-transitions">prefix transition</Terminology> once the cause is fixed.

Check these causes:

- The old prefix in the message is the network your addresses still use.
- The <Terminology title="One switch for a whole kind of setting" to="/docs/reference/terminology#fields-and-change-plans">field group</Terminology> that holds the addresses is on, or the fields are ticked, on the Fields tab.
- The values are literal IPv6 addresses or networks in <Terminology title="A setting the package is allowed to rewrite" to="/docs/reference/terminology#fields-and-change-plans">approved fields</Terminology>, including any you ticked under [Other Settings](/docs/configure/configuration-scopes#other-settings).
- Nobody changed the addresses already, by hand or with the <Terminology title="Version 1.x: the update.php script run by Cron" to="/docs/reference/terminology#package-origins">legacy updater</Terminology>.
- An earlier <Terminology title="The run stopped at a check or safety stage" to="/docs/reference/terminology#run-outcomes">Failure</Terminology> didn't already save the new values, as described in [Backups and Recovery](/docs/operate/backups-and-recovery#after-a-failed-run).
- The <Terminology title="How big your ISP's prefix is, like /56; you set it" to="/docs/reference/terminology#addresses-and-prefixes">Delegated Prefix Length</Terminology> wasn't widened, as described in [Interface and Prefix](/docs/configure/interface-and-prefix#changing-the-prefix-length).

If the saved addresses still use the old prefix, fix the cause and run the check again. If the saved addresses already use the active prefix, verify every affected address and service, then select **Status → Actions → Baseline Recovery → Accept Current Prefix** to make it the new <Terminology title="The recorded starting prefix that changes are measured from" to="/docs/reference/terminology#baselines-and-transitions">baseline</Terminology>.

:::warning

**Accept Current Prefix** does not inspect the saved addresses, write configuration, or reload services. Do not use it when any approved field still needs to be updated from the old prefix.

:::

## Run Failed

Each failure gives its reason after `Run failed:` in **Summary**, the <Terminology title="An alert in pfSense's own notices list" to="/docs/reference/terminology#notifications-and-logs">WebGUI notice</Terminology>, and the <Terminology title="pfSense's general log, where every run leaves lines" to="/docs/reference/terminology#notifications-and-logs">system log</Terminology>. In <Terminology title="The latest run's lines, shown right after you start it" to="/docs/reference/terminology#running-checks">Command Output</Terminology>, the reason follows `IPv6 Prefix Updater failed:`.

It may have only a <Terminology title="An fe80 address that is never used as a source" to="/docs/reference/terminology#addresses-and-prefixes">link-local address</Terminology>, be down, or be a WAN that receives only a <Terminology title="The IPv6 network your ISP hands you, which can change" to="/docs/reference/terminology#addresses-and-prefixes">delegated prefix</Terminology>. |

Failures that happen before the <Terminology title="The file holding each baseline, kept across reinstalls" to="/docs/reference/terminology#running-checks">package state</Terminology> is read don't update **Last Run**. That covers the address and settings messages above and a <Terminology title="The file holding each baseline, kept across reinstalls" to="/docs/reference/terminology#running-checks">package state</Terminology> file that can't be read, which then appear only in <Terminology title="The latest run's lines, shown right after you start it" to="/docs/reference/terminology#running-checks">Command Output</Terminology>, the <Terminology title="An alert in pfSense's own notices list" to="/docs/reference/terminology#notifications-and-logs">WebGUI notice</Terminology>, and the <Terminology title="pfSense's general log, where every run leaves lines" to="/docs/reference/terminology#notifications-and-logs">system log</Terminology>.

For the WireGuard message, installing the WireGuard package or turning the WireGuard <Terminology title="One switch for a whole kind of setting" to="/docs/reference/terminology#fields-and-change-plans">field group</Terminology> off lets the next run continue. Turning the group off also means those <Terminology title="The address on a WireGuard tunnel interface" to="/docs/reference/terminology#pfsense-features">tunnel addresses</Terminology> are no longer updated.

If the <Terminology title="The file holding each baseline, kept across reinstalls" to="/docs/reference/terminology#running-checks">package state</Terminology> is damaged, removing `/cf/conf/ipv6-prefix-updater/state.json` from a shell lets the next run record a new <Terminology title="The recorded starting prefix that changes are measured from" to="/docs/reference/terminology#baselines-and-transitions">baseline</Terminology>. A new <Terminology title="The recorded starting prefix that changes are measured from" to="/docs/reference/terminology#baselines-and-transitions">baseline</Terminology> accepts the current prefix as it is, so addresses that still use an older prefix stay unchanged.

For a failure after the save, fix the verification or reload problem first. Then either restore the pre-update revision and rerun the update, or verify that the saved new-prefix values and affected services are correct and select **Status → Actions → Baseline Recovery → Accept Current Prefix**.

The accepted action updates only the package <Terminology title="The recorded starting prefix that changes are measured from" to="/docs/reference/terminology#baselines-and-transitions">baseline</Terminology>, records an **Accepted** outcome, and ends the repeated warning loop. [Backups and Recovery](/docs/operate/backups-and-recovery#after-a-failed-run) gives the full recovery procedure.

## Repeated Failure Notices

A <Terminology title="The run stopped at a check or safety stage" to="/docs/reference/terminology#run-outcomes">Failure</Terminology> on a scheduled run adds a new <Terminology title="An alert in pfSense's own notices list" to="/docs/reference/terminology#notifications-and-logs">WebGUI notice</Terminology> every time the schedule runs. Fixing the cause, or clearing **<Terminology title="Automatic checks on a schedule, off until you enable them" to="/docs/reference/terminology#running-checks">Enable Scheduled Updates</Terminology>** until you can, stops new notices.

## Another Run Owns the Lock

The message `Another run owns the package lock; this invocation exited without reading configuration.` means a prefix check, release check, or self-update was already running. The <Terminology title="Keeps two checks from ever running at once" to="/docs/reference/terminology#running-checks">run lock</Terminology> is released as soon as that operation ends, even if it crashed, so the message clears on its own.

To see whether a check is still running, run `ps ax | grep ipv6-prefix-updater` from a shell. The lock file stays on disk between runs by design, and deleting it isn't needed.

## Report a Bug

Bug reports go to the [GitHub issue tracker](https://github.com/mrjackyliang/pfsense-ipv6-prefix-updater/issues/new/choose). It is recommended to include:

- The package version from `pkg info pfSense-pkg-Ipv6PrefixUpdater`.
- The pfSense version.
- Each <Terminology title="The interface whose address reveals your current prefix" to="/docs/reference/terminology#interfaces-and-detection">Monitored Interface</Terminology> with its <Terminology title="How big your ISP's prefix is, like /56; you set it" to="/docs/reference/terminology#addresses-and-prefixes">Delegated Prefix Length</Terminology>, and the <Terminology title="One switch for a whole kind of setting" to="/docs/reference/terminology#fields-and-change-plans">field groups</Terminology> that are on.
- A screenshot of the Status tab and the <Terminology title="The latest run's lines, shown right after you start it" to="/docs/reference/terminology#running-checks">Command Output</Terminology>.
- The matching <Terminology title="pfSense's general log, where every run leaves lines" to="/docs/reference/terminology#notifications-and-logs">system log</Terminology> lines.

It is recommended to replace real public addresses with `2001:db8::` examples before posting.
