See what the current baseline and latest run recorded, and start a check, preview, or baseline recovery from the Status tab.

## Current State

The **Status** tab under **Services → IPv6 Prefix Updater** starts with this table, which has one row per monitored interface and describes the <Terminology title="The recorded starting prefix that changes are measured from" to="/docs/reference/terminology#baselines-and-transitions">baseline</Terminology> that the next check compares against:

- **<Terminology title="The interface whose address reveals your current prefix" to="/docs/reference/terminology#interfaces-and-detection">Monitored Interface</Terminology>**: the interface description followed by pfSense's internal name, such as `LAN (lan)`.
- **<Terminology title="The stored prefix each check compares against" to="/docs/reference/terminology#baselines-and-transitions">Last Successful Prefix</Terminology>**: the prefix and its length, such as `2001:db8:abcd:7800::/56`.
- **<Terminology title="The live address the prefix is read from on each run" to="/docs/reference/terminology#interfaces-and-detection">Last Successful Source Address</Terminology>**: the address in <Terminology title="The short lowercase spelling, such as 2001:db8::1" to="/docs/reference/terminology#addresses-and-prefixes">canonical form</Terminology>. A <Terminology title="Same prefix as last time, so there is nothing to do" to="/docs/reference/terminology#run-outcomes">No change</Terminology> run also refreshes it.
- **Last Successful Update**: the UTC time when the <Terminology title="The recorded starting prefix that changes are measured from" to="/docs/reference/terminology#baselines-and-transitions">baseline</Terminology> was initialized, accepted, or moved after the last <Terminology title="Prefix changed and every approved field was updated" to="/docs/reference/terminology#run-outcomes">Success</Terminology>, such as `2026-10-24T14:00:00+00:00`.

Before an interface's first run, its row shows `Not initialized. Run a normal check once to establish a safe baseline.` A <Terminology title="The recorded starting prefix that changes are measured from" to="/docs/reference/terminology#baselines-and-transitions">baseline</Terminology> taken over from the legacy updater shows `Not recorded by this package version` as its source address until the first check.

## Last Run

This panel records the latest run. When you monitor one interface, it shows that interface's result directly:

- **Outcome**: the result, explained in [Run Outcomes](/docs/operate/run-outcomes).
- **Timestamp (UTC)**: when the run finished.
- **<Terminology title="The live address the prefix is read from on each run" to="/docs/reference/terminology#interfaces-and-detection">Observed Source Address</Terminology>**: the address pfSense returned for the <Terminology title="The interface whose address reveals your current prefix" to="/docs/reference/terminology#interfaces-and-detection">Monitored Interface</Terminology>.
- **<Terminology title="The prefix seen right now, compared with the last one" to="/docs/reference/terminology#interfaces-and-detection">Observed Prefix</Terminology>**: the network calculated from that address and the <Terminology title="How big your ISP's prefix is, like /56; you set it" to="/docs/reference/terminology#addresses-and-prefixes">Delegated Prefix Length</Terminology>.
- **Changed Fields**: the number of <Terminology title="A setting the package is allowed to rewrite" to="/docs/reference/terminology#fields-and-change-plans">approved fields</Terminology> the run changed, or would change after a <Terminology title="A preview of the changes that writes nothing" to="/docs/reference/terminology#running-checks">dry run</Terminology>.
- **<Terminology title="A copy of the config taken right before any write" to="/docs/reference/terminology#backups-and-service-reloads">Configuration Backup Created</Terminology>**: `Yes`, or `No - this run did not write configuration`.
- **<Terminology title="Applies changed settings to a running service" to="/docs/reference/terminology#backups-and-service-reloads">Reloaded Services</Terminology>**: the services the run reloaded, or would reload after a <Terminology title="A preview of the changes that writes nothing" to="/docs/reference/terminology#running-checks">dry run</Terminology>.
- **Summary**: one sentence about the result, including the previous prefix after a <Terminology title="Your prefix changed, so the package goes to work" to="/docs/reference/terminology#baselines-and-transitions">prefix transition</Terminology>.
- **Packages**: shown when the run changed another package's settings, with one line per package, such as `Applied the <package> package settings again.` [Fields](/docs/configure/configuration-scopes#other-packages-settings) lists each message.
- **Skipped Fields**: shown when ticked fields no longer exist, with `These selected fields no longer exist, so the run skipped them. Review them on the Fields tab.` and each field's identity.

It is recommended to check the observed address and prefix first. They show whether pfSense returned the intended address and whether the length produced the expected network.

**Last Run** isn't updated when another check holds the <Terminology title="Keeps two checks from ever running at once" to="/docs/reference/terminology#running-checks">run lock</Terminology> or when a run stops before reading its <Terminology title="The file holding each baseline, kept across reinstalls" to="/docs/reference/terminology#running-checks">package state</Terminology>, such as when no monitored interface has a <Terminology title="A public IPv6 address in 2000::/3, the only kind used" to="/docs/reference/terminology#addresses-and-prefixes">global address</Terminology>. A <Terminology title="The run stopped at a check or safety stage" to="/docs/reference/terminology#run-outcomes">Failure</Terminology> always shows `0` changed fields, as [Run Outcomes](/docs/operate/run-outcomes#failures-after-the-save) explains.

### Last Run by Interface

When you monitor more than one interface, **Last Run** shows the totals and **Summary** counts the interfaces that were updated, unchanged, or need attention. The **Last Run by Interface** table below it lists each interface with its own outcome, observed prefix, changed fields, and summary.

- **Changed Fields** in **Last Run** counts each field once, even when two interfaces that share a <Terminology title="The IPv6 network your ISP hands you, which can change" to="/docs/reference/terminology#addresses-and-prefixes">delegated prefix</Terminology> both planned it.
- An interface without a <Terminology title="A public IPv6 address in 2000::/3, the only kind used" to="/docs/reference/terminology#addresses-and-prefixes">global address</Terminology> reports <Terminology title="The run stopped at a check or safety stage" to="/docs/reference/terminology#run-outcomes">Failure</Terminology> in its own row while the other interfaces are still checked.
- If two interfaces plan different values for the same field, the run stops before writing anything and reports which field disagreed.

## Actions

| Action                                                                                                                                  | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
|-----------------------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Run Now                                                                                                                                 | Runs a full check, even while <Terminology title="Automatic checks on a schedule, off until you enable them" to="/docs/reference/terminology#running-checks">scheduled updates</Terminology> are off. It records a <Terminology title="The recorded starting prefix that changes are measured from" to="/docs/reference/terminology#baselines-and-transitions">baseline</Terminology> when none exists and applies a <Terminology title="Your prefix changed, so the package goes to work" to="/docs/reference/terminology#baselines-and-transitions">prefix transition</Terminology> when it finds one. |
| <Terminology title="A preview of the changes that writes nothing" to="/docs/reference/terminology#running-checks">Dry Run</Terminology> | Runs the same check without a backup or a write. Before a <Terminology title="The recorded starting prefix that changes are measured from" to="/docs/reference/terminology#baselines-and-transitions">baseline</Terminology> exists, it reports <Terminology title="A dry run showing the baseline it would record" to="/docs/reference/terminology#run-outcomes">Initialization preview</Terminology>.                                                                                                                                                                                                  |
| Accept Current Prefix                                                                                                                   | After confirmation, records the active source address, prefix, and length as the new <Terminology title="The recorded starting prefix that changes are measured from" to="/docs/reference/terminology#baselines-and-transitions">baseline</Terminology>. It does not inspect approved fields, create a backup, write configuration, or reload services.                                                                                                                                                                                                                                                  |

Run Now and <Terminology title="A preview of the changes that writes nothing" to="/docs/reference/terminology#running-checks">Dry Run</Terminology> are <Terminology title="A check you start yourself, even with schedules off" to="/docs/reference/terminology#running-checks">manual runs</Terminology>. **Accept Current Prefix** is a recovery action and should be used only after the saved addresses and affected services have been verified.

Each action displays a completion or warning banner. The confirmation on **Accept Current Prefix** is the final safeguard before the package replaces its comparison baseline.

A check that finds another run in progress also shows the completed banner, so it is recommended to read the <Terminology title="The latest run's lines, shown right after you start it" to="/docs/reference/terminology#running-checks">Command Output</Terminology> as well.

## Command Output

After an action, a read-only **Latest Run** box appears under **<Terminology title="The latest run's lines, shown right after you start it" to="/docs/reference/terminology#running-checks">Command Output</Terminology>**:

```text
Status: No change
Interface: lan
Observed source address: 2001:db8:abcd:78aa::1
Previous prefix: 2001:db8:abcd:7800::
Current prefix: 2001:db8:abcd:7800::/56
Planned or changed fields: 0
Configuration backup: Not created
Reloaded services: None
Summary: The active IPv6 prefix is unchanged; no approved configuration targets were read or written.
```

The previous prefix is printed without its length. A failed run shows a single line that starts with `IPv6 Prefix Updater failed:` instead.

After a <Terminology title="A preview of the changes that writes nothing" to="/docs/reference/terminology#running-checks">dry run</Terminology> or a change, `Field changes:` follows with each address the run replaced, or would replace, and the field it belongs to:

```text
Field changes:
- aliases/alias/0/address: 2001:db8:abcd:78aa::10 → 2001:db8:abcd:88aa::10
```

## Choosing Fields

Which fields a run updates is chosen on the **Fields** tab, which lists every address inside each <Terminology title="The recorded starting prefix that changes are measured from" to="/docs/reference/terminology#baselines-and-transitions">baseline</Terminology> prefix. [Fields](/docs/configure/configuration-scopes) explains the groups, single-field exceptions, and Other Settings.
